> **主线版本**：C++11

## 1. 引言：当"父亲"不止一个

Ch01 的单继承很清晰——Dog 继承 Animal，一个基类一个派生类。对象内存布局是"基类数据 + 派生类数据"，vptr 一个，指针转换简单。

但 C++ 支持**多重继承**（Multiple Inheritance, MI）——一个类同时继承多个基类：

```cpp
class Flyable   { /* 飞行接口 */ };
class Swimmable { /* 游泳接口 */ };

// Duck 需要两者——单继承做不到
class Duck : public Flyable, public Swimmable { };
```

MI 带来了三个 Ch01 没有的挑战：

1. **对象内存布局不再简单**——两个基类各带 vptr，对象变成"多个基类子对象 + 派生类数据"
2. **指针会"飘移"**——`(Swimmable*)&duck` 和 `(Flyable*)&duck` 是不同地址
3. **菱形继承**——同一个祖父类通过两条路径出现在派生类中→数据重复→歧义

本章不是"劝你用 MI"——是"如果你维护了用到 MI 的代码，你至少要知道它带来了什么"。读完你能理解为什么 Java 禁止多继承，以及 C++ 怎么用虚继承和接口模式规避陷阱。

## 2. 多重继承的基本语法

### 2.1 两个独立的基类

```cpp
#include <iostream>

class Flyable {
public:
    virtual void fly() { std::cout << "flying\n"; }
    virtual ~Flyable() {}
};

class Swimmable {
public:
    virtual void swim() { std::cout << "swimming\n"; }
    virtual ~Swimmable() {}
};

// Duck 同时拥有飞行和游泳的能力
class Duck : public Flyable, public Swimmable {
public:
    void fly() override  { std::cout << "duck flying\n"; }
    void swim() override { std::cout << "duck swimming\n"; }
};
```

**语法**：`class D : public B1, public B2`——逗号分隔基类。

**这是 MI 最合理的用法——两个基类提供完全独立的接口**。Flyable 只管飞行，Swimmable 只管游泳——没有重叠、没有冲突。Duck 自然地同时是一个 Flyable 和一个 Swimmable。

### 2.2 比组合好在哪

有人会说"为什么不用组合"：

```cpp
// 组合版本——也能达到类似效果
class Duck {
    Flyable fly_behavior;
    Swimmable swim_behavior;
public:
    void fly() { fly_behavior.fly(); }
    void swim() { swim_behavior.swim(); }
};
```

组合的问题——**你不能把 `Duck*` 传给需要 `Flyable*` 的函数**。不满足"is-a"关系。MI 的 Duck 同时是一个 Flyable——可以当成 Flyable 用：

```cpp
void let_it_fly(Flyable* f) { f->fly(); }
Duck d;
let_it_fly(&d);   // ✓ MI——Duck 就是一个 Flyable
// 组合版本做不到——Duck 不是一个 Flyable
```

## 3. 多重继承的对象内存布局——指针为什么"飘移"

### 3.1 亲眼看到两个 vptr

单继承对象只有一个 vptr。MI 对象——每个有虚函数的基类各带一个 vptr：

```cpp
#include <iostream>

struct B1 {
    int x = 1;
    virtual ~B1() {}
};

struct B2 {
    int y = 2;
    virtual ~B2() {}
};

struct D : B1, B2 {
    int z = 3;
};

int main() {
    D d;
    std::cout << "&d:    " << &d << '\n';
    std::cout << "(B1*)&d: " << static_cast<B1*>(&d) << '\n';
    std::cout << "(B2*)&d: " << static_cast<B2*>(&d) << '\n';

    // 典型输出（64 位）：
    // &d:    0x7fff1234
    // (B1*)&d: 0x7fff1234    ← 和 &d 一样（第一个基类，偏移 0）
    // (B2*)&d: 0x7fff1244    ← 多了 16 字节（sizeof(B1) = vptr 8B + int 4B + padding 4B）！
    return 0;
}
```

**两个指针不一样**——这不是 bug。`B2*` 指向 D 对象中的 B2 子对象部分，而 B2 子对象在 B1 子对象之后。

### 3.2 完整的内存布局图

```
D 对象的内存布局：
┌────────────────────┐  ← &d (也是 B1* 的位置，第一个基类偏移 0)
│  B1::vptr          │  → B1 虚表（指向 D::f_B1, D::~D 等）
│  B1::x = 1         │
│  (padding 4B)      │
├────────────────────┤  ← B2* = &d + sizeof(B1)（第二个基类子对象的起始）
│  B2::vptr          │  → B2 虚表（指向 D::f_B2, D::~D 等）
│  B2::y = 2         │
│  (padding 4B)      │
├────────────────────┤
│  D::z = 3          │  ← 派生类自己的数据
└────────────────────┘
```

| 指针类型 | 地址 | 偏移 |
|---|---|---|
| `D*` | 对象起始 | 0 |
| `B1*` | 对象起始（第一个基类） | 0 |
| `B2*` | `&d + sizeof(B1)` | 16（64 位） |

### 3.3 编译器的 this 指针调整

把 `D*` 转成 `B2*` 时，编译器**自动插入偏移计算**：

```cpp
D*  pd = &d;
B2* pb = pd;           // 编译器生成：pb = (B2*)((char*)pd + sizeof(B1))
// 等价于 pb = (B2*)((char*)pd + 16)

B2* pb = &d;           // 同样——取地址时编译器知道需要加偏移
```

反过来——从 `B2*` 回到 `D*` 需要减去偏移：

```cpp
B2* pb = &d;                         // pb 指向 B2 子对象（偏移 16）
D* pd = dynamic_cast<D*>(pb);       // 需要 dynamic_cast——编译器不确定 pb 指向的 B2 是不是 D 的一部分
// dynamic_cast 查虚表→找到 B2→D 的偏移量→pb - offset→得 D 的地址
```

**为什么 `dynamic_cast` 比 `static_cast` 慢**——它需要读虚表确认对象是不是真的属于目标类型，而不是盲目加减偏移。

### 3.4 虚表和 offset_to_top

虚表里多了一个关键条目——`offset_to_top`：

```
B2 虚表（在 D 对象中）：
┌──────────────────┐
│ offset_to_top: -16│  ← 从 B2* 回到 D* 的偏移（负数——往前跳）
│ typeinfo 指针     │
│ ~D / ~B2 等      │
│ B2 的虚函数地址   │
└──────────────────┘
```

`dynamic_cast<D*>(pb)` 的流程：
1. 读 pb→vptr → B2 虚表
2. 读虚表中的 offset_to_top → -16
3. `(char*)pb + (-16)` → D 的起始地址
4. 验证类型匹配 → 成功返回 D*，失败返回 nullptr

这就是 `dynamic_cast` 在 MI 下的完整工作原理——它需要虚表数据，所以只能对多态类型（有虚函数）使用。

## 4. 菱形继承——同一个祖父出现两次

### 4.1 问题——数据重复

MI 最臭名昭著的问题是菱形继承——通过两条路径继承同一个祖先：

```
    Animal
    /    \
Mammal  Winged
    \    /
     Bat
```

```cpp
#include <iostream>

class Animal {
public:
    int age = 0;
    Animal() { std::cout << "Animal()\n"; }
};

class Mammal : public Animal {};
class Winged : public Animal {};
class Bat : public Mammal, public Winged {};

int main() {
    Bat b;
    // b.age = 5;          // ✗ 编译错误——"age is ambiguous"！哪个 age？
    b.Mammal::age = 5;     // ✓ 明确指定走 Mammal 路径
    b.Winged::age = 3;     // ✓ 另一个 age——不一样的！

    std::cout << b.Mammal::age << '\n';  // 5
    std::cout << b.Winged::age << '\n';  // 3——两个不同的 age！
    return 0;
}
```

**问题**：`Animal` 的 `age` 在 Bat 对象里存在**两份**——一份来自 Mammal→Animal，一份来自 Winged→Animal。`b.age` 歧义——编译器不知道你要哪个。浪费内存 + 不一致风险。

### 4.2 内存里到底发生了什么

Bat 对象的内存布局（普通继承）：

```
┌──────────────────┐
│  Mammal 子对象     │
│    Animal::age=5  │  ← 第一个 age（来自 Mammal 路径）
├──────────────────┤
│  Winged 子对象     │
│    Animal::age=3  │  ← 第二个 age（来自 Winged 路径）
├──────────────────┤
│  Bat 自己的数据    │
└──────────────────┘
```

Animal 的构造函数也被调了两次——构造 Mammal 时调一次，构造 Winged 时调一次。Animal 被构造两次！

```cpp
Bat b;
// 输出：
// Animal()   ← Mammal 构造时
// Animal()   ← Winged 构造时
```

**为什么编译器不自动合并**：C++ 的设计原则是"你明确选择多重继承→我给你每个路径独立的拷贝。如果你只想要一份→明确说虚继承"。

## 5. 虚继承——"我只要一份祖父"

### 5.1 语法——`virtual` 修饰继承

```cpp
#include <iostream>

class Animal {
public:
    int age = 0;
    Animal() { std::cout << "Animal()\n"; }
};

class Mammal : public virtual Animal {};  // 🆕 virtual
class Winged : public virtual Animal {};  // 🆕 virtual
class Bat : public Mammal, public Winged {};

int main() {
    Bat b;
    b.age = 5;  // ✓ 只有一个 age——走哪个路径都一样
    std::cout << b.age << '\n';  // 5
    // Animal() 只被调了一次！
    return 0;
}
```

### 5.2 虚继承是怎么做到的——vbptr

虚继承后内存布局大不一样。Animal 的数据不再"嵌"在 Mammal 和 Winged 内部——它被**提到对象末尾**。每个派生类多了一个虚基类指针（vbptr）：

```
Bat 对象的内存布局（虚继承）：
┌───────────────────────┐  ← &b, B1* 都是这里
│  Mammal::vbptr ───────┼───┐
│  Mammal 独有的数据      │   │  ← 指向虚基类表
├───────────────────────┤   │
│  Winged::vbptr ───────┼───┼─┐
│  Winged 独有的数据      │   │ │
├───────────────────────┤   │ │
│  Bat 自己的数据         │   │ │
├───────────────────────┤   │ │
│  Animal::age (唯一一份)  │ ←─┼─┘  ← 虚基类数据在末尾
└───────────────────────┘   │
                            │
                 虚基类表 (Mammal):   虚基类表 (Winged):
                 ┌─────────────┐    ┌─────────────┐
                 │ offset → 32 │    │ offset → 24 │
                 └─────────────┘    └─────────────┘
```

**访问 `b.age` 的实际过程**：
1. 从 Bat 对象中读 Mammal 的 vbptr
2. 根据 vbptr 找到虚基类表
3. 从表中读 Animal 的偏移量
4. `&b + offset` 得到 `&age` → 读 age

而普通继承——`age` 的偏移在编译时就能确定（直接加 `sizeof(base) + offset_of_age`）。虚继承多了一次**运行时**间接寻址。

### 5.3 虚继承的代价

| | 普通继承 | 虚继承 |
|---|---|---|
| 对象大小 | 基类数据在子对象内——无额外开销 | 多一个 vbptr（8 字节） |
| 数据访问 | 编译时常量偏移——`&obj + 常量` | 运行时查表——vbptr→虚基类表→偏移 |
| 构造 | 构造链：基类→派生类 | 最派生类负责构造虚基类（中间层忽略） |
| 菱形数据 | 多份副本 + 歧义 | 一份副本——无歧义 |

**核心结论**：虚继承解决菱形继承的数据重复问题——但代码是对象变大 + 访问变慢。**不要"预防性"用虚继承**——只在真的菱形继承时才用。Java 通过禁止多继承（只允许单继承类 + 多实现接口）从根本上避免了菱形数据重复。

### 5.4 构造函数规则——最派生类负责虚基类

虚继承的构造规则是 C++ 标准最精妙的点之一：

```cpp
class Animal {
public:
    int age;
    Animal(int a) : age(a) {}
};

class Mammal : public virtual Animal {
public:
    Mammal() : Animal(0) {}  // 这个 Animal(0) 在构造 Bat 时被忽略！
};

class Winged : public virtual Animal {
public:
    Winged() : Animal(0) {}  // 这个也被忽略！
};

class Bat : public Mammal, public Winged {
public:
    Bat() : Animal(5) {}  // ← 只有最派生类的 Animal 初始化生效！
};
```

**规则**：虚基类由**最派生类**（most derived class，即最终创建的对象类型）初始化。中间层的初始化语句被编译器忽略。如果不加这个规则，Mammal 的构造器调一次 Animal 初始化为 0、Winged 的又调一次初始化为 0 → Animal 被构造两次 → UB。

```cpp
Bat b;
// b.age = 5——只有 Bat 构造器里的 Animal(5) 生效
// Mammal 和 Winged 里的 Animal(0) 被编译器无视

Mammal m;  // 如果单独构造 Mammal→Animal(0) 生效（Mammal 变成最派生类）
```

## 6. 指针转换与 MI 工程总结

### 6.1 `sizeof` 的 MI 影响

```cpp
struct Empty { };                          // sizeof = 1（空基类优化）
struct Single : Empty { int x; };          // sizeof = 4（空基类优化——Empty 不占空间）
struct MI_first : Empty, Empty { };        // sizeof ≥ 2——两个同类型空基类需要 distinct addresses（取决于 ABI）

struct A { int a; virtual ~A() {} };
struct B : A { int b; };                   // sizeof = 16（vptr 8B + A::a 4B + B::b 4B —— B::b 放在 A::a 后面的空隙，不需额外 padding）

// 需看具体 ABI。简化版：
// sizeof(B) = sizeof(vptr) + sizeof(A::a) + sizeof(B::b) + padding
```

更清晰的演示：

```cpp
#include <iostream>

struct A { int x; virtual ~A() {} };       // vptr 8B + int 4B + padding 4B = 16
struct B { int y; virtual ~B() {} };       // 同上 = 16
struct D : A, B { int z; };               // A 16B + B 16B + D::z 4B + padding 4B = 40

std::cout << sizeof(A) << ' ' << sizeof(B) << ' ' << sizeof(D) << '\n';
// 16 16 40
```

### 6.2 指针转换的三种情况

```cpp
D d;
// 情况 1：向上转型——编译时自动调整偏移
A* a = &d;        // D* → A*：A 是第一个基类，偏移 0——不调整
B* b = &d;        // D* → B*：B 在 A 之后，偏移 sizeof(A)——编译器自动 +16

// 情况 2：向下转型——需要 dynamic_cast（MI 下 static_cast 不安全）
D* da = dynamic_cast<D*>(a);  // ✓ 运行时查虚表确认类型
D* db = dynamic_cast<D*>(b);  // ✓ 查虚表→减偏移→验证

// 情况 3：void* 不要用于 MI！
void* v = &d;
// D* dp = (D*)v;    // 危险——如果 v 实际是 B* 转来的，找回的是 B 子对象的位置
// 规则：MI 下永远用 dynamic_cast 做向下转型，永远不把 MI 对象的指针存成 void*
```

### 6.3 "三不"原则——多重继承的工程指南

> | 原则 | 说明 |
> |---|---|
> | 1. **不加数据成员的接口类**可以 MI | 类似 Java interface 的 C++ 实现——纯虚函数、无数据成员 |
> | 2. **有数据成员的类**避免 MI | 数据成员参与菱形继承→重复或需要虚继承（更复杂） |
> | 3. **虚继承只在真的菱形继承时用** | 不要"预防性"加 `virtual`——除非你确定这个类会参与菱形结构 |

```cpp
// ✓ 推荐——接口类只有纯虚函数，可以放心 MI
struct Serializable { virtual std::string serialize() const = 0; virtual ~Serializable() {} };
struct Cloneable    { virtual Cloneable* clone() const = 0; virtual ~Cloneable() {} };

class MyWidget : public Widget, public Serializable, public Cloneable { };

// ✗ 不推荐——数据类参与 MI
class BadDesign : public DataHolder1, public DataHolder2 { };  // 两个带数据的基类→大概率菱形
```

## 7. 可运行错误实验

### 实验 1：指针飘移——亲眼看到 B1* 和 B2* 指向不同地址

```cpp
#include <iostream>

struct B1 { int x = 1; virtual ~B1() {} };
struct B2 { int y = 2; virtual ~B2() {} };
struct D : B1, B2 { int z = 3; };

int main() {
    D d;
    B1* p1 = &d;
    B2* p2 = &d;
    D*  pd = &d;

    std::cout << "&d:    " << &d  << '\n';
    std::cout << "B1*:   " << p1 << " (same as &d)\n";
    std::cout << "B2*:   " << p2 << " (offset="
              << ((char*)p2 - (char*)p1) << " bytes from B1*)\n";
    std::cout << "D*:    " << pd << " (same as B1*)\n";

    // 典型输出：
    // &d:    0x7ffe1234
    // B1*:   0x7ffe1234 (same as &d)
    // B2*:   0x7ffe1244 (offset=16 bytes from B1*)
    // D*:    0x7ffe1234 (same as B1*)
    return 0;
}
```

**编译运行**：`g++ -std=c++11 mi_ptr.cpp -o mi_ptr && ./mi_ptr`

### 实验 2：菱形继承的数据重复 + 虚继承修复

```cpp
#include <iostream>

// === 普通继承版本——数据重复 ===
struct A_normal { int data = 0; };
struct B_normal : A_normal {};
struct C_normal : A_normal {};
struct D_normal : B_normal, C_normal {};

// === 虚继承版本——只有一份 ===
struct A_virt { int data = 0; };
struct B_virt : virtual A_virt {};
struct C_virt : virtual A_virt {};
struct D_virt : B_virt, C_virt {};

int main() {
    D_normal dn;
    dn.B_normal::data = 1;
    dn.C_normal::data = 2;
    std::cout << "普通继承: " << sizeof(dn) << " bytes, "
              << "B::data=" << dn.B_normal::data
              << " C::data=" << dn.C_normal::data << '\n';
    // 输出：普通继承: 8 bytes, B::data=1 C::data=2

    D_virt dv;
    dv.data = 42;
    std::cout << "虚继承:   " << sizeof(dv) << " bytes, "
              << "data=" << dv.data << '\n';
    // 输出：虚继承: 24 bytes, data=42
    // 虚继承对象更大（vbptr 开销），但 data 只有一份
    return 0;
}
```

## 8. 面试题

### 面试题 1：MI 对象的内存布局

**面试官**：`class D : public B1, public B2 {}; D d; B1* p1 = &d; B2* p2 = &d;`——`p1` 和 `p2` 的地址一样吗？为什么？

**回答**：不一样。`p1` 指向 D 对象中 B1 子对象的起始位置（通常就是对象起始地址——偏移 0），`p2` 指向 D 对象中 B2 子对象的位置（偏移了 `sizeof(B1)` 字节）。编译器自动做了 this 指针调整——转成 `B2*` 时插入偏移计算。验证：`(char*)p2 - (char*)p1` 输出非 0。

**追问（面试官）**：`dynamic_cast` 在 MI 下怎么知道要减多少偏移？

**追问回答**：虚表里记录了 `offset_to_top` ——一个专门存储"从这个基类子对象回到完整派生类对象"的偏移量。`dynamic_cast<Duck*>(swim_ptr)` → 读 Swimmable 的虚表 → 查 offset_to_top 条目 → `swim_ptr - offset` 得到 Duck 的地址 → 再验证类型匹配（通过 RTTI 的 type_info）。这就是 `dynamic_cast` 比 `static_cast` 慢的根本原因——多了一次虚表查找 + 运行时类型验证。

### 面试题 2：菱形继承与虚继承

**面试官**：什么是菱形继承？C++ 怎么解决？虚继承有什么代价？

**回答**：类 D 通过两条路径继承 A（B→A 和 C→A）→ A 的数据在 D 里有两份副本 → `d.a` 歧义且内存浪费。虚继承解决——`class B : virtual public A` ——编译器只保留一份 A 的副本。代价：(1) 每个派生类多一个 vbptr（8 字节）；(2) 每次访问 A 的成员多一次间接寻址——读 vbptr→查虚基类表→加偏移→访问数据（vs 普通继承的编译时常量偏移）；(3) 构造规则变复杂——虚基类由最派生类负责初始化，中间层的初始化语句被编译器忽略。

**追问（面试官）**：Java 为什么禁止多继承（只能单继承类）？C++ 怎么用接口模式避免菱形问题？

**追问回答**：Java 禁止多继承类就是为了彻底避免菱形继承的数据重复和歧义——只有接口能多继承（接口没有数据成员→没有数据重复问题）。C++ 可以用相同模式——只让**纯抽象类**（只有纯虚函数、无数据成员）参与多重继承，数据保持单继承链。这就是"三不"原则——接口类 MI 没问题，数据类走单继承。C++ STL 中的 `iostream` 就是同时继承 `istream` 和 `ostream`（两个都有数据成员），用的是虚继承。

### 面试题 3：虚继承的内存布局和构造规则

**面试官**：虚继承的对象比普通继承多什么？为什么访问虚基类的成员更慢？

**回答**：多一个 vbptr（虚基类指针），指向虚基类表（记录虚基类在对象中的偏移量）。访问 `d.age` → 读 Mammal 的 vbptr → 查表中 Animal 的偏移 → `&d + offset` → 读 age。普通继承中 `d.age` 等价于 `*(&d + sizeof(Mammal) + offset_of_age)` ——编译时常量，不查表。虚继承多一次间接寻址。

**追问（面试官）**：那构造函数里虚基类怎么初始化？Mammal 和 Winged 的构造器里都初始化 Animal 了吗？

**追问回答**：不会——**最派生类**（most derived class，这里是 Bat）负责初始化虚基类。Mammal 和 Winged 构造函数里的 Animal 初始化被编译器忽略（除非 Mammal 或 Winged 被单独作为对象构造）。标准这样做是为了防止虚基类被多次构造——如果不加这个规则，Bat 构造时 Mammal 调一次 Animal()、Winged 调一次 Animal() → Animal 被构造两次 → UB。这个规则是 C++ 虚继承最重要的精细控制点。

## 9. 本章小结

| 概念 | 核心理解 |
|---|---|
| 多重继承 | `class D : public B1, public B2` ——同时拥有两个基类 |
| 指针飘移 | B1* 和 B2* 指向不同地址——编译器自动插入偏移计算 |
| 双 vptr | MI 下每个有虚函数的基类各带一个 vptr |
| offset_to_top | 虚表条目——从基类子对象回到派生类对象的偏移 |
| 菱形继承 | 同祖先走两条路径→数据两份→歧义+浪费 |
| 虚继承 | `virtual public A`——所有路径共享一份 A |
| vbptr | 虚基类指针——间接访址的代价 |
| 最派生类初始化 | 虚基类由最终对象类型负责构造——防止多次初始化 |
| "三不"原则 | 接口 MI 可以，数据类避免 MI，不预防性虚继承 |
