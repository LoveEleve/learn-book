## 1. 引言：编译时不够用了

Stage2 的核心是**编译时多态**——模板让编译器按参数类型生成不同代码。`max<int>` 和 `max<double>` 是两份不同的函数，在编译时就已经确定。这覆盖了 80% 的场景。

但剩下的 20% 需要**运行时多态**——程序运行时才知道"当前处理的是圆还是矩形"：

```cpp
// 用户点击屏幕——运行时才知道画的是哪种形状
Shape* selected = get_selected_shape();  // 可能返回 Circle* 或 Rectangle*
selected->draw();  // 到底画圆还是画方？编译时不知道
```

Stage1 Ch01 §5 做过一件事——用 C 手写虚函数表：

```cpp
// C 的方式——手写 vtable（函数指针表）+ void*
struct shape_vtable { void (*draw)(void*); double (*area)(void*); };
struct Circle { struct shape_vtable* vtable; double r; };
// 繁琐、危险、不类型安全——但思路是对的
```

C++ 把这三个步骤（定义虚表、初始化虚指针、运行时查表）全部交给编译器——你只写 `virtual`，编译器生成一切。本章从 C 的手写 vtable 出发，逐步带你看到 C++ 编译器在背后做了什么。

## 2. 继承的基本语法——从 C 的"组合"到 C++ 的"继承"

### 2.1 最简单的继承

```cpp
#include <iostream>

class Animal {
public:
    void eat() { std::cout << "eating\n"; }
};

class Dog : public Animal {  // Dog 继承 Animal
public:
    void bark() { std::cout << "barking\n"; }
};

Dog d;
d.eat();   // Dog 继承了 Animal 的 eat()
d.bark();  // Dog 自己的方法
```

`class Dog : public Animal` 的含义——Dog 拥有 Animal 的所有 public/protected 成员，同时可以添加自己的。Dog 的 `eat()` 不是 Dog 自己定义的——是编译器自动继承下来的。

### 2.2 三种继承方式

| 继承方式 | 基类 public → 派生类 | 基类 protected → 派生类 | 使用场景 |
|---|---|---|---|
| `public` | 保持 public | 保持 protected | 最常用——"Dog is an Animal" |
| `protected` | 变为 protected | 变为 protected | 少见——"用基类实现，暴露给子类" |
| `private` | 变为 private | 变为 private | "用基类实现，不暴露基类接口" |

```cpp
class Dog : public Animal { };       // is-a——Dog 就是一个 Animal
class Stack : private std::vector<int> { };  // implemented-in-terms-of——Stack 用 vector 实现，不暴露 vector 接口
```

**`private` 继承和组合的区别**：两者都表达"用基类实现但不暴露接口"。组合（`Stack { vector<int> data; }`）更清晰——优先用组合。`private` 继承的独特场景——需要访问基类的 protected 成员，或者需要重写基类的虚函数。

### 2.3 C 的模拟方式和对比

C 里"继承"是靠**内嵌结构体**模拟的：

```cpp
// C 的做法
struct Animal_C { int age; };

struct Dog_C {
    struct Animal_C base;  // 继承——Animal 作为第一个成员
    int bark_count;
};

// 指针转换
struct Dog_C d;
struct Animal_C* a = (struct Animal_C*)&d;  // 手动转——危险
// 如果 Animal 不是第一个成员，这里就错了
```

C++ 的继承确保基类子对象在派生类对象中的偏移在编译时固定——`static_cast<Animal*>(dog_ptr)` 是安全的指针计算，不需要手动维护偏移量。

## 3. 虚函数——运行时决定调哪个版本

### 3.1 问题——没有虚函数时

继承让 Dog 复用 Animal 的代码。但更重要的需求是"统一接口"——通过同一个指针调用不同行为：

```cpp
#include <iostream>

class Animal {
public:
    void speak() { std::cout << "...\n"; }  // 非虚函数
};

class Dog : public Animal {
public:
    void speak() { std::cout << "Woof!\n"; }  // 只是"隐藏"了基类的 speak
};

class Cat : public Animal {
public:
    void speak() { std::cout << "Meow!\n"; }
};

// 通过基类指针调用——编译时决定调哪个版本
Animal* a1 = new Dog();
Animal* a2 = new Cat();
a1->speak();  // "..."——调的是 Animal::speak，不是 Dog::speak！
a2->speak();  // "..."——同理
```

**为什么**：编译器看到 `a1` 的类型是 `Animal*` ——直接生成 `Animal::speak()` 的调用。编译器不知道也不关心 `a1` 实际指向 Dog——这就是非虚函数的"编译时绑定"。

### 3.2 加 `virtual` ——运行时绑定

在基类的方法声明前面加 `virtual`，一切都变了：

```cpp
#include <iostream>

class Animal {
public:
    virtual void speak() { std::cout << "...\n"; }  // 🆕 virtual
};

class Dog : public Animal {
public:
    void speak() override { std::cout << "Woof!\n"; }  // C++11 override
};

class Cat : public Animal {
public:
    void speak() override { std::cout << "Meow!\n"; }
};

Animal* a1 = new Dog();
Animal* a2 = new Cat();
a1->speak();  // "Woof!"——运行时调用 Dog::speak
a2->speak();  // "Meow!"——运行时调用 Cat::speak
```

**区别**：非虚函数——编译时看指针类型。虚函数——运行时看指针指向的**真实对象类型**。

```cpp
// 这个对比是面试必考的
Animal* p = new Dog();
p->speak();        // "Woof!"（虚函数——运行时查找 Dog 的版本）
p->Animal::speak(); // "..."（显式调用基类版本——编译时确定）
```

### 3.3 `override` ——编译时说"我在重写"

`override` 是 C++11 的关键字——它不是语法糖，而是**防错机制**：

```cpp
class Animal {
public:
    virtual void speak() const;  // 注意：const 成员函数
};

class Dog : public Animal {
public:
    void speak() override;  // 🔴 编译错误！speak() 和 speak() const 不是同一个函数
};
```

**常见的 `override` 捕获的 bug**：

| 你写错了什么 | 不加 override | 加了 override |
|---|---|---|
| 函数名拼错 `spaek()` | 静默定义新函数——运行时不走虚函数路径 | 编译错误——"no function to override" |
| 参数不同 `speak(int)` | 定义重载——不是重写 | 编译错误 |
| const 缺了 `speak()` | 同上 | 编译错误 |
| 返回值不兼容 `int speak()` | 同上 | 编译错误 |

**没有 `override` 的 C++98 时代**——拼错一个字母就静默定义了新函数，基类指针永远调用不到你的"重写"版本。这是 C++98 的一个安全漏洞，`override` 彻底修复了它。

### 3.4 `final` ——阻止重写和继承

```cpp
class Animal {
public:
    virtual void speak() final { /* ... */ }  // 子类不能重写 speak
};

class Dog : public Animal {
public:
    // void speak() override { }  // 🔴 编译错误——speak 被标记为 final
};

class Chihuahua final : public Dog { };  // Chihuahua 不能被继承
// class MiniChihuahua : public Chihuahua { };  // 🔴 编译错误
```

**`final` 的性能含义——去虚化（devirtualization）**：

```cpp
class Foo final {
public:
    virtual void f() { /* ... */ }
};

Foo obj;
obj.f();  // 编译器知道 Foo 没有子类→不可能有重写→直接调用 Foo::f()，不走虚表
```

编译器看到 `final` 后知道"不可能有子类重写此函数"——在知道确切类型的调用点（如栈对象、`final` 类指针），可以把虚函数调用优化为直接调用，省去 vptr→虚表→函数地址的两次间接寻址。这是 C++ "零开销抽象"的又一个例子——你写虚函数得到灵活性，编译器在用不到灵活性时把它优化成普通函数调用。

### 3.5 虚函数和模板的区别——Stage2 到 Stage3 的桥梁

这是贯穿 Stage2 和 Stage3 的核心理解：

| | 模板（编译时多态） | 虚函数（运行时多态） |
|---|---|---|
| 决定时间 | 编译时 | 运行时 |
| 机制 | 编译器生成多份代码 | vptr + vtable 间接跳转 |
| 开销 | 零（代码膨胀） | 一次间接寻址（~5-10 cycles） |
| 灵活性 | 必须在编译时知道类型 | 运行时动态决定 |
| 典型场景 | `vector<int>` vs `vector<double>` | 插件系统——运行时加载新形状类 |

**什么时候用哪个**：编译时能确定的类型→模板（性能最优）。类型必须在运行时决定→虚函数。两者不冲突——`std::function` 用类型擦除（内部藏了一个虚表）在运行时存不同类型的可调用对象。

## 4. 虚表（vtable）——虚函数是怎么实现的

虚函数不是魔术。编译器用两张表 + 一个指针实现——这是本章最核心的概念。

### 4.1 对象的内存布局

每个有虚函数的对象在数据的**最前面**多了一个隐藏指针——`vptr`（虚表指针）：

```
Animal 对象:                     Dog 对象:
┌────────────┐                  ┌────────────┐
│   vptr     │ ───┐             │   vptr     │ ───┐
├────────────┤    │             ├────────────┤    │
│  (数据成员)  │    │             │  (数据成员)  │    │
└────────────┘    │             │  Dog 独有数据 │    │
                  │             └────────────┘    │
                  ▼                               ▼
           Animal 虚表                       Dog 虚表
        ┌──────────────┐               ┌──────────────┐
        │  speak ──────→ Animal::speak │  speak ──────→ Dog::speak
        │  ~Animal ────→ Animal::~Animal│  ~Dog ───────→ Dog::~Dog
        └──────────────┘               └──────────────┘
```

**三个关键数字**：

- **每个对象**：多 8 字节（64 位平台的 vptr）
- **每个虚函数类**：一张虚表（所有同类的对象共享同一张虚表）
- **每次虚函数调用**：多一次间接跳转（读 vptr → 查虚表 → 跳转，~5-10 cycles）

```cpp
// sizeof 实证
struct Plain { int x; };           // sizeof = 4
struct Virtual { virtual ~Virtual() {} int x; };  // sizeof = 16（8B vptr + 4B int + 4B 对齐）
```

### 4.2 虚函数调用的指令级视图

```cpp
Animal* p = new Dog();
p->speak();  // 编译器生成（简化）：
// mov rax, [p]           ; rax = p 指向的对象
// mov rax, [rax]         ; rax = vptr（对象头 8 字节）
// mov rax, [rax + N]     ; rax = 虚表[N]（speak 在虚表中的槽位）
// call rax               ; 跳转到实际的 speak 函数
```

三次内存访问——比直接调用（`call Dog_speak` 一次）多了两次间接读取。10 cycles vs 5 cycles——不是零，但在绝大多数场景可以忽略（比一次函数调用本身的开销还小）。

### 4.3 构造和析构时 vptr 指向谁——虚函数不生效的根源

构造一个派生类对象时，vptr 不是一开始就指向派生类虚表——它**逐步切换**：

```
时间线——Dog 对象的构造过程：
1. 分配内存
2. 进入 Animal 构造函数：
   vptr → Animal 虚表  ← 此时如果调 speak，调的是 Animal::speak
3. Animal 构造完成
4. 进入 Dog 构造函数：
   vptr → Dog 虚表      ← 此时如果调 speak，调的是 Dog::speak
5. Dog 构造完成
```

析构时反过来——vptr 从 Dog 虚表**逐步回退**到 Animal 虚表。这就是"构造函数/析构函数里虚函数不多态"的根源——不是你写的代码有问题，是 vptr 在那个时刻确实指向当前构造层的虚表。

```cpp
class Base {
public:
    Base() { print(); }  // 构造里调虚函数
    virtual void print() { std::cout << "Base\n"; }
};

class Derived : public Base {
public:
    Derived() : Base() {}  // 先构造 Base
    virtual void print() { std::cout << "Derived\n"; }
};

Derived d;  // 输出 "Base"——不是 "Derived"
// 因为 Base 构造时 vptr 指向 Base 虚表→调用 Base::print
```

这就是实验 2 要验证的——亲手看到"构造里的虚函数不走多态"。

## 5. 虚析构函数——`delete` 基类指针的资源泄漏

### 5.1 问题——没有虚析构会怎样

这是 C++ 最经典的生产 bug 之一：

```cpp
#include <iostream>

class Animal {
public:
    Animal() { std::cout << "Animal()\n"; }
    ~Animal() { std::cout << "~Animal()\n"; }  // 🔴 不是虚的！
};

class Dog : public Animal {
    char* buffer;
public:
    Dog() : buffer(new char[1024]) { std::cout << "Dog() allocated 1KB\n"; }
    ~Dog() { delete[] buffer; std::cout << "~Dog() freed 1KB\n"; }
};

int main() {
    Animal* p = new Dog();
    delete p;
    // 输出：
    // Animal()
    // Dog() allocated 1KB
    // ~Animal()         ← 只调了 Animal 的析构！
    //                   ← Dog 的析构没被调——buffer 泄漏 1KB
    return 0;
}
```

**为什么**：`delete p` 时编译器看到 `p` 的类型是 `Animal*`。析构函数不是虚的→编译时决定调 `~Animal()`。编译器不知道 `p` 实际指向 Dog→`~Dog()` 不跑→`buffer` 不释放→泄漏。注意这是 C++ 标准定义的**未定义行为**（UB）——编译器有权产生任何结果，只是大多数实现表现为"不调派生类析构函数"。

### 5.2 修复——加 `virtual`

```cpp
class Animal {
public:
    virtual ~Animal() {}  // ✓ 虚析构
};
```

现在 `delete p` 通过虚表找到真实的析构函数——先调 `~Dog()` 释放 Dog 的资源，再调 `~Animal()` 释放 Animal 的资源。**标准析构链——派生类→基类，自动递归**。

### 5.3 核心规则

> **只要类有虚函数或可能被继承→析构函数必须 `virtual`。**

| 场景 | 要不要虚析构 | 原因 |
|---|---|---|
| 有虚函数的基类 | **必须** | 通过基类指针 `delete` 是常态 |
| 可能被继承的基类 | **应该** | 使用者可能通过基类指针 `delete` |
| `final` 类 | 不需要 | 不能被继承，不存在基类指针指向子对象 |
| 纯值类型的类 | 不需要 | 不会被继承 |

**为什么构造函数不能是虚的**：构造时编译器知道确切类型——`new Dog()` 直接调 `Dog::Dog()`。不需要虚表找——这也是为什么构造函数不能是虚的原因。

## 6. 抽象类与纯虚函数——Java `interface` 的 C++ 版本

### 6.1 纯虚函数 `= 0`

```cpp
class Shape {
public:
    virtual double area() const = 0;  // 纯虚函数——"= 0"表示没有实现
    virtual void draw() const = 0;
    virtual ~Shape() {}               // 虚析构——有了虚函数必须加
};
```

`= 0` 的意思是——"这个函数在这里没有默认实现，派生类必须提供"。和普通虚函数的区别：普通虚函数有默认实现（派生类可以选择重写），纯虚函数**没有默认实现**（派生类必须重写）。

### 6.2 抽象类——不能实例化

至少有一个纯虚函数的类叫抽象类——你不能创建它的对象：

```cpp
// Shape s;  // ✗ 编译错误——抽象类不能实例化
Shape* s = new Circle(5.0);  // ✓ 通过基类指针指向具体派生类
```

```cpp
class Circle : public Shape {
    double r;
public:
    Circle(double radius) : r(radius) {}
    double area() const override { return 3.14159 * r * r; }
    void draw() const override { /* 画圆 */ }
};

class Rectangle : public Shape {
    double w, h;
public:
    Rectangle(double width, double height) : w(width), h(height) {}
    double area() const override { return w * h; }
    void draw() const override { /* 画方 */ }
};

// 运行时多态——同一个接口，不同行为
Shape* shapes[] = { new Circle(5), new Rectangle(3, 4) };
for (auto* s : shapes) {
    std::cout << s->area() << '\n';  // 78.54, 12
}
```

### 6.3 和 Java `interface` 的区别

| | C++ 抽象类 | Java `interface` |
|---|---|---|
| 纯虚方法 | `= 0` | `abstract` |
| 可以有数据成员 | 可以 | 不能（只能 static final 常量） |
| 可以有已实现方法 | 可以 | 不能（Java 8+ `default` 方法可以） |
| 多重"继承" | 多继承（Ch02） | 多实现 |
| 关键字 | 没有——靠 `= 0` 定义 | `interface` |

C++ 没有 `interface` 关键字——抽象类（含纯虚函数）就是接口。这比 Java 更灵活（可以混入数据成员和已实现方法）但也更容易滥用。

### 6.4 纯虚析构的特殊性

一个罕见但重要的场景——你想让类成为抽象类但没有合适的纯虚函数：

```cpp
class AbstractBase {
public:
    virtual ~AbstractBase() = 0;  // 纯虚析构——使类成为抽象类
};
AbstractBase::~AbstractBase() {}  // 必须提供定义！析构链需要调用它
```

纯虚析构函数**必须提供定义**——因为派生类析构时最终会调它。普通的纯虚函数不需要定义。

## 7. RTTI——运行时查类型

### 7.1 `dynamic_cast` ——安全的向下转型

```cpp
Animal* a = get_animal();  // 可能是 Dog* 或 Cat*

// C 风格转换——不检查，错了就是 UB
Dog* d1 = (Dog*)a;  // 🔴 如果 a 实际是 Cat→UB

// dynamic_cast——运行时检查
Dog* d2 = dynamic_cast<Dog*>(a);
if (d2) {
    d2->bark();  // ✓ 是 Dog 才执行
}
Cat* c2 = dynamic_cast<Cat*>(a);
if (c2) {
    c2->meow();  // ✓ 是 Cat 才执行
}
```

**指针 vs 引用版本的 `dynamic_cast`**：

```cpp
// 指针版本——失败返回 nullptr
Dog* d = dynamic_cast<Dog*>(a);

// 引用版本——失败抛 std::bad_cast 异常
try {
    Dog& d = dynamic_cast<Dog&>(*a);
} catch (std::bad_cast& e) {
    // 不是 Dog
}
```

### 7.2 `typeid` ——查真实类型

```cpp
#include <typeinfo>

if (typeid(*a) == typeid(Dog)) {
    std::cout << "是 Dog\n";
}

std::cout << typeid(*a).name() << '\n';  // "3Dog" 或 "Dog"——取决于编译器
```

**注意 `typeid` 的陷阱**：对非多态类型（没有虚函数），`typeid` 在编译时求值——不看实际类型只看声明类型：

```cpp
struct NonPoly { };
NonPoly* np = new NonPoly();
typeid(*np);  // 总是 NonPoly——即使 np 指向派生类
```

### 7.3 RTTI 的代价

- **`dynamic_cast`**：运行时按字符串比较类型名或遍历虚表——比 `static_cast` 慢一个数量级。不放在热路径。
- **`typeid`**：对多态类型也是运行时开销。对非多态类型零开销（编译时求值）。
- **需要 `-frtti` 编译选项**（默认开启）。有些嵌入式项目关掉 RTTI 以减小二进制体积。

**不滥用 RTTI**——如果一个函数需要频繁做 `dynamic_cast` 然后根据类型分支，说明设计有问题——应该用虚函数把"根据类型做不同的事"封装在类内部。

## 8. 可运行错误实验

### 实验 1：虚析构函数缺失导致资源泄漏

```cpp
#include <iostream>

class Animal {
public:
    Animal() { std::cout << "Animal()\n"; }
    ~Animal() { std::cout << "~Animal()\n"; }  // 🔴 不是虚的！
};

class Dog : public Animal {
    char* buf;
public:
    Dog() : buf(new char[1024]) { std::cout << "Dog() allocated 1KB\n"; }
    ~Dog() { delete[] buf; std::cout << "~Dog() freed 1KB\n"; }
};

int main() {
    Animal* p = new Dog();
    delete p;
    // 输出：
    // Animal()
    // Dog() allocated 1KB
    // ~Animal()
    // ← ~Dog() 没被调——1KB 泄漏！
    return 0;
}
```

**编译运行**：`g++ -std=c++11 leak.cpp -o leak && ./leak`
**用 valgrind 验证**：`valgrind --leak-check=full ./leak` → "1,024 bytes in 1 blocks are definitely lost"

**修复**：把 `~Animal()` 改为 `virtual ~Animal() {}`——重新编译运行，现在看到 `~Dog()` + `~Animal()` 都输出，valgrind 无泄漏。

### 实验 2：构造函数里的虚函数不生效

```cpp
#include <iostream>

class Base {
public:
    Base() { print(); }               // 构造里调虚函数
    virtual void print() { std::cout << "Base\n"; }
    virtual ~Base() {}
};

class Derived : public Base {
public:
    Derived() : Base() {}             // 先构造 Base
    virtual void print() { std::cout << "Derived\n"; }
};

int main() {
    Derived d;  // 输出 "Base"——不是 "Derived"！
    d.print();  // 输出 "Derived"——构造完后才走多态
    return 0;
}
```

**输出**：
```
Base        ← Base 构造时 vptr 指向 Base 虚表→调用 Base::print
Derived     ← 构造完成后 vptr 指向 Derived 虚表→调用 Derived::print
```

## 9. 面试题

### 面试题 1：虚函数的实现机制

**面试官**：虚函数是怎么实现的？`virtual` 给对象增加了什么开销？

**回答**：虚表（vtable）+ 虚指针（vptr）。每个有虚函数的类有一张虚表——类的所有对象共享同一张虚表，表里存的是该类实际调用的虚函数地址。每个对象有一个 vptr（通常对象头 8 字节），指向它所属类的虚表。调用 `a->speak()` → 读 vptr → 查虚表中 speak 条目 → 跳转到实际函数。开销：(1) 每个对象多 8 字节（vptr）；(2) 每次虚函数调用多一次间接寻址（~5-10 cycles）；(3) 构造函数/析构函数里虚函数不多态——因为 vptr 在构造/析构过程中逐步切换（构造：基类→派生类；析构：派生类→基类）。

**追问（面试官）**：构造函数里调虚函数会多态吗？

**追问回答**：不会。在构造函数执行期间，vptr 指向**当前正在构造的类**的虚表。构造从基类到派生类逐步进行——Base 构造时 vptr 指向 Base 虚表（即使对象最终是 Derived），此时调虚函数走的是 Base 自己的版本。如果此时走多态调用 Derived 的重写版本→Derived 的数据成员还没初始化→UB。同理，析构函数里 vptr 从派生类虚表逐步回退到基类虚表——虚函数也不多态。

### 面试题 2：虚析构函数

**面试官**：什么时候基类的析构函数必须加 `virtual`？不加会怎样？

**回答**：只要类有虚函数或可能被继承→析构函数必须 `virtual`。不加→`Animal* a = new Dog(); delete a;` 只调 `~Animal()` 不调 `~Dog()`→`Dog` 中分配到堆上的数据不释放→资源泄漏。规则：有虚函数或打算被继承的类→析构函数必须 virtual。`final` 类可以不加（不能被继承，不存在基类指针指向派生对象的问题）。

**追问（面试官）**：为什么析构函数可以虚而构造函数不能？

**追问回答**：构造时——编译器知道确切类型（你写的 `new Dog()`），不需要虚表来选择正确的构造函数→构造函数不是虚的。析构时——通过基类指针 `delete`，编译器只知道声明类型（`Animal*`），必须靠虚表找到真实析构函数→析构函数必须是虚的。本质原因：构造是"已知目标的自顶向下"，析构是"未知目标的需查表"。

### 面试题 3：`override` 和 `final`

**面试官**：`override` 和 `final` 各解决什么问题？加了有什么好处？

**回答**：`override` ——告诉编译器"我在重写基类的虚函数"，防止拼写错误（函数名/参数/const/返回值任一写错→编译错误而不是静默定义新函数）。这是 C++98 的安全补丁——过去一个拼写错误就让虚函数调用静默失败，调试极其困难。`final` ——阻止进一步重写（`void f() final`）或阻止继承（`class Foo final`）。两大好处：(1) 编译器帮你检查真的在重写；(2) `final` 给去虚化优化机会——编译器知道无子类重写→在知道确切类型的调用点把虚函数调用优化为直接调用。

**追问（面试官）**：`final` 类的虚函数调用为什么能被优化？

**追问回答**：编译器看到 `class Foo final` 后知道不可能有任何类继承 Foo→虚表中所有虚函数都只有 Foo 自己的版本，不可能被替换。于是在调用点（栈对象 `Foo obj; obj.f()` 或 `Foo* p; p->f()`），编译器可以跳过 vptr→虚表的间接跳转，直接调用 `Foo::f()`。结果——`final` 类有虚函数的灵活性，但和普通函数一样快。这是 C++ "零开销抽象"的标准案例——语法提供灵活性和安全性，编译器在不需要灵活性的地方回收开销。

## 10. 本章小结

| 概念 | 核心理解 |
|---|---|
| 继承 | `class Dog : public Animal` ——自动继承基类接口和数据 |
