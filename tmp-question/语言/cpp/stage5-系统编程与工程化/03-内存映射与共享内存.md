## 1. 引言：C 的 `mmap` 需要多少行胶水代码

`mmap` 是 Linux 最强大的系统调用之一——把文件映射到内存地址空间，之后读写文件就像读写内存一样。但 C 里用起来很痛苦：

```cpp
// C 的模式——mmap 和 munmap 完全手动
int fd = open("data.bin", O_RDONLY);
struct stat st; fstat(fd, &st);

void* addr = mmap(NULL, st.st_size, PROT_READ, MAP_PRIVATE, fd, 0);
if (addr == MAP_FAILED) { close(fd); return -1; }

// 使用 addr...
int* data = static_cast<int*>(addr);
int sum = 0;
for (size_t i = 0; i < st.st_size / sizeof(int); i++) sum += data[i];

munmap(addr, st.st_size);  // 别忘了！
close(fd);                  // 别忘了！
// 两条路径、两个资源类型、每处都要手动释放
```

C++ 可以把这个过程包装成 RAII——一个类搞定 mmap 的打开、映射、释放。本章展示 C++ 怎么让 `mmap` 变成"打开文件，文件内容自动出现在内存里，离开作用域自动清理"。

## 2. RAII `mmap` 封装——一条规则替代四处手动管理

### 2.1 最简封装

```cpp
#include <sys/mman.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdexcept>

class MMapFile {
    int   fd_ = -1;
    void* addr_ = MAP_FAILED;
    size_t size_ = 0;

public:
    // 构造——打开 + mmap
    MMapFile(const char* path) {
        fd_ = open(path, O_RDONLY);
        if (fd_ < 0) throw std::runtime_error("cannot open file");

        struct stat st;
        fstat(fd_, &st);
        size_ = st.st_size;

        addr_ = mmap(NULL, size_, PROT_READ, MAP_PRIVATE, fd_, 0);
        if (addr_ == MAP_FAILED) {
            close(fd_);
            throw std::runtime_error("mmap failed");
        }
    }

    // 析构——munmap + close（逆序）
    ~MMapFile() {
        if (addr_ != MAP_FAILED) munmap(addr_, size_);
        if (fd_ >= 0) close(fd_);
    }

    // 禁止拷贝（mmap 资源唯一）
    MMapFile(const MMapFile&) = delete;
    MMapFile& operator=(const MMapFile&) = delete;

    // 允许移动
    MMapFile(MMapFile&& other) noexcept
        : fd_(other.fd_), addr_(other.addr_), size_(other.size_) {
        other.fd_ = -1;
        other.addr_ = MAP_FAILED;
    }

    // 数据访问——像数组一样
    const void* data() const { return addr_; }
    size_t      size() const { return size_; }

    template <typename T>
    const T* as() const { return static_cast<const T*>(addr_); }
};
```

### 2.2 使用——三行替代 C 的十五行

```cpp
#include <iostream>

int main() {
    MMapFile file("data.bin");                    // 打开 + mmap——一行
    const int* data = file.as<int>();             // 以 int[] 访问——一行
    size_t count = file.size() / sizeof(int);

    int sum = 0;
    for (size_t i = 0; i < count; i++) sum += data[i];

    std::cout << "sum: " << sum << '\n';
    return 0;
}  // file 析构——自动 munmap + close——零手动清理
```

**三个关键设计**：
1. **禁止拷贝**——`mmap` 的内存区域只能有一个"主人"。拷贝会 double-free
2. **允许移动**——可以转移所有权到另一个 `MMapFile`
3. **构造失败时清理**——构造函数内如果 `mmap` 失败，先 `close(fd)` 再抛异常——不泄漏

## 3. `madvise`——给内核"建议"

`mmap` 之后，你可以给内核"建议"怎么管理这些页面：

```cpp
#include <sys/mman.h>

class MMapFile {
    // ...
public:
    // 顺序读——内核提前预取后续页面
    void advise_sequential() {
        madvise(addr_, size_, MADV_SEQUENTIAL);
    }

    // 随机访问——内核不预取
    void advise_random() {
        madvise(addr_, size_, MADV_RANDOM);
    }

    // 很快还需要这页——内核不急着回收
    void advise_willneed() {
        madvise(addr_, size_, MADV_WILLNEED);
    }

    // 这页不需要了——内核优先回收
    void advise_dontneed() {
        madvise(addr_, size_, MADV_DONTNEED);
    }
};
```

**什么时候用**：遍历大文件（几百 MB 的日志分析）→ `MADV_SEQUENTIAL`——内核提前加载下一页。`MADV_DONTNEED` 在"这一片数据已经处理完了、不会再访问"时用——释放物理内存给其他进程。只是建议——内核可以不理会。

## 4. 共享内存——RAII 包装 `shm_open`

### 4.1 两个进程共享同一块内存

共享内存是 IPC 中最快的方式——没有内核中转、没有序列化——数据就在物理内存里，两个进程的页表映射到同一块物理页：

```cpp
#include <sys/mman.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <string>

class SharedMemory {
    int   fd_ = -1;
    void* addr_ = MAP_FAILED;
    size_t size_ = 0;

public:
    // 创建共享内存（写方）
    SharedMemory(const char* name, size_t size, bool create = true) : size_(size) {
        int flags = O_RDWR;
        if (create) flags |= O_CREAT | O_EXCL;

        fd_ = shm_open(name, flags, 0666);
        if (fd_ < 0) throw std::runtime_error("shm_open failed");

        if (create) ftruncate(fd_, size_);  // 设置大小

        addr_ = mmap(NULL, size_, PROT_READ | PROT_WRITE, MAP_SHARED, fd_, 0);
        if (addr_ == MAP_FAILED) { close(fd_); throw std::runtime_error("mmap failed"); }
    }

    ~SharedMemory() {
        if (addr_ != MAP_FAILED) munmap(addr_, size_);
        if (fd_ >= 0) close(fd_);
    }

    SharedMemory(const SharedMemory&) = delete;
    SharedMemory& operator=(const SharedMemory&) = delete;

    void* data()       { return addr_; }
    size_t size() const { return size_; }
};
```

### 4.2 生产者-消费者——用共享内存交换数据

```cpp
// 共享数据结构——两进程必须有一致的布局定义
struct SharedData {
    std::atomic<bool> ready{false};
    int values[100];
};

// 生产者
void producer() {
    SharedMemory shm("/my_shm", sizeof(SharedData));
    auto* data = new (shm.data()) SharedData{};  // placement new——在共享内存上构造对象
    // ready{false} 通过 placement new 真正初始化了 std::atomic

    for (int i = 0; i < 100; i++) data->values[i] = i * i;
    data->ready.store(true, std::memory_order_release);  // 发布——消费者可见
    // shm 析构不调用 shm_unlink——消费者还需要读
}

// 消费者
void consumer() {
    SharedMemory shm("/my_shm", sizeof(SharedData), false);  // create=false
    auto* data = static_cast<SharedData*>(shm.data());       // 生产者已用 placement new 初始化

    while (!data->ready.load(std::memory_order_acquire));  // 等待就绪
    int sum = 0;
    for (int i = 0; i < 100; i++) sum += data->values[i];
}
```

**注意事项**：
- **`std::atomic` 保证了跨进程可见性**——配合 release/acquire 内存序（Stage3 Ch04 已讲）
- **共享数据结构不能有指针**——进程 A 的指针在进程 B 的地址空间里无效。数据结构必须是"纯值"——`int`、`array`、`atomic`
- **`shm_unlink` 是独立的**——析构时 `mmap` 自动释放，但 `/dev/shm/my_shm` 需要手动 `shm_unlink`（不在 RAII 包装内——因为可能有多个消费者）

## 5. 内存池——预分配的大块内存

### 5.1 概念——为什么需要

每次 `new` 都可能走 `mmap`/`brk`（系统调用）。对于频繁分配小对象——大量的系统调用开销不可接受。内存池的思路——一次性 `mmap` 一大块（如 1MB），后续的分配从池中切一小块（指针加减，O(1)，零系统调用）：

```cpp
#include <cstddef>
#include <stdexcept>

class Arena {
    char*  buf_;
    size_t size_;
    size_t offset_ = 0;

public:
    Arena(size_t size) : size_(size) {
        buf_ = static_cast<char*>(mmap(NULL, size,
            PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0));
        if (buf_ == MAP_FAILED) throw std::runtime_error("mmap failed");
    }

    ~Arena() { munmap(buf_, size_); }

    // 每次分配——指针后移——O(1)，零系统调用
    void* alloc(size_t n) {
        if (offset_ + n > size_) return nullptr;  // 池用完了
        void* p = buf_ + offset_;
        offset_ += n;
        return p;
    }

    void reset() { offset_ = 0; }  // 一次性"释放"所有分配——重置偏移即可
};
```

### 5.2 使用——批量分配 + 一次性释放

```cpp
int main() {
    Arena arena(1024 * 1024);  // 1MB

    int* a = static_cast<int*>(arena.alloc(sizeof(int) * 100));
    double* b = static_cast<double*>(arena.alloc(sizeof(double) * 50));

    // 使用 a 和 b...

    arena.reset();  // 一次性释放所有——比 150 次 delete 快 100 倍
    return 0;
}
```

**arena 的核心优势**：释放 `reset()` 只是把 `offset_` 重置为 0——不需要为 150 个对象分别调 `delete`。适合**一次性处理、用完清场**的场景——编译器的语法分析、游戏的一帧逻辑、Web 服务器的一个请求。

## 6. 可运行实验

### 实验：mmap 大文件读取 vs fstream 逐行读

```cpp
#include <iostream>
#include <fstream>
#include <chrono>
#include <sys/mman.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>

class MMapFile {
    int fd_ = -1; void* addr_ = MAP_FAILED; size_t size_ = 0;
public:
    MMapFile(const char* path) {
        fd_ = open(path, O_RDONLY);
        struct stat st; fstat(fd_, &st); size_ = st.st_size;
        addr_ = mmap(NULL, size_, PROT_READ, MAP_PRIVATE, fd_, 0);
    }
    ~MMapFile() { if (addr_ != MAP_FAILED) munmap(addr_, size_); if (fd_ >= 0) close(fd_); }
    const char* data() const { return static_cast<const char*>(addr_); }
    size_t size() const { return size_; }
};

int main() {
    const char* path = "/tmp/test_1M.txt";  // 先创建 1MB 测试文件

    // mmap 方式
    auto start = std::chrono::steady_clock::now();
    MMapFile file(path);
    const char* data = file.data();
    size_t sum = 0;
    for (size_t i = 0; i < file.size(); i++) sum += data[i];
    auto mmap_time = std::chrono::steady_clock::now() - start;

    // fstream 方式
    start = std::chrono::steady_clock::now();
    std::ifstream in(path);
    char c; sum = 0;
    while (in.get(c)) sum += c;
    auto fstream_time = std::chrono::steady_clock::now() - start;

    std::cout << "mmap:    " << std::chrono::duration_cast<std::chrono::milliseconds>(mmap_time).count() << " ms\n";
    std::cout << "fstream: " << std::chrono::duration_cast<std::chrono::milliseconds>(fstream_time).count() << " ms\n";
    // mmap 通常快 3-10 倍——因为避免了每次 read 的系统调用开销
    return 0;
}
```

**编译运行**：`dd if=/dev/zero of=/tmp/test_1M.txt bs=1M count=1 && g++ -std=c++11 -O2 mmap_test.cpp -o mmap_test && ./mmap_test`

## 7. 面试题

### 面试题 1：mmap RAII 封装的关键设计

**面试官**：写一个 RAII 包装 `mmap` 的类，哪些操作必须禁止？构造和析构的释放顺序是什么？

**回答**：禁止拷贝（`= delete`）——因为 `mmap` 的内存区域不能有两个"主人"（double-munmap 是 UB）。允许移动——转移所有权到另一个对象。析构时的释放顺序是**逆序**——先 `munmap`（释放映射），后 `close(fd)`（关闭文件描述符）。构造时的异常安全——如果 `mmap` 失败，必须 `close(fd)` 再抛异常（因为 `fd` 已打开但 `mmap` 失败时不会自动关）。

**追问（面试官）**：什么时候 RAII 的析构函数不能自动 `shm_unlink`？

**追问回答**：共享内存场景——可能有多个消费者。如果第一个消费者的析构函数就 `shm_unlink`，后面的消费者打开不到共享内存了。`shm_unlink` 应该在确认没有消费者之后再调用——通常由单独的"清理器"负责，不在 RAII 包装内。

### 面试题 2：共享内存数据结构的限制

**面试官**：共享内存中的数据结构必须满足什么条件？为什么不能有指针？

**回答**：必须"纯值"——`int`、`array`、`atomic`、固定大小的 struct——不能有 `std::string`（内部有堆指针）、不能有 `std::vector`（也是指针）、不能有裸指针。原因——进程 A 的 `malloc` 地址在进程 B 的页表里没有映射。A 的 `string` 内部 `char*` 指向 A 的堆地址→B 读过去是野指针→UB。替代方案——固定大小 char 数组或 `offset`（相对偏移量，替代绝对指针）。

**追问（面试官）**：跨进程同步怎么保证？

**追问回答**：`std::atomic<T>` 配合 release/acquire 内存序——和同一进程内的多线程同步完全一样的模式。`producer: store(release)` → `consumer: load(acquire)` 建立 happens-before——消费者看到 `ready=true` 后保证能看到所有写入。也可以用 `pthread_mutex_t` 放在共享内存中（设置 `PTHREAD_PROCESS_SHARED` 属性）。

### 面试题 3：Arena 分配器 vs 默认 new/delete

**面试官**：Arena 分配器和默认的 `new`/`delete` 有什么区别？什么时候用？

**回答**：`new`/`delete`——每次分配都走系统调用（`mmap`/`brk`）或复杂的 malloc 内部管理。Arena——预分配一大块→分配是指针移动（O(1)，零系统调用）→释放是重置指针（O(1)，一个操作释放所有）。适用场景——**批量小对象，用完整体释放**——编译器语法分析、游戏帧逻辑、Web 请求处理。不适用——**对象生命周期不同**——你需要逐个 `delete` 的场景。

**追问（面试官）**：Arena 的"释放"怎么保证不泄漏？

**追问回答**：Arena 不提供逐个 `delete`——它的释放是整块回收（`reset()` 或析构 `munmap`）。Arena 中"构造"的对象如果持有外部资源（如文件句柄、其他堆指针）→必须手动清理这些资源再 `reset()`。所以 Arena 最适合 POD 类型或没有外部资源的对象——用完了直接 `reset`。

## 8. 本章小结

| 概念 | C 的做法 | C++ 的做法 | 核心收益 |
|---|---|---|---|
| `mmap` | 手动 `open`+`mmap`+`munmap`+`close` | `MMapFile` RAII | 异常安全——抛异常也释放 |
| 大文件读取 | `read` 循环——每次系统调用 | `mmap` 直接映射——内存访问即可 | 3-10x 性能提升 |
| `madvise` | `madvise(addr, len, flag)` | 成员函数封装 | 语义明确——`advise_sequential()` |
| 共享内存 | `shm_open`+`mmap` 手动管理 | `SharedMemory` RAII | 构造打开、析构释放 |
| 内存池 | 每次 `new`/`delete` | `Arena` 批量分配+整块释放 | 避免频繁系统调用 |
