## 1. 引言：从"用模板"到"写泛型库"

Stage2 教了模板的基础用法——写 `max<T>`、特化 `vector<bool>`、SFINAE 做编译时分派。那时你是"模板的使用者"——调用标准库里的模板，享受编译器替你生成代码。

本章教你"模板库作者"的思维。你要写的不是 `max<T>`——而是一个**可以问任何类型"你是什么、你能做什么"的泛型工具**。当别人传入 `int` 时自动适配 int 的实现，传入 `double` 时自动适配 double 的实现——而且一切在编译时完成，零运行时开销。

`<type_traits>` 是这个思维的核心——**编译时的类型数据库**。`decltype` 从表达式"抄"类型。`constexpr` 让编译时计算像写普通函数一样。tag dispatch 让你用函数重载替代复杂的 `enable_if`。

## 2. `<type_traits>`——编译时的"类型数据库"

### 2.1 三类模板——检测、变换、计算

```cpp
#include <type_traits>

// 第一类：类型检测——"这个类型有什么特性？"
static_assert(std::is_integral<int>::value,      "int is integral");
static_assert(std::is_pointer<int*>::value,       "int* is a pointer");
static_assert(std::is_class<std::string>::value,  "string is a class");
static_assert(std::is_same<int, int>::value,      "same type");

// 生产示例：检查继承关系
struct B { virtual ~B() {} };
struct D : B {};
static_assert(std::is_base_of<B, D>::value, "D inherits B");  // ✓

// 第二类：类型变换——"从这个类型变出另一个类型"
using T = int;
using ConstT = std::add_const<T>::type;             // const int
using PtrT   = std::add_pointer<T>::type;            // int*
using RawT   = std::remove_reference<int&>::type;    // int
using DecayT = std::decay<const int&>::type;         // int（去掉 const 和 &）

// 第三类：类型计算——"给出一组类型中的'最优'选择"
using Common = std::common_type<int, double>::type;  // double
```

**为什么叫"萃取"（trait）**：你从类型中"榨取"信息——不运行代码、不等运行时、编译时就全知道了。"T 是不是整数？"→编译时知道了。"T 去掉引用是什么？"→编译时变出来。"T 和 U 哪个大？"→编译时算出来。

**和 C 的对比**：C 里你能用 `sizeof` 问大小——但不能问"T 是不是整数""T 是不是指针"。C 的类型检测全靠程序员自己知道——错了就 UB。

### 2.2 10 个最常用的 trait——速查表

| trait | 作用 | 生产场景 |
|---|---|---|
| `is_integral<T>` | T 是整数？ | enable_if 限制模板只接受整数 |
| `is_floating_point<T>` | T 是浮点？ | 同上 |
| `is_pointer<T>` | T 是指针？ | 区分 `delete` vs `delete[]` |
| `is_class<T>` | T 是 class？ | 区分基本类型和对象类型 |
| `is_same<A, B>` | A 和 B 相同类型？ | 编译时禁止某种实例化 |
| `is_base_of<Base, T>` | T 继承自 Base？ | 编译时类型检查 |
| `enable_if<Cond, T>` | Cond 为 true→T 有效 | SFINAE（Stage2 Ch04 已讲） |
| `remove_reference<T>` | 去掉 T 的引用 | 模板内部需要"原始类型" |
| `decay<T>` | 去掉 const/volatile/引用 | 标准库内部 `std::move` 和 `std::forward` 用它 |
| `conditional<Cond, A, B>` | Cond 为 true→A，false→B | 编译时 if-else |

### 2.3 `std::decay`——标准库内部的类型归一化

`std::decay` 是把任何类型"退化"为适合按值传递的形式——去掉 const、去掉 volatile、去掉引用、函数类型转为函数指针、数组类型转为指针：

```cpp
std::decay<int>::type;            // int
std::decay<const int&>::type;     // int（去掉 const 和 &）
std::decay<int[5]>::type;         // int*（数组退化为指针）
std::decay<int(int)>::type;       // int(*)(int)（函数退化为函数指针）
```

**为什么标准库用 `decay`**：你写 `std::move(t)` 时，`std::move` 内部用 `remove_reference` 获取 T 的原始类型；`std::thread` 的构造函数内部用 `decay` 把传给线程的参数"归一化"为值类型——避免线程拿着引用访问已销毁的栈变量。

## 3. `decltype`——从表达式"抄"类型

### 3.1 基本用法

`auto` 从初始化表达式推导变量类型。`decltype` 从**任何表达式**推导类型——**不执行表达式**：

```cpp
#include <vector>

int x = 5;
decltype(x)      y = 10;       // y 是 int——从 x 的类型推导
decltype(x + 0.5) z = 3.14;    // z 是 double——x+0.5 的类型

std::vector<int> v = {1, 2, 3};
decltype(v[0])    elem = v[0];  // elem 是 int&——v[0] 返回 int&
decltype(v.size()) sz = v.size(); // sz 是 size_t
```

### 3.2 `decltype(x)` vs `decltype((x))`——面试必考的陷阱

这是本章最重要的细节——**双括号改变结果**：

```cpp
int x = 5;
decltype(x)  a = x;   // a 是 int——x 是变量名
decltype((x)) b = x;  // b 是 int&——(x) 是左值表达式！
```

| 表达式 | decltype 结果 | 原因 |
|---|---|---|
| `x`（变量名） | `int` | 变量的声明类型 |
| `(x)`（括号表达式） | `int&` | `(x)` 是左值表达式 |
| `x + 0` | `int` | 纯右值表达式 |
| `std::move(x)` | `int&&` | 亡值表达式 |

**为什么这样设计**：`decltype` 区分"我要这个变量的声明类型"和"我要这个表达式的值类别"。`(x)` 加了括号从变量名变成表达式→`decltype` 对左值表达式返回引用类型。这不是 bug——是故意设计用来精准捕获值类别。

### 3.3 返回类型后置

C++11 中如果模板函数的返回类型依赖参数类型——必须在 `->` 后声明：

```cpp
template <typename T1, typename T2>
auto multiply(T1 a, T2 b) -> decltype(a * b) {
    return a * b;
}

auto result = multiply(3, 3.14);  // result 是 double——3 * 3.14 的类型
```

`-> decltype(a * b)` 在参数 `a, b` 声明之后——`decltype` 能引用参数名。C++14 起 `auto` 返回类型推导简化了这个需求。

## 4. `const` 与 `constexpr` 深度——编译时的安全网

### 4.1 `constexpr` 函数——编译时计算写起来像普通函数

C++11 的 `constexpr` 不只用于变量——函数也能标记为 `constexpr`：

```cpp
// 编译时的阶乘——编译器在编译时就算出值
constexpr int factorial(int n) {
    return n <= 1 ? 1 : n * factorial(n - 1);  // C++11 限制：只能一个 return 语句
}

int arr[factorial(5)];       // arr[120]——编译时常量
static_assert(factorial(5) == 120, "bad math");

// 生产场景——编译时计算哈希值
constexpr unsigned int hash(const char* s, unsigned int h = 0) {
    return *s == '\0' ? h : hash(s + 1, (h * 31 + *s));
}
static_assert(hash("hello") != hash("world"), "hash collision!");
```

**`constexpr` 函数不一定在编译时执行**：如果参数是编译时常量（`factorial(5)`）→编译时算好值。如果参数是运行时值（`factorial(n)` 中 `n` 是输入）→函数像普通函数一样在运行时执行。`constexpr` 是**可能性**不是**强制性**。

### 4.2 `const` 正确性——从变量到成员函数

`const` 表达了"这个不改变"的承诺——编译器帮你强制执行：

```cpp
// const 变量——初始化后不能修改
const int max_connections = 100;
// max_connections = 200;  // ✗ 编译错误

// const 引用——通过引用不能修改原对象
void print(const std::string& s) {
    // s += "!";  // ✗ 编译错误——s 是 const 引用
    std::cout << s;  // ✓ 只读
}

// const 成员函数——保证不修改对象的成员变量
class Buffer {
    char* data;
    size_t len;
public:
    size_t size() const { return len; }  // ✓ const 成员——只读
    // void mutate() const { data[0] = 'x'; }  // ✗ 编译错误——不能修改成员
};
```

**`const` 成员函数的重载**——同一个函数名，`const` 和非 `const` 版本是不同的函数：

```cpp
class Vec {
public:
    const int& operator[](int i) const { return data[i]; }  // const 对象调用这个
    int&       operator[](int i)       { return data[i]; }  // 非 const 对象调用这个
};

const Vec cv;
int x = cv[0];   // ✓ 调用 const 版本——返回 const int&
Vec v;
v[0] = 5;        // ✓ 调用非 const 版本——返回 int&
```

**核心原则**：如果一个成员函数不修改对象状态——标记为 `const`。如果你没有标记——`const Vec` 就不能调用它。

### 4.3 `constexpr` vs `const` vs 模板元编程

| | `const` | `constexpr` | 模板元编程 |
|---|---|---|---|
| 保证 | 不可修改 | **编译时确定值** | 编译时计算 |
| 变量 | `const int x = rand();` 可以是运行时 | `constexpr int x = 5;` 必须是编译时 | — |
| 函数 | 成员函数不修改对象 | 函数**可能**编译时执行 | `template<int N> struct Fact;` |
| C++11 限制 | — | 只一个 `return` 语句 | 全图灵完备 |
| 可读性 | 最高 | 高 | 低——递归模板 |

## 5. Tag Dispatch——不用 `enable_if` 的编译时分派

### 5.1 用函数重载替代 SFINAE

`enable_if` 功能强大——但写出来的代码难读。Tag dispatch 用**空 struct 标签 + 函数重载**实现编译时分派——清晰且零开销：

```cpp
// 定义 tag 类型——空 struct，纯做编译时标记，不占内存
struct random_access_tag {};
struct bidirectional_tag {};

// 版本 1：随机访问迭代器——O(1) 直接跳
template <typename Iter>
void advance(Iter& it, int n, random_access_tag) {
    it += n;
}

// 版本 2：双向迭代器——O(n) 一步步走
template <typename Iter>
void advance(Iter& it, int n, bidirectional_tag) {
    if (n > 0) while (n--) ++it;
    else       while (n++) --it;
}

// 统一入口——用 trait 获取 tag，自动分派到正确版本
template <typename Iter>
void advance(Iter& it, int n) {
    using category = typename std::iterator_traits<Iter>::iterator_category;
    advance(it, n, category{});  // 编译时选择重载——零开销
}
```

**工作原理**：
1. `iterator_traits<Iter>` 从迭代器类型中萃取出 `iterator_category`
2. `category{}` 创建一个空 tag 对象
3. 编译器根据 tag 类型选择匹配的 `advance` 重载
4. 空 tag 对象在优化后不产生任何代码——零开销

### 5.2 Tag dispatch vs `enable_if`——什么时候用哪个

| | Tag Dispatch | `enable_if` |
|---|---|---|
| 机制 | 函数重载区分 | SFINAE 排除 |
| 代码可读性 | 清晰——一目了然 | 复杂——长模板语法 |
| 条件格式 | "我有哪个 tag" | "满足任意布尔条件" |
| 典型场景 | 迭代器类型选择 | 根据 `is_copy_constructible` 选择移动 vs 拷贝 |

**原则**：优先 tag dispatch——只在条件不能用 tag 表达时才用 `enable_if`。STL 的 `advance`/`distance`/`copy` 都大量使用 tag dispatch。

## 6. 模板元编程实战——编译时选择容器

把 trait、conditional、模板别名串起来——写一个"根据类型大小自动选择最优容器"的工具：

```cpp
#include <vector>
#include <list>
#include <array>
#include <type_traits>

// 编译时选择：小类型用 vector（连续内存，缓存友好），大类型用 list（避免搬迁）
template <typename T>
using best_container = typename std::conditional<
    (sizeof(T) <= 64),         // 编译时条件
    std::vector<T>,             // ≤ 64 字节 → vector
    std::list<T>                // > 64 字节 → list
>::type;

best_container<int>  c1;       // vector<int>——int 只有 4 字节
best_container<std::array<char, 128>> c2;  // list<array<...>>——128 字节
```

这不是语法教学——是"工具组合解决实际问题"的思维。`conditional`（编译时 if-else）+ `sizeof`（编译时常量）+ 模板别名（`using`）——三个独立工具拼装成一个新的抽象。

**和运行时 `if` 的区别**：同一份二进制里，`c1` 的代码是 `vector<int>` 的实现，`c2` 的代码是 `list<T>` 的实现——编译时已确定，不产生任何分支判断的运行时开销。

## 7. 强制转型与 `explicit`——类型转换的安全边界

### 7.1 C++ 四把刀 vs C 风格转换

C 的 `(T)x` 可以完成 `static_cast`/`reinterpret_cast`/`const_cast` 三种转换中的任何一种——编译器**不告诉你**用了哪一种，也不检查安全性。C++ 把三种转换拆成三把命名清晰的刀：

```cpp
double pi = 3.14159;

// static_cast——相关类型之间的明确转换
int i = static_cast<int>(pi);          // ✓ double → int，损失精度是显式的

// dynamic_cast——运行时安全检查的多态向下转型
Animal* a = get_animal();
Dog* d = dynamic_cast<Dog*>(a);        // ✓ 检查 a 是不是真的 Dog
if (d) { d->bark(); }                  // nullptr → 不是

// const_cast——去掉 const（极罕用）
const int* cp = &i;
// *cp = 5;                            // ✗ 不能修改 const
int* mp = const_cast<int*>(cp);        // ⚠️ 谨慎——修改原始 const 对象是 UB

// reinterpret_cast——重新解释比特位（最危险）
int x = 42;
// char* p = reinterpret_cast<char*>(&x); // ⚠️ 不保证可移植性
```

| 转型 | 用途 | 风险 |
|---|---|---|
| `static_cast` | 相关类型转换、向上转型 | 低——编译时检查 |
| `dynamic_cast` | 多态安全向下转型 | 中——运行时开销 |
| `const_cast` | 去掉 const | 高——修改原 const 对象是 UB |
| `reinterpret_cast` | 比特位重解释 | 极高——仅 FFI/系统编程 |
| C 风格 `(T)x` | 以上任一种 | 最高——意图不明确、不检查 |

**为什么推荐 C++ 风格**：grep 一下 `static_cast` 就能找到所有"合法类型转换"的位置。grep `const_cast` 立刻定位到所有"去掉 const"的危险点。grep `(int)` 找不到——它是 C 风格、混杂在正常代码里。

### 7.2 `explicit`——阻止意外的隐式转换

单参数构造函数默认允许隐式转换——这在很多时候是 bug 的来源：

```cpp
class Widget {
    int value;
public:
    explicit Widget(int n) : value(n) {}  // ✓ explicit——禁止隐式构造
};

Widget w1(42);       // ✓ 显式构造
// Widget w2 = 42;  // ✗ explicit 禁止——"Widget = int" 不自然
// void process(Widget w); process(42);  // ✗ 也被禁止
```

**`explicit operator bool()`**（C++11）——转换操作符也可以标记 `explicit`：

```cpp
class Connection {
public:
    explicit operator bool() const { return is_alive(); }
    // 有 explicit 时：
    // if (conn) { ... }        // ✓ 布尔上下文——允许
    // bool b = conn;            // ✗ 显式转换——禁止
    // int x = conn + 5;         // ✗ 算术上下文——禁止
};
```

`explicit operator bool` 是标准库 `std::unique_ptr` 和 `std::shared_ptr` 做"判空"的方式——`if (ptr)` 可以，`int x = ptr;` 不行。防止智能指针被意外当成整数。

## 8. 可运行错误实验

### 实验：`decltype((x))` 返回引用的陷阱

```cpp
#include <iostream>
#include <type_traits>

int main() {
    int x = 5;

    auto a = x;                          // a 是 int（auto 丢弃引用）
    static_assert(std::is_same<decltype(a), int>::value);

    decltype(x)  b = x;                  // b 是 int——x 是变量名
    static_assert(std::is_same<decltype(b), int>::value);

    decltype((x)) c = x;                 // c 是 int&——(x) 是左值表达式！
    static_assert(std::is_same<decltype(c), int&>::value);
    c = 10;                              // 修改 c 就是修改 x
    std::cout << "x=" << x << '\n';      // 10——不是 5

    return 0;
}
```

**编译运行**：`g++ -std=c++11 decltype.cpp -o decltype && ./decltype`

**核心体验**：`decltype(x)` 和 `decltype((x))` 的结果不同——这是标准故意设计的，不是 bug。`static_assert` + `is_same` 可以在编译时就验证这些区别，不用等到运行时。

## 9. 面试题

### 面试题 1：`decltype` 双括号陷阱

**面试官**：`int x = 5; decltype(x)` 和 `decltype((x))` 返回什么类型？有什么区别？

**回答**：`decltype(x)` 返回 `int`——`x` 是变量的**名字**，decltype 返回变量的声明类型。`decltype((x))` 返回 `int&`——`(x)` 加了括号从变量名变成**左值表达式**，decltype 对左值表达式返回引用类型。这个设计用来区分"我要这个变量的声明类型"和"我要这个表达式的值类别"——是 C++ 类型系统的精髓之一。

**追问（面试官）**：`decltype(auto)` 和 `auto` 的区别？

**追问回答**：`decltype(auto)`（C++14）用 `decltype` 的规则推导类型而非 `auto` 的规则。`auto` 丢弃引用和顶层 const——`auto x = func()` 中 `func()` 返回 `int&` 时 `x` 是 `int` 不是 `int&`。`decltype(auto) x = func()` 保留引用——`x` 是 `int&`。需要完美转发返回值的引用属性时用 `decltype(auto)`。

### 面试题 2：`constexpr` 函数 vs 普通函数

**面试官**：C++11 的 `constexpr` 函数有什么限制？和 C++14 的区别？

**回答**：C++11 限制——函数体只能包含一个 `return` 语句（不能有循环/局部变量/if/switch），只能通过三元运算符 `?:` 和递归调用实现逻辑。C++14 放宽——可以有多条语句、循环、局部变量、if 分支。C++11 的阶乘写成 `return n <= 1 ? 1 : n * factorial(n-1)`，C++14 可以写成普通的 `for` 循环形式。

**追问（面试官）**：`constexpr` 函数一定在编译时执行吗？什么时候走运行时？

**追问回答**：不一定——`constexpr` 表示"在这个上下文中**可以**被编译时求值"。如果参数是编译时常量（如 `factorial(5)`）→编译器在编译时算好值并嵌入常量。如果参数是运行时值（如 `factorial(n)`，`n` 是用户输入）→函数像普通函数一样在运行时执行。`constexpr` 是**可能性**不是**强制性**。

### 面试题 3：Tag dispatch vs `enable_if`

**面试官**：Tag dispatch 和 `enable_if` 的区别？什么时候用哪个？

**回答**：Tag dispatch——用空 struct 标签 + 函数重载区分——清晰、零语法负担、零运行时开销。`enable_if`——用 SFINAE 在模板替换阶段排除无效版本——灵活但语法复杂。优先 tag dispatch——只有需要"根据多种布尔条件组合选择"时才用 `enable_if`。STL 的 `advance`/`distance`/`copy` 大量用 tag dispatch——少数场景（如根据 `is_copy_constructible` 选择移动 vs 拷贝）用 `enable_if`。

**追问（面试官）**：Tag dispatch 用的空 tag 对象有运行时开销吗？

**追问回答**：没有——空 struct 对象作为函数参数传入，编译器在优化时直接内联并消除它。tag dispatch 是零运行时开销的编译时分派机制——编译后的代码和手写 if-else 一样快，但类型安全得多（编译时就知道走哪个分支）。

## 10. 本章小结

| 概念 | 核心理解 |
|---|---|
| trait 三类 | 类型检测（`is_integral`）→变换（`decay`）→计算（`common_type`） |
| `decltype(x)` vs `(x)` | 变量名→声明类型；括号表达式→引用类型——经典陷阱 |
| `constexpr` 函数 | 编译时计算——C++11 只一个 return，参数常量时编译时执行 |
| `const` 正确性 | 变量/引用/成员函数——编译器强制"不修改"的承诺 |
| Tag dispatch | 空 struct + 重载——更清晰的 enable_if 替代方案 |
| `conditional` | 编译时 if-else——`std::conditional<条件, A, B>::type` |
| 强制转型 | C++ 四把刀替代 C 风格 `(T)x`——`static`/`dynamic`/`const`/`reinterpret` |
| `explicit` | 阻止意外的隐式构造——`Widget w = 5` 被禁止 |
