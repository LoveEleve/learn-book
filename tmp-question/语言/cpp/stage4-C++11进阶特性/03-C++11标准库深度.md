## 1. 引言：别再手写 C 的工具了

Stage2 的 STL 覆盖了容器和算法——`vector`/`map`/`sort`/`find`。但 C++11 还补充了大量"不用自己写的标准工具"——它们替代的是你习惯在 C 里手写的功能：

| C 的做法 | C++11 标准库 | 为什么更好 |
|---|---|---|
| `gettimeofday()` + 手算毫秒差 | `<chrono>` | 类型安全——不会搞混秒和毫秒 |
| `sscanf()` 或 POSIX `regex.h` | `<regex>` | 跨平台——一次编译，处处运行 |
| 手写多返回值 struct | `<tuple>` | 一行返回多个值——临时包装不用建 struct |
| `rand() % N` | `<random>` | 分布均匀 + 线程安全 + 可重现 |
| `enum COLOR { RED, ... }` | `enum class` | 作用域限定——不污染全局 |
| 手写数组 + `sizeof` | `<array>` | 编译时常量 size + 可用 STL 算法 |

本章不是"API 大全"——只讲每个库的 3-5 个核心操作，目标是读完你能自信地打开 cppreference 查剩下的。

## 2. `<chrono>`——告别 `gettimeofday` 和 `sleep(1)`

### 2.1 三个时钟

`<chrono>` 提供了三个时钟——每个有明确的用途和限制：

```cpp
#include <chrono>
#include <thread>
#include <iostream>

// system_clock——墙上时钟，会受 NTP/系统管理员影响而跳变
auto now_wall = std::chrono::system_clock::now();

// steady_clock——单调钟，只前进不退——超时/延时/性能测量的唯一选择
auto start = std::chrono::steady_clock::now();
std::this_thread::sleep_for(std::chrono::milliseconds(100));
auto end = std::chrono::steady_clock::now();

auto elapsed = std::chrono::duration_cast<std::chrono::milliseconds>(end - start);
std::cout << "slept " << elapsed.count() << " ms\n";
```

| 时钟 | 含义 | 用途 | 问题 |
|---|---|---|---|
| `system_clock` | 墙上时钟 | 日志时间戳、和外部时间交互 | 会跳变（NTP 步进/闰秒/`date -s`） |
| `steady_clock` | 单调钟 | **所有超时/延时/性能测量** | 不能转成"今天的日期" |
| `high_resolution_clock` | 最高精度（通常是 steady_clock 别名） | 基准测试 | 不一定稳定 |

### 2.2 `duration_cast`——为什么需要显式转换

`end - start` 返回的是 `steady_clock::duration`（实现定义的单位——通常是纳秒）。`duration_cast` 把它转成你关心的单位：

```cpp
// duration_cast 是截断转换——可能丢失精度
auto ns = std::chrono::duration_cast<std::chrono::nanoseconds>(elapsed);   // 高精度
auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(elapsed);  // 毫秒
auto s  = std::chrono::duration_cast<std::chrono::seconds>(elapsed);       // 秒→1500ms→1秒（丢弃500ms）

// C++17 的 floor/ceil 是向下/向上取整——C++11 只有 duration_cast（截断）
```

需要显式 cast 而不是隐式转换——因为精度降级会丢失数据。`duration_cast` 强迫你意识到"我在降精度"。

### 2.3 和 C 的对照

```cpp
// C 里：
struct timeval start, end;
gettimeofday(&start, NULL);
// ... 做点什么 ...
gettimeofday(&end, NULL);
long long ms = (end.tv_sec - start.tv_sec) * 1000 + (end.tv_usec - start.tv_usec) / 1000;
// 可能重复、可能写错、不能区分秒 vs 毫秒

// C++11：
auto start = std::chrono::steady_clock::now();
auto end   = std::chrono::steady_clock::now();
auto ms    = std::chrono::duration_cast<std::chrono::milliseconds>(end - start).count();
// 类型安全——duration 知道自己是纳秒，cast 到毫秒是显式操作
```

## 3. `<regex>`——告别 `sscanf` 和手写字符串解析

### 3.1 基本操作

```cpp
#include <regex>
#include <string>
#include <iostream>

std::string text = "Contact us at support@example.com or sales@foo.org";

// 构造正则——用原始字符串 R"(...)" 避免反斜杠地狱
std::regex email_re(R"((\w+)(\.\w+)*@(\w+)(\.\w+)+)");

// regex_search——找第一个匹配
std::smatch match;
if (std::regex_search(text, match, email_re)) {
    std::cout << "Found: " << match.str() << '\n';  // support@example.com
}

// regex_replace——替换所有匹配
auto masked = std::regex_replace(text, email_re, "[hidden]");
// "Contact us at [hidden] or [hidden]"
```

### 3.2 原始字符串 `R"(...)"` ——告别反斜杠地狱

```cpp
// C 风格的转义——读起来像乱码
std::regex old_style("(\\w+)(\\.\\w+)*@(\\w+)(\\.\\w+)+");

// C++11 原始字符串——写什么就是什么
std::regex raw_style(R"((\w+)(\.\w+)*@(\w+)(\.\w+)+)");
```

原始字符串以 `R"(...)` 的形式写——括号之间的内容**不转义**。反斜杠就是反斜杠，换行就是换行。

### 3.3 性能陷阱——`regex` 构造有编译开销

```cpp
// 🔴 坏习惯——循环里每次都构造 regex（每次都重新编译状态机）
for (const auto& line : lines) {
    std::regex re(R"(\d+)");
    std::regex_search(line, re);  // re 的 99% 时间花在构造上
}

// ✓ 好习惯——构造一次，复用
static const std::regex re(R"(\d+)");  // static——只有一份
for (const auto& line : lines) {
    std::regex_search(line, re);  // 纯匹配——无构造开销
}
```

`regex` 的构造函数把正则字符串编译成内部状态机——这部分的计算量取决于正则的复杂度。构造一次、无限复用。

### 3.4 和 C 的对照

C 里要么手写字符扫描（几十行）、要么用 POSIX `regex.h`（C API、不跨平台）。C++11 `regex` 是跨平台标准库——一次编译，处处运行。

## 4. `<tuple>` 与 `<pair>`——多返回值和异构容器

### 4.1 返回多个值

```cpp
#include <tuple>
#include <string>
#include <iostream>

// 不用手写 struct——用 tuple 临时包装多返回值
std::tuple<int, std::string, bool> get_user(int id) {
    return std::make_tuple(25, "Alice", true);
}

// 访问——按位置：get<0>, get<1>, get<2>
auto result = get_user(42);
std::cout << std::get<0>(result) << ", "    // 25
          << std::get<1>(result) << ", "    // "Alice"
          << std::get<2>(result) << '\n';   // 1 (true)

// C++11 的 tie——一次性拆包（需要先声明变量）
int age; std::string name; bool active;
std::tie(age, name, active) = get_user(42);
// age=25, name="Alice", active=true
```

### 4.2 `pair`——两个值的 tuple 特化

```cpp
#include <map>
#include <string>

std::pair<std::string, int> entry = {"Alice", 30};
std::cout << entry.first  << '\n';  // "Alice"
std::cout << entry.second << '\n';  // 30

// map 的每个元素就是 pair
std::map<std::string, int> ages;
ages["Alice"] = 30;
for (const auto& kv : ages) {
    std::cout << kv.first << ": " << kv.second << '\n';
}
```

### 4.3 tuple/struct 的选择

| 场景 | 用什么 | 原因 |
|---|---|---|
| 返回两个值 | `pair` | 轻量——`.first/.second` |
| 返回三个及以上、临时用 | `tuple` | 一行 `make_tuple` |
| 返回多个值、有语义名字 | **手写 struct** | `result.age` 比 `get<0>(result)` 清晰 |

## 5. `<random>`——告别 `rand() % N`

### 5.1 引擎和分布分离

`<random>` 把随机数生成拆成两步——引擎（产生随机位）和分布（把随机位映射到你想要的分布）：

```cpp
#include <random>
#include <iostream>

// Step 1：引擎——随机位来源
std::random_device rd;                      // 硬件熵源——用于种子
std::mt19937 rng(rd());                     // Mersenne Twister 引擎

// Step 2：分布——把随机位映射到范围
std::uniform_int_distribution<int> die(1, 6);  // 骰子——1 到 6
for (int i = 0; i < 5; i++)
    std::cout << die(rng) << ' ';   // 如：3 1 6 2 5

// 其他分布
std::normal_distribution<double>  gauss(0.0, 1.0);   // 正态分布
std::bernoulli_distribution       coin(0.5);          // 硬币——50%
```

### 5.2 为什么 `rand() % N` 是错的

```cpp
// rand() 返回 0~RAND_MAX。假设 RAND_MAX=32767：
// rand() % 6 中，0 的概率 = 5462/32768 ≈ 16.67%
//          5 的概率 = 5461/32768 ≈ 16.66%
// 不是均匀分布！低几个数出现概率更高
int unfair = rand() % 6;

// uniform_int_distribution(1,6) 用 rejection sampling——
// 超出目标范围倍数的随机位被丢弃并重试，消除偏置
std::uniform_int_distribution<int> fair(1, 6);
```

### 5.3 可重现性和线程安全

```cpp
// 可重现——固定种子：测试和调试必备
std::mt19937 rng(42);
std::uniform_int_distribution<int> dist(1, 6);
std::vector<int> seq;
for (int i = 0; i < 10; i++) seq.push_back(dist(rng));
// 每次运行 seq 完全一样——可以写进单元测试

// 线程安全——每个线程创建自己的 rng，不共享全局状态
// (rand() 是全局的——多线程调用 rand() 是 UB)
```

## 6. 语言基础特性速览——补上"你一直在用但没学过"的

### 6.1 `std::array`——不会退化成指针的 C 数组

```cpp
#include <array>
#include <algorithm>
#include <iostream>

std::array<int, 5> arr = {1, 2, 3, 4, 5};

std::cout << arr.size() << '\n';     // 5——编译时常量
std::sort(arr.begin(), arr.end());   // 可以用 STL 算法！

// 和 C 数组的关键区别——传参时不退化成指针
void process(std::array<int, 5>& a);  // ✓ 保持完整类型 + 知道大小
void process(int a[]);                 // ✗ 退化成 int*——丢失大小
```

### 6.2 `enum class`——作用域枚举

```cpp
// C 的 enum——值泄漏到全局作用域、隐式转 int
enum Color { RED, GREEN, BLUE };
int x = RED + 5;  // OK——RED 隐式转为 0，变量名 RED 不在任何命名空间里

// C++11 的 enum class——作用域限定 + 类型安全
enum class Color { Red, Green, Blue };
enum class Status { Active, Inactive };

Color c = Color::Red;
// Color c2 = Status::Active;  // ✗ 类型不同
// int y = Color::Red;         // ✗ 不隐式转 int
int y = static_cast<int>(Color::Red);  // ✓ 必须显式转
```

### 6.3 `namespace`——命名空间

读者天天写 `std::` 但不知道原理：

```cpp
#include <iostream>
#include <string>

namespace my_lib {
    void log(const std::string& msg) {
        std::cout << "[MYLIB] " << msg << '\n';
    }
    namespace detail {  // 嵌套命名空间——内部实现，外部不应使用
        int internal_counter = 0;
    }
}

my_lib::log("hello");
// using namespace std;  // ✗ 不推荐——把整个 std 名字空间倒入全局→命名冲突
// using std::cout;       // ✓ 可以——只导入需要的
```

### 6.4 `std::initializer_list`——花括号初始化

从 Stage1 就在用 `vector<int> v = {1,2,3}` ——幕后是 `initializer_list`：

```cpp
#include <vector>

std::vector<int> v = {1, 2, 3, 4, 5};
// 编译器等价于：
// std::initializer_list<int> tmp = {1, 2, 3, 4, 5};
// std::vector<int> v(tmp);

// 自定义类也可以支持
class MyVec {
public:
    MyVec(std::initializer_list<int> list) {
        for (int x : list) push_back(x);  // list 支持 range-for
    }
    void push_back(int) { /* ... */ }
};
MyVec mv = {1, 2, 3};  // ✓ 调用 initializer_list 构造函数
```

### 6.5 补充速查

| 特性 | 用途 | 替代 |
|---|---|---|
| `std::to_string(42)` | 数字→字符串 | C 的 `sprintf`/`itoa` |
| `std::stoi("42")` | 字符串→数字 | C 的 `atoi`/`sscanf` |
| `std::forward_list<T>` | 单向链表（少一个指针） | `std::list<T>`——内存更省 |
| `std::unordered_set<T>` | 哈希集合（只存 key） | `unordered_map<T, void>` 不需要 value |

## 7. 可运行错误实验

### 实验：`regex` 循环构造的性能陷阱

```cpp
#include <iostream>
#include <regex>
#include <chrono>

int main() {
    std::string text = "abc 123 def 456 ghi 789";
    const int N = 10000;

    // 🔴 坏习惯——每次循环都构造 regex（每次都重新编译状态机）
    auto start = std::chrono::steady_clock::now();
    for (int i = 0; i < N; i++) {
        std::regex re(R"(\d+)");
        std::regex_search(text, re);
    }
    auto mid = std::chrono::steady_clock::now();

    // ✓ 好习惯——构造一次，复用
    static const std::regex re(R"(\d+)");
    for (int i = 0; i < N; i++) {
        std::regex_search(text, re);
    }
    auto end = std::chrono::steady_clock::now();

    auto re_construct = std::chrono::duration_cast<std::chrono::milliseconds>(mid - start);
    auto re_use       = std::chrono::duration_cast<std::chrono::milliseconds>(end - mid);
    std::cout << "re-construct: " << re_construct.count() << " ms\n";
    std::cout << "re-use:       " << re_use.count()       << " ms\n";
    // re-construct 通常慢 10-100 倍
    return 0;
}
```

**编译运行**：`g++ -std=c++11 regex_perf.cpp -o regex_perf && ./regex_perf`

## 8. 面试题

### 面试题 1：chrono 三时钟

**面试官**：`system_clock` 和 `steady_clock` 的区别？为什么超时计算不能用 `system_clock`？

**回答**：`system_clock` 是墙上时钟——NTP 步进、闰秒、管理员 `date -s` 都可能导致时间跳变（回退或跳跃）。`steady_clock` 是单调钟——从某个未指定的起始点开始**只前进不退**，不受外部影响。超时计算用 `system_clock` 可能因为时间回退→负超时→死循环。这和 C 里 `gettimeofday` vs `CLOCK_MONOTONIC` 是同一个道理——C++11 把它包装成了类型安全的 `<chrono>`。

**追问（面试官）**：`duration_cast` 是做什么的？为什么需要显式 cast？

**追问回答**：`duration_cast<target>(dur)` ——把时间段从一种单位转换成另一种（纳秒→毫秒）。需要显式 cast 是因为转换可能**截断精度**——1500 毫秒转成秒是 1 秒，丢掉 500 毫秒。C++ 不允许隐式精度降级——`duration_cast` 强迫你意识到"我在降精度"。C++17 的 `floor`/`ceil` 提供向下/向上取整替代方案。

### 面试题 2：random 库 vs rand()

**面试官**：C++11 的 `<random>` 和 C 的 `rand()` 有什么区别？为什么不能用 `rand() % N`？

**回答**：(1) 分布质量——`rand() % N` 不均匀（low bias，因为 RAND_MAX 通常不是 N 的整倍数）。`uniform_int_distribution(1, N)` 用 rejection sampling 保证每个值概率完全相等。(2) 引擎和分布分离——你可以独立换引擎（测试用固定种子、加密用硬件熵源）或分布（正态、伯努利）。(3) 线程安全——每线程独立创建 `mt19937`，不共享全局状态（`rand()` 的全局状态在多线程下是 UB）。(4) 可重现性——`mt19937(42)` 每次运行生成相同序列→单元测试的金标准。

**追问（面试官）**：`std::random_device` 是真正的随机数吗？能当引擎用吗？

**追问回答**：取决于实现——通常用硬件熵源（`/dev/urandom`、RDRAND 指令）。但如果平台没有熵源→可能退化为伪随机。`random_device` 的**吞吐量远低于** `mt19937`——所以只用于**种子生成**（`mt19937 rng(rd())`），不用于大量随机数生成。

### 面试题 3：regex 的性能

**面试官**：`regex` 有什么性能陷阱？生产代码中怎么避免？

**回答**：`regex` 构造时把正则字符串编译成内部状态机——有编译开销。循环里每次都构造 `regex` 对象→同样的编译重复做→性能灾难。正确做法——构造一次，复用：`static const regex re(R"(\d+)");`。另外 `regex_match`（全匹配）比 `regex_search`（部分匹配）快——后者需要尝试从每个位置开始匹配。

**追问（面试官）**：C++ regex 比 Python/JS 的正则慢吗？为什么？

**追问回答**：通常慢——C++ 标准库的实现（libstdc++/libc++）没有用 JIT 编译或其他高级优化（Google RE2 有，但不是标准库）。原因是 C++ 标准库的设计目标是跨平台兼容、不含外部依赖。Python 的 `re` 模块可以调用 C 扩展优化。如果正则匹配是热点路径→考虑第三方库 PCRE/RE2。

## 9. 本章小结

| 库 | 核心操作 | 替代 C |
|---|---|---|
| `<chrono>` | `now()` / `duration_cast` / `sleep_for` | `gettimeofday` + 手算 |
| `<regex>` | `regex_search` / `regex_replace` + `R"(...)"` | `sscanf` / POSIX regex |
| `<tuple>` | `make_tuple` / `get<N>` / `tie` | 手写多返回值 struct |
| `<random>` | `mt19937` + 分布 / `random_device` 种子 | `rand() % N` |
| `<array>` | 编译时常量 size + 可用 STL 算法 | C 数组 |
| `enum class` | 作用域限定 + 类型安全 | C `enum`（全局泄漏） |
| `namespace` | 避免名字冲突——`my::func()` vs `your::func()` | C 的手动前缀 |
| `initializer_list` | `vector<int> v = {1,2,3}` 的幕后机制 | — |

**本章没讲但后续章节会讲**：`<filesystem>`（C++17 文件操作）、`<optional>`/`<variant>`（C++17 类型安全）、`<string_view>`（C++17 零拷贝字符串视图）。
