## 1. 引言：你不是在学一门新语言——你在升级你的工具箱

你已经精通 C——你能用 `malloc`/`free` 管理内存、用 `pthread_mutex_lock` 做同步、用 `epoll` 写高并发服务器、用 `mmap` 操作文件。这些技能不会浪费——C++ 是 C 的超集，99% 的 C 代码在 C++ 编译器下都能编译通过。

那为什么要学 C++？因为 C 在三个地方让你反复手写相同的样板代码：

1. **资源管理**——每个 `malloc` 要配 `free`、每个 `fopen` 要配 `fclose`、每个 `pthread_mutex_lock` 要配 `unlock`。漏一个就是内存泄漏或死锁。
2. **泛型编程**——`qsort` 用 `void*` + 函数指针，类型不安全；你想写一个"通用的栈"得用宏或 `void*`，丢失了编译时类型检查。
3. **抽象表达**——C 的 `struct` 是纯数据容器，没有"方法"概念。你想模拟面向对象得手写函数指针表（vtable）+ `void*` 强转，代码冗长且不安全。

C++ 在保留 C 的零开销抽象的前提下，给了你三件新工具：**RAII**（资源获取即初始化——自动管理生命周期）、**模板**（编译时类型安全的泛型）、**类**（带方法的 struct + 自动构造析构）。

本章不一口气讲完所有 C++11 新特性——只讲**最基本、生产代码中每天都会遇到的语法变化**，让你能写出第一段 C++ 程序。每一节都从"你在 C 里怎么写"开始，然后展示"C++ 里可以怎么写"。

## 2. Hello, C++——第一段能编译运行的 C++ 程序

### 2.1 从 C 的 `printf` 到 C++ 的 `std::cout`

你在 C 里写第一个程序：

```c
#include <stdio.h>
int main() {
    char name[64];
    printf("What's your name? ");
    scanf("%63s", name);
    printf("Hello, %s!\n", name);
    return 0;
}
```

C++ 里写同样功能的程序：

```cpp
#include <iostream>       // C++ 标准输入输出
#include <string>          // C++ 字符串类型
int main() {
    std::string name;                          // 不用预先分配大小
    std::cout << "What's your name? ";         // 输出——不用格式串
    std::cin  >> name;                         // 输入——不用 %s 担心溢出
    std::cout << "Hello, " << name << "!\n";   // 拼接用 <<
    return 0;
}
```

**编译与运行**：
```bash
g++ -std=c++11 hello.cpp -o hello && ./hello
```

注意三个变化：

1. **`.c` → `.cpp`，`gcc` → `g++`**——C++ 源文件后缀和编译器命令不同。`g++` 内部还是调用 GCC 的 C++ 前端，但它自动链接 C++ 标准库（`libstdc++`）。
2. **`<stdio.h>` → `<iostream>`**——C++ 的输入输出头文件。`printf`/`scanf` 在 C++ 里仍然可用（C++ 是 C 的超集），但 `std::cout`/`std::cin` 更类型安全——你不需要写 `%s`/`%d` 格式串，编译器自动推导。
3. **`char name[64]` → `std::string name`**——C++ 的字符串类型自动管理内存，不需要预分配大小，不会缓冲区溢出。`cin >> name` 读多长就分配多大。
4. **`<<` 和 `>>` 为什么是"输出"和"输入"？** ——这两个运算符在 C 里是位移（`<<` 左移、`>>` 右移）。C++ 里它们的含义变了——因为 C++ 支持**运算符重载**（operator overloading）——你可以给 `<<` 定义"输出"的含义，编译器根据左操作数的类型决定用"位移"还是"输出"：`int x = 1 << 3;` ← 还是位移（右操作数是整数），`cout << "hello";` ← 输出（左操作数是 `ostream`）。运算符重载在 Ch02 的类中展开——这里你只需要知道"同一个符号，不同上下文做不同的事"。

### 2.2 `std::` 是什么？`using namespace std;` 又是什么？

`std::cout` 里的 `std::` 是**命名空间**前缀——`cout` 属于标准库的 `std` 命名空间。命名空间的概念在 §5 详讲，这里你只需要知道：`std::cout` = "标准库里的 `cout`"。

如果你嫌 `std::` 写起来烦，可以加一行：

```cpp
#include <iostream>
#include <string>
using namespace std;          // 把 std 里的所有名字拉到当前作用域

int main() {
    string name;               // 不用写 std::string
    cout << "What's your name? ";
    cin  >> name;
    cout << "Hello, " << name << "!\n";
    return 0;
}
```

`using namespace std;` 是"偷懒写法"——学习中可以用，生产代码慎用。原因：大项目里 `std` 有几百个名字，全部拉进来可能和你自己的函数名冲突（如你自己写了一个 `count` 函数，和 `std::count` 冲突）。本章的代码示例为了简洁会用 `using namespace std;`，但会标注哪些地方生产代码不应该这样写。

## 3. 引用——一个"不会空的指针"

### 3.1 C 的指针痛点

在 C 里，写一个 `swap` 函数你必须用指针：

```c
void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }
// 调用方：swap(&x, &y);  ← 必须取地址
```

这有两个痛点：(1) 调用方必须写 `&` 取地址——容易忘；(2) 函数内部必须检查 `if (a == NULL)`——万一调用方传了 NULL 就是段错误。

更大的痛点：函数参数是 `int *p` 时，读代码的人不知道"这个函数会不会修改 `*p`"——指针既能读又能写，语义模糊。

### 3.2 C++ 的引用——"别名"

C++ 给了引用（reference）——变量的"别名"：

```cpp
void swap(int &a, int &b) { int t = a; a = b; b = t; }
// 调用方：swap(x, y);  ← 不用取地址
```

`int &a` 是引用参数——`a` 就是调用方传入的变量本身，不是副本。修改 `a` 就是修改调用方的变量。

| 你在 C 里这样写 | C++ 里可以这样 |
|---|---|
| `void swap(int *a, int *b)` 调用 `swap(&x, &y)` | `void swap(int &a, int &b)` 调用 `swap(x, y)` |
| 函数参数 `int *p`，需要检查 `if (p == NULL)` | 函数参数 `int &r`，编译期保证不会为空 |
| 从函数返回指针 `int* get() { return &data; }` | 从函数返回引用 `int& get() { return data; }` |

**核心理解**：引用就是"别名"——`int &r = x;` 之后，`r` 和 `x` 是同一个东西。对 `r` 的任何操作就是对 `x` 的操作。

### 3.3 什么时候用引用，什么时候用指针

引用不能为空、不能重新绑定——这些"限制"实际上是"保证"：

- **用引用**：函数参数不想拷贝大对象时（传引用避免拷贝）、函数想修改传入的变量时、返回左值时（如 `vec[i]` 返回引用，支持 `vec[i] = 42`）
- **用指针**：参数可以是"空"时（NULL 表示"没有"）、运行时需要切换指向不同对象时、和 C API 交互时（C 不认识引用）

**生产建议**：函数参数默认用引用——只有需要"可选"（可以为空）或"可重新指向"时才用指针。这比 C 的"全用指针"更安全——引用不为空是编译期保证，不是运行时 `if` 检查。

### 3.4 引用的底层实现（面试常问）

引用在底层是怎么实现的？编译器把引用实现为 `T* const`（常量指针）——你写 `int &r = x;`，编译器生成类似 `int *const __r = &x;` 的代码。使用 `r` 时编译器自动解引用（`*(__r)`）。

这就是为什么：
- 引用不能为空——它必须在定义时绑定到一个存在的对象（就像 `int *const` 必须初始化）
- 引用不能重新绑定——`const` 指针不能重新赋值
- `sizeof(引用)` 返回的是引用对象的实际大小——编译器自动解引用后取大小

引用不是"魔法"——它是指针的语法糖，零额外运行时开销。

### 3.5 `const` 引用——生产代码最常见的引用形式

你写一个函数，接受一个很大的对象但不想修改它。C 里有两种方式：

```c
void print(const struct BigData *data) {  // 传指针——"我不会修改它"
    printf("%d\n", data->value);
}
print(&big);  // 调用方必须取地址
```

C++ 里用 `const` 引用——既避免拷贝（引用不拷贝），又不让修改（const 保护）：

```cpp
void print(const BigData& data) {   // 传 const 引用——"我不会修改它"
    cout << data.value << "\n";
}
print(big);  // 调用方不用取地址，看起来像传值
```

**这就是 `const` 引用成为 C++ 函数参数的默认选择的原因**——它同时满足三个需求：不拷贝（性能）、不修改（安全）、调用方语法简洁（不用 `&`）。打开任何 C++ 项目，`void foo(const string& s)` 是最常见的函数签名。

### 3.6 悬垂引用——返回局部变量的引用是 UB

C 程序员知道不能返回局部变量的指针：

```c
int* bad() { int x = 42; return &x; }   // 🔴 返回后 x 已死——野指针
```

C++ 的引用有同样的陷阱——引用看起来"不像指针"，更容易犯：

```cpp
int& bad() { int x = 42; return x; }    // 🔴 返回后 x 已死——悬垂引用！
// int y = bad();  ← UB！y 读的是已销毁的 x
```

**解决**：返回引用只用于返回**比函数活得久的对象**——静态变量、成员变量、传入的引用参数本身。

## 4. `new` 和 `delete`——替代 `malloc`/`free`

### 4.1 C 的 `malloc`/`free` 痛点

在 C 里分配动态内存：

```c
struct Foo *f = malloc(sizeof(struct Foo));
if (!f) { perror("malloc"); return -1; }
f->a = 1; f->b = 2;     // 手动初始化
// ...
free(f);                 // 手动释放
```

两个步骤：`malloc` 分配内存 → 手动初始化字段。`free` 释放内存但不做任何清理。如果 `Foo` 里有 `FILE*` 或其他资源——`free` 不会帮你 `fclose`。

### 4.2 C++ 的 `new`/`delete`

C++ 的 `new` 做了两件事：分配内存 + 调用构造函数（初始化）。`delete` 也做两件事：调用析构函数（清理） + 释放内存。

```cpp
struct Foo {
    int a, b;
    Foo(int x, int y) : a(x), b(y) {}   // 构造函数——Ch02 详讲
};

Foo *f = new Foo(1, 2);    // 分配 + 构造一步完成
// ...
delete f;                   // 析构 + 释放一步完成
```

| 你在 C 里这样写 | C++ 里可以这样 |
|---|---|
| `int *p = malloc(100 * sizeof(int));` + 检查 NULL | `int *p = new int[100];` |
| `free(p);` | `delete[] p;` |
| `struct Foo *f = malloc(sizeof(Foo));` 然后 `f->a = 1;` | `Foo *f = new Foo(1, 2);`——分配+初始化一步 |

**关键规则**：`new` 配 `delete`，`new[]` 配 `delete[]`——不能混用。混用的后果在 §10 的实验中展示。

### 4.3 `new` 失败时抛异常——不是返回 NULL

C 程序员习惯在 `malloc` 后检查 NULL：

```c
int *p = malloc(100 * sizeof(int));
if (!p) { perror("malloc"); return -1; }
```

C++ 的 `new` 默认**不返回 NULL**——分配失败时抛异常 `std::bad_alloc`（异常在 Ch03 详讲）：

```cpp
int *p = new int[100];   // 分配失败 → 抛 std::bad_alloc → 不会返回 NULL
// 所以不需要 if (!p) 检查——如果 p 存在，一定分配成功
```

如果你想要 `new` 像 `malloc` 一样"失败时返回 NULL"，用 `nothrow` 版本：

```cpp
#include <new>
int *p = new (std::nothrow) int[100];
if (!p) { /* 分配失败，可以检查 NULL */ }
```

**生产建议**：大多数 C++ 代码用默认的抛异常版本——因为内存分配失败通常是不可恢复的错误，让异常直接终止程序比"返回 NULL 然后漏掉检查"更安全。只有当你**确定**要像 C 一样手动检查时，才用 `nothrow`。

### 4.3 `malloc` 还能用吗？

能——C++ 是 C 的超集，`malloc`/`free` 完全可用。什么场景下你仍然需要 `malloc`：

1. **需要 `realloc` 扩容**——C++ 没有 `new` 的等价物。`std::vector` 内部用 `new` 分配+拷贝扩容，但如果你自己管理内存池需要 `realloc`，只能用 `malloc`/`realloc`/`free`。
2. **与 C 库交互**——C 库返回的内存是 `malloc` 分配的，你必须用 `free` 释放。用 `delete` 释放 `malloc` 的内存是未定义行为。
3. **自定义内存池**——用 `mmap`/`sbrk` 直接向 OS 要内存，不经过 `::operator new`。

除此之外，C++ 代码优先用 `new` 或智能指针（Ch04 详讲）。

## 5. 函数重载——同一个名字，不同的参数

### 5.1 C 的痛点

C 不支持函数重载——同名函数只能有一个。于是你写了大量带类型后缀的函数：

```c
int    add_int(int a, int b)       { return a + b; }
double add_double(double a, double b) { return a + b; }
// 还有 add_long、add_float...
```

函数体完全一样——只是类型不同。这是纯粹的重复代码。

### 5.2 C++ 的函数重载

C++ 允许同名函数只要参数不同就视为不同函数——编译器根据调用时传入的参数类型自动选择：

```cpp
int    add(int a, int b)           { return a + b; }
double add(double a, double b)     { return a + b; }
// 甚至不同参数个数
int    add(int a, int b, int c)    { return a + b + c; }

int    x = add(3, 5);           // 调用 add(int, int)
double y = add(3.14, 2.71);     // 调用 add(double, double)
int    z = add(1, 2, 3);        // 调用 add(int, int, int)
```

编译器怎么区分？通过 **name mangling**（名称修饰）——编译器把 `add(int, int)` 编译成类似 `_Z3addii` 的符号名，`add(double, double)` 编译成 `_Z3adddd`。链接器看到的是不同的符号名，不会冲突。name mangling 的细节留给 Stage2（编译链接阶段）讲——这里你只需要知道"编译器自动区分"。

**不能重载的情况**：只有返回值不同——不行。编译器无法从调用点（`add(3, 5)`）判断你想要哪个返回类型。

### 5.3 重载歧义——什么时候编译器"不知道选哪个"

有多个重载版本时，编译器按"最佳匹配"选择。但有时候没有"最佳匹配"——这时编译报错：

```cpp
int  add(int a, int b)    { return a + b; }
double add(double a, double b) { return a + b; }

add(3, 3.14);   // 🔴 歧义！第一个参数匹配 int，第二个匹配 double——没有唯一最佳
add(3.14, 3);   // 🔴 同样歧义——两个重载都不是完美匹配
```

C++ 允许隐式类型转换（`int` ↔ `double`），所以 `add(3, 3.14)` 两个重载版本都"部分匹配"——编译器不知道该选哪个→编译错误。你需要显式转换一个参数：`add(3.0, 3.14)` 或 `add(3, static_cast<int>(3.14))`。

### 5.4 默认参数——重载的"语法糖"

C++ 还支持默认参数——调用时省略的参数自动用默认值：

```cpp
void log(const char* msg, int level = 0) {
    // level 默认 0
}
log("error");       // 等同于 log("error", 0)
log("warning", 1);  // 显式传 level
```

默认参数和函数重载功能有重叠——`log(const char*)` + `log(const char*, int)` 也可以用重载实现。默认参数更简洁，但重载更灵活（两个版本的函数体可以完全不同）。

## 6. 命名空间——告别函数名前缀

### 6.1 C 的痛点

C 没有命名空间——同名函数全局冲突。于是 C 项目用"前缀"避免重名：

```c
void redis_init(void);
void ngx_http_init(void);
void mysql_log(const char *msg);
```

前缀是"约定"不是"强制"——两个人写了同名的 `init()` 就链接冲突。Nginx 用 `ngx_`、Redis 用 `redis_`、MySQL 用 `mysql_`——前缀越短容易冲突，越长写起来烦。

### 6.2 C++ 的命名空间

C++ 用 `namespace` 把名字分组——不同命名空间里的同名函数不冲突：

```cpp
namespace moduleA {
    void init() { /* ... */ }
}
namespace moduleB {
    void init() { /* ... */ }
}

moduleA::init();   // 用 :: 访问命名空间里的名字
moduleB::init();   // 另一个 init
```

### 6.3 跨文件的命名空间

C 的 `static` 是"文件私有"——不是"命名空间"。C++ 的命名空间可以跨文件使用——头文件声明、`.cpp` 实现、另一个 `.cpp` 调用：

```cpp
// math.h —— 头文件中声明
namespace math {
    int add(int a, int b);    // 只声明
    int mul(int a, int b);
}

// math.cpp —— 实现文件
#include "math.h"
namespace math {
    int add(int a, int b) { return a + b; }
    int mul(int a, int b) { return a * b; }
}

// main.cpp —— 使用方
#include "math.h"
int main() {
    int sum = math::add(3, 4);    // 调用——用 :: 访问
    return 0;
}
```

**核心理解**：命名空间像文件的"目录"——把同名的东西放在不同名字下。`math::add` 和 `physics::add` 是两个完全不同的函数，不会冲突。

### 6.4 匿名命名空间——C++ 替代文件级 `static`

C 里用 `static` 让函数只在当前文件内可见：

```c
// helper.c
static void internal_do_work(void) { /* ... */ }  // 其他 .c 看不到
```

C++ 仍然支持文件级 `static`（兼容 C），但更好的写法是**匿名命名空间**（unnamed namespace）：

```cpp
// helper.cpp
namespace {
    void internal_do_work() { /* ... */ }  // 其他 .cpp 看不到
}
// 等价于 C 的 static void internal_do_work()
```

**为什么用匿名命名空间替代 `static`**：匿名命名空间是"命名空间有一个编译器生成的名字"——其他 `.cpp` 看不到这个名字，所以无法引用。这和 C 的 `static` 效果一样——但匿名命名空间里可以放类、模板、变量，`static` 对这些东西有限制。C++ 里推荐用匿名命名空间替代文件级 `static`。

### 6.5 `using namespace std;` 的生产陷阱

```cpp
using namespace std;   // 把 std 里所有名字拉进来
```

学习中可以用——少打 `std::`。生产代码慎用——`std` 里有几百个名字（`count`、`find`、`sort`、`min`、`max`...），全部拉进来可能和你自己的函数名冲突。更安全的做法是只 `using` 你需要的：

```cpp
using std::cout;       // 只拉 cout
using std::endl;       // 只拉 endl
// cout << "hi" << endl;  ← 可以直接写
```

## 7. `constexpr` 与 `nullptr`——两个小但重要的改进

### 7.1 `nullptr`——类型安全的空指针

C 的 `NULL` 是什么？取决于实现——`#define NULL ((void*)0)` 或 `#define NULL 0`。两种都有问题：

```c
void foo(int x);
void foo(int *p);
foo(NULL);    // NULL 是 0——调用的是 foo(int)！不是 foo(int*)
```

`NULL` 本质是整数——可以被隐式转为 `int`，编译器选了 `foo(int)` 而不是 `foo(int*)`。这不是你想要的。

C++11 的 `nullptr` 是单独的类型（`std::nullptr_t`）——只能赋给指针，不能赋给整数：

```cpp
int  *p = nullptr;   // ✓ 正确
int   x = nullptr;   // ✗ 编译错误——nullptr 不能当整数

void foo(int x);
void foo(int *p);
foo(nullptr);        // ✓ 调用 foo(int*)——nullptr 是指针类型
```

**生产建议**：C++ 代码里永远用 `nullptr` 替代 `NULL`——类型安全，不会选错重载。

### 7.2 `constexpr`——真正的编译时常量

C 的 `const` 有个微妙的语义——它是"运行时不可修改"，不保证"编译时值已知"：

```c
const int N = rand();   // C 里合法——N 在运行时确定，但之后不可改
```

C++ 的 `const` 继承了这个语义——`const int N = rand();` 在 C++ 里也合法。但你想用 `N` 做数组大小就不行——编译器不知道 `N` 是编译时常量。

C++11 的 `constexpr` 保证值在编译时算好：

```cpp
constexpr int N = 10;       // ✓ 编译时常量
int arr[N];                  // ✓ N 可以做数组大小

const int M = rand();        // 合法但 M 不是编译时常量
// int arr2[M];              // ✗ 编译错误——M 不是常量表达式

constexpr int K = rand();    // ✗ 编译错误——rand() 不是编译时函数
```

**和 C 的 `const` 对比**：C 的 `const` 比 C++ 的 `const` 更接近 `constexpr`——C 的 `const int N = 10; int arr[N];` 在 C 中可能触发 VLA 警告但编译器在接受时当作编译时常量。C++ 的 `const` 更严格——`const` 变量不一定是常量表达式（可能运行时初始化），`constexpr` 才明确保证编译时求值。

**生产建议**：声明编译时常量时优先用 `constexpr` 替代 `const`——语义更明确，编译器在编译时就能捕获"这个值不是常量"的错误。

### 7.3 `constexpr` 函数——编译时执行的函数

`constexpr` 不仅用于变量——也可以用于函数。C++11 的 `constexpr` 函数在编译时求值（当参数是编译时常量时）：

```cpp
constexpr int square(int n) {
    return n * n;          // C++11 限制：函数体只能有一个 return 语句
}

int arr[square(5)];        // = arr[25] ——编译时算出！square(5) 在编译时执行
constexpr int N = square(10); // N = 100 ——编译时常量

int x = square(get_value()); // 参数是运行时值 → square 像普通函数一样在运行时执行
```

**`constexpr` 函数的双重身份**：当参数是编译时常量时→编译时执行；当参数是运行时变量时→运行时执行（和普通函数一样）。这和 `const` 变量的"运行时确定"完全不同——`constexpr` 函数既是编译时工具、也是运行时函数。

C++14 放宽了限制（可以有多条语句、`if` 分支、循环），Ch04 详讲。

## 8. `auto`——让编译器帮你写类型

### 8.1 C 的痛点

C 的类型声明有时很冗长：

```c
unsigned long long x = 100ULL;
struct hash_table_iterator *it = hash_table_begin(tbl);
```

类型从右边表达式中一眼能看出来——但你还得在左边手写一遍。C 的 `typeof` 扩展（GCC）能推导，但不是标准。

### 8.2 C++11 的 `auto`

`auto` 让编译器从初始化表达式推导类型：

```cpp
auto x = 100ULL;              // x 是 unsigned long long
auto it = tbl.begin();        // it 是 hash_table_iterator
auto result = compute(x);     // result 是 compute 的返回类型
```

**核心理解**：`auto` 不是"动态类型"——它在编译时就确定了类型，只是省了你手写的功夫。编译后 `auto x` 和 `unsigned long long x` 生成的机器码完全一样。

### 8.3 什么时候用 `auto`，什么时候不用

**用 `auto`**：
- 类型名很长时（如 `std::vector<std::string>::iterator`——后面 Stage2 会遇到）
- 类型从右边表达式明显能看出时（`auto p = new Foo(1, 2);`——一看就是 `Foo*`）
- 迭代器、Lambda 等类型名难以手写的情况

**不用 `auto`**：
- 类型名有助于理解代码意图时——`int count = get_count();` 比 `auto count = get_count();` 更清晰（明确告诉读者 count 是 int）
- 数值类型推导可能出意外时——`auto x = 5 / 2;` 推导出 `int`（值 2），不是 `double`（值 2.5）

### 8.4 `auto&` vs `auto`——拷贝还是引用？

这是 C 程序员最容易忽略的陷阱——`auto` 推导时**丢掉**引用和 `const`：

```cpp
std::vector<int> v = {1, 2, 3};
auto x = v[0];    // x 是 int——v[0] 的值被**拷贝**到 x。修改 x 不影响 v[0]
auto& y = v[0];   // y 是 int&——y 就是 v[0] 本身。修改 y 就是修改 v[0]
const auto& z = v[0]; // z 是 const int&——不可修改 v[0] 的值，也不拷贝

x = 10;  // v[0] 还是 1——x 是拷贝
y = 10;  // v[0] 变成 10——y 是引用
```

**什么时候用哪种**：
- `auto`——需要独立副本时（基本类型 `int`/`double` 用这个就行）
- `auto&`——需要修改原值时、需要避免拷贝大对象时
- `const auto&`——需要避免拷贝但不修改时——**range-for 遍历容器的最常用写法**：`for (const auto& item : container) { ... }`

**生产建议**：`auto` 是工具不是教条——不要为了 `auto` 而 `auto`。可读性优先。

## 9. 可运行实验：`new[]` 配 `delete`（不是 `delete[]`）

这是 C++ 初学者最容易踩的坑之一——`new[]` 分配的数组必须用 `delete[]` 释放，不能用 `delete`。混用的后果不是编译错误（编译器不强制检查），而是**运行时部分析构函数不执行**——资源泄漏。

```cpp
#include <iostream>

struct Foo {
    int id;
    Foo(int i) : id(i) { std::cout << "Foo(" << id << ") created\n"; }
    ~Foo()            { std::cout << "Foo(" << id << ") destroyed\n"; }
};

int main() {
    Foo *arr = new Foo[3]{Foo(1), Foo(2), Foo(3)};  // 创建 3 个对象
    delete arr;  // 🔴 错误！应该是 delete[] arr
    return 0;
}
```

**编译运行**：
```bash
g++ -std=c++11 -Wall test.cpp -o test && ./test
```

**预期输出**：
```
Foo(1) created
Foo(2) created
Foo(3) created
Foo(1) destroyed    ← 只有 Foo(1) 的析构被调用
```

三个"created"，只有一个"destroyed"——`Foo(2)` 和 `Foo(3)` 的析构函数没跑。它们的内存虽然在 OS 层面被释放了（`delete` 释放了数组起始的内存块），但如果析构函数里有 `fclose` 或 `free`——那两个对象的资源永久泄漏。

**修复**：`delete[] arr;`——`delete[]` 知道这是一个数组，会遍历调用每个元素的析构函数。

## 10. 面试题

### 面试题 1：引用 vs 指针

**面试官**：C++ 的引用和指针有什么区别？什么时候用引用什么时候用指针？

**回答**：引用是"别名"——`int &r = x;` 之后 `r` 就是 `x`，不能重新绑定到别的变量。指针是"地址值"——可以重新赋值、可以为空。引用不能为空（编译器保证），指针可以是 NULL。用引用：函数参数不想拷贝大对象时、函数想修改传入变量时、返回左值（如 `vec[0]` 返回引用支持赋值回元素）。用指针：参数可以是"没有"时（NULL 表意）、运行时需要切换指向目标时。

**追问（面试官）**：引用底层是怎么实现的？为什么不能是空？

**追问回答**：编译器把引用实现为 `T* const`（常量指针）——你写 `int &r = x;`，编译器生成类似 `int *const __r = &x;` 的代码。不能为空是因为引用必须在定义时绑定到一个存在的对象——和指针的 `const` 版本不同在于引用语法上不需要 `*` 和 `&`。这也是为什么 `sizeof(引用)` 返回的是引用对象的实际大小（编译器自动解引用）。

### 面试题 2：new/delete vs malloc/free

**面试官**：`new` 和 `malloc` 的根本区别是什么？混用会怎样？

**回答**：`new` = 分配内存 + 调构造函数；`delete` = 调析构函数 + 释放内存。`malloc` 只分配内存，不调构造函数。如果 `new` 分配后用 `free` 释放——析构函数不跑 → 资源泄漏（如 `FILE*` 没 `fclose`）。如果 `malloc` 分配后用 `delete` 释放——行为未定义（`delete` 期望对象是 `new` 分配的）。`new[]` 必须配 `delete[]`，`new` 必须配 `delete`。

**追问（面试官）**：那什么情况下需要用 `malloc` 而不是 `new`？

**追问回答**：(1) 需要 `realloc` 扩容——C++ 没有直接等价物；(2) 与 C 库交互——C 库返回 `malloc` 分配的内存，你必须用 `free` 释放；(3) 自定义内存池用底层分配 API（`mmap`/`sbrk`），不经过 `::operator new`。除此之外，C++ 代码里优先用 `new`/智能指针。

### 面试题 3：constexpr vs const

**面试官**：C++ 里 `const` 和 `constexpr` 的区别？什么时候 `const` 不够用？

**回答**：`const` = "运行时不可修改"，不保证编译时值已知。`constexpr` = "编译时一定能算出值"。区别——`const int N = rand();` 合法（N 在运行时确定），`constexpr int N = rand();` 编译错误。`constexpr` 能用于数组大小、模板参数、静态断言——这些地方要求编译时常量。生产代码中优先用 `constexpr` 声明编译时常量——让编译器在编译时捕获错误。

**追问（面试官）**：那 C 里的 `const` 是不是最接近 C++ 的 `constexpr`？

**追问回答**：C 的 `const` 比 C++ 更接近 `constexpr`——C 的 `const int N = 10; int arr[N];` 可能触发 VLA 警告但编译器在接受时会当作编译时常量。C++ 的 `const` 更严格——`const int N = 10; int arr[N];` 在 C++ 中也是合法的（因为 N 是常量表达式），但 `const int N = foo(); int arr[N];` 不合法（VLA 不是 C++ 标准），而 `constexpr int N = foo();` 明确要求 foo 是 `constexpr` 函数——语义更加显式。

## 11. 本章小结

| C 的写法 | C++11 的写法 | 解决了什么 |
|---|---|---|
| `printf`/`scanf` + 格式串 | `std::cout`/`std::cin` + `<<`/`>>` | 类型安全，不用写 `%s`/`%d` |
| `swap(&x, &y)` + NULL 检查 | `swap(x, y)` 引用参数 | 不为空、不需取地址 |
| `malloc` + 手动初始化 | `new Foo(1, 2)` 分配+构造 | 一步完成，不漏初始化 |
| `add_int`/`add_double` 重命名 | `add(int)`/`add(double)` 重载 | 一个名字搞定 |
| `redis_init`/`ngx_init` 前缀 | `redis::init`/`ngx::init` 命名空间 | 编译器保证不冲突 |
| `NULL` 可能选错重载 | `nullptr` 类型安全 | 不会误匹配 `int` 重载 |
| `const` 不保证编译时常量 | `constexpr` 保证 | 数组大小/模板参数可用 |
| 冗长类型名手写 | `auto` 编译器推导 | 省力、可读 |
