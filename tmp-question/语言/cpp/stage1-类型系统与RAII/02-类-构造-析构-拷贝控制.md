## 1. 引言：C 的 struct 只能"装数据"，C++ 的 class 能"管理生命"

在 C 里，`struct` 是一个数据容器——你把几个字段放在一起，每个字段的值靠手工初始化、手工清理：

```c
struct Person {
    char *name;
    int age;
};

struct Person p;
p.name = malloc(64);
strcpy(p.name, "Alice");
p.age = 30;
// ... 用 p ...
free(p.name);   // 必须记得——忘了就泄漏
```

三个步骤，每一步都可能出错：忘记 `malloc`、忘记初始化 `age`、忘记 `free`。如果代码有多条错误返回路径——每条路径上都要记得清理——C 的 `goto cleanup` 模式就是干这个的。

C++ 的 `class` 让这三件事自动化了：**创建时自动初始化（构造函数）、销毁时自动清理（析构函数）、拷贝时自动处理（拷贝控制）**。你不需要"记住"清理——编译器在对象离开作用域时替你准时调用析构函数。

本章的核心信息：**C++ 的 class 不是"加了方法的 struct"，而是拥有"生命周期自动管理"的新物种。**

## 2. 从 struct 到 class——第一堂课

### 2.1 C 的 struct vs C++ 的 struct

在 C 里，你想给 `struct Point` 加一个"打印自己"的功能，只能单独写一个函数：

```c
struct Point { int x; int y; };
void print_point(const struct Point *p) {
    printf("Point(%d, %d)\n", p->x, p->y);
}
struct Point p = {1, 2};
print_point(&p);
```

C++ 允许把函数放进 struct 里面——成员函数（member function）：

```cpp
struct Point {
    int x;
    int y;
    void print() {    // 成员函数——可以直接访问 x 和 y
        std::cout << "Point(" << x << ", " << y << ")\n";
    }
};

Point p{1, 2};
p.print();   // 调用——像用 . 访问成员变量一样
```

**`p.print()` 是怎么工作的？** 成员函数里有一个隐式参数——`this` 指针——指向调用它的对象。编译器把 `p.print()` 翻译成类似 `Point::print(&p)` 的代码，函数内部访问 `x` 和 `y` 其实是通过 `this->x` 和 `this->y` 实现的。你可以显式写 `this->x`，但大多数时候不需要——编译器自动补。

### 2.2 struct 和 class 的唯一区别

C++ 的 `struct` 和 `class` 几乎完全一样——唯一的区别是**默认访问权限**：

```cpp
struct Point {     // struct 默认 public
    int x;         // 外部可以直接 p.x
    int y;
};

class Point {      // class 默认 private
    int x;         // 外部看不到——编译错误
    int y;
public:
    Point(int a, int b) : x(a), y(b) {}  // 公开的构造函数
};
```

| 关键字 | 默认访问权限 | 常用于 |
|---|---|---|
| `struct` | public | 纯数据聚合（像 C 的用法） |
| `class` | private | 有构造函数/析构函数/成员函数的"完整对象" |

注：继承时默认权限也不同——`struct D : B` 默认 public 继承，`class D : B` 默认 private 继承。继承在 Stage3 详讲。

**本章用 `class`**——因为这一章讲的就是"带有构造/析构的完整对象"。

## 3. 构造函数——创建对象时自动执行

### 3.1 C 的两步初始化和 C++ 的一步构造

在 C 里，创建一个带数据的 `Point` 需要两步：

```c
struct Point p;
p.x = 1;         // 第 1 步——忘了就随机值
p.y = 2;         // 第 2 步——忘了就随机值
```

C++ 的构造函数把这两步合并成一步——创建对象的同时就初始化了：

```cpp
class Point {
    int x, y;
public:
    Point(int a, int b) : x(a), y(b) {}   // 构造函数——和类同名，没有返回类型
};
Point p(1, 2);   // 创建 + 初始化一步完成
```

### 3.2 初始化列表——比在函数体里赋值更高效

构造函数里 `: x(a), y(b)` 叫**初始化列表**（initializer list）。它和"在函数体里赋值"有什么区别？

```cpp
// 初始化列表版本——x 和 y 在对象"出生"时就被初始化为 a 和 b
Point(int a, int b) : x(a), y(b) {}

// 函数体赋值版本——x 和 y 先被"默认初始化"，再被赋值为 a 和 b
Point(int a, int b) {
    x = a;   // 如果 x 是对象（如 string）——先"默认构造"一次，再"赋值"一次
    y = b;   // 初始化列表省掉了"默认构造"这一步
}
```

对于基本类型（`int`、`double`）——两者没区别（默认初始化的代价为零）。但对于对象类型（`std::string`、`std::vector`）——初始化列表更高效：直接一次构造完成，避免了"先默认构造再赋值"。

**三种必须用初始化列表的情况**——不能用函数体赋值替代：
1. **`const` 成员**——const 变量不能赋值（只能初始化）
2. **引用成员**——引用必须在定义时绑定（不能"先声明再绑定"）
3. **没有默认构造函数的成员**——如果成员的类没有 `T()` 默认构造，必须在初始化列表里调用它的有参构造函数

这三种情况下如果试图在函数体里赋值——编译直接报错。所以好习惯是**默认用初始化列表**——不等到"发现编译报错才改"。

### 3.3 默认构造函数——如果没写任何构造函数

如果你一个字都不写——编译器生成一个默认构造函数（什么都不做——基本类型字段的值是随机的，和 C 的 struct 行为一样）。但**一旦你写了任何一个构造函数**（哪怕只有一个参数），编译器就不生成默认构造函数了：

```cpp
class Point {
    int x, y;
public:
    Point(int a, int b) : x(a), y(b) {}   // 自定义构造函数
};

Point p;        // ✗ 编译错误！没有默认构造函数
Point p(1, 2);  // ✓ 只有这个能用
```

如果你还需要默认构造函数——用 `= default` 让编译器帮你生成一个：

```cpp
class Point {
    int x, y;
public:
    Point() = default;                      // 让编译器生成默认构造函数
    Point(int a, int b) : x(a), y(b) {}     // 自定义构造函数
};

Point p;        // ✓ 现在可以了——x 和 y 是随机值
Point p(1, 2);  // ✓ 这个也能用
```

### 3.4 `explicit`——防止隐式类型转换

单参数构造函数有一个微妙的陷阱——它允许**隐式类型转换**：

```cpp
class Point {
    int x;
public:
    Point(int a) : x(a) {}
};

Point p = 5;   // 🔴 合法！但你看这行——5 被隐式转成了 Point(5)
void draw(Point p);
draw(42);      // 🔴 也合法！42 被隐式转成了 Point(42)——这可能不是你想要的
```

`explicit` 禁止这种隐式转换——调用方必须显式写 `Point(5)`：

```cpp
class Point {
    int x;
public:
    explicit Point(int a) : x(a) {}
};

Point p = 5;   // ✗ 编译错误——不能隐式转换
Point p(5);    // ✓ 必须显式构造
draw(Point(42)); // ✓ 显式构造后传入
```

**生产建议**：单参数构造函数默认加 `explicit`——除非你确实需要"整数可以直接当 Point 用"的语义。

### 3.5 `const` 成员函数——承诺不修改对象

C 里没有"这个函数不修改参数"的强制语法——你只能靠 `const struct Point *p` 暗示"我不会改"。C++ 把这种承诺变成了编译时检查：

```cpp
class Point {
    int x, y;
public:
    Point(int a, int b) : x(a), y(b) {}
    void print() const {           // 🆕 const 成员函数
        std::cout << "(" << x << "," << y << ")";
        // x = 5;                  // ✗ 编译错误——const 函数不能修改成员！
    }
    void move(int dx, int dy) {    // 非 const 成员函数——可以修改成员
        x += dx; y += dy;
    }
};

const Point origin(0, 0);  // const 对象
origin.print();             // ✓ const 对象只能调用 const 成员函数
// origin.move(1, 1);       // ✗ 编译错误——move 不是 const 函数
```

**规则**：`const` 对象只能调用 `const` 成员函数。非 `const` 对象两种都能调用。这是 C++ 的 **const-correctness** 的基础——编译器帮你强制执行"不修改"的承诺。

## 4. 析构函数——对象销毁时自动执行

### 4.1 C 的"别忘了清理"和 C++ 的"自动清理"

C 里你手动管理资源——每个 `fopen` 要配 `fclose`、每个 `malloc` 要配 `free`：

```c
void use_file() {
    FILE *f = fopen("data.txt", "r");
    if (!f) return;
    char buf[256];
    if (fgets(buf, sizeof(buf), f) == NULL) {
        fclose(f);    // 错误路径 1——别忘了
        return;
    }
    // ... 处理 ...
    fclose(f);         // 正常路径——别忘了
}
```

C++ 的析构函数把清理自动化了——你只写一次清理逻辑，编译器在对象销毁时准时调用：

```cpp
class File {
    FILE *f;
public:
    File(const char* path) : f(fopen(path, "r")) {
        if (!f) throw std::runtime_error("Cannot open file");
    }
    ~File() { if (f) fclose(f); }   // 析构函数——名字是 "~类名"，没有参数
    operator FILE*() { return f; }  // 隐式类型转换——让 File 对象可以当 FILE* 使用
};
```

`operator FILE*()` 是一个**隐式类型转换运算符**——当代码需要一个 `FILE*` 但你传入了一个 `File` 对象时，编译器自动调用它转换为 `FILE*`。这就是为什么 `fgets(buf, sizeof(buf), f)` 能工作——`fgets` 第三个参数需要 `FILE*`，编译器看到 `f` 是 `File` 类型，自动调用 `operator FILE*()` 拿到内部的 `f` 指针。

**构造函数失败怎么办？** 上面的 `File` 在 `fopen` 返回 NULL 时抛 `std::runtime_error` 异常（异常在 Ch03 详讲）。抛异常后——对象从来没"活过"，析构函数不跑（不跑也无害——`f` 是 NULL）。另一种方式：设一个 `bool is_open()` 让调用方检查——类似 C 的 `if (!f)`。

void use_file() {
    File f("data.txt");             // 打开——构造函数 fopen
    char buf[256];
    if (fgets(buf, sizeof(buf), f) == NULL) {
        return;                     // 🔑 不用 fclose！f 的析构函数自动调用
    }
    // ... 处理 ...
}  // 🔑 正常退出——f 的析构函数自动调用
// 不管从哪条路退出——析构函数一定执行
```

### 4.2 析构函数的三个关键特征

1. **没有参数,不能重载**——一个类只能有一个析构函数。没有"怎么销毁"的选择——销毁只有一种方式。
2. **什么时候被调用**：栈对象离开作用域、`delete` 堆对象、临时对象表达式结束。
3. **析构函数是 RAII 的基石**——你不调用它，编译器替你准时调用。这就是 Ch01 引言说的"C++ 给了你 RAII"的具体实现。

**析构函数和 C 的对比**：C 的 `free` 只释放内存——不帮你清理 `FILE*` 或 `pthread_mutex_t`。C++ 的析构函数释放内存 + 清理资源——两个步骤一步完成。

## 5. 拷贝构造函数——`a = b` 背后的故事

### 5.1 C 的"拷贝"只是逐字节复制

C 里 struct 的赋值是逐字节拷贝：

```c
struct Person a = { .name = malloc(64), .age = 30 };
strcpy(a.name, "Alice");

struct Person b = a;   // b 是 a 的逐字节拷贝
// b.name == a.name ——指向同一块内存！
free(a.name);           // a 释放了 name
// b.name 现在是野指针——UAF！
```

C 的拷贝是"浅拷贝"——指针的值被拷贝了，但指向的数据没有。两个 struct 共享同一块堆内存——释放一个，另一个的指针就悬空了。

### 5.2 C++ 的默认拷贝构造函数

C++ 给每个类自动生成一个拷贝构造函数——它的行为和 C 一样：**逐成员拷贝**。对于指针成员——拷贝的是地址，不是数据：

```cpp
class Buffer {
    char *data;
    size_t size;
public:
    Buffer(const char *src) : size(strlen(src) + 1), data(new char[size]) {
        memcpy(data, src, size);
    }
    ~Buffer() { delete[] data; }
    // 没有自定义拷贝构造函数——编译器生成了逐成员拷贝
};

Buffer a("hello");
Buffer b = a;   // 🔴 b.data == a.data——两个对象指向同一块内存！
// a 析构 → delete[] data
// b 析构 → delete[] data——🔴 double-free！
```

**编译运行**——这段代码在析构时崩溃（double-free）。`g++ -std=c++11 shallow_copy.cpp -o shallow_copy && ./shallow_copy`。

### 5.3 自定义深拷贝——拷贝数据而不是指针

修复：自己写拷贝构造函数，分配新内存、拷贝数据：

```cpp
class Buffer {
    char *data;
    size_t size;
public:
    Buffer(const char *src) : size(strlen(src) + 1), data(new char[size]) {
        memcpy(data, src, size);
    }
    ~Buffer() { delete[] data; }

    // 🆕 拷贝构造函数——深拷贝
    Buffer(const Buffer &other) : size(other.size), data(new char[size]) {
        memcpy(data, other.data, size);   // 拷贝数据——不是指针
    }
};

Buffer a("hello");
Buffer b = a;   // ✓ b.data 是新分配的内存——和 a.data 独立
// a 析构 → delete[] a.data
// b 析构 → delete[] b.data——两个独立释放，互不影响
```

### 5.4 拷贝赋值运算符——`a = b` 不是"初始化"

`Buffer b = a;` 调用的是拷贝构造函数（对象出生时）。`b = a;` 调用的是**拷贝赋值运算符**（对象已经活着）：

```cpp
Buffer& operator=(const Buffer &other) {
    if (this != &other) {            // 🔑 检查自己赋给自己
        delete[] data;               // 释放自己的旧数据
        size = other.size;
        data = new char[size];       // 分配新内存
        memcpy(data, other.data, size);  // 拷贝对方的数据
    }
    return *this;
}
```

**为什么必须检查 `this != &other`**：`a = a;` 自己赋给自己——如果先 `delete[] data` 释放了自己的 data，再 `memcpy(data, other.data, size)`——但 `other.data` 也是自己的 data，已经被删除了→UB。

**一个更深的问题**：上面先 `delete[] data` 再 `new` 的模式是**异常不安全**的——如果 `new char[size]` 抛异常 `std::bad_alloc`（内存不足），旧 data 已经被 `delete[]` 了，但新 data 没分配成功→对象的 data 指针指向已释放的内存→后续析构 `delete[] data` 是 double-free。**强异常安全**的写法是"先分配新内存、成功后再释放旧内存"：

```cpp
Buffer& operator=(const Buffer &other) {
    if (this != &other) {
        char *new_data = new char[other.size];     // 1. 先分配新内存——可能失败
        memcpy(new_data, other.data, other.size);   // 2. 拷贝数据
        delete[] data;                               // 3. 成功后才释放旧内存
        data = new_data;
        size = other.size;
    }
    return *this;
}
```

这个模式叫 **copy-and-swap**——Ch03 移动语义中会进一步展开。

## 6. `= delete`——禁用拷贝

有些资源不应该被拷贝——互斥锁、文件句柄、socket。如果允许拷贝→两个对象"拥有"同一个锁→谁 unlock？谁 close？

```cpp
class Mutex {
    pthread_mutex_t mtx;
public:
    Mutex()  { pthread_mutex_init(&mtx, nullptr); }
    ~Mutex() { pthread_mutex_destroy(&mtx); }

    Mutex(const Mutex&) = delete;            // 🔑 禁止拷贝构造
    Mutex& operator=(const Mutex&) = delete;  // 🔑 禁止拷贝赋值
};
```

`= delete` 告诉编译器"不要生成这个函数"——任何人尝试拷贝时直接编译报错：

```cpp
Mutex a, b;
Mutex c = a;   // ✗ 编译错误：use of deleted function
```

**和"不写"的区别**：不写→编译器自动生成默认版本（逐成员拷贝）。`= delete`→编译器不生成，尝试使用时编译报错。`= delete` 是一种主动的防御——明确告诉使用者"这个类不能被拷贝"。

**`= delete` vs C++98 的 `private` 拷贝**：C++98 里"禁止拷贝"是把拷贝构造函数声明为 `private`——外部代码不能访问。但类内部的成员函数仍然可以拷贝，而且错误信息是"访问私有成员"不是"函数被删除"。`= delete`（C++11）是彻底禁掉——类内部也不能用，错误信息更明确。

## 7. Rule of Three——三个特殊函数的共生关系

### 7.1 规则

**如果你需要自定义下面任何一个，几乎肯定需要定义另外两个**：

1. **析构函数**
2. **拷贝构造函数**
3. **拷贝赋值运算符**

### 7.2 为什么

回顾 `Buffer` 类——它管理了堆内存（`char *data`）：

1. **析构函数释放了 data**——Buffer 需要它（管理了额外资源）
2. 如果用了**默认拷贝构造**——两个对象指向同一个 data→第一个析构释放→第二个用野指针→double-free
3. 如果用了**默认拷贝赋值**——同样的浅拷贝→同样的 double-free

三个函数是"共生"的——因为类管理了资源，所以必须控制这个资源在构造/赋值/析构三个时刻的行为：

```cpp
class Buffer {
    char *data;
    size_t size;
public:
    Buffer(const char *src);                       // 构造函数
    ~Buffer() { delete[] data; }                    // 析构——释放 data
    Buffer(const Buffer &other);                    // 拷贝构造——深拷贝 data
    Buffer& operator=(const Buffer &other);         // 拷贝赋值——释放旧 data，深拷贝新 data
};
```

### 7.3 Rule of Three→Rule of Five

C++11 扩展了这个规则——多了**移动构造函数**和**移动赋值运算符**（Rule of Five）。移动比拷贝快数个数量级——"偷"指针而不是拷贝数据。Ch03 详讲。

### 7.4 什么时候 Rule of Three 退化为 Rule of Zero

如果你的类成员全部是"自己管理自己的"类型（`std::string`、`std::vector`、`std::unique_ptr`）——编译器自动生成的五个函数完全正确——你一个字都不需要写。这就是 **Rule of Zero**——"用标准库的类型而不是裸指针，让编译器替你管理"。

Rule of Three 主要出现在"类内部用裸指针管理资源"的场景——而这个场景在现代 C++ 里越来越少（因为有智能指针——Ch04 详讲）。

## 8. 可运行实验：浅拷贝→double-free→深拷贝修复

```cpp
#include <iostream>
#include <cstring>

class Buffer {
    char *data;
    size_t size;
public:
    Buffer(const char *src) : size(strlen(src) + 1), data(new char[size]) {
        memcpy(data, src, size);
        std::cout << "Buffer(\"" << data << "\") created\n";
    }
    // 🔴 没有自定义拷贝构造——编译器生成浅拷贝
    ~Buffer() {
        std::cout << "~Buffer(\"" << (data ? data : "(null)") << "\")\n";
        delete[] data;
    }
};

int main() {
    Buffer a("hello");
    Buffer b = a;   // 🔴 浅拷贝——b.data == a.data
    return 0;
    // a 析构 → delete[] data
    // b 析构 → delete[] data  ← 🔴 同一块内存被释放两次！
}
```

**编译运行**：
```bash
g++ -std=c++11 -Wall shallow.cpp -o shallow && ./shallow
# 输出 crash——double free or corruption (fasttop)
```

**修复**——加上拷贝构造函数：
```cpp
Buffer(const Buffer &other) : size(other.size), data(new char[size]) {
    memcpy(data, other.data, size);
    std::cout << "Buffer copied\n";
}
// 重新编译运行——正常运行，两次析构，不复 double-free
```

这个实验是本章的灵魂——亲手写出 crash，亲手修复。比读十页理论更深刻。

## 9. 面试题

### 面试题 1：拷贝构造 vs 拷贝赋值

**面试官**：`Buffer b = a;` 和 `b = a;` 有什么区别？各调用哪个函数？

**回答**：`Buffer b = a;` 是**初始化**——调用拷贝构造函数 `Buffer(const Buffer&)`。`b = a;` 是**赋值**——调用拷贝赋值运算符 `Buffer& operator=(const Buffer&)`。关键区别：拷贝构造时对象还没"出生"（内存未初始化），直接分配新内存并拷贝。拷贝赋值时对象已经"活着"（已有值）——必须先释放旧内存，再分配新内存、拷贝新数据。

**追问（面试官）**：拷贝赋值运算符里为什么要检查 `if (this != &other)`？不检查会怎样？

**追问回答**：`a = a;` 自己赋给自己——如果不检查→第 1 步 `delete[] data` 释放了自己的 data→第 2 步 `new char[size]` 用 `other.size` 分配——但 `other` 就是 `*this`，`data` 已被释放→内存里是随机值→`size` 可能是随机值→分配错误内存→后续 `memcpy` 从已释放的 data 读数据→crash。检查 `if (this != &other)` 跳过清理-分配-拷贝→直接返回 `*this`。

### 面试题 2：Rule of Three

**面试官**：什么时候需要自己写拷贝构造函数、拷贝赋值、析构函数？为什么三个必须一起写？

**回答**：类管理了"额外资源"（堆内存、文件句柄、锁、socket）时需要。如果析构函数释放了 data，但用了默认拷贝构造——两个对象指向同一个 data→第一个析构释放→第二个析构用野指针→崩溃。如果写了拷贝构造但没写拷贝赋值——`a = b` 用的是默认浅拷贝，同样的 double-free。三个函数是"共生"的——一个管理资源，三个必须一起管理。

**追问（面试官）**：什么时候 Rule of Three 可以退化为 Rule of Zero？

**追问回答**：当类的所有成员都是"自己管理自己的"标准库类型时——`std::string`、`std::vector`、`std::unique_ptr`——编译器自动生成的特殊函数完全正确，一个字都不需要写。这就是 Rule of Zero——用标准库类型替代裸指针，让编译器替你管理生命周期。这对应 Ch04 的智能指针主题。

### 面试题 3：=delete 的应用

**面试官**：`= delete` 和"不写"有什么区别？什么场景用 `= delete`？

**回答**：不写——编译器自动生成默认版本（逐成员拷贝）。`= delete`——编译器不生成，试用时编译报错。用 `= delete` 的场景——(1) 文件句柄、互斥锁、socket 不应该被拷贝（谁 close/free/unlock 说不清）；(2) 单例模式——禁止构造第二个实例；(3) 防止隐式转换——`void foo(int); void foo(double) = delete;` 禁止 `foo(3.14)`。

**追问（面试官）**：`= delete` 和 C++98 的 `private` 拷贝构造有什么区别？

**追问回答**：`private` 拷贝构造——外部代码不能访问。但类内部的成员函数和友元函数仍然可以拷贝。错误信息是"访问私有成员"——不告诉你"为什么不能"。`= delete` 对所有代码生效（包括类内部），错误信息明确（"use of deleted function"）。C++11 开始优先用 `= delete`。

## 10. 本章小结

| C 的写法 | C++11 的写法 | 解决了什么 |
|---|---|---|
| `struct Point p; p.x=1; p.y=2;` 两步初始化 | `Point(int a, int b) : x(a), y(b)` 构造一步 | 不会忘初始化 |
| `fclose(f)` 每条路径上都要写 | `~File() { fclose(f); }` 析构自动调 | 不会忘清理 |
| 拷贝 struct = 逐字节复制→野指针 | `Buffer(const Buffer&)` 深拷贝 | 拷贝独立、安全释放 |
| 文档约定"don't copy" | `= delete` 编译期阻止 | 编译器强制执行 |
| 三个函数有关系但各自写 | Rule of Three——三个共生 | 编译器不能替你判断 |
