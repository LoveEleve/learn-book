> **定位**：Stage1 第二章。前提——读者已完成 Ch01（引用/new/重载/命名空间/auto），**从未写过 C++ 类**。
> **主线版本**：C++11

---

## 1. 本章要解决的核心问题

在 C 里，`struct` 只是一个数据容器——你创建它、初始化它、清理它，全部手工。C++ 的 `class` 把这三件事自动化了：**创建时自动初始化（构造）、拷贝时自动处理（拷贝控制）、销毁时自动清理（析构）**。

本章的核心信息：**C++ 的 class 不是"加了方法的 struct"，而是拥有"生命周期自动管理"的新物种。**

---

## 2. 节结构（6 节）

### §1 从 struct 到 class — 第一堂课

| 你在 C 里这样写 | C++ 里可以这样 |
|---|---|
| `struct Point { int x; int y; };` `struct Point p = {1, 2};` | `struct Point { int x; int y; };` `Point p{1, 2};` — 一样的 |
| 要打印点：单独写 `void print_point(struct Point p)` | 放进 struct：`struct Point { void print() { printf... } };` 调用 `p.print();` |

- **从 Ch01 §3 回顾**：Ch01 讲了 `new`/`delete` 替代 `malloc`/`free`——但没有构造函数和析构函数，`new Point` 和 `malloc` 没本质区别。本章的核心就是给 `new`/`delete` 加上构造和析构——让对象"出生"和"死亡"时自动执行代码。
- **C++ 的 struct 和 class 的区别**：唯一区别是默认访问权限——struct 默认 public，class 默认 private。此外完全一样。
- **`this` 指针**：成员函数里有一个隐式参数 `this`，指向调用它的对象
- **目标**：读者在这一节写出第一个带成员函数的 struct，理解 `p.print()` 中的 `p` 就是 `this`

### §2 构造函数 — 创建对象时自动执行

| 你在 C 里这样写 | C++ 里可以这样 |
|---|---|
| `struct Point p; p.x = 1; p.y = 2;` — 两步初始化 | `Point(int a, int b) : x(a), y(b) {}` — 一行 |
| 忘了初始化 → 值随机 → bug | 构造函数保证创建时一定初始化 |

- **构造函数长什么样**：和类同名，没有返回类型
- **初始化列表**（`: x(a), y(b)`）：在对象还没"活过来"之前就把成员设好——比在函数体里赋值更高效
- **默认构造函数**：如果没写任何构造函数，编译器生成一个空的（什么都不做）
- **多个构造函数**：重载——传两个参数走双参构造函数，不传参数走默认构造函数
- **`= default`**：告诉编译器"帮我生成默认的"——当你写了另一个构造函数但又需要默认的时
- **🆕 `explicit` 关键字**：单参数构造函数默认支持隐式类型转换——`Point p = 5;` 会把 5 偷偷转成 `Point(5)`。`explicit Point(int a)` 禁止这种隐式转换——C++ 核心安全习惯。
- **🆕 `const` 成员函数**：`void print() const { ... }` ——承诺"这个函数不修改对象"。const 对象只能调用 const 成员函数。C 里没有这概念——这是 C++ 的 const-correctness 基础。

### §3 析构函数 — 对象销毁时自动执行

| 你在 C 里这样写 | C++ 里可以这样 |
|---|---|
| `fclose(f); free(buf);` — 每次用完都要记得清理 | `~File() { fclose(f); }` — 对象销毁时自动调用 |

- **析构函数长什么样**：`~ClassName()`，没有参数，不能重载（一个类只能有一个）
- **什么时候被调用**：栈对象离开作用域、delete 堆对象、临时对象表达式结束
- **核心理解**：析构函数是 C++ RAII 的基石——你不调用它，编译器替你准时调用
- **最简单的析构示例**：一个包装 `FILE*` 的类，构造函数 `fopen`，析构函数 `fclose`——使用方完全不用碰 fclose

### §4 拷贝构造函数 — `a = b` 背后的故事

```cpp
// C 里两个"相同"的 struct 根本不是一回事
struct Point a = {1, 2};
struct Point b = a;   // C 里这行只是逐字节拷贝——如果 a 里面有指针，b 指同一块内存！
```

- **默认拷贝构造函数**：逐成员拷贝——基本类型拷贝值，指针拷贝地址（不是指向的数据！）
- **为什么需要自己写拷贝构造函数**：如果类里有指针指向堆上的数据，默认的"浅拷贝"让两个对象指向同一块内存→ double-free 或 UAF
- **自定义拷贝构造函数**：`Point(const Point& other) : x(other.x), y(other.y) {}`
- **拷贝赋值运算符**：`Point& operator=(const Point& other)` —— 注意自己赋给自己的情况

**本节的可运行实验**：写一个带 `char* data` 成员的 Buffer 类，用默认拷贝（浅拷贝）→ double-free 崩溃，改自定义拷贝（深拷贝）→ 安全

### §5 `= delete` — 禁用拷贝

有些资源不应该被拷贝——文件句柄、互斥锁、socket：
```cpp
class Mutex {
public:
    Mutex(const Mutex&) = delete;            // 不能拷贝
    Mutex& operator=(const Mutex&) = delete;  // 不能赋值
};
```

- 面试常问：什么资源不应该被拷贝？为什么？
- 对比：C 里要实现同样的限制，你需要文档约定"don't copy this struct"——编译器不帮你检查
- C++ 里 `= delete` 让编译器在别人尝试拷贝时直接报错

### §6 Rule of Three — 三个特殊函数的"共生关系"

**如果自定义了下面任何一个，几乎肯定需要定义另外两个**：
1. 析构函数
2. 拷贝构造函数
3. 拷贝赋值运算符

```cpp
class Buffer {
    char* data;
    size_t size;
public:
    Buffer(const char* src);              // 构造函数
    ~Buffer() { delete[] data; }          // 析构——释放 data
    Buffer(const Buffer& other);          // 拷贝构造——深拷贝 data
    Buffer& operator=(const Buffer& other); // 拷贝赋值——释放旧 data，深拷贝新 data
};
```

- **为什么需要三个**：析构函数释放 data → 但如果用了默认拷贝构造，两个对象指向同一个 data → 第一个析构释放了 data，第二个析构释放野指针 → 崩溃
- **Rule of Five（C++11）**：还需要移动构造函数和移动赋值——留给 Ch03 移动语义

## 4. 面试题（3 组，每组含答案+追问）

### 面试题 1：拷贝构造 vs 拷贝赋值

**面试官**：`Point b = a;` 和 `b = a;` 有什么区别？各调用哪个函数？

**回答**：`Point b = a;` 是初始化——调用**拷贝构造函数** `Point(const Point&)`。`b = a;` 是赋值——调用**拷贝赋值运算符** `Point& operator=(const Point&)`。关键区别：拷贝构造是在对象"出生"时执行（内存未初始化），拷贝赋值是在对象"活着的"时执行（对象已有值，需要先清理再拷贝）。Rule of Three 之所以要求三个函数——因为需要析构释放资源 + 拷贝构造初始化新资源 + 拷贝赋值先释放旧资源再拷贝新资源。

**追问（面试官）**：拷贝赋值运算符里为什么要检查"自己赋给自己"？不检查会怎样？

**追问回答**：`a = a;` 如果没检查——`delete[] data` 释放了自己的 data → 然后 `new char[size]` 用 `other.size` 分配——但 `other` 就是 `*this`，`data` 已被释放→内存里是随机值→分配的大小可能是随机值→崩溃。检查 `if (this != &other)`——如果是自己赋给自己，直接返回。这是拷贝赋值的标准防御模式。

### 面试题 2：Rule of Three

**面试官**：什么时候需要自己写拷贝构造函数、拷贝赋值、析构函数？为什么三个必须一起写？

**回答**：类管理了"额外资源"（堆内存、文件句柄、锁、socket）时需要。如果析构函数释放了 `data`，但用了默认拷贝构造——两个对象指向同一个 `data`→第一个析构释放了→第二个析构用野指针→崩溃。如果写了拷贝构造但没写拷贝赋值——`a = b` 用的是默认赋值（浅拷贝），同样的 double-free。三个函数是"共生"的——一个管理资源，三个必须一起管理。

**追问（面试官）**：C++11 里 Rule of Three 变成了 Rule of Five——多了哪两个？为什么需要？

**追问回答**：多了**移动构造函数**和**移动赋值运算符**（Ch03 移动语义）。移动的意义是"资源转移"而不是"拷贝"——`Buffer b2 = std::move(b1);` 把 `b1.data` 指针直接转给 `b2`，`b1.data` 设为 nullptr——不需要分配新内存和拷贝数据。大型 Buffer 的移动比拷贝快数个数量级。Rule of Five 对应：如果你需要自定义其中任何一个，通常五个都需要——这是 Ch03 的核心内容。

### 面试题 3：=delete 的应用

**面试官**：`= delete` 和"不写"有什么区别？什么场景用 `= delete`？

**回答**：不写——编译器自动生成默认版本（逐成员拷贝/什么都不做）。`= delete`——编译器**不**生成，有人尝试使用时编译报错。用 `= delete` 的场景——(1) 文件句柄、互斥锁、socket 不应该被拷贝；(2) 单例模式——禁止拷贝和复制；(3) 防止隐式转换——`void foo(int); void foo(double) = delete;`，禁止 `foo(3.14)` 调用。

**追问（面试官）**：C++ 里 `= delete` 和 `private` 拷贝构造（C++98 的旧写法）有什么区别？

**追问回答**：`private` 拷贝构造只防外部代码——类内部的成员函数和友元函数仍然可以拷贝。而且错误信息是"访问私有成员"而不是"这个函数被删除了"——信息量不够。`= delete` 对所有代码生效（包括类内部），错误信息明确（"use of deleted function"）。C++11 开始优先用 `= delete`。
