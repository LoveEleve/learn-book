## 2. 写作规范（10 条铁律）

1. **PLAN 只是大纲**——不转录，站在技术专家角度重新讲解，字数无上限，讲透为止
2. **每个英文术语首次出现必须**：全称 + 一句话定义
3. **主线 C++11**——C++14/17/20 特性仅在涉及处标注版本号，不展开
4. **每个特性从 C 的对应写法出发**——"你在 C 里怎么写 → C++ 里怎么替代"
5. **每节开头用"为什么"提问**，不是定义堆砌
6. **面试题 3 组**：完整四段式——面试官→回答→追问→追问回答（不是标题描述）
7. **可运行实验**：完整代码 + 编译命令 + 预期输出（不是文字描述）
8. **一章写完 → 深度 review → 修复所有缺口 → 再写下一章**。不批量。
9. **不设行数目标**——"讲解清楚为止"，行数是内容深度的自然结果
10. **前置依赖**写在文章开头——读者知道需要什么前置知识

## 3. 写作流程

```
1. 读 PLAN.md（同级目录下的 -PLAN.md）
2. 写正文（同级目录下的 .md，无 -PLAN 后缀）
3. 深度 review：
   - C++11 兼容性检查
   - 逻辑链："读者能理解这个跳转吗？"
   - 缺失内容："C 程序员会在这里卡住吗？"
   - 面试题四段式完整性
   - 可运行实验代码完整性
4. 修复所有缺口
5. 确认后进入下一章
```
