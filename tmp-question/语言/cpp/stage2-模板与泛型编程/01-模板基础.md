## 1. 引言：把"写三遍"变成"写一遍"

Stage1 教你写了 `Buffer`、`File`——每个类都是一个特定的类型。但现实中的需求是"同一个逻辑用在不同的类型上"：

```cpp
int    max_int(int a, int b)       { return a > b ? a : b; }
double max_double(double a, double b) { return a > b ? a : b; }
// long? float? string? 你要写多少个版本？
```

函数体完全一样——只是类型不同。这就是**重复代码的根源**。

C 有两种泛型手段，都不完美：`void*` + 函数指针（`qsort` 的模式——类型不安全、有函数调用开销）；宏 `#define MAX(a,b) ((a)>(b)?(a):(b))`（无类型检查、有副作用——`MAX(i++, j)` 自增两次）。

C++ 模板给了第三种方案：**编译器替你生成代码——你说"我想要 `max<int>`"，编译器生成一份 `int max(int a, int b)`。** 零运行时开销、完全类型安全。

本章教模板的基础层：函数模板、类模板、特化。变参模板和 SFINAE 留给 Ch04。

## 2. 函数模板——只用写一次

### 2.1 模板的定义和使用

```cpp
// 模板的定义——template <typename T> 告诉编译器"T 是类型占位符"
template <typename T>
T max(T a, T b) {
    return a > b ? a : b;    // 只要 T 支持 > 运算符就能用
}

// 使用——编译器从参数自动推导 T
int    x = max(3, 5);                                    // T = int
double y = max(3.14, 2.71);                              // T = double
std::string s = max(std::string("abc"), std::string("xyz")); // T = string
```

**`typename` vs `class`**：`template <typename T>` 和 `template <class T>` 完全一样。本教材统一用 `typename`——表达更准确（T 可以是 int/double 等基本类型，不一定是 class）。

### 2.2 模板不是函数——是"蓝图"

这是理解模板最关键的心智模型：**`max` 不是函数——它是一个"蓝图"**。`max<int>` 才是真正的函数（编译器根据蓝图生成的）。

```cpp
max(3, 5);       // 第一次调用——编译器生成 max<int>(int, int)
max(3.14, 2.71); // 第二次调用——编译器生成 max<double>(double, double)
max(10, 20);     // 第三次调用——同一 TU 内复用已生成的 max<int>
```

程序里没有 `max`——只有你调用后编译器生成的 `max<int>`、`max<double>` 等。每种类型组合生成一份独立的机器码。

> **生产提示**：上面的 `max` 模板用按值传递（`T a, T b`）——对 `int`/`double` 没问题，但对 `string` 等大型对象会产生不必要的拷贝。标准库的 `std::max` 使用 `const T&` 避免拷贝：`template <typename T> const T& max(const T& a, const T& b)`。模板本身不强制你用什么参数形式——根据 T 的语义选择最合适的。

## 3. 类模板——泛型容器

### 3.1 从 Stack 开始

用模板写一个栈——元素类型是 T，大小是 N：

```cpp
template <typename T, int N>
class Stack {
    T data[N];          // 用模板参数 N 指定数组大小
    int top;
public:
    Stack() : top(0) {}
    void push(const T& val) { data[top++] = val; }   // 生产代码加 assert(top < N)
    T pop() { return data[--top]; }                   // 生产代码加 assert(top > 0)
    bool empty() const { return top == 0; }
};

// 使用——每种类型组合生成一份独立的类
Stack<int, 10>           int_stack;   // 元素 int，大小 10
Stack<std::string, 100>  str_stack;   // 元素 string，大小 100
// 编译器生成两份完全独立的代码——int_stack 和 str_stack 的 push/pop 没有任何关联
```

### 3.2 模板参数可以是什么

- **类型参数**：`typename T`（或 `class T`）——可以是任何类型
- **非类型模板参数**：`int N`、`size_t S`、枚举、指针——必须是**编译时常量**

```cpp
Stack<int, 10> s1;           // ✓ 10 是编译时常量
constexpr int N = 20;
Stack<int, N> s2;             // ✓ N 是 constexpr——编译时常量

int n = read_from_config();
// Stack<int, n> s3;          // ✗ n 是运行时变量——编译错误
```

**不能传什么**：浮点数（`double 3.14`）、字符串字面量（`"hello"`）、类的对象——这些都不是编译时常量。

### 3.3 每种实例化是独立编译的

`Stack<int, 10>` 和 `Stack<double, 10>` 在生成的机器码里是两套独立的 `push`/`pop` 函数——零运行时开销。和手写 `IntStack`、`DoubleStack` 两份代码**一样快**——编译器替你写了那两份代码。

## 4. 模板参数推导——编译器怎么"猜"T

### 4.1 什么时候编译器能推导

```cpp
template <typename T>
T max(T a, T b) { return a > b ? a : b; }

max(3, 5);        // a 和 b 都是 int → T = int ✓
max(3.14, 2.71);  // a 和 b 都是 double → T = double ✓
// max(3, 3.14);  // ✗ 一个 int 一个 double——T 推导不一致——编译错误
```

编译器从**函数参数**推导模板类型。如果参数类型一致→推导成功。如果不一致→编译错误（除非显式指定）。

**更危险的陷阱——`max("hello", "world")` 比较的是指针！** 字符串字面量 `"hello"` 的类型是 `const char[6]`，作为函数参数时退化为 `const char*`。T 推导为 `const char*`，`>` 比较的是**内存地址**而非字符串内容——编译通过但语义错误。和之前的 `max(3, 3.14)` 不同——那个至少会**编译失败**，而这个**静默运行**——是更严重的 bug：

```cpp
max("hello", "world");  // 🔴 T = const char*，比较指针地址——结果依赖栈布局！
// 正确做法：显式转换为 string
max(std::string("hello"), std::string("world"));
```

### 4.2 什么时候必须显式指定

```cpp
// 场景 1：返回类型和参数类型不同——推导不了返回类型
template <typename To, typename From>
To cast(From val) { return static_cast<To>(val); }

auto x = cast<int>(3.14);     // ✓ 显式指定 To = int，From 从 3.14 推导 = double

// 场景 2：没有函数参数可以推导
template <typename T>
T create() { return T(); }

auto x = create<int>();       // ✓ 显式指定 T = int
```

**和 `auto` 的关系**：`auto x = max(3, 5);` ——`auto` 推导出 `int`，模板从 `(3, 5)` 推导出 `T = int`。两个推导机制互相配合——`auto` 推导变量类型，模板推导参数类型。

> **C++17 起——类模板参数推导（CTAD）**：§3.1 的 `Stack<int, 10> int_stack;` 在 C++17 可以简写为 `Stack int_stack(/*推导 N*/...);`。编译器从构造函数的参数自动推导模板参数——和函数模板推导 T 是同一原理。C++17 之前类模板必须显式写 `<int, 10>`——这也是函数模板参数推导扩展到类模板的自然演进。本章后续仍用 C++11 显式写法以保证兼容性。

## 5. 模板特化——对特定类型"开个后门"

大部分类型用通用模板就够了。但有时需要给特定类型提供**不一样的实现**——这叫**特化**：

```cpp
// 通用版本——对大多数类型
template <typename T>
const char* type_name() { return "unknown"; }

// 全特化——对 int
template <>
const char* type_name<int>() { return "int"; }

// 全特化——对 double
template <>
const char* type_name<double>() { return "double"; }

std::cout << type_name<int>()    << '\n';  // "int"
std::cout << type_name<double>() << '\n';  // "double"
std::cout << type_name<long>()   << '\n';  // "unknown" ——没特化，走通用版本
```

**全特化 vs 偏特化**：本节只讲全特化（`template <>`——全部模板参数固定）。偏特化（`template <typename U> class Foo<U, int>`——部分参数固定）留给 Ch04。

**特化的典型用途**：`std::vector<bool>` 是位压缩的全特化（每个 `bool` 只占 1 bit，省内存——但牺牲了 `&v[0]` 返回 `bool*` 的语义）；`std::hash<T>` 对 `int`/`string`/`double` 各有特化，返回哈希值。

**特化和虚函数的本质区别**：虚函数（Stage3 Ch01）是**运行时**分派——程序运行时才知道调哪个版本。模板特化是**编译时**分派——编译完成后只有一个版本存在，零运行时开销。

### 5.2 偏特化——部分参数固定，部分保持泛型

Ch04 会详讲，但这里先让你知道偏特化长什么样：

```cpp
// 通用模板——两个类型参数都是泛型
template <typename T1, typename T2>
class Pair { /* ... */ };

// 偏特化——第二个参数固定为 int，第一个保持泛型
template <typename T>
class Pair<T, int> { /* 特殊的实现 */ };

Pair<double, int> p;   // 走偏特化版——第二个参数是 int
Pair<int, double> p2;  // 走通用版——第二个参数不是 int
```

偏特化给"某一维度的参数做约束"——"只要第二个参数是 int，不管第一个是什么，走这个版本"。Ch04 配合变参模板和 SFINAE 会让偏特化的威力完全展现。

### 5.3 模板模板参数——模板本身作为参数

模板参数可以不是一个具体的类型——而是**一个模板**。这让代码的抽象层次再上一个台阶：

```cpp
#include <vector>
#include <list>
#include <memory>   // std::allocator

// Container 不是一个类型——它是一个模板！
// "给我一个模板，我就用你的元素类型 T 去实例化它"
template <typename T, template <typename, typename> class Container>
class Stack {
    Container<T, std::allocator<T>> data;  // Container 用 <T, allocator> 实例化
public:
    void push(const T& val) { data.push_back(val); }
    T pop() {
        T val = data.back();
        data.pop_back();
        return val;
    }
};

// 同一个 Stack——底层容器可以不同
Stack<int, std::vector> sv;  // 内部 vector<int, allocator<int>> data;
Stack<int, std::list>   sl;  // 内部 list<int, allocator<int>> data;
```

**为什么需要**：C++11 没有直接的"概念"约束（Concepts 在 C++20）。模板模板参数是一种"编译时告诉编译器：你给我的是一个容器模板"的方式——比 `template<typename Container>` 更明确地表达意图（"Container 是一个模板"）。

### 5.4 依赖名与 `typename`——模板体内的类型归属

在模板**内部**写代码时，有一个特殊的语法规则——依赖类型**必须**加 `typename`：

```cpp
template <typename Container>
void print_first(const Container& c) {
    // typename——告诉编译器"Container::value_type 是一个类型"
    typename Container::value_type first = c.front();
    std::cout << first;
}
```

**为什么必须加 `typename`**：编译器在第一次看到 `Container::value_type` 时**不知道**它是一个类型还是一个静态成员变量（因为 `Container` 是模板参数——还没被实例化）。如果没有 `typename`，编译器默认假定它是静态成员（不是类型）——编译错误。

```cpp
template <typename T>
void example(T& obj) {
    T::value_type x;       // ✗ 编译错误——编译器不知道 value_type 是类型
    typename T::value_type x; // ✓ 明确告诉编译器——"这是类型"
}
```

这个规则也适用于嵌套类型：`typename Container::const_iterator it = v.begin();`

### 5.5 成员模板——类的成员函数也可以独立模板化

一个类的**某个成员函数**可以是模板——不要求整个类都是模板：

```cpp
class Printer {
public:
    // 成员函数模板——接受任何类型的参数来打印
    template <typename T>
    void print(const T& value) {
        std::cout << value << '\n';
    }
};

Printer p;
p.print(42);          // T = int
p.print("hello");     // T = const char*
p.print(3.14);        // T = double
// p 本身不是模板——只有 print() 是模板
```

更实用的场景——模板类的构造函数独立模板化：

```cpp
template <typename T>
class Wrapper {
    T value;
public:
    // 这个构造函数是独立的模板——可以从"不同但可转换"的类型构造
    template <typename U>
    Wrapper(const Wrapper<U>& other) : value(other.get()) {}

    T get() const { return value; }
};

Wrapper<int> wi(42);
Wrapper<double> wd(wi);  // ✓ U=int→T=double——int 可以转 double
```

这比"写一个 `Wrapper(const Wrapper<T>& other)`"更灵活——允许从 `Wrapper<U>` 转换到 `Wrapper<T>`（只要 `U` 能转换到 `T`）。

## 6. 模板代码必须放在头文件中

### 6.1 分离编译的陷阱

这是 C++ 模板最常见的新手陷阱——你按 C 的习惯写好 `.h`（声明）和 `.cpp`（实现），分文件编译：

```cpp
// max.h —— 声明
template <typename T>
T max(T a, T b);

// max.cpp —— 实现
#include "max.h"
template <typename T>
T max(T a, T b) { return a > b ? a : b; }

// main.cpp —— 使用
#include "max.h"
int main() {
    int x = max(3, 5);           // ✗ 链接错误！编译器找不到 max<int> 的定义
    return 0;
}
```

**为什么**：模板是"蓝图"——编译器看到 `max<int>` 被调用时**才生成代码**。但如果 `max` 的定义在 `max.cpp` 里，`main.cpp` 编译时看不到定义→生成不了 `max<int>` 的代码→链接器找不到 `max<int>` 的符号→`undefined reference`。

**修复**：把模板的全部定义（不只是声明）放在头文件中——每个编译单元都能看到模板定义，编译器看到调用点就立即生成代码。

**和 C 的类比**：这和 C 的 `static inline` 函数必须放头文件的原理一样——每个编译单元生成自己的副本，链接器去重或合并。模板则是每个编译单元生成相同代码，链接器选取一份。

## 7. 可运行实验：分离编译的链接错误

```cpp
// max.h —— 只有声明
template <typename T>
T max(T a, T b);

// max.cpp —— 实现在这里
#include "max.h"
template <typename T>
T max(T a, T b) { return a > b ? a : b; }

// main.cpp —— 使用
#include "max.h"
int main() {
    int x = max(3, 5);             // ✗ undefined reference to `int max<int>(int, int)`
    auto y = max(3.14, 2.71);      // ✗ undefined reference to `double max<double>(double, double)`
    return 0;
}
```

**编译运行**：
```bash
g++ -std=c++11 max.cpp main.cpp -o max_test
# 输出：undefined reference to `int max<int>(int, int)`
# 输出：undefined reference to `double max<double>(double, double)`
```

**修复**——把 `max.cpp` 的所有代码移到 `max.h` 里：
```bash
g++ -std=c++11 main.cpp -o max_test   # 成功！
```

## 8. 面试题

### 面试题 1：模板的编译模型

**面试官**：模板函数和普通函数在编译时有什么区别？为什么模板代码必须放头文件？

**回答**：普通函数——编译器直接生成机器码。模板——编译器不生成任何代码直到你用到它。`max<int>` 被调用时，编译器根据头文件里的模板定义在调用点生成 `int max(int, int)`。如果定义在 `.cpp` 里→调用点看不到定义→生成不了代码→链接错误。所以模板定义必须放头文件——每个编译单元都能看到。

**追问（面试官）**：模板会增大二进制体积吗？每个类型都生成一份会不会代码膨胀？

**追问回答**：会——`max<int>`、`max<double>`、`max<string>` 各生成一份独立代码。但这是"按需生成"——你只为你用到的类型付出代价。C 的 `void*`（无类型安全 + 函数指针开销）和 Java 泛型（类型擦除 + 装箱开销）各有代价——C++ 模板用二进制体积换运行时零开销，和手写三份独立函数一样快。如果代码膨胀是实际问题，C++11 提供了 `extern template`——在头文件中声明 `extern template class vector<int>;` 告诉编译器"这个实例化已在别的编译单元生成，别在此 TU 重复"。

### 面试题 2：类模板与类型独立性

**面试官**：`Stack<int, 10>` 和 `Stack<int, 100>` 是同一个类型吗？为什么？

**回答**：不是——不同模板参数生成不同的类。`Stack<int, 10>` 和 `Stack<int, 100>` 是完全不同的类型——它们的 `push`/`pop` 是不同的函数，`sizeof` 差 90 个 int。不能把一个赋给另一个——就像 `int` 不能赋给 `double`。模板实例化是**编译时类型生成**——每个参数组合产生一个全新的类型。

**追问（面试官）**：那如果两个编译单元各自实例化了 `Stack<int, 10>`——它们的类型是同一个吗？

**追问回答**：是同一个类型——链接器会把不同编译单元生成的相同实例化合并（去重），最终二进制里只有一份 `Stack<int, 10>` 的代码。模板的"代码膨胀"只会膨胀**你实际用到的不同参数组合的数量**——不会因为多个编译单元各自用到同一个组合而翻倍。

### 面试题 3：模板特化

**面试官**：模板特化是什么？`std::vector<bool>` 是哪种特化？

**回答**：对特定类型提供不同的模板实现。`vector<bool>` 是全特化——唯一模板参数 T 固定为 bool。每个 bool 占 1 bit（不是 1 byte）——这是"用语义牺牲换空间优化"的著名设计争议（`&v[0]` 不返回 `bool*`）。

**追问（面试官）**：全特化和偏特化的区别？什么时候用偏特化？

**追问回答**：全特化——所有模板参数都固定（`template <> class Foo<int>`）。偏特化——只固定部分参数（`template <typename U> class Pair<U, int>`——第二个参数固定为 int，第一个保持泛型）。偏特化用于"对某一维度的参数做约束"——比如"只要第二个参数是 int，不管第一个是什么类型，走这个版本"。Ch04 详讲。

## 9. 本章小结

| 概念 | 核心理解 |
|---|---|
| 函数模板 | 蓝图→编译器按类型生成具体函数——零开销 |
| 类模板 | `Stack<T, N>`——类型 + 大小的泛型容器 |
| 模板参数推导 | 编译器从调用参数自动猜 T——猜不了就显式写 `<int>` |
| 模板特化 | 通用版覆盖 90%——特化版覆盖剩下的 10% |
| 偏特化 | 只固定部分参数——`Pair<T, int>`——对一维约束 |
| 模板模板参数 | 模板本身作为参数——`template <typename> class Container` |
| 依赖名 + `typename` | 模板体内未知类型前必须加 `typename` |
| 成员模板 | 类的一个成员函数独立模板化——`Wrapper<U>` → `Wrapper<T>` |
| 头文件陷阱 | 模板定义在 `.cpp` → 链接错误——必须放 `.h` |
| 编译模型 | 调用时才生成代码——"按需生成"而非"全量生成" |
