# C++ 技术专家学习路线

> **定位**：本文是 C++ 技术专家视角的完整学习路线。前提——读者已完成 C 语言 20 章学习（Stage1-4），具备扎实的 C 基础（内存模型/编译链接/pthread/系统编程）。
> **主线标准**：**C++11** 为主。C++14/17/20 特性仅在涉及处标注版本号，不展开为独立章节或完整小节。理由：C++11 是工业界最稳定的基准版本（所有主流编译器完整支持，Linux 内核直到 2022 年才升级到 C11），绝大多数生产 C++ 项目仍以 C++11 为目标。
> **参考书来源**：`02-C-C++编程/` 下的 C++ 相关书籍：
> - 《C++程序设计语言 第4版》（Stroustrup，上下册）— C++ 之父权威参考
> - 《深入理解C++11》— C++11 新特性详解
> - 《深度探索C++对象模型》（Lippman）— 虚表/多重继承底层
> - 《精通现代C++ 11/14/17/20》— 现代特性全覆盖
> - 《C++性能优化指南》— 性能专题
> - 《C++代码调试的艺术 第2版》— 调试专题
> - 《C++编程之禅——从理论到实践》— 工程实践

## 0. 设计哲学：C++ 不是"C with Classes"

### 0.1 C++ 在技术栈中的位置

C++ 占据"系统语言 + 应用框架"的中间地带——它保留 C 的底层控制能力（零开销抽象），同时提供现代语言的抽象工具（RAII/泛型/异常）：

| 领域 | C++ 的角色 |
|---|---|
| 操作系统内核 | 极少（Linux 拒绝 C++），Windows 部分 C++ |
| 数据库引擎 | **主力**：MySQL/ClickHouse/LevelDB/RocksDB/MongoDB |
| 中间件 | gRPC/Envoy/Brpc/Boost |
| 语言运行时 | V8/JavaScriptCore/HotSpot JIT/Chakra |
| 浏览器 | Chromium/Firefox/WebKit 核心引擎 |
| 游戏引擎 | Unreal Engine/Unity（C++ 底层）/Cocos |
| 量化交易 | 几乎所有低延迟交易系统 |
| AI 推理 | TensorFlow/PyTorch 底层算子/TVM/ONNX Runtime |
| 桌面应用 | Qt/wxWidgets/Electron 的 native 模块 |
| 嵌入式 | Arduino（C++）/ESP32/ROS（机器人） |

**一个完成 C 学习的工程师进入 C++ 不是"再学一门语言"，而是获得三类新能力**：
1. **抽象能力**——不用手写 vtable、不用 `void*` + 函数指针，有真正的多态和范型
2. **资源安全**——RAII 消除"忘记 free/忘记 close/忘记 unlock"
3. **表达能力**——STL 提供标准容器和算法，模板提供零开销泛型

### 0.2 从 C 到 C++ 的学习路径差异

| 维度 | C 的学习路径 | C++ 的学习路径 |
|---|---|---|
| 核心概念 | 内存模型 → 编译链接 → 系统调用 | **类型系统与抽象** → 模板-STL → 对象模型 |
| 资源管理 | 手动 malloc/free → 所有权约定 | **RAII + 智能指针**——编译时保证 |
| 多态 | 手写 vtable（函数指针 + void*） | **虚函数 + 模板**——编译器和标准库提供 |
| 泛型 | `void*`+宏+`_Generic`（编译时分发） | **模板**——编译时类型安全，零开销 |
| 并发 | pthread + C11 `<stdatomic.h>` | **std::thread/std::async + std::atomic<T>** |
| 安全 | 编译器选项防御（-fstack-protector 等） | **语言级安全**（RAII 防泄漏、智能指针防 UAF） |
| 学习重心 | 理解"为什么 C 没有 X" | 理解"C++ 给的 X 是怎么实现的" |

**核心原则**：C++ 的学习不是"C + 类"——是从 C 的"信任程序员"迁移到 C++ 的"编译时保证"。学 C++ 的核心不是"会用 STL"，而是"理解 STL 为什么零开销、为什么 shared_ptr 有 16 字节开销、为什么虚表会引入一次间接寻址"。

## 1. 学习路线总览：5 个 Stage，20 章

```
Stage1（类型系统与资源管理）      4 章  →  C++ 基础抽象：类/移动/RAII/智能指针
    ↓
Stage2（模板与泛型编程）          4 章  →  模板/STL 容器/STL 算法/concepts
    ↓
Stage3（对象模型与运行时）        4 章  →  虚函数/继承/异常安全/内存模型
    ↓
Stage4（现代 C++ 核心特性）       4 章  →  C++14/17/20 新特性/设计模式/性能
    ↓
Stage5（系统编程与工程化）        4 章  →  C++ 并发/FFI/CMake 进阶/毕业项目
```

### 1.1 与 C 学习路线的对比

| | C 5 Stage | C++ 5 Stage |
|---|---|---|
| 起点 | 零基础 | **已完成 C 20 章** |
| Stage1 | 核心语法（编译/内存/类型/安全） | **类型系统与资源管理**（类/移动/RAII） |
| Stage2 | 高级特性（预处理/符号/ELF/ABI） | **模板与泛型**（模板/STL/concepts） |
| Stage3 | 并发（pthread/原子/内存模型） | **对象模型**（虚函数/继承/异常） |
| Stage4 | 系统编程（syscall/IPC/epoll/Socket） | **现代特性**（C++14/17/20/设计模式） |
| Stage5 | 工程实践（OOP/错误处理/FFI）→ 毕业项目 | **系统编程+工程化**（并发/FFI/CMake/项目） |

### 1.2 每章标准（继承 C 的 4 维度审计）

与 C 章节相同的质量标准，每章 ≥ 28/40（每维 ≥ 7/10）：

| 维度 | 标准 |
|---|---|
| **技术专家深度** | 解释"为什么这样设计"、有编译器/运行时实现、有"如果让我设计 C++ 这个特性"推演 |
| **面试覆盖** | 2-3 个标准面试题 + 答案 + 面试官追问到第二层 |
| **生产陷阱** | "这个写法的生产后果" + 可运行的错误实验 |
| **章节间依赖** | 前置章节引用 + 通向后续主题 + 本章对 Stage 目标的贡献 |

## 2. Stage1：类型系统与 RAII（4 章）

**目标**：从 C 程序员视角理解 C++ 的核心抽象——类不是"带方法的 struct"，而是资源管理的单位。RAII 是 C++ 最重要的设计模式。

| 章节 | 核心内容 | 参考书 |
|---|---|---|
| **01-从C到C++：心智模型迁移** | 命名空间/引用/new-delete/函数重载/default delete/inline→constexpr/nullptr/auto/range-for | C++程序设计语言 §2-6, 深入理解C++11 |
| **02-类：构造/析构/拷贝控制** | 默认/拷贝/移动构造函数、析构函数、=default/=delete、Rule of Five、初始化列表、委托构造 | C++程序设计语言 §16-18 |
| **03-移动语义与右值引用** | 左值/右值/纯右值、std::move、移动构造/赋值、完美转发、RVO/NRVO、noexcept 与移动 | 深入理解C++11 §3-4, C++程序设计语言 §19 |
| **04-RAII 与智能指针** | RAII 原则、unique_ptr/shared_ptr/weak_ptr、make_unique/make_shared、循环引用、自定义 deleter、与 C malloc 的互操作 | C++程序设计语言 §19, 深入理解C++11 §5 |

---

## 3. Stage2：模板与泛型编程（4 章）

**目标**：C++ 模板不是"宏的升级版"——是编译时类型安全、零开销的泛型系统。STL 是模板思想的标准实现。

| 章节 | 核心内容 | 参考书 |
|---|---|---|
| **01-模板基础** | 函数模板/类模板/模板实参推导/非类型模板参数/模板特化与偏特化 | C++程序设计语言 §22-23 |
| **02-STL 容器与迭代器** | vector/map/unordered_map/set/迭代器体系/allocator/容器选择指南 | C++程序设计语言 §31-33 |
| **03-STL 算法与函数对象** | sort/find/transform/copy_if/lambda/function/bind/range-for 与算法 | C++程序设计语言 §32-34 |
| **04-变参模板与 SFINAE** | variadic templates（可变参数模板）、SFINAE（替换失败不是错误）、enable_if、模板元编程入门、tag dispatch | C++程序设计语言 §28, 深入理解C++11 §7-8 |

> **注**：C++20 Concepts 简化了 SFINAE，但绝大多数生产项目仍以 C++11 的 SFINAE/enable_if 为主。Concepts 在本章仅作为"C++20 发展趋势"一句话提及。

---

## 4. Stage3：对象模型与运行时（4 章）

**目标**：C++ 最核心的运行时机制——对象在内存中的真实布局、虚函数调用的间接寻址、异常的开销。这是面试中 C++ 与 C 区分度最大的领域。

| 章节 | 核心内容 | 参考书 |
|---|---|---|
| **01-继承与多态** | public/private/protected 继承、虚函数/vtable/虚指针布局、override/final、RTTI/dynamic_cast | 深度探索C++对象模型 §1-4, C++程序设计语言 §20-21 |
| **02-多重继承与虚继承** | 多继承对象布局、菱形继承、虚基类、sizeof 与 vptr | 深度探索C++对象模型 §3-4 |
| **03-异常安全** | try-catch/throw、栈展开、noexcept、RAII 与异常安全保证（basic/strong/nothrow）、析构函数不应抛异常 | C++程序设计语言 §13, 精通现代C++ §9 |
| **04-C++ 内存模型** | std::atomic<T>、与 C11 atomic 对照、happens-before、memory_order、与 Java volatile 的区别 | C++程序设计语言 §41, C++性能优化指南 |

## 5. Stage4：C++11 进阶特性与工程实践（4 章）

**目标**：C++11 中 Stage1-3 未覆盖的进阶主题——Lambda 闭包、类型萃取、标准库深度、编码惯用法。本章不是"新特性列表"，而是"C++11 这些工具帮你解决什么 C 里解决不了的问题"。

| 章节 | 核心内容 | 参考书 |
|---|---|---|
| **01-Lambda 与函数对象** | Lambda 表达式、闭包与捕获列表、std::function、std::bind、与函数指针的对比、Lambda 在 STL 算法中的使用 | 深入理解C++11 §6, C++程序设计语言 §11 |
| **02-类型萃取与模板元编程进阶** | type_traits（is_pointer/is_same/remove_reference）、decltype、auto 返回类型推导、编译时条件选择（enable_if 进阶）、constexpr 函数 | 深入理解C++11 §7-8, C++程序设计语言 §28 |
| **03-C++11 标准库深度** | chrono（时间库）、regex（正则）、tuple/pair、random（随机数）、array、forward_list、<type_traits> 实战 | 深入理解C++11 §10-11, 精通现代C++ §2-3 |
| **04-性能与内存优化** | 移动语义的性能收益、SSO（短字符串优化）、emplace 系列、定制 allocator、noexcept 与编译器优化、`-O2` vs `-O3` 对 C++ 的影响、perf 分析 C++ 代码 | C++性能优化指南 |

> **注**：C++14/17/20 的增强（`auto` 返回类型推导→C++14、结构化绑定→C++17、`std::optional/variant`→C++17、concepts→C++20）在对应主题处标注版本号，不展开为独立小节。主线永远是 C++11。

**目标**：把 C++ 用到生产中——并发、与 C 代码交互、现代构建系统、用 5 个 Stage 全部知识完成一个生产级毕业项目。

## 8. 与 C 学习路线的最终整合

```
    C 语言 20 章（已完成）
         ↓
Stage5 毕业项目（KV/HTTP）   ← C 的句号
         ↓
    C++ 20 章（待开始）      ← 继承 C 基础，从 C 的心智模型迁移到 C++
         ↓
C++ 毕业项目                ← 双向对比：同一个 HTTP 服务器，C 版 vs C++ 版
```

**两个毕业项目的关系**：C 的毕业项目是你"用 C 从零搭建一切"的能力证明。C++ 的毕业项目是同一个需求用 C++ 重写——对比体现代差——C 里你手写的 vtable/引用计数/手动错误返回码，在 C++ 里变成了虚函数/shared_ptr/异常。
