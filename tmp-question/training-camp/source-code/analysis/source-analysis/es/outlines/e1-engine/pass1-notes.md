## 标记问题 (≥5)

1. **Q1: IndexingStrategy 为什么是"计划-执行"两阶段?** — 计划时确定版本/seqNo/分支, 执行时无决策 — 主分片和副本共用? (execute 前生成 seqNo 的时序)
2. **Q2: append-only 优化 (canOptimizeAddDocument) 的正确性** — autoGeneratedIdTimestamp 怎么防重试重复索引? (注释 L1143-1173: maxUnsafeAutoIdTimestamp 语义)
3. **Q3: LiveVersionMap 双 map 切换怎么保证并发正确?** — refresh 前旧 map 保留, 读 current+old; afterRefresh 后 old 清空 — 无锁读怎么安全?
4. **Q4: NRT 可见性 (refresh) 与实时读 (realtime get) 的区别** — realtime get 走 LiveVersionMap 不查 Lucene; 面试必问"ES 写入后立即能查到吗?"
5. **Q5: flush vs refresh vs commit 三者的关系** — refresh 开新 reader (内存段可见), flush = refresh + IndexWriter.commit + translog 轮转 (E-3 衔接)
6. **Q6: 文档失败与 tragic 的边界** — indexIntoLucene catch (InternalEngine.java:1404-1430): 主分片文档失败返回 IndexResult(FAILURE), 副本失败视为 tragic — 为什么主副不同?
7. **Q7: 并发控制 (读锁/写锁/uid 锁)** — index 持 readLock + versionMap.acquireLock(uid) (InternalEngine.java:1139) — 与 E-3 translog 锁层次对照
8. **Q8: 与 Redis 持久化对照** — Redis RDB (快照) vs Lucene commit (段快照); AOF vs translog — 双写一致性怎么保证?
