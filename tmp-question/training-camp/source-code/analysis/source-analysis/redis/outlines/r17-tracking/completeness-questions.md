# R-17 客户端缓存 — completeness-questions (全视角提问验证)

## 开发者视角

1. CLIENT TRACKING on 之后, 哪些命令的键会被记住? (只读命令, call() 尾打点)
2. 客户端断连后表里的 ID 怎么清理? (惰性 — 发送时跳过, 不主动清)
3. NOLOOP 模式怎么判定"自己改的键"? (target == server.current_client)
4. CLIENT CACHING 标志什么时候清? (每条命令后, MULTI 内保活)
5. 失效消息为什么可能延迟到响应之后? (pending 队列 + execution_nesting 门控)
6. FLUSHALL 后客户端收到什么? (RESP NULL — 全失效)
7. 表超限时驱逐策略? (随机采样 + effort 100→200→300 递增)
8. BCAST 前缀冲突会怎样? (报错拒绝, 不静默)

## 架构师视角

9. 为什么用双层 rax 不用 dict? (前缀压缩 + 二进制 key 免分配)
10. 为什么失效即删表项? (懒重建 vs 就地更新权衡)
11. BCAST 的"零内存"代价是什么? (未缓存键也收失效; 每前缀一条聚合消息)
12. 为什么消息必须严格在响应后? (RESP 解析器共享输出缓冲)
13. 重定向设计解决什么问题? (RESP2 无 push; 业务连接与失效通道解耦)
14. 限额驱逐与 maxmemory 淘汰的关系? (完全独立; 前者伪失效, 后者真实键)
15. 为什么 CONFIG SET 后 cron 也要查? (idle 场景生效, 双调用点)
16. execution_nesting 门控的必要性? (EXEC 批量响应穿插)

## 学生视角

17. 客户端缓存和服务器缓存 (R-23) 的区别? (值在客户端 vs 值在服务器)
18. RESP2 客户端完全收不到失效消息吗? (无重定向 → 静默丢弃)
19. 为什么叫"服务端协助"的客户端缓存? (服务器只发失效信号, 不存值)
20. BCAST 和普通模式什么时候选哪个? (键空间模式固定 → BCAST; 键集小 → 精确)
