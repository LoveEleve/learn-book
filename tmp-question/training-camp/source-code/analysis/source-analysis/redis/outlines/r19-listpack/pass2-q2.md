# 闭环笔记 q2: 编码族 — 9 种编码的空间-访问权衡

## 假设
整数 6 档 (7/13/16/24/32/64 bit) + 字符串 3 档 (6/12/32 bit) — 用编码字节的前缀位模式区分; 小值用紧凑编码省空间。

## 验证过程
- 编码表 (listpack.c:30-82):
  - 7BIT_INT: 0x00xxxxxx (最高位 0) — 1B 编码字节+1B 值 = 2B entry, 范围 0-127
  - 6BIT_STR: 0x80 (10) — 1B 编码含 6bit 长度, 短串 ≤63B 只需 1B 头
  - 13BIT_INT: 0xC0 (110) — 2B 值 (13bit)
  - 12BIT_STR: 0xE0 (1110) — 2B 长度前缀
  - 16/24/32/64BIT_INT: 0xF1-F4 (1111 0001...) — 全字节标识
  - 32BIT_STR: 0xF0 — 5B 长度前缀
  - EOF: 0xFF — 与 32BIT_INT 的 F4 之间预留 (F5-FF 未用)
- **前缀位模式分层** (无歧义解码): 0 → 7BIT_INT; 10 → 6BIT_STR; 110 → 13BIT_INT; 1110 → 12BIT_STR; 1111 0000-0100 → 32BIT_STR/16/24/32/64BIT_INT
- 空间收益: 整数 0-127 只要 2B (vs 字符串 "123" 4B+backlen); 短串 ≤63B 头只要 1B
- 整数选择 (lpEncodeInteger L515+): 按值域选 7/13/16/24/32/64
- lpCurrentEncodedSizeBytes (L434-446): 解码侧按前缀判定大小

## 代码类型
Algorithmic (前缀编码) — 编码设计

## 跨域关联
- R-4 (sds 内容) → 字符串数据的来源
- q3 (整数嗅探) → 字符串→整数编码的判定
- 对照: R-1 (EMBSTR 44B 阈值) → 字符串编码的另一次空间优化

## 结论
9 种编码用前缀位模式分层 (0/10/110/1110/1111...): 短整数 2B、短字符串 1B 头 — 小值场景空间最优; 解码靠首字节前缀无歧义分派。EOF=0xFF 独立于编码空间。
