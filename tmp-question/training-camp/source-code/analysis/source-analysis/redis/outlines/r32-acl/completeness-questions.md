# R-32 ACL — completeness-questions (全视角提问验证)

## 开发者视角

1. 命令权限存在哪? (1024 位位图, cmd->id 索引)
2. 怎么精确允许 CONFIG GET 但禁止 CONFIG SET? (子命令白名单 +config|get)
3. %R~ 和 ~ 的区别? (读写分离 vs 默认读写)
4. 多 selector 什么语义? (任一通过即允许 — OR)
5. 改权限对已连接客户端生效吗? (实时验证 + pubsub 收窄断开)
6. 密码怎么加? (>pass 明文 / #hash 哈希 / nopass)
7. ACL LOG 怎么看? (ACL LOG / RESET; 聚合条目)
8. dryrun 干什么? (预演权限不执行)

## 架构师视角

9. 为什么 1024 位位图而不是 dict? (O(1) 判定 + 128B/selector)
10. 规则左到右顺序语义的设计收益? (标准"全拒后放开"模式)
11. 多 selector 为什么 7.0 才加? (读写分离需求演进 — 旧语法无法表达"只读所有键+写特定键")

13. pubsub 收窄断开的必要性? (权限即契约, 降权必须同步)
14. aclfile 与 RDB/AOF 分离的意义? (安全配置独立管理/迁移)
15. 密码时序比较的实现? (全长度比较防分支预测)
16. ACL LOG 聚合 vs 逐条? (审计完整性 vs 刷屏防护)
