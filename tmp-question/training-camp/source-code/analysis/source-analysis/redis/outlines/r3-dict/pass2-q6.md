# 闭环笔记 q6: dictScan 反向游标 — rehash 期间遍历不丢 (重复/中途新增可漏)

## 假设
dictScan 用"反向二进制游标" (rev+1+rev) 遍历: 游标按位反转递增, 保证 rehash (扩/缩) 期间迭代开始前存在的键不丢 (不丢 (重复/中途新增可漏)), 返回新游标供续扫。

## 验证过程
- dictScan (dict.c:1369-1375) → dictScanDefrag (L1377+):
  - 非 rehash (L1401-1421): `de = ht_table[0][v & m0]` 遍历桶 → `v |= ~m0; v = rev(v); v++; v = rev(v)` — **反转递增**: 把低 m 位反转后 +1 再反转 = 二进制计数顺序遍历"块"
  - rehash 中 (L1422-1470): 小表遍历桶 + **大表中该桶的展开区 (do-while 循环 v & (m0^m1))** — 小表桶对应大表多个桶 (扩容时 1→2/4/8...), 全部访问
- 算法核心: rev+1+rev 使游标遍历顺序 = 从最高位递增 — 表扩缩时, 已访问/未访问区域保持边界一致 (经典 dictScan 论文算法, 2013 由 antirez 引入)
- 契约: 每次调用返回新游标; 调用方 (如 KEYS/SCAN/HSCAN) 保存游标循环调用直到游标归 0
- 不丢 (重复/中途新增可漏)的保证: 表大小 2 的幂 + 反转游标递增 — 扩表时旧桶的键落在"后续游标"区域 (不会重复); 缩表时同理

## 代码类型
Algorithmic (位运算遍历算法) — 教科书级技巧

## 跨域关联
- R-21 (db 键空间 SCAN/KEYS) → 主消费方
- R-27 (SSCAN) / R-25 (HSCAN) → 通用游标契约
- R-18 (defrag dictDefragBucket) → 遍历中 defrag

## 结论
dictScan 反向游标 = rev(v)+1+rev(v): 位反转递增使遍历顺序与表扩展同构 — rehash 期间 (双表) 小表桶 + 大表展开区全访问, 保证 SCAN 类命令在迁移中不丢 (重复/中途新增可漏)。这是 Redis 增量遍历安全的算法基石。
