# RM-7 Producer 发送 — completeness-questions (全视角提问验证)

## 开发者视角

1. send 三模式怎么选? (SYNC 等待/ASYNC 回调/ONEWAY 免响应)
2. 重试几次? (SYNC 1+2; 异步/单向不重试)
3. 什么错值得重试? (retryResponseCodes 白名单)
4. 慢 broker 冷却多久? (7 档映射 0-30s; 隔离固定 10s)
5. 队列怎么轮询? (ThreadLocalIndex 递增取模)
6. 重试时怎么换队列? (resetIndex + lastBroker 排除)
7. 批量累积怎么触发? (延迟/字节双条件)
8. 异步回调在哪执行? (回调线程池)

## 架构师视角

9. 异常三分类的设计? (客户端/网络/broker 不同故障语义)
10. 延迟→冷却分段的取舍? (自适应避开 vs 过度惩罚)
11. 双维度 (延迟+可达) 的意义? (5.x 探测恢复)
12. 三级选择降级? (可用→可达→兜底)
13. 为什么异步不重试? (调用方控制 — 语义清晰)
14. 超时预算逐次扣减? (端到端超时语义)
15. 轮询 vs 随机 vs hash? (均衡/顺序/机房间)
16. 批量累积的代价? (延迟 30s 上限内吞吐换时延)

## 学生视角

17. send() 背后几步? (路由→选择→kernel→重试)
18. 故障冷却是什么? (慢 broker 一段时间不选)
19. SEND_OK 保证什么? (存储确认, 非消费确认)
20. 为什么异步发送要自己处理重试? (返回即所有权转移)
