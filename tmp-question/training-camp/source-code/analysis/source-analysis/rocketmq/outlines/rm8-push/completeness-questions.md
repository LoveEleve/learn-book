# RM-8 消费-Push — completeness-questions (全视角提问验证)

## 开发者视角

1. 拉取请求怎么排队? (PullMessageService 阻塞队列)
2. 延迟分级? (异常 3s/缓存流控 50ms/broker 流控 20ms/挂起 1s)
3. 长轮询参数? (broker 挂 15s/客户端等 30s)
4. 缓存怎么流控? (span 2000/条数 1000/字节 100MiB)
5. 消费线程池多大? (20 固定)
6. 批量消费默认? (1)
7. 消费失败去哪? (sendMessageBack 延迟重试)
8. 有序消费怎么保证? (MessageQueueLock 队列锁)

## 架构师视角

9. "Push" 为什么是伪推送? (长轮询 pull + broker 挂起)
10. 拉取-消费解耦的缓冲设计? (TreeMap + 流控)
11. 并发 vs 有序的取舍? (吞吐 vs 顺序保证)
12. 进度双实现 (集群/广播) 的理由? (共享 vs 独立)
13. 为什么集群进度在 broker? (重平衡后续读)
14. 流控三阈值的面? (跨度/条数/字节)
15. POP vs 传统拉取? (ack 语义 vs offset)
16. at-least-once 的代价? (消费幂等归业务)

## 学生视角

17. Push 消费者怎么"自动"收消息? (后台拉取线程 + 长轮询)
18. ProcessQueue 是什么? (拉取与消费之间的缓存)
19. 消费失败会怎样? (延迟重试, 最多 N 次后死信)
20. 集群和广播消费什么区别? (进度共享 vs 独立)
