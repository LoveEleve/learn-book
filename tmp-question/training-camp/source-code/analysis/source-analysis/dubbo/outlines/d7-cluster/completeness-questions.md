# D-7 集群容错 — completeness-questions (全视角提问验证)

## 开发者视角

1. 默认策略? (@SPI failover)
2. join 时发生什么? (三层包装)
3. 重试几次? (RETRIES+1, 附件可覆盖)
4. 什么异常不重试? (isBiz 业务异常)
5. 粘滞? (sticky 同节点连续)
6. 路由在哪执行? (directory.list)
7. Mock 降级? (wrapper 织入)
8. ZoneAware? (preferred 最高优先)

## 架构师视角

9. 为什么 join 三层包装? (策略与横切面分离)
10. 为什么重试前刷新目录? (地址变化生效)
11. 为什么业务异常不重试? (无意义+副作用)
12. 为什么 selected > available? (重试不撞车)
13. 为什么粘滞? (缓存/JIT 友好)
14. 为什么策略 = 失败语义? (幂等读重试/非幂等写 fastfail)
15. 为什么 Forking 先到先得? (延迟收益 vs 流量放大)
16. 为什么路由两段式? (预路由缓存 + 实际路由)
17. 为什么 Mock 用 Wrapper? (不侵入策略)

## 学生视角

18. 什么是集群容错? (失败时怎么办)
19. 什么是重试? (换节点再试)
20. 什么是路由? (按规则筛节点)
21. 什么是降级? (兜底响应)
