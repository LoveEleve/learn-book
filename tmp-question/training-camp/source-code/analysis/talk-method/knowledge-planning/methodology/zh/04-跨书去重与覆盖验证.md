# 跨书去重与覆盖验证

> 角色：AI 自约束操作规范。聚类之后、写作之前必读。
> 先修：`01-如何从TOC提取知识点.md` + `02-知识点深度标准.md` + `03-主题聚类与前置依赖.md`
> 输入：主题聚合（来自 01）+ 深度分类（来自 02）+ 教学顺序（来自 03）
> 阅读顺序：01 → 02 → 03 → 04（本文）。

## 核心原则

**多本书覆盖同一知识点提供互补的视角，不是重复内容。** 合并不是消除冗余——是从所有可用来源中组装最丰富的理解。

---

## 1. 覆盖映射

对主题中每个知识点，映射哪些书覆盖了它以及从什么角度：

```
## 覆盖映射：CFS 调度器

| 书 | 覆盖度 | 角度 | 深度 |
|----|--------|------|------|
| 书 A §3.1-3.3 | 充足 | 算法原理 | 工作层 |
| 书 B §4.2-4.5 | 充足 | 内核实现 | 深层 |
| 书 C §2.4 | 不足（仅 1 页） | 仅性能调优 | 表层 |

合并深度目标：深层（来自 02 分类——这是 🔴 知识点）
主要来源：书 B（最完整的内核实现角度）
补充来源：书 A（算法清晰度）、书 C（调优角度——边缘）
```

### 覆盖等级

| 等级 | 判定标准 | 合并操作 |
|------|---------|----------|
| **充足** | 书为该知识点提供了工作层或更好的内容 | 用作主要或补充来源 |
| **不足** | 书提到该主题但覆盖为表层或牵强 | 仅在增加主要来源没有的独特角度时使用 |
| **缺失** | 书完全不覆盖此知识点 | 不对这个知识点引用此书 |

### 单书主题（N=1）

如果一个主题只有一本书贡献内容：
- 主要来源默认为该书
- 不需要跨书去重——不可能有冲突
- 覆盖缺口更可能出现——做缺口分析（§4）时格外警惕
- 标注主题级状态：`[N=1 — 共识信号不可用]`

## 2. 多源合并

### 主要来源选择

对每个知识点，选择一个主要来源：

```
主要来源 = 同时满足以下条件的书：
1. 以所需深度（02 标准）覆盖此知识点
2. 提供最完整的结构覆盖（数据结构、调用流程、架构）
3. 如果多本书同时满足以上两点 → 选教学叙事最好的那本

其他书是补充来源。
```

### 主要来源平局判定

当 ≥2 本书的覆盖等级和角度完全相同时：

```
用 01 §3 共识信号：在同一知识点家族中出现在更多章节的书为主要来源。
如果仍平局 → 选例子更好或结构更清晰的那本。
```

### 合并规则

```
1. 基础内容来自主要来源——遵循其结构和叙事流
2. 用其他书的独特角度补充：
   - 书 B 加了书 A 缺少的实现细节 → 加入
   - 书 C 加了性能调优视角 → 作为子节加入
   - 不重复主要来源已有的内容
3. 不强合并矛盾信息——标记为冲突（§3）
4. 不自创"衔接"内容来连接不同书的视角
   ——如果真的不一致，呈现双方观点并标注来源
```

### 合并产出

```
## 内容计划：CFS 调度器

主要来源：书 B §4.2-4.5（内核实现角度）
深度目标：深层（🔴）

内容大纲：
1. CFS 设计原则（书 A §3.1——算法清晰）
2. 内核实现（书 B §4.2-4.5——主要来源）
   - sched_entity、cfs_rq 结构
   - pick_next_task_fair() 调用路径
   - vruntime 跟踪与更新
3. 性能影响（书 C §2.4——补充来源）
   - 调度延迟与调优
   - /proc/sched_debug 解读

跨书补充：
- 书 A：vruntime 公平性概念（更好的教学解释）
- 书 C：调优角度（仅此处有）
```

## 3. 不一致处理

当两本书提供关于同一知识点的**矛盾**信息时：

### 检测

```
1. 对比结构声明（函数名、结构体字段名、调用链）
2. 对比机制描述（X 如何工作？）
3. 对比数字声明（默认值、阈值、超时值）
```

### 解决

| 场景 | 操作 |
|------|------|
| 一本书明显错误（过时版本、笔误） | 使用正确的那本。加注差异：`[注：书 A §3 说 X，但书 B §4 说 Y。按内核源码验证后 Y 正确。]` |
| 两者可能都对（不同版本、不同配置） | 带版本/配置上下文呈现双方。标注：`[版本注：书 A（5.0 之前）描述 X；书 B（5.0+）描述 Y。]` |
| 无法解决（无外部来源验证） | 呈现双方观点。标注：`[未解决：书 A §3 说 X；书 B §4 说 Y。需内核源码验证。]` |

### 冲突记录

```
## 跨书冲突：{知识点}

| 声明 | 书 A（§3） | 书 B（§4） | 解决 |
|------|----------|----------|------|
| 默认 weight | 1024 | 1024 / 1.25 | 都对（不同上下文——已解释） |
| nice→weight 映射 | 公式 X | 公式 Y | [未解决：书 A §3 说 X；书 B §4 说 Y。需内核源码验证。] |
```

## 4. 缺口分析与 AI 补充

**来自 01/02 的输入**：01 §5 和 02 中记录的缺口标记（`[缺口]`）必须合并进本节的缺口分析。覆盖映射中发现的新缺口追加。

### 缺口类型

| 缺口 | 检测 | 操作 |
|------|------|------|
| **浅覆盖** | 书覆盖为表层但需要深层（02 判定） | AI 补充到目标深度 |
| **角度缺口** | 书覆盖机制但缺结构/图 | AI 补充结构组件 |
| **完全缺口** | 无书覆盖此 🔴 知识点 | AI 基于外部知识写作——标注 `[缺口：{概念} — AI补充]` 并附理由 |

### AI 补充决策流程

```
知识点有覆盖缺口？
├── 是 🔴（面试/生产必备）？
│   ├── 是 → AI 必须补充到目标深度（02 标准）
│   └── 否 → 是 🟡（≥3 个其他知识点依赖）？
│              ├── 是 → AI 补充到工作层
│              └── 否 → 🟢：跳过此知识点（不编造）
```

### 补充质量规则

1. **来源标注**：每个补充声明必须引用 ≥2 个独立参考（内核源码、官方文档、权威在线参考）
2. **不可验证声明**：标注 `[待验证]`（与 01 §核心约束 #2 对齐）
3. **不补充 🟢 知识点**：零书覆盖的表层知识点跳过——不补充
4. **补充范围**：仅在知识点主题边界内补充——不添加无关材料

## 5. 冲突+缺口组合场景

当一个知识点同时存在跨书矛盾**和**覆盖缺口时：

```
例子：书 A 说"默认 weight 是 1024"，书 B 说"默认 weight 是 1024 / 1.25"。
两本书都只提供表层覆盖——🔴 目标需要深层内容。

解决：
1. 先解决冲突（按 §3）：确定哪个版本正确
2. 再从正确版本补充到深层
3. 无法解决 → 呈现双方观点并标记 [未解决：{声明 A} vs {声明 B} — 需验证]，
   从更可能正确的版本补充，附说明
```

## 6. 补充时的跨主题依赖检查

当 AI 补充的知识点的依赖项属于另一个主题（03 §3）：

```
IF 该依赖被 BLOCKED（前置主题未完成）：
  → 不为此知识点写内容
  → 标记为 [BLOCKED — 主题 X 尚未完成]
  → 跳到本主题中下一个未被阻塞的知识点
```

## 7. 来源标注格式

每个知识点的最终内容必须包含来源块：

```
---
来源：
  主要：{书名} §{章节}（{覆盖度：充足/不足}）
  补充：{书名} §{章节} — {独特贡献}
  AI 补充：[{概念级/结构级/全深层（02 标准）}] — 补充自 {参考1}、{参考2}
  冲突：[{描述 + 解决} — 或 "无"]
  缺口：[{缺口：{概念}} — AI补充 — 或 "无"]
  跨主题依赖：[{BLOCKED — 主题 X 尚未完成} — 或 "无"]
---
```

## 9. 完成检查单

主题内所有知识点合并完毕后：

- [ ] **覆盖已映射**：每个知识点有覆盖图，含每本书的覆盖等级和角度
- [ ] **主要来源已选定**：每个知识点有一个指定主要来源，附理由（平局判定已用）
- [ ] **单书主题已标注**：N=1 主题标注 `[N=1 — 共识信号不可用]`
- [ ] **补充已识别**：跨书补充已记录，附独特贡献说明
- [ ] **冲突已解决或已记录**：所有跨书差异已记录，附解决状态
- [ ] **缺口已处理**：🔴/🟡 缺口有 AI 补充计划；补充引用 ≥2 参考；🟢 缺口跳过
- [ ] **组合场景已处理**：冲突+缺口的知识点按 §5 解决
- [ ] **无自创衔接**：未为连接不同书视角而自创内容
- [ ] **来源已标注**：每个知识点有完整来源块，含全部字段
- [ ] **跨主题依赖已检查**：BLOCKED 依赖已标记并跳过
- [ ] **待用户审查**：合并计划在开始写内容前经用户确认
- [ ] **准备写作**：所有知识点有内容大纲

## 10. 反模式

### 1. 把多书覆盖当重复

```
错误："书 A、B、C 都覆盖 CFS → 选一本，其他扔掉"
正确：书 A、B、C 从不同角度覆盖 CFS → 合并独特角度。
      算法（A）+ 实现（B）+ 调优（C）= 完整图景。
```

### 2. 强合并矛盾

```
错误："书 A 说 X，书 B 说 Y → 写一个听起来对的折中"
正确：带来源呈现双方。如果一方可验证为正确，注明差异。
      无法解决时呈现双方并标记验证。
```

### 3. 补充不标来源

```
错误：添加深层结构内容但不标注引用来源
正确：每个补充声明必须引用 ≥2 个参考。不可验证的明确标注。
```

### 4. 补充 🟢 缺口

```
错误："无书覆盖这个 🟢 知识点 → AI 写一节"
正确：无任何书覆盖的 🟢 知识点跳过。仅补充 🔴 和 🟡 缺口。
```
