# 主题聚类与前置依赖

> 角色：AI 自约束操作规范。设计主题结构和教学顺序前必读。
> 先修：`01-如何从TOC提取知识点.md` + `02-知识点深度标准.md`
> 输入：所有书的所有知识点（来自 01）+ 深度分类（来自 02）
> 阅读顺序：01 → 02 → 03（本文）→ 04。

## 核心原则

**知识点不是孤立存在的。** 任何复杂概念 = 基础概念组合。如果概念 A 依赖理解概念 B，B 必须先讲——绝不写"后面会讲"或"前述"。与源码分析 02 完全同构。

## 1. 主题聚类

### 如何聚类

书籍提供原始素材。主题由**机制边界**形成——不是按书名。

```
错误："书A、B、C 书名都有 'Linux' → 一个主题"
正确：进程调度和内存管理是不同的机制 → 不同主题
```

一本书可能贡献知识点到多个主题。例如，《深入Linux内核架构》可能同时贡献进程调度、内存管理、文件系统。

### 聚类规则

1. **机制边界**：共享同一底层机制的知识点属于同一主题
2. **知识点数量**：一个主题应 ≥5 个知识点；<5 个考虑与相邻主题合并。*相邻* = 共享机制族（如都处理进程生命周期事件）或位于同一条依赖链上（A→B→C 表示 B 与 A 和 C 都相邻）。纯空间邻近（"在主题列表中位置接近"）不算相邻。
3. **依赖局部性**：候选主题中 ≥80% 的知识点之间有内部依赖（不跨越主题边界相互依赖）→ 主题边界正确。用下方的初步依赖扫描评估此规则——不是聚类后 §2 才构建的完整依赖图。初步扫描是粗粒度的（每个知识点 1-2 个最明显的依赖）；80% 阈值容忍这种粗糙度。
4. **不强制归属**：知识点不适合任何主题 → 创建跨主题引用或独立小主题

### 初步依赖扫描（聚类定稿前）

主题边界定稿前，做轻量依赖扫描：
- 对每个知识点，列出 1-2 个最明显的依赖
- 用这个粗粒度图评估 80% 局部性规则
- 完整依赖图（含所有依赖、机制级理由）在 §2 构建——这只是初步估算

### 收敛条件

满足以下**全部**条件时停止聚类：
1. 所有知识点已分配到主题
2. 每个主题有书面的范围描述和机制边界
3. 所有主题通过初步依赖扫描的 80% 局部性验证

如果 2 轮迭代后聚类仍不稳定，将不稳定知识点标记为 `[TODO: 聚类边界不清 — 需人工审查]` 后继续——§2 的完整依赖图会解决剩余的歧义。

### 聚类产出

```
## 主题提案

### 主题 1：{名称}
范围：{一段描述机制边界的话}
知识点：{列出，附 01 优先级和 02 重要性}
贡献书籍：{书A §X，书B §Y，...}

### 主题 2：{名称}
...
```

## 2. 主题内部排序

### 构建依赖图（强制，任何主题写作前完成）

对主题内每个知识点，列出它依赖的**所有**知识点：

```
知识点：CFS 调度器
  依赖：进程优先级（nice 值）—— CFS 使用 nice→weight→vruntime
        红黑树 —— CFS tasks_timeline 是 rb_root
        时钟中断 —— 调度器由时钟中断触发
        [BLOCKED — 主题 1 尚未完成]
  不依赖：实时调度（独立机制）
```

### 依赖定义

```
"A 依赖 B" = 不理解 B 的机制，就无法理解 A 的行为或设计原因。

依赖是机制层面（不是概念相关性）。
"CFS 和 RT 调度都涉及调度器"是相关性，不是依赖。
"CFS 使用 nice 值映射计算 weight"是机制依赖。
```

主题内**所有**知识点都完成此列表后，才能开始写作。任何知识点依赖列表不完整的 → 阻塞。

### 拓扑排序

构建完依赖图后，按拓扑排序——所有被依赖的知识点必须排在被依赖它的知识点之前。零依赖的知识点排在最前面。

### 环形依赖

**检测**：如果 A 依赖 B 且 B 依赖 A，拓扑排序失败。

**策略（三轮化解，与源码分析 02 §1.4 同构）**：

1. **双方只做表层讲解**——建立双方的基本概念，够命名接口边界
2. **联合做工作层/深层写作**——在同一轮中交叉参照写完双方内容
3. **各自独立收尾**——各自回归 02 判定的深度等级独立完成

**环形概念示例**：
- 进程调度 ↔ 上下文切换（调度决定 WHAT to switch，上下文切换是 HOW to switch）
- 缺页 ↔ 内存分配（缺页触发分配，分配改变缺页条件）
- VFS ↔ 文件系统实现（VFS 定义接口，实现遵循 VFS 契约）

### 排序产出

```
## 教学顺序：{主题名}

拓扑排序结果：
1. 进程优先级（叶子，零依赖）
2. 红黑树（叶子，零依赖）
3. 时钟中断（叶子，零依赖）
4. CFS 调度器（依赖 1, 2, 3）
5. 上下文切换（依赖 4）[与 #4 环形 — 三轮策略]
6. 多核调度（依赖 4, 5）
```

## 3. 跨主题前置依赖

> §2→§3 流程：跨主题依赖在 §2 的逐知识点依赖图构建过程中被发现——当某个依赖属于不同主题时。立即记录并传播到 §3 做正式的前置标记。不要把跨主题依赖检测推迟到 §3。

### 依赖定义（与 §2 相同）

跨主题依赖遵循与主题内部相同的定义（§2）：**依赖是机制层面，不是概念相关性。** 主题 B 依赖主题 A 当且仅当：主题 B 中某知识点需要理解主题 A 中某知识点的机制才能解释其行为或设计原因。纯粹的主题关联（"两者都是 Linux 内核相关"）不构成依赖。

### 主题间依赖

主题 B 中某知识点依赖主题 A 中某知识点 → 整个主题 B 只能在主题 A 完成后启动。

```
例子：
主题 3（内存管理）→ 依赖主题 1 的"虚拟内存"概念
→ 主题 3 BLOCKED 直到主题 1 完成

主题 6（eBPF）→ 依赖主题 1（内核原理）且主题 4（网络）
→ 主题 6 BLOCKED 直到主题 1 且主题 4 完成
```

### 依赖标记

对每个主题，列出：
- **前置主题**：必须在**本主题之前**完成
- **依赖概念**：具体需要其他主题哪些知识点
- **原因**：一句依赖链解释

```
主题 3：内存管理
前置主题：主题 1（进程）
依赖概念：虚拟内存（主题 1 §MMU）、页表（主题 1 §TLB）
原因：不理解虚拟内存概念无法理解分页/交换
```

### 跨主题依赖图

为整个课程体系构建主题级依赖图：

```
主题 1（进程核心）         ← 无前置（基础）
主题 2（内存）             ← 依赖主题 1
主题 3（文件系统）         ← 依赖主题 1, 2
主题 4（网络）             ← 依赖主题 1, 2
主题 5（调度/性能）        ← 依赖主题 1
主题 6（eBPF/可观测）      ← 依赖主题 1, 4
主题 7（数据结构）         ← 无前置（基础，横切关注）
主题 8（系统编程）         ← 依赖主题 1, 2, 4
```

## 4. 完成检查单

设计完所有知识点的主题和排序后：

### 逐主题

- [ ] **主题边界已定义**：机制边界清晰，无知识点被强制归错类
- [ ] **依赖图已构建**：每个知识点有完整依赖列表，依赖不完整则标记 [BLOCKED]
- [ ] **拓扑排序已验证**：没有依赖出现在被依赖之后
- [ ] **环形依赖已识别**：每对环形依赖记录三轮化解策略
- [ ] **跨主题依赖已标记**：任何依赖其他主题内容的知识点标记了前置主题名和依赖概念

### 课程级

- [ ] **主题依赖图已构建**：每个主题列了前置主题
- [ ] **基础主题先讲**：课程内零依赖的主题排在最前面
- [ ] **无环形主题依赖**：如主题 A 依赖 B 且 B 依赖 A，先尝试重新聚类（大多数跨主题环形依赖说明主题边界有误）。如果重新聚类失败（机制层面确实存在环形——如调度 ↔ 内存管理），在主题级应用三轮策略（§2 环形依赖）：先表层 → 联合深写 → 独立收尾。
- [ ] **教学顺序已建立**：完整的主题级顺序已记录
- [ ] **阻塞主题已识别**：前置主题尚未完成的多题已标记
- [ ] **待用户审查**：主题结构和教学顺序在开始写作前经用户确认

## 5. 反模式

### 1. 按书名聚类

```
错误："书A、B、C 都是 Linux 相关 → 一个 Linux 主题"
正确：书是原始素材。主题是机制边界。一本书可能贡献到 3 个不同主题。
```

### 2. 按重要程度排序而非按依赖排序

```
错误："CFS 是 🔴，进程优先级是 🟡 → 先讲 CFS"
正确：CFS 依赖进程优先级 → 先讲进程优先级，不管重要程度
      依赖顺序永远覆盖重要程度决定教学顺序
```

### 3. 跨主题引用 "后面会讲"

```
错误："CFS 使用 nice 值（nice 值在主题 进程优先级 中讲解，后面会讲）"
正确：如果主题 进程优先级 还没完成 → CFS 不能在这个主题里。
      要么重新聚类，要么标记 CFS 为 [BLOCKED] 等待 Process Priority 完成。
```

### 4. 坚持小主题不合并

```
错误："这个主题只有 3 个知识点 → 必须是独立主题"
正确：<5 个知识点且无清晰机制边界 → 与共享机制依赖的相邻主题合并
正确：<5 个知识点但有清晰、独立的机制边界 → 保持为独立小主题。
      ≥5 规则是指引，不是硬截断。机制边界是首要聚类标准。
```
