# AI 自约束启动契约 — 知识规划

> **每次知识规划前必读。** 此文是绑定契约。违反本文任何规则意味着规划无效。
> 权威来源：核心约束（§1）和契约（§3）提取自 methodology/01-04。交叉规则（§4）源自 04。踩坑清单（§5）补充自全部四篇文档的反模式。
> 阅读顺序：01 → 02 → 03 → 04 → 本文（最后读，作为执行摘要）。

---

## 1. 核心约束

### 防编造

1. **每个知识点必须追溯到 TOC 标题。** 目录没出现的概念，不提取。不确定的写 `[待验证]`——不得猜测。
2. **每个结构声明必须可独立验证。** 内核结构体、函数名、调用链——grep 验证源码。源码不可访问时标注 `[待验证]`。
3. **不自创算法、公式或概念。** 不知道确切公式时用概念性描述。不编造细节填补缺口。
4. **置信度仅由 TOC 标题特征决定**——显式名称匹配、标题具体性、概念到标题的距离。不使用 AI "感觉不确定"作标准。在两级之间犹豫时选低的那一级。
5. **TOC 给到第几层就提取到第几层。** 不根据书名声誉猜测更深内容。4 级以上少见但可提取——提供细粒度分解，仍不提供实现细节。

### 流程完整

6. **知识点优先**——组织原则是"后端工程师必须理解什么"，不是"这本书包含什么"，也不是"面试问什么"。
7. **先完成 01 提取，再 02 深度分类；先完成 02，再 03 聚类；先完成 03，再 04 合并。** 不跳步。
8. **依赖顺序永远覆盖重要程度。** A 依赖 B → 先讲 B，不管 A 是 🔴 还是 B 是 🟡。
9. **禁止"后面会讲"（前向引用未学概念）。** 如果概念 A 依赖未学的概念 B，要么先讲 B，要么标记 A 为 [BLOCKED]。后向引用已讲概念不仅允许，而且被期待——这是拓扑教学顺序的意义。
10. **🟢 知识点零书覆盖 → 跳过。** 不为 🟢 缺口编造内容。仅 🔴 和 🟡 缺口由 AI 补充。

### 深度标准

11. **深度由面试+生产频率（🔴/🟡/🟢）决定，不是由书的页数或覆盖决定。** 书只提供主题边界，AI 生成全部内容。
12. **深层（🔴）含结构组件**（结构体名+字段角色、函数签名+调用流程、文字版架构图）+ 可选源码片段作为结构证据。不逐行追踪实现体内部。
13. **两个独立坐标**：01 优先级（多书共识信号）和 02 重要程度（实际相关度）是独立的。P1 知识点的可能是 🟢。P3 知识点可能是 🔴。分别判断。

## 2. 预规划检查单

### 主题级（提取前，每个主题一次）

- [ ] **主题已确认**：用户指定了规划哪个主题
- [ ] **书单已确认**：所有贡献该主题的书已识别
- [ ] **TOC 可读**：全部 TOC 文件存在且可访问
- [ ] **主题范围清晰**：一页纸的范围描述已起草

### 主题级（提取后，02 深度分类前）

- [ ] **全部书已提取**：主题内每本书都有单书提取表
- [ ] **无编造**：每个知识点可追溯到 TOC 标题
- [ ] **不确定性已标注**：所有中低置信度条目标 `[待验证]`
- [ ] **优先级已分配**：跨书聚合完成，含基于共识的 P1/P2/P3
- [ ] **单书主题已注明**：N=1 标注 `[N=1 — 共识信号不可用]`
- [ ] **同义词已归一**：同一概念跨书使用统一的标准名称
- [ ] **缺口已标记**：缺失的预期知识点已记录 `[缺口：...]`

### 主题级（深度分类后，03 聚类前）

- [ ] **每个知识点已分档**：🔴/🟡/🟢 已分配，含判定理由
- [ ] **01 优先级已记录**：来自跨书聚合的 P1/P2/P3 已传递
- [ ] **下限已满足**：所有面试+生产必备知识达到深层
- [ ] **上限已遵守**：🟢 条目仅限于表层（1-2 句话）
- [ ] **AI 补充范围已定义**：每个需 AI 补充的知识点列出了补充范围
- [ ] **缺口已标记**：🔴 条目零书覆盖的标记 `[缺口]`，不编造
- [ ] **用户已确认分类**：用户已审查并批准深度决策表

### 主题级（聚类后，04 合并前）

- [ ] **主题边界已定义**：机制边界清晰，无知识点被强制归错类
- [ ] **依赖图已构建**：每个知识点有完整依赖列表，不完整则标记 [BLOCKED]
- [ ] **拓扑排序已验证**：没有依赖出现在被依赖之后
- [ ] **环形依赖已识别**：每对环形依赖记录三轮化解策略
- [ ] **跨主题依赖已标记**：依赖其他主题内容的知识点标记了前置主题名
- [ ] **用户已确认结构**：合并前用户已批准主题结构和教学顺序

## 3. 执行步骤契约

### 第一步：01 提取

| 必须 | 禁止 |
|------|------|
| 只从 TOC 标题提取 | 直接抄 TOC 当知识点 |
| 中/低置信度标注 `[待验证]` | 全部标高置信度 |
| 跨书使用统一的英文标准名称 | 不同书对同一概念用不同名称 |
| 缺失预期知识点标记 `[缺口：{概念}]` | 编造任何 TOC 中不存在的概念 |
| 单书主题标明 `[N=1 — 共识信号不可用]` | 把单书主题当成有共识信号 |

### 第二步：02 深度分类

| 必须 | 禁止 |
|------|------|
| 用判定三问（面试/生产频率→依赖数→书提到没） | 用书页数决定深度 |
| 🔴 零书覆盖标记 `[缺口]` | 编造 🔴 内容却不标 `[缺口]` |
| 遵守上限：🟢 条目仅 1-2 句话 | 为 🟢 条目写深层内容 |
| 每个知识点记录 01 优先级和 02 重要程度 | 混淆 P1（共识）与 🔴（重要性） |
| 每个需 AI 补充的知识点定义补充范围 | 未指定范围就补充 |

### 第三步：03 聚类

| 必须 | 禁止 |
|------|------|
| 按机制边界聚类，不按书名 | 按书名聚类 |
| 写任何内容前先建依赖图 | 依赖图不完整就写内容 |
| 拓扑排序，依赖的在前被依赖的在后 | 按重要程度顺序讲而非依赖顺序 |
| 跨主题依赖标记前置主题名 | 允许"后面会讲"前向引用 |
| 环形依赖应用三轮化解策略 | 忽略环形依赖 |

### 第四步：04 合并

| 必须 | 禁止 |
|------|------|
| 每个知识点选一个主要来源 | 把多书覆盖当重复消除 |
| 用其他书的独特角度补充 | 强行合并矛盾信息 |
| 解决或记录所有跨书冲突 | 写一个"听起来对的折中"但实际编造的 |
| 🔴 缺口 AI 基于外部知识补充，引用 ≥2 参考 | 补充 🟢 缺口（🟢 缺口跳过） |
| 每个知识点含完整来源块 | 补充不标注引用来源 |
| 跨主题依赖标记 `[BLOCKED — 主题 X 尚未完成]` | 写依赖未完成主题的内容 |

### 深度自诊断（写完后展示前）

以下任一为真则深度不足 → **返回加深**：

- [ ] 所有描述都是"做了什么"，没有任何"为什么这样做"
- [ ] 🔴 知识点零结构组件列出
- [ ] 说不清设计权衡或替代方案
- [ ] 🔴 知识点只有定义，无机制解释
- [ ] AI 补充缺少 ≥2 来源引用

## 4. 跨主题规则

来自 03 §3。每个主题的产出必须满足：

1. **前置标记**：每个主题列出前置主题和具体依赖概念，附依赖链解释
2. **[BLOCKED] 处理**：知识点依赖未完成主题中的概念 → 标记 `[BLOCKED — 主题 X 尚未完成]`，不写
3. **主题依赖图**：每个主题列出前置主题。基础主题（零依赖）先教
4. **禁止环形主题依赖**：优先尝试重新聚类，机制级环形存在则主题级应用三轮策略
5. **缺口传播**：01 §5 和 02 的缺口标记（`[缺口]`）必须合并进 04 §4。覆盖映射中发现的新缺口追加

## 5. 踩坑清单

从方法论反模式提取。规划完后、展示前检查。

- [ ] **无 TOC 抄袭**——章节标题是输入，不是产出。每章分解为面向后端工程师的子知识点
- [ ] **无书名声誉猜测**——"这是名著所以一定讲 X"是编造。目录没写就不提取
- [ ] **无面试题导向提取**——知识点是概念/机制，不是问答对
- [ ] **无同义词漂移**——同一概念跨书用统一标准名称
- [ ] **无书页数定深度**——50 页的 🟢 话题 1-2 句话，2 页的 🔴 话题 AI 扩展
- [ ] **无同等对待**——🔴 深层、🟡 工作层、🟢 表层。深度匹配重要性
- [ ] **无补充变源码分析**——深层 = 结构组件 + 调用流程 + 可选源码片段。不逐行源码游走
- [ ] **无跳过必备**——🔴 条目不管书说什么都必须完全覆盖
- [ ] **无 P1=🔴 混淆**——优先级（共识）和重要程度（相关度）是两个独立坐标
- [ ] **无前向引用**——禁止"后面会讲"。后向引用已讲概念正确
- [ ] **无书名聚类**——主题是机制边界，不是书名
- [ ] **无按重要程度排序教学**——依赖顺序永远覆盖重要程度
- [ ] **无强制小主题**——<5 个知识点且无清晰机制边界 → 合并到相邻主题
- [ ] **无把多书覆盖当重复**——多书是互补视角，不是冗余要消
- [ ] **无强合并矛盾**——带来源呈现双方，或验证后解决
- [ ] **无补充不标来源**——每个 AI 补充引用 ≥2 参考
- [ ] **无 🟢 缺口填补**——无书覆盖的 🟢 知识点跳过

## 违例处理

规划中违反 §1 或 §3 任何规则：

1. **立即暂停当前步骤。**
2. **修复违例**——重读受影响 TOC，重新验证声明，回溯。
3. **不继续**——违例解决前不进入下一步。
4. **违例不可修复**——前置主题未完成 → 标记知识点或主题为 [BLOCKED]，转向下一个未被阻塞的项目。
