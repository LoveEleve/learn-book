# 补充说明：源码分析项目的知识规划流程

> 本文件是 00-域发现.md 和 01-三层循环框架.md 的补充——说明纯源码项目中知识规划的位置。

## 完整流程

```
域发现 (00)
  ↓
知识规划 (knowledge-planning/05)
  逐源提取 → 聚合 → 深度分类 → 聚类
  ↓
方案选择 (04) + 书级规划
  ↓
Per-Article Outline (01 §Pass 3)
```

## 为什么必须插入知识规划

**没有知识规划的后果**（OpenJDK 实证）：
- G1 GC: 45692行源码/195文件 → 1篇57行大纲
- 原因：没有先逐源提取机制，直接跳到"写大纲" → 只能凭记忆写概述

**有知识规划的效果**（内功修炼实证）：
- OS内核: 6本书/287raw KPs → 提取→聚合→分类→聚类 → 产出结构化大纲

## 关键原则

1. **为什么之前总是跳？** 方法论的默认流程是"域发现 → Per-Article Outline"——这是为有 TOC 书籍的项目设计的。纯源码项目缺少"书"作为中间层，必须在域发现和 Per-Article Outline 之间插入知识规划。
2. **知识规划不是替代 Pass 0+1+2**: 知识规划是域发现和 Pass 0 之间的步骤。Pass 0+1+2 仍然需要执行——知识规划确定了"讲什么"，Pass 0+1+2 处理"怎么深度验证"。
3. **巨型域必须逐子主题做知识规划**: G1 GC 这样的巨型域，域级的知识规划不能替代逐子主题的详细提取。
