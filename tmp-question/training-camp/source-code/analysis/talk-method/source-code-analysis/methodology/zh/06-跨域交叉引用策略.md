# 跨域交叉引用策略

> 角色：AI 自约束操作规范。进入第三遍叙事前必读；第二遍出现跨域关联时参考。
> 先修：`01-三层循环框架.md` + `02-依赖顺序与分解原则.md` + `04-方案选择决策树.md`
> 本文假设已掌握 01（Pass 0-3 框架）、02（依赖图）、03（深度标准）、04（方案决策）、05（工具使用）。跨域引用整合所有五份文档的知识。
> 输入：当前域 + 同一仓库中所有已分析的域
> 阅读顺序：01 → 02 → 03 → 04 → 05 → 06（本文）。完整执行顺序见 01。

## 核心原则

**域不是孤岛。** 每个域都存在于依赖图中。分析域 B 时会发现关于域 A 的新认知——这不是 bug，是特性。问题是：发现了之后怎么处理？

---

## 1. 什么时候回头看

分析域 B 的第二遍时，可能发现域 A（已分析、已写文章）的理解有误或不完整。三级响应：

### 第一级：微小澄清（不动）

触发条件：域 A 的文章中某句话不够精确。域 B 的新认知增加细节但不改变核心理解。

操作：**不动域 A 的文章。** 把澄清嵌入域 B 的文章中：
- "注：域 A 的分析中将 X 描述为 Y。域 B 的分析表明，X 更准确的本质是 Z——这不否定 A 的分析，只增加精确度。"

理由：域 A 的文章已是"定稿"。追每一个细微差异会产生无限的修改循环。

### 第二级：重大修正（追加，不重写）

触发条件：域 B 揭示域 A 的核心机制理解有误。不是细枝末节——根本理解需要修正。

操作：**在域 A 的文章末尾追加修正段。** 不重写整篇文章：
```
### [来自 {域 B} 分析的修正]
最初理解：{域 A 之前说的}
新理解：{域 B 揭示的}
源码证据：{触发此修正的 B 的源码位置 file:line}
```

理由：追加保留分析历史，同时修正错误。重写会掩盖学习过程，且可能引入新错误。

### 第三级：需重新分析（标记待重写）

触发条件：域 B 揭示域 A 的理解如此根本性错误，整篇文章无效。

操作：**标记域 A 待重新分析。** 在域 A 的文章顶部加一行：
```
> ⚠️ [需重新分析 — 来自 {域 B} 分析的标记]
> 原因：[一句话]
```

然后继续域 B。重新分析在当前仓库拓扑顺序中的所有剩余域完成后进行。重新分析标记持续到那时为止。

**决策流程**：
```
B 的第二遍中，对 A 产生了新认知？
├── A 的核心机制有误？
│   ├── 否 → 第一级：微小澄清，嵌入 B 的文章
│   └── 是 → 整篇分析都无效？
│              ├── 否 → 第二级：追加修正段到 A 的文章
│              └── 是 → 第三级：标记 A 待重写，继续 B
```

---

### 环形依赖例外

对于标记为环形依赖的域（02 §1.4），三级 look-back 在联合第二轮分析中**不适用**。由于两个域同时在分析中，都不是"已分析定稿"状态。修正应直接嵌入联合 Pass 2 闭环笔记中，不对任何一方做标记。三级响应仅适用于域 A 在**之前的分析周期**中已完成的情况（不同仓库，或同一仓库但域 A 属于另一个在之前的分析 session 中已完成的依赖子图）。

## 2. 跨域引用格式

域 B 的文章引用域 A 的分析时，使用此格式：

### 标准引用

```
{域 A} 分析 §{章节}
```

示例：`Netty EventLoop 分析 §3.2`

### 嵌入式摘要

当引用的概念对理解域 B 至关重要时，加上 1-2 句摘要：

```
如 {域 A} 分析（§3.2）所述，ByteBuf 通过引用计数管理内存——每次 retain() 必须配对 release()。域 B（ChannelHandler）在此基础上的扩展是……
```

### 该做和不该做

```
该做：概念对 B 的叙事至关重要时，嵌入 1-2 句摘要
该做：辅助性上下文用 §{章节} 引用
不该做：重新解释域 A 的全部机制——引用它，不要复制它
不该做：引用尚未分析的域（违反 01 的"禁止后面讲"规则）
```

## 3. 新发现回流

> 此处与 01 的"已定义 → 回第一遍"不同（后者是 Pass 2 中关于**本站**遗漏类的处理）。本章仅处理**跨域发现**——分析当前域时发现的关于**另一个域**的新信息。

### 发现记录

域 B 分析中发现域 A 的新信息，但不属于第一/二/三级（如某个之前未注意的实现细节，但不改变核心理解）：

在域 B 的第二遍闭环笔记末尾创建**发现记录**：

```
## 跨域发现

来源：域 B 第二遍，闭环笔记 {#}
发现：{关于域 A 的什么}
已对照验证：域 A 源码 {file:line}
```

当发现是结构性元素（类/接口/模式）时，使用 01 的基本元素分解格式："元素: [一句话] — 对应源码 {file:line}"（见 01 §第一遍产出格式）

### 发现传播

域 B 完成后，检查发现记录是否需要行动。对照其他域源码验证前，按 05 §索引刷新检查索引时效。

| 发现类型 | 传播操作 |
|----------|---------|
| 域 A 遗漏了边界情况 | 追加到域 A 的文章（第二级） |
| 域 A 有一个未记录的内部接口被 B 使用 | 为 A 增加 §跨域引用 章节 |
| 域 A 的理解正确，只需更多细节 | 第一级——嵌入 B 的文章 |

### 多域影响

如果域 B 的发现影响 ≥3 个已分析域：

1. 创建汇总记录：`progress/cross-domain/{discovery-id}.md`
2. 对每个受影响域，添加简要引用指向汇总记录
3. 不要逐一编辑 3+ 篇文章——汇总记录是唯一真相源

## 4. 第三遍的跨域引用章节

每个产生 Pass 3 文章的域（方案 A 和 B-with-Pass3）必须包含跨域引用章节。方案 C 和 D 的域见下方 §非 Pass 3 域。

```
## 5. 交叉引用

← {拓扑顺序中的前一个域}：{一句话解释为什么它是依赖}
→ {下一个域}：{一句话解释谁依赖它}
另见：{相关域} — {简要描述关系}
```

> 此格式是 01 单行简版的细化——多行带解释的格式为准。所有 Pass 3 文章使用此格式，不用 01 的简版。

### 规则

- **←（前置）**：必须是本域依赖的域，来自依赖图。如果是拓扑顺序中的第一个域（零依赖），写"根域——无上游依赖"
- **→（后置）**：哪些下游域依赖本域？没有就写"叶子域——无下游依赖"
- **另见**：任何主题相关（非直接依赖）的域——如同一框架内的两种不同调度策略

### 非 Pass 3 域

用方案 C 或 D 分析的域不产生 Pass 3 文章。跨域连接按以下方式处理：

- **C（浅层）**：在简略 Pass 2 输出中记录为独立的闭环笔记
- **D（扫描）**：在架构摘要段落中加入"依赖/被依赖"一句话

---

## 5. 质量检查

声明域的文章"完成"前，验证：

- [ ] 跨域引用章节完整（← / → / 另见）
- [ ] 没有引用尚未分析的域（"将在后面讲解"）
- [ ] 所有引用使用标准格式（{域名} 分析 §{章节}）
- [ ] 本域分析产生的任何第二/三级修正已应用到受影响域
- [ ] 发现记录（如有）已按 §3 传播

任何一项未通过，第三遍不算完成。
