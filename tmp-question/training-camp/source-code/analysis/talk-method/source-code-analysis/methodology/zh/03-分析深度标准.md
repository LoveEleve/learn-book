# 分析深度标准

> 角色：AI 自约束操作规范。第一遍选择问题和第二遍执行时必读。
> 先修：`01-三层循环框架.md`
> 阅读顺序：01 → 02 → 03（本文）→ 04 → 05 → 06。完整执行顺序见 01。

## 核心问题

拿到一段代码，判断分析到什么深度算够了。

## 判断标准

**不问"这是底层优化吗？"——问"这段代码承载了设计决策吗？"**

### 必须深挖（承载设计决策）

| 信号 | 例 |
|------|------|
| 数据结构选择（为什么用 A 不用 B） | SelectedSelectionKeySet 用数组替代 HashSet — 因为 NIO Selector 的 O(n) keys 遍历是真实瓶颈 |
| 并发策略（为什么用锁 A 不用锁 B） | LazyIndex 用 ReentrantLock 不用 synchronized — 为了 defer mmap 到首次访问 |
| 内存管理策略（为什么要这样分配） | sdshdr5 永远不用于扩容 — 因为追加时自动升级到 sdshdr8，避免短字符串的频繁 realloc |
| 压缩/编码选择（为什么压缩中间节点） | quicklist 中间节点 LZF 压缩 — 省内存但两端不压（保证 head/tail 操作性能） |
| 异常处理策略（为什么吞掉/传播/转换） | Seata undo_log 的 SQLIntegrityConstraintViolationException → 并发回滚保护 |

### 可以跳过（无设计决策）

| 信号 | 例 |
|------|------|
| getter/setter/toString/hashCode | 纯数据访问，无决策 |
| 日志打印、异常包装 | `log.error("xxx", e)` — 无决策 |
| 纯转发 delegate | `return target.doX()` — 无决策 |
| deprecated 的旧代码路径 | 标记为 `[已废弃]`，跳过分析 |
| 测试文件（第一遍已读过） | 第一遍读测试理解意图，第二遍不再碰 |

### 灰色地带（需要判断）

| 信号 | 处理 |
|------|------|
| 常量值选择（为什么是 512 不是 256） | 如果有注释解释 → 设计决策，深挖。如果没有 → 标记 `[待验证]`，默认不深挖 |
| 配置项默认值 | 同一逻辑 |
| 排序/优先级数值 | 如果和其他域有交叉影响（如 Filter order）→ 设计决策，深挖 |

## 深度不足的检测信号

第二遍完成后，如果以下任一成立，说明深度不够：

- [ ] 描述全是"它做了什么"，没有"为什么这样做"
- [ ] 没有任何跨域关联提及（指深入分析中对"此机制如何与其他域交互或依赖"的交叉思考——不是等 Pass 3 再写的正式交叉引用，而是 Pass 2 中体现的跨域意识）
- [ ] 说不出来这个设计的替代方案是什么
- [ ] 每个闭环笔记 < 200 字
- [ ] 源码引用只有方法签名，没有方法体

→ **回第二遍补深**。

## 过度分析的检测信号

如果以下成立，说明在浪费精力：

- [ ] 连续 3 个闭环笔记的结论都是"getter/setter，无设计决策"

→ 说明问题选错了，**重新挑标记问题**，而不是继续深挖同一个文件。
