# AI 自约束启动契约

> **每次域分析前必读。** 此文是绑定契约。违反本文任何规则意味着分析无效。
> 权威来源：核心约束（§1）和方案契约（§3）提取自 methodology/01-06。跨域规则（§4）源自 06。踩坑清单（§5）补充跨 session 写作错误。
> 阅读顺序：01 → 02 → 03 → 04 → 05 → 06 → 本文（最后读，作为执行摘要）。

---

## 1. 核心约束

开始任何域分析前，全部验证通过。任何一条不满足，不得继续。

### 防编造

1. **每个函数名、类名、方法签名必须 grep 验证**后才能写入产出。不确定的写 `[待验证]`——不得猜测。
2. **每个数字声明（行数、字节数、超时值）必须 `wc -l` 或源码阅读验证。** 不凭心智模型估算。
3. **每个数据结构声明（字段、类型、关系）必须从实际头文件/源码读取。** 不从名称推断。
4. **不得在未 grep 确认的情况下写技术名称**（如 Caffeine、useGeneratedKeys、selectorExpression）。
5. **代码块必须可编译或显式标注**：所有代码块要么逐字来自源码（标注 `file:line`），要么标 `[伪代码]`。来源见 01 核心约束 #5。

### 流程完整

6. **必须先完成第一遍的全部产出，才能进入第二遍。** 至少 3 个闭环问题才能进入第三遍。
7. **禁止"后面讲"——所有依赖必须先分析。** 参考依赖图（02）。
8. **不限制任何产出的行数。** 讲透为止。"至少"存在（≥5 标记问题），"至多"不存在。
9. **每个结论必须标注源码位置：** `file:line`。
10. **始终优先使用语义工具（JavaLens/LSP/codegraph）而非文本匹配（grep）。** 仅在所有语义/索引工具不可用时降级到 grep（05 降级链：Java 为 JavaLens→codegraph→grep，C 为 LSP+clangd→codegraph→grep）。
11. **Pass 2 发现新类/包不在 Pass 1 继承树中 → 暂停，回退到 Pass 1** 扫描该包/类，更新继承树，添加标记问题（01 §已定义 → 回第一遍）。

### 深度标准

12. **问"这段代码承载设计决策吗？"——而非"这是底层优化吗？"**（03）。承载设计决策就深挖。设计决策信号包括：数据结构选择、并发策略、内存策略、压缩/编码、异常处理策略。
13. **连续两个闭环笔记得出"getter/setter，无设计决策"→ 重新选择标记问题，且不继续深挖同一文件**（03）。

## 1.5 域分析前问题

**任何域分析前必问。** AI 先提出推荐答案，用户确认或纠正。如果 AI 能从源码自己找到答案（README、pom.xml、类名），**不要问用户**——自己找。

### 问题

| # | 问题 | AI 能自己答吗？ | 怎么找 |
|---|------|---------------|--------|
| Q1 | 分析哪个框架？版本？ | **能** — 从目录名、pom.xml、build.gradle | `cat pom.xml \| grep version`，`ls` 根目录 |
| Q2 | 入口点是哪个类哪个方法？ | **能** — 从 README、docs/、类名 | 搜 Bootstrap/Starter/Factory/Context/Engine |
| Q3 | 目标是面试准备还是生产理解？ | **不能** — 用户判断 | AI 推荐："都要（面试用工作层，生产用深层）" |
| Q4 | 深度期望：全量深析还是先扫轮廓？ | **不能** — 用户判断 | AI 推荐："🔴 全量深析，🟡 标准分析" |
| Q5 | 时间约束？ | **不能** — 用户判断 | AI 推荐："无——全量分析" |

### 格式

```
Q1: 分析哪个框架？版本？
➡️ 我建议：{框架} {版本}（来自 {证据}）
   确认吗？

Q2: 入口点是什么？
➡️ 我建议：{类}.{方法}()（来自 {证据}）
   确认吗？

Q3: 目标是面试准备、生产理解、还是都要？
➡️ 我建议：都要——面试用工作层，生产用深层。
   确认吗？

Q4: 深度——全量深析还是先扫轮廓？
➡️ 我建议：🔴 全量深析（A 方案），🟡 标准（B 方案），🟢 表层（C/D 方案）。
   确认吗？

Q5: 时间约束？
➡️ 我建议：无——全量分析所有域。
   确认吗？
```

### 规则

- **Q1-Q2**：AI 必须从源码自己找答案。找不到才问用户。
- **Q3-Q5**：用户必须回答（或确认 AI 的推荐）。这些决定深度和范围。
- **绝不问用户 AI 自己能查到的东西。** 从源码找事实，不从用户找事实。

## 2. 域分析前检查单

### 仓库级（每个仓库一次，第一个域之前完成）

- [ ] **预分析轻扫**：所有域做轻量扫描——`find src/main/java -type d` + `grep '^public (class|interface)'` + `grep -E '^import|^@'` 看顶层依赖。不是完整 Pass 1（02 §预分析轻扫）
- [ ] **依赖图已构建**：所有域映射完成，无 [PENDING]（02 §1.2）
- [ ] **环形依赖已识别**：每对环形依赖记录三轮化解策略（02 §1.4）
- [ ] **Hub 候选已标记**：被 ≥10 个域依赖的域 → 潜在 A 升级（04 §Hub 升级）

### 域级（每个域，Pass 0 之前）

- [ ] **依赖图**：本域所有依赖已分析完成（02 §1.2）。任何依赖为 [PENDING] 则阻塞。
- [ ] **方案已选定**：按决策树（04）确定 A/B/C/D。记录选择理由。
- [ ] **方案选择产出已记录**（04 格式）：
  ```
  ## 方案选择：{域名}
  优先级：{🔴/🟡} | 方案：{A/B/C/D} | 通过：{...}
  时空溯源：{是/否} | 极简复现：{是/否}
  需先分析的依赖：{列出} | 理由：[一句话]
  ```
- [ ] **叶子域检查**：🟡 且零下游依赖 → 最低 B，除非真薄封装（04 §叶子域）
- [ ] **工具可用**：语义工具（JavaLens/LSP+clangd）、索引工具（codegraph/codebase-memory-mcp）、GitHub MCP、Git MCP 全部确认可用。降级链已验证（05 §域分析前工具检查）
- [ ] **索引新鲜**：codegraph 和 codebase-memory-mcp 索引最新。上次索引后仓库有更新则重建。首次分析：现在建索引（05 §索引刷新）
- [ ] **时空溯源就绪**：A 方案 🔴 域，找到最早语义 tag
- [ ] **Hub 升级检查**：🟡 域在仓库级 Hub 扫描中被标记 → 升级 A（04 §Hub 升级）
- [ ] **无受损完整性**：本域绝不引用尚未分析的域

## 3. 方案行为契约

### A：全深度（🔴）

| 必须 | 禁止 |
|------|------|
| 完成 Pass 0→1→2→3 | 跳过 Pass 3 |
| Pass 2 发现新类/包 → 暂停，回 Pass 1 | 不更新继承树就继续 Pass 2 |
| 时空溯源（checkout 早期版本） | 跳过时空溯源 |
| harness/ 中极简复现 | 未做复现验证就写文章 |
| 面试题（≥2 普通 + ≥1 陷阱） | 省略设计权衡章节 |
| Pass 1 读 ≥2 测试文件 | 跳过测试文件 |

### B：标准（🟡 有设计决策）

| 必须 | 禁止 |
|------|------|
| 完成 Pass 0→1→2 | <5 个标记问题值得合成时就进 Pass 3 |
| Pass 2 发现新类/包 → 暂停，回 Pass 1 | 不更新继承树就继续 Pass 2 |
| Pass 2 闭环笔记含显式跨域关联 | 文章没有任何跨域引用 |
| 在适用处（03 深度标准）闭环笔记含设计权衡 | 所有标记问题当同等深度处理 |
| Pass 1 读 ≥2 测试文件 | 跳过测试文件 |

### C：浅层（🟡 简单机制）

| 必须 | 禁止 |
|------|------|
| 完成 Pass 0→1 | 跳过 Pass 0（简单域也要建立上下文） |
| 简略 Pass 2：答 1-2 个最关键的 | 写完整叙事（闭环笔记即最终产出） |
| 其余标记问题标注为 `[trivial — skipped]`（见 04 §C） | 静默忽略标记问题 |
| Pass 1 读 ≥2 测试文件 | 跳过测试文件 |

### D：扫描（胶水/枚举/封装）

| 必须 | 禁止 |
|------|------|
| 简略 Pass 1：继承树 + 元素分解 | 生成标记问题 |
| 架构摘要段落（"依赖/被依赖"） | 完全跳过（胶水也要文档化） |
| 摘要含跨域关联 | 写深度闭环笔记 |

### 深度自诊断（Pass 2 之后，Pass 3 之前）

Pass 2 完成后，以下任一为真则深度不足 → **回到 Pass 2 加深**（03）：

- [ ] 所有描述都是"它做了什么"，没有任何"为什么这样做"
- [ ] 没有任何跨域关联被提及
- [ ] 说不清被拒绝的替代设计是什么
- [ ] 任何闭环笔记 < 200 字
- [ ] 源码引用只有方法签名，没有方法体

## 4. 跨域铁律

来自 06。每个域的产出必须满足：

1. **交叉引用章节**：←（依赖） / →（依赖我） / 另见（相关）。根域："根域——无上游依赖"。叶子域："叶子域——无下游依赖"。
2. **引用格式**：`{域名} 分析 §{章节}`。概念对叙事至关重要时嵌入 1-2 句摘要。
3. **不引用未分析域**：绝不写"将在后面讲解"（01 核心约束 #7）。
4. **发现回头看**：Pass 2 中发现已分析域的问题：
   - 微小澄清 → 嵌入当前域文章（第一级）
   - 重大修正 → 追加修正段到受影响域（第二级）
   - 完全无效 → 标记受影响域 [需重新分析]，继续当前域（第三级）
   - 环形依赖例外：联合 Pass 2 中直接嵌入修正，无需标记。
5. **多域发现**：≥3 个域受影响 → 创建 `progress/cross-domain/{discovery-id}.md`——汇总记录是唯一真相源。

## 5. 踩坑清单

来自实际跨 session 写作错误。写完之后、展示之前检查。

- [ ] **无编造函数名**——每个函数/类名 grep 验证过源码（01 核心约束 #1）
- [ ] **无虚假技术栈**——Caffeine、useGeneratedKeys、selectorExpression 全都 grep 确认存在或无（01 核心约束 #4）
- [ ] **无错误的 Key 前缀**——每个 Key 格式从 `RedisKeyConstants` 或同等来源读取
- [ ] **无"已记录"逃避**——每个发现要么已修复，要么已证明不是问题
- [ ] **无"编译通过 = 已验证"捷径**——代码修改后必须重启服务 + curl 功能测试
- [ ] **无代码块当伪代码**——所有代码块要么逐字来自源码（标注），要么显式标注 `[伪代码]`（01 核心约束 #5）
- [ ] **无过期索引**——Pass 1 前验证索引新鲜（05 §索引刷新）
- [ ] **退出检查**：本文所有检查项通过后才声明域"完成"

## 6. 等等——用户中断信号

**用户可以在任何时候中断 AI**，通过说：
- "wait" / "stop" / "不对" / "等等"
- "我听不懂" / "重新讲"

当用户说任何一句：

1. **立即停止当前分析** —— 不继续到下一阶段
2. **重新说明当前状态** —— 你在哪里、已经做了什么、接下来要做什么
3. **请求澄清** —— "哪里没跟上？需要重新讲哪里？"
4. **不继续** —— 直到用户确认理解正确

这不是违例——是安全阀。用户有权在任何时候因任何原因中断任何分析。

## 违例处理

分析过程中违反 §1 或 §3 任何规则：

1. **立即暂停当前阶段。**
2. **修复违例**——重读受影响源码、重新 grep 缺失声明、回溯到违例阶段。
3. **违例未解决前不得进入下一阶段。**
4. **违例不可修复时**（如依赖尚未分析），标记域为 [BLOCKED]，转向下一个可分析域。
