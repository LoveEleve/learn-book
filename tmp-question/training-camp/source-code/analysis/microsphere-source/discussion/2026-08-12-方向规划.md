## 一、五个根本问题的结论（会话讨论沉淀）

1. **某个仓库的作用是什么？**
   读法：pom 依赖链（上游是谁）+ 模块划分（能力边界）+ 包结构（解决什么需求）。
   例：multiactive = 多活/区域路由通用抽象（Zone 上下文→定位器→云厂商实现→自动装配→生态集成 7 模块分层）。

2. **小马哥为什么要实现这些仓库？（推断）**
   - 教学活教材：机制收敛可视化（官方一个模式分散几十个类，microsphere 1-3 个类讲全）——最大价值
   - 统一 API 抽象：把分散生态（nacos/redis/druid/apollo/etcd/zk）统一成自家 SPI
   - Spring 内部机制（Environment/BeanPostProcessor/NamedContextFactory/条件装配）的教学载体
   - 生态空白（如多活 zone 路由 2021 年前后无成熟开源）+ 个人开源品牌

3. **实现是否会过时？——分层看**
   - 模式/决策层 → [时间无关]（提取对象，永不过时）
   - API/依赖层 → [过时→现代替代]（实证：netflix 模块基于已过时 Ribbon；javax→jakarta）
   - 工程面 → 教学性质（0.2.12-SNAPSHOT），无生产责任，重写无产品价值
   - 注意：microsphere-spring-cloud 自身已跟进 2022~2025.1 多版本 profile（parent pom:96-135）

4. **如何把别人的东西变成自己的？**
   不学类，学决策。四步：解构（决策点清单）→ 重述（自己的语言）→ 对比（官方实现对照）→ **落地（自己的工程里重写/实现一遍）**。
   核心转变：**"别人实现的"只有自己重写一遍 + 上真线才算"自己的"**。

5. **是否要重写/发散？**
   - 重写仓库本身：不值得（无生产价值、无测试责任）
   - **重新实现功能：完全可以**（用户明确授权）——落地目标是 my-xhs（真实线上项目），不是复制 microsphere

## 二、新方向：从"分析工程"到"落地工程"

```
旧方向：分析小马哥做了什么 → 提取知识点 → 存档
新方向：提取知识点 → 转现代主流实现 → 官方已实现标注+链接源码分析
        → 官方缺口自主实现（可重写）→ my-xhs 结合落地
```

**每个知识点的四步流程**：

```
microsphere 源码 → 知识点
  → ① 现代主流实现是什么？（具体类/库，本地源码验证 code/spring/）
  → ② 官方已实现？→ 标注 [已实现→链接源码分析文档]
  → ③ 官方没有？→ 写"如果我来实现"自主方案（可重写，进 my-xhs）
  → ④ my-xhs 结合：已用 / 该用没用（差距）/ 不该用（理由）
```

**性质变化**：source/ 提取从"第二个提取主体"（与课程平行）变成"知识落地工程"（课程 L1 的升级补全）。L3 总大纲随之变为"知识 + 现代实现 + 自主实现 + 线上落地"的完整闭环。

## 三、方法论：穷尽提取 + 三层叠加（不是替换）

> 重要修正（会话讨论确认）：**穷尽提取不能丢**——02 SOP 核心是"宁可多提取标低置信度，也不遗漏"。
> "触发点提取"会退回"按主题找文件"的老坑（02 反模式 2），漏知识点。

```
每仓库 = 穷尽逐文件提取（02 SOP 完整保留，防漏）
       + 每个知识点叠加三层新处理：
         ① 现代主流实现对照（官方已实现→标注+链接 / 未实现→自主实现）
         ② 自主实现分级（官方缺口→完整设计 / 官方已有→练习级）
         ③ my-xhs 落地判定（已用 / 该用没用 / 不该用）
```

产出文档 = 穷尽映射表，每行多三列（现代实现 / 自主实现 / my-xhs 决策）。
漏知识点的风险只在提取层，映射层只是附加值——提取层必须原样穷尽。

## 四、方法论三分类（相对旧 10 SOP）

### 能沿用（无需改）
- **08** 需求→自主实现→参考实现→对比（核心视角，直接适用）
- **04** 过时处理（三级过时 + 替代物细节——正是"现代主流实现"骨架）
- **03** 维度/深度/优先级（知识点打标签，供 L2/L3 聚合）

### 要改（骨架沿用、焦点转移）
- **02** 源码逐文件提取：穷尽性保留，但每行映射表扩展三列（现代实现/自主实现/my-xhs 决策）
- 提取单位：文件→知识点（可能跨文件），一个文件可能 0 个知识点

### 要新写（新方法论核心，旧 SOP 没有）
1. **现代主流实现映射规则**：判定"官方已实现"（code/spring/ 本地源码验证）→ 标注格式 `[已实现→链接]` + 链接结构
2. **自主实现深度分级**：官方缺口 → 完整设计（需求/设计/取舍/可重写）；官方已有 → 练习级
3. **my-xhs 落地决策规则**：已用/该用没用/不该用三分法 + 进不进 my-xhs 判定 + 与 my-xhs-优化规划 P1/P2 衔接
