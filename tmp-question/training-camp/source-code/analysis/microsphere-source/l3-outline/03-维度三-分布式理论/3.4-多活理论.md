## 0. 先分清三个概念（stage-4-01 KP-04 多活概念体系——架构师发散）

| 概念 | 含义 |
|------|------|
| **高可用** | 故障自动转移（主备——备机平时不用） |
| **灾备** | 灾难切换（备灾中心——平时不服务，灾时接管） |
| **多活** | **多个都活**（多机房同时服务——没有"闲着"的备——资源利用率最高的容灾形态） |

**一句话**：高可用是"自动换备"，灾备是"灾时接管"，多活是"全都在干活"——**多活是容灾形态的终点**（不是"备着"而是"都活着"）。

## 2. 多活六级架构（源码 07 6.1——每层多活做什么）

多活不是"整个系统切机房"——是**分层逐级多活**（18-01 实证）：

```
① 接入层多活（DNS/Gateway 切流）
② 无状态服务层多活（多机房部署 + 负载均衡——2.3/2.7）
③ 配置层多活（配置中心多副本——2.2）
④ 数据库层多活（数据复制/切换——2.6/2.8 的 dynamic——★最难的层）
⑤ 缓存层多活（缓存复制/多写——2.6）
⑥ 消息层多活（MQ 集群多机房——2.10）
```

**层与层的顺序是难度顺序**：越往下越难（无状态服务多活最容易——加副本即可；**数据层多活最难**——数据一致性 + 复制 + 切换——2.8 的存储多活正是第④⑤层）。

## 3. 两种部署模型（源码 07 6.1——取舍核心）

| | A 按 Zone 独立部署 | B 单实例多 Zone |
|---|---|---|
| 形态 | 每个 Zone 一套完整实例（独立部署） | 一个实例内按 zone 切换资源（数据源/缓存） |
| 数据 | 各 Zone 独立数据副本 | 单实例多数据源（切换） |
| 隔离 | 彻底（进程级） | 进程内（轻量） |
| 成本 | 高（每 Zone 一套） | 低 |
| 代表 | 跨机房独立部署 | **18-dynamic 的选择（子上下文重建）+ my-xhs（预建池切换）** |

**教学结论**：B 模型（单实例多 Zone）是**中小规模多活**的务实选择（2.8 的两架构对照——子上下文 vs 预建池——是 B 模型的两种机制实现）。

> 可跳过（进阶级）：**数据形态**——多活的数据库层形态（Source-Replica 源-副本——18-01 的架构名）/多主复制/单元化（**单元化 = 流量按维度分片到单元**——每单元自带完整数据——异地多活的高阶形态——阿里单元化实践的业界常识——训练营未深入，[缺口：外部补源]）。

## 4. Zone/Region 概念（源码 07 6.1）

**Region（地域）**：地理区域（华东/华北——物理距离远——RTT 大）；**Zone（可用区）**：Region 内的隔离单元（独立电力/网络——同城两个机房 = 同 Region 双 Zone）。

**对多活的影响**：同 Region 双 Zone（同城双活——RTT 小——数据同步可行）；跨 Region（异地多活——RTT 大——**3.1 的死亡三角量化：跨洲延迟必然舍弃强一致**——2.8 反模式第 2 条的理论根源）。

## 5. 容灾级别：同城双活 vs 异地多活（stage-4-01 交叉 + 业界常识）

| 级别 | 形态 | RTO/RPO | 代价 |
|------|------|---------|------|
| 备份恢复 | 备份 + 恢复 | 小时级/分钟级（数据丢） | 低 |
| 同城双活 | 同城双机房同时服务 | 分钟级/秒级 | 中（同步复制可行） |
| 异地多活 | 跨地域多机房 | 秒级/最终一致 | 高（异步复制 + 冲突处理） |

**RTO（恢复时间）/RPO（恢复点——丢多少数据）**：容灾设计的第一步是定 RTO/RPO 目标——**"能接受丢多少数据、多久恢复"决定了多活的级别**（成本跟着目标走）。
