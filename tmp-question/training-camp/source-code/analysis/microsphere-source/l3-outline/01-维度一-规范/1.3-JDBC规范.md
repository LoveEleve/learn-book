# 03. JDBC：Java 是怎么连上数据库的

> 配套实验：`sca-lab/custom-java-infra/spec-jdbc`（8 个断言，H2 内存库——不需要装 MySQL 就能跑）
> 前置：会写 SQL 就行。不用先懂任何 Java 数据库知识。

你在 Spring Boot 项目里见过这行配置：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/myxhs
```

项目一跑起来，代码里就能查数据库了。这中间发生了什么？"jdbc:mysql://..." 这串东西是怎么把 Java 和数据库连起来的？这一章顺着一条链路走一遍——**URL → 驱动 → 连接 → 语句 → 事务 → 连接池 → 元数据**——每一步都回答一个"为什么"。看完你会发现：你天天用的 MyBatis、Spring JDBC，底层全踩在这条链上。
> 课程交叉：stage-2-13（JDBC 事务实践，主属 2.5 章节）+ stage-4-17/2-25（JDBC 多活/读写分离，主属 2.8/2.6 章节）

## 1. 起点：那串 URL 是什么

先看那行配置。`jdbc:mysql://127.0.0.1:3306/myxhs` 拆开是：

- `jdbc:` —— 固定前缀，意思是"这是数据库连接地址"
- `mysql` —— 子协议，告诉系统"连的是 MySQL"（换成 `h2` 就是 H2、`oracle` 就是 Oracle）
- `127.0.0.1:3306/myxhs` —— 主机、端口、库名

**它就是个地址串**。数据库驱动（每个数据库厂商提供的一个 jar）看到 `jdbc:mysql` 就说"这是我的"，看到 `jdbc:h2` 就退让。实验里用的 H2 是 `jdbc:h2:mem:jdbc-spec`（内存库，跑完就没了——方便验证）。`JdbcSpecTest.urlConvention` 断言了这串地址能连上。

> 可跳过（进阶级）：MySQL 驱动支持"一个地址串里写多个主机"（Multi-Host 四模式：SINGLE/LOADBALANCE/FAILOVER/REPLICATION）——`jdbc:mysql://主库,备库1,备库2`——驱动自己管故障切换（`failOverReadOnly` 故障期写保护——多活章节详谈）。知道有这回事就行。

---

## 2. 谁"认领"这串 URL：驱动和 DriverManager

### 每个数据库一个驱动 jar

MySQL 有 mysql-connector-j，H2 有 h2。你项目里引入哪个 jar，就能连哪个库。这个 jar 里有一个类实现了 `java.sql.Driver` 接口——这个接口说："给我一个 URL，我能判断这 URL 是不是我的（`acceptsURL`），是我的我就负责建连接。"（完整接口还有 `getPropertyInfo`（返回连接属性的说明，工具用）等——进阶级，用到再看。）

### DriverManager：驱动们的登记处

问题来了：项目启动时，谁把 MySQL 驱动和 H2 驱动都叫来排队？答案是 `DriverManager`（JDK 自带的"驱动登记处"）。

**老教程教过的写法**（JDBC 3.0 时代，现在过时了）：

```java
Class.forName("com.mysql.cj.jdbc.Driver");  // 手动把驱动类加载进来
```

**现在的写法**（JDBC 4.0 起）：什么都不用写。驱动 jar 里藏了一个文件（`META-INF/services/java.sql.Driver`），JVM 启动时 `DriverManager` 自己按这个文件把驱动加载进来——这就是第一章讲的 SPI（`ServiceLoader`，服务发现），JDBC 是最早大规模用它的规范。

实验 `JdbcSpecTest.driverAutoRegisteredViaSpi` 证明了这点：全程没写 `Class.forName`，`DriverManager.getDrivers()` 里已经有 H2 驱动。

> 可跳过（排查用）："驱动明明在 classpath，却说找不到驱动"——最常见原因是类加载器问题（Web 容器场景），`DriverManager` 会检查驱动对调用方是否可见。

## 3. 连接：一次会话，用完要还

`Connection` 就是你和数据库之间的一次会话。用它执行 SQL、管理事务，用完全部关闭。

**为什么"关闭"是大事？** 因为数据库连接是稀缺资源——建一条连接要网络握手、要认证，很贵。所以连接都是"池化"的（第 6 节），池里就那几十条。**借了不还 = 池被借空 = 整个应用连不上数据库**——这是线上最经典的事故链。现代写法用 `try-with-resources`（Java 7 起）：

```java
try (Connection conn = dataSource.getConnection();
     PreparedStatement ps = conn.prepareStatement("SELECT ...")) {
    // 用
}  // 自动关闭（还回池里）
```

实验里所有代码都是这个写法。

## 4. 发 SQL：从"拼字符串"到"占位符"（防注入的核心）

### 反面教材：字符串拼接

最早你可能这么写：

```java
String sql = "SELECT * FROM account WHERE name = '" + userName + "'";
```

如果 `userName` 是 `bob' OR '1'='1`——SQL 就变成了 `WHERE name = 'bob' OR '1'='1'`——**永远为真，整个表被查走**。这就是 SQL 注入：用户输入变成了代码。历史上无数网站死在它手上。

### 正确写法：SQL 骨架和参数分开

```java
PreparedStatement ps = conn.prepareStatement(
    "SELECT * FROM account WHERE name = ?");   // ? 是占位符
ps.setString(1, userName);                       // 参数走 set 方法，不是拼进 SQL
```

SQL 的"骨架"和"数据"分开了——`?` 永远只被当成一个值，用户输入再邪恶也只是数据，不是代码。**MyBatis 里 `#{}` 防注入，底层就是这个机制**。顺带：数据库会把预编译的 SQL 缓存执行计划（同骨架不同参数复用），这也是它比裸拼接快的原因之一（"预编译"）。三种语句里另两类——普通 `Statement`（裸 SQL，别用）和 `CallableStatement`（调存储过程）——知道存在即可。

实验 `JdbcSpecTest.preparedStatementParameters` 验证了：把 `bob' OR '1'='1` 当参数插进去，它只是个普通字符串。

> 可跳过（进阶级）：批量插入（`addBatch` 一次网络往返插一万条）、自增主键回填（`getGeneratedKeys`——MyBatis 的 useGeneratedKeys 底层）、游标滚动（大结果集）、SQL 类型映射（`JDBCType`/`Types` 常量——存储过程传 NULL 时用）。知道存在，用到再查。

## 5. 事务：转账为什么不会丢一半钱

### 场景：转账

把 100 元从 A 转给 B，要做两件事：

```
A 账户扣 100
B 账户加 100
```

如果第一句执行完、第二句执行前断电了——钱就丢了。**事务**解决这个：把两句包成一个整体，要么都成，要么都回滚，数据库保证这一点（这就是 ACID——原子性/一致性/隔离性/持久性）。

### Connection 上的三个方法

```java
conn.setAutoCommit(false);   // 关掉 autoCommit（默认 true = 每句自动提交）——现在开始是一个事务
扣钱();
加钱();
conn.commit();               // 全部成功 → 提交（数据生效）
// 或者 conn.rollback();     // 任何一步失败 → 回滚（数据像没发生过）
```

实验 `JdbcSpecTest.transactionCommitAndRollback` 演示了全过程：先插入再 rollback，数据查不到；再插入再 commit，数据就在了。

### 隔离级别：两个事务同时改同一行，谁看到什么

一句话人话版：**两个事务同时在操作同一行数据，隔离级别决定"互相能看到多少"**。JDBC 定义了四档：

| 级别 | 一句话 |
|------|--------|
| READ_UNCOMMITTED | 别人没提交的也能看到（可能有脏数据） |
| READ_COMMITTED | 只能看到已提交的（多数数据库默认） |
| REPEATABLE_READ | 一个事务里反复读，结果一致（MySQL 默认） |
| SERIALIZABLE | 串行执行，最安全最慢 |

> 可跳过（进阶级）：Savepoint（事务里打个点，回滚只回到点——长事务的部分回滚）。用到再看。

## 6. 连接池：为什么不能每次"现建连接"

### 场景：每次查询都现建连接有多慢

建一条数据库连接 = 网络握手 + 认证 + 初始化——几十毫秒。你的接口如果每次查询都现建，光连接开销就吃掉大半时间。**连接池**的思路：启动时预先建好一批连接放着，谁用谁"借"，用完"还"（不是真关）。

### DataSource：连接池的统一接口

JDBC 规范里，获取连接的接口是 `javax.sql.DataSource`——**所有连接池（HikariCP、Druid）都是这个接口的实现**：

```java
DataSource ds = new HikariDataSource(config);  // 池：预先建 10 条连接
try (Connection conn = ds.getConnection()) {   // "借"
    ...
}                                              // close() = "还"回池里
```

实验 `JdbcSpecTest.dataSourceIsThePoolingContract` 用 H2 自带的 DataSource 实现验证了这个契约（Hikari 和它同构，只是多了池化）。

**进阶（一句话）**：因为获取连接都走这一个接口，所有"数据库增强"都挂在它身上——读写分离（my-xhs 的 `ReadWriteRoutingDataSource` 就是"读走从库、写走主库"的 DataSource）、慢 SQL 日志（P6Spy）、分库分表（ShardingSphere）——**全是 DataSource 的"包装"（设计模式叫装饰器）**。连接健康检查走 `Connection.isValid(timeout)`（规范接口，实验断言里用了——框架用它替代硬编码 `SELECT 1`）。

## 7. 元数据：ORM 凭什么"不知道表结构也能干活"

### 场景

MyBatis 帮你把查询结果变成对象。它怎么知道表 `account` 有哪些列？——它问数据库：**"你这张表长什么样？"** 数据库会如实回答。

JDBC 给了两个"问"的接口：

- `DatabaseMetaData`：问数据库（驱动名/版本/表结构）
- `ResultSetMetaData`：问查询结果（这一列叫什么/什么类型）

实验 `JdbcSpecTest.metadataIsUsable` 验证了：能读出表 `ACCOUNT` 的列名，也能读出查询结果的列名——**ORM、通用导出工具、数据库管理工具全靠它**。

---

## 本章小结：一条链回顾

```
jdbc:mysql://...（地址串）
  → 驱动认领（acceptsURL，SPI 自动加载——不用 Class.forName）
  → Connection（会话，用完要还——泄漏 = 事故）
  → PreparedStatement（SQL 骨架与参数分离——防注入）
  → 事务（setAutoCommit(false) + commit/rollback——ACID）
  → DataSource（连接池接口——借还语义，一切增强的挂载点）
  → 元数据（问数据库表长什么样——ORM 的地基）
```

**my-xhs 落地点**：连接池已用（Hikari + Prometheus 指标实证）/ 读写分离 DataSource 已用（ReadWriteRoutingDataSource——DataSource 包装的实战）/ 防注入由 MyBatis `#{}` 承接（底层就是 PreparedStatement）——**规范本体必须掌握，具体用法框架都替你包好了**。
