聊到 Java 微服务，大多数人只认识 Spring。但 Java 微服务不止 Spring 一家——**Quarkus、Helidon、Open Liberty** 这些框架背后有一套共同的标准：**MicroProfile**（Eclipse 基金会维护，2016 年启动）。它把微服务需要的"配置、容错、健康检查、OpenAPI、REST Client"等能力规范化了——Spring 是"一家公司说了算"，MicroProfile 是"一群厂商定的标准"。

## 1. MicroProfile Config 的核心思想：配置源就是 SPI

### 场景

你的应用配置来自很多地方：环境变量、配置文件、配置中心（Nacos/Apollo）、启动参数……MicroProfile Config 的答案：**把每个"配置来源"抽象成一个 `ConfigSource`（SPI），框架按优先级把所有 ConfigSource 合并成一张只读的 k-v 表**。

```java
// 自定义一个 ConfigSource（实验）——任何 k-v 来源都能接入
public class MemoryConfigSource implements ConfigSource {
    private final Map<String, String> properties;
    public String getValue(String propertyName) { return properties.get(propertyName); }
    public int getOrdinal() { return 300; }   // 优先级（ordinal），越大越优先
}
```

### 使用：getValue + 类型转换

```java
Config config = ConfigProvider.getConfig();         // 拿到合并后的配置
String name = config.getValue("app.name", String.class);   // 读取（自动类型转换）
Integer timeout = config.getValue("app.timeout", Integer.class);  // "30" → 30（内置 Converter）
```

实验 `MicroProfileConfigTest` 验证了三件事：①自定义 ConfigSource 可插拔 ②**ordinal 决定优先级**（ordinal 300 的源压过默认 100 的 application.properties）③**内置类型转换**（字符串自动转 Integer）——不存在的键返回空（`getOptionalValue`）。

### 注解方式：@ConfigProperty

CDI 环境（Quarkus 等）里用注解注入：

```java
@Inject
@ConfigProperty(name = "app.timeout", defaultValue = "30")
Integer timeout;
```

> 可跳过（进阶级）：
- **内置 ConfigSource**：框架自带环境变量/系统属性/`application.properties` 等源（实验里 ordinal 100 的默认源）——你的自定义源和它们按 ordinal 排队合并
- **占位符插值**：值里可以引用别的键——`url=${app.host}:${app.port}`（配置键可组合，注意循环引用会报错）
- **Profiles**（按环境选配置段）和 `ConfigSourceProvider`（一个 SPI 产生多个 ConfigSource）
- **配置键命名**：约定 kebab-case（`app.timeout`），大小写不敏感地解析

知道存在即可。

## 2. 与 Spring 配置的对照（教学价值所在）

| 概念 | Spring | MicroProfile Config |
|------|--------|-------------------|
| 配置来源抽象 | `PropertySource` | `ConfigSource`（SPI） |
| 读取 | `@Value("${key}")` | `@ConfigProperty(name=...)` |
| 绑定对象 | `@ConfigurationProperties` | `@ConfigProperty` 字段级（无对象绑定） |
| 类型转换 | `ConversionService` | `Converter`（内置） |
| 来源注册 | 框架内置固定几种 | **完全 SPI 可插拔** |

对照结论：**两套体系的骨架高度同构**（都是"来源抽象 + 注解读取 + 类型转换"），差异在微调——MicroProfile 把"配置来源"做成了纯 SPI（第一章的机制），Spring 更偏框架内置。**学会任何一套，另一套就是换皮**——这也是训练营 stage-2-24 讲完 Nacos/Apollo 后补一句 MicroProfile 的原因（配置的规范面互通）。

## 本章小结

**知识本体**：MicroProfile = 微服务能力标准家族（Config/Fault Tolerance/Health/OpenAPI/REST Client/Metrics）——训练营只覆盖 **Config**：ConfigSource SPI（来源抽象 + ordinal 优先级）→ Config 聚合读取（getValue/Converter 类型转换）→ @ConfigProperty 注解注入 + Profiles。
