# 维度一索引：规范（Standard）

> 定位：**"标准是什么"**——JDK/Servlet/JDBC/Validation/MicroProfile/Spring 抽象/云原生的规范本体
> 文章：7 篇（01~07）| 实验：8 个模块（spec-jdk/apt/servlet/jdbc/validation/microprofile/spring/protocol）
> 教学价值：**规范是知识本体——工具会过时，规范与机制永不过时**（4.7 的核心命题在此维度的展开）

---

## 一、维度定位

规范维度回答**"标准是谁定的、长什么样、怎么实现"**——从 JDK 原生规范到云原生生态规范。核心认知：**框架是规范的实现，规范是框架的契约**——学规范 = 学"为什么框架这么设计"。

## 三、维度内知识主线

```
JDK 规范（01——基础契约）
  ├── Web 规范（02 Servlet → 07 HTTP/Reactive/Triple——Web 栈的契约升级）
  ├── 数据规范（03 JDBC → 04 Validation——数据的读写与校验契约）
  └── 框架抽象（06 Spring 抽象 → 05 MicroProfile——"规范"的两种组织方式）
```

## 四、交叉主线（穿出本维度）

- **1.1 ↔ 4.7**：JDK 演进替代图谱（Base64/SPI/资源束被 JDK 收编——工具库的规范本体）
- **1.2 ↔ 5.1**：Servlet 生命周期 → Tomcat 调优（容器参数的契约面）
- **1.3 ↔ 5.4**：DataSource 契约 → 连接池（HikariCP 是 JDBC 的实现）
- **1.6 ↔ 4.5**：Spring 抽象契约 ↔ 扩展点实现（一体两面）
- **1.7 ↔ 5.3**：Reactive Streams 规范 → Reactive 本质（规范锚点）
