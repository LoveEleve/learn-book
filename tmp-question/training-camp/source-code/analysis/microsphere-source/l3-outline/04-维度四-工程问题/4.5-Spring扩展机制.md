# 26. Spring 扩展机制：扩展点的教学宝库

> 配套实验：`spec-spring/extension`（3 个断言——BPP/监听器/多播器——**spec-spring 模块共 7 个断言**，另 4 个 SpringSpecTest 在 1.6 章节）+ 1.6 章节（契约面）
> 定位：**扩展点实现面**——Spring 内部机制（BeanFactory/事件/Environment/生命周期）的扩展点怎么用；**契约在 1.6 章节、实现在这里**（一体两面）
> 来源：源码 03 二章、03 四章（注入点/事件拦截/请求匹配/@Enable）+ 04 二章（启动生命周期）+ 07 一章、07 7.3（子上下文）
> 前置：1.6 章节（@AliasFor/条件注解/生命周期契约）

microsphere-spring 是**Spring 内部机制的扩展点教学宝库**——每个 KP 都是一个"Spring 少用扩展点"的示范（官方把扩展点藏在框架内部，microsphere 把它们演示出来）。这一章把核心扩展点讲透：依赖注入解析、事件拦截链、生命周期监听、启动钩子、子上下文。

---

## 1. 依赖注入解析 SPI（03 2.1——BeanFactory 级）

**注入点四形态统一**（Field/Method/Constructor/Parameter——:83-112）：microsphere 把四种注入位置统一成"注入点"模型——**组合注册中心**（全量收集）+ **并行依赖解析**（CompletionService 提交-收集——:205——多个依赖并行解析提速）。

**对照**：Spring 内部**依赖图懒构建**（用到才解析）vs microsphere **主动全量预构建**（启动拓扑/优雅停机用）——**"懒 vs 主动"的两种依赖解析策略**。

---

## 2. 事件拦截链（03 2.2——多播器级 AOP）

**两级拦截**（事件级 + 监听器级）+ **回调式责任链**（拦截器手动 `chain.intercept()` 放行——**不调则链短路吞事件**——**AOP 环绕语义的事件版**——Servlet Filter 同款——2.7 的责任链同族）+ **继承官方多播器**（extends SimpleApplicationEventMulticaster——**final 防重写**——扩展不破坏官方语义）。

实验 `eventInterceptorChain` 验证了多播器分发的基础语义（事件 → 监听器）。

**应用**：Spring 事件统一埋点/审计（所有事件先过拦截器——2.10 的事件化 × 本仓库的拦截链）。

---

## 3. 生命周期监听与双钩（03 2.3/2.4）

**BeanFactory 三时点**（KP-211 族——Bean 定义注册/实例化/销毁三个关键时刻的监听——"在定义层面干预，不只是实例层面"）+ **Environment 双钩**（四组——系统属性/环境变量/配置文件/属性源的加载与变更监听面——2.2 配置联动）。实验 `beanPostProcessorHooks` 验证了 **BeanPostProcessor**（bean 初始化前后钩子——扩展点核心——官方 `AutowiredAnnotationBeanPostProcessor` 就是它（源码锚点）——所有"Bean 增强"都挂这里）。

**@Import 模板 + 可选导入**（03 2.6——`ImportSelector` 的 `selectImports` **按条件返回导入类**——"可选导入" = 满足条件才导入——4.2 条件装配的导入面）+ **@Enable 对称双注解 + 两级 Import 链**（03 4.3——Enable → Enable → Registrar + **@OverrideAnnotationAttributes 策略化覆盖**——4.2 的装配入口 × 本仓库的注解增强）。

**泛型 BPP 适配器**（03 2.5——类型化后处理器）+ **跨生态转换桥**（03 2.7——1.1 的转换家族在 Spring 面）。

---

## 4. 框架无关请求匹配与端点元数据（03 四章）

**WebRequestRule 六规则**（Methods/Params/Headers/Consumes/Produces/Pattens——泛型模板基座）：**Spring 官方在 servlet 和 reactive 重复定义两套 RequestCondition——microsphere 一套通用**（"一处定义，两栈使用"——2.7 双栈交叉）。

> **拼写教训（缺陷家族第 2 例）**：`WebRequestPattensRule`——**Pattens 拼错**（StacKTrace 后第二例——API 稳定约束）。

**端点映射元数据**（03 4.2——十字段模型：patterns/methods/params/headers/consumes/produces/negated 八条件 + Builder + hashCode 缓存）：**MVC 内部端点信息外部化**——网关路由发现/监控的基础（2.7 的 we:// 端点路由的元数据来源——能力消费链）。

## 5. 启动生命周期扩展（04 二章）

| 扩展 | 机制 |
|------|------|
| **RunListener 适配器**（04 2.1） | 8 回调空实现模板（子类只覆写需要的——:20）+ Logging 生命周期日志 + FailureReport 失败报告 |
| **一次性启动监听幂等**（04 2.2） | **按 contextId 幂等**（静态 Map 类级共享——同一监听器类所有实例共享处理记录——多 context 防重）+ final 模板方法 |
| **条件评估报告/启动诊断**（04 2.3） | 条件报告主动构建（官方 debug=true 才有）+ **FailureAnalyzer 三件套**（Exception + Analyzer + DiagnosisListener——构件冲突友好报错） |

**工程意义**：启动期是"最后一次能全局干预"的窗口（监听器/初始化器/BPP 都在这生效）——**启动钩子 = 治理的入口**（my-xhs 用 BeanPostProcessor 1 处/ApplicationListener 1 处实证）。

## 6. 子上下文隔离（07 一章 + 7.3——深潜）

**子上下文基座**（07 1.1——extends AnnotationConfigApplicationContext + postProcessBeanFactory 注入全定制）+ **refresh 12 步生命周期**（7.3——利用哪些步骤 :93——postProcessBeanFactory/finishRefresh）+ **Environment 合并深潜**（7.3——merge 语义/removeSynthesized/detach——合成源防污染——2.2 配置面联动）+ **Bean 回注**（1.2——跨上下文暴露——2.6 的两架构已述）。

**4.5 的核心命题**：子上下文 = "BeanFactory 三时点 × Environment 双钩 × 事件监听"的**组合应用**（一个完整扩展点的集大成案例——2.8 的事件传播链消费终点——**事件驱动重建**（07 1.3——DynamicJdbcConfigChangedEvent → 重建——2.8 详述，此处引用）。

## 本章小结

**知识本体**：Spring 扩展点 = 注入点解析（四形态统一 + 并行解析）+ **事件拦截链**（多播器级责任链——实验）+ **生命周期**（三时点/双钩/BPP——实验）+ **请求匹配/端点元数据**（框架无关 + 十字段模型——Pattens 拼写教训）+ **启动扩展**（RunListener/幂等/诊断）+ **子上下文**（组合应用集大成）。

**实验验证**：BPP 前后钩子 / ApplicationListener 生命周期 / 多播器分发（3 断言——spec-spring/extension）。

**my-xhs 判定**：BPP 已用（1 处）/ ApplicationListener 已用（1 处）/ 事件拦截链该用没用（统一埋点/审计参考——2.10 评估）/ RunListener 该用没用（启动钩子——官方扩展点）。
