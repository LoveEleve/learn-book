## 0. 经典三层架构（标题的本体）

**Controller（展示）→ Service（业务）→ DAO/Mapper（数据）**——MVC 分层的工程模板核心：每层只依赖下一层（依赖方向单一）+ 各层职责单一（参数校验/业务规则/SQL）。**所有微服务工程的模块划分（my-xhs 的 web/service/mapper 分层）都是这层的放大**——"三层"是"微服务分层"的原型。

---

## 1. REST 工程：服务端与客户端（stage-1-03/04 交叉）

**服务端**（stage-1-03——主属 1.4）：统一响应模型（ApiBase/ApiResponse/StatusCode——stage-1-03 KP-01~04）+ Bean Validation 校验（1.4 章节）+ 统一异常（@RestControllerAdvice——1.4 已述）。

**客户端**（stage-1-04）：**客户端 API 校验**（KP-01——请求参数的校验面——1.4 Bean Validation 的客户端应用）+ RestTemplate 的**三层扩展架构**（KP-03——请求工厂/拦截器/转换器）+ `ClientHttpRequestFactory` 装饰器模式（KP-04——连接池/超时配置的注入点）+ 客户端性能优化（KP-06——连接复用/超时）。

> **现代对照**（1.7 章节）：RestTemplate → WebClient → **HTTP Interface**（Spring 6 声明式——四客户端演进）。

## 2. 脚手架：Spring Initializr（stage-1-23/24）

### 运用面（stage-1-23）

start.spring.io 的模块化设计：**ProjectDescription（项目描述元模型）**（KP-04——类型/语言/依赖/版本的全量描述）+ **生成流程**（KP-05——ProjectGenerator + GenerationContext/Invoker/Result）+ **元数据与配置**（InitializrMetadata/Properties——KP-06——可扩展的生成器配置）。

### 原理面（stage-1-24）

生成调用的内部链（KP-02~06）：ProjectRequest → `ProjectGenerationInvoker`（生成调用流程）→ `ProjectDescription` 合成 → **`ProjectGenerationContext` 子上下文**（每个生成请求独立上下文——KP-05——**4.5 章节的子上下文模式在工程面的应用**）+ `ProjectContributor`（内容生成器——按项目类型定制）。

**工程意义**：脚手架 = "元模型 + 模板生成器"的架构（工程化效率的来源——"生成出来直接能跑"）。

## 4. 三高优化方法论（stage-3-02——贯穿一切优化的框架）

**六步循环**（02 篇——优化方法论的基座）：

```
评估定基线 → 改前测量 → 找瓶颈 → 改 → 改后测量 → 好则留坏则回滚
```

配套：瓶颈识别（KP-02——CPU/内存/IO/锁）/ 性能分析（KP-03——Profiler/JFR）/ 优化技术谱（KP-04——容器/JVM/框架/代码）/ 测试类型（KP-05——压测/微基准/端到端）/ 性能指标（KP-06——TPS/RT 分布）。

> **本 L3 的贯穿约束**：每主题的"现代实现映射"都要配套"改前基线 + 改后对比"（my-xhs P1-2 压测基线——最大的工程差距——2.9 已述）。

## 5. 架构升级（stage-3-03/06）

### 可观测整合（stage-3-03）

**微服务化改造模式**（KP-06——单体 → 微服务的拆法）。

## 6. RPC 架构升级（stage-3-10）

**Dubbo 定位与开源路线**（KP-01）：Apache 顶级项目——从阿里巴巴开源到 Apache 孵化——Dubbo 2.x（经典）→ 3.x（Triple/Proxyless——1.7/3.1 交叉）。

**Dubbo 调用链**（KP-02——服务暴露与消费）：Provider 暴露 → Consumer 引用 → **Invoker/Invocation 模型**（KP-06——RPC 调用的统一抽象——一切协议/集群/过滤都包装在 Invoker 上）+ **Filter 责任链**（KP-05——2.4/4.3 的责任链模式在 RPC 面）+ **Cluster 消费端链路**（KP-04——集群容错：Failover/Failfast）+ 注册中心抽象（KP-03——2.1 交叉）。

**升级动机**（stage-3 梳理）：HTTP 升级 → RPC（性能/强类型）——**RPC 是 HTTP 的升级路径**（1.7 章节的 gRPC/Triple 协议面在此工程化）。
