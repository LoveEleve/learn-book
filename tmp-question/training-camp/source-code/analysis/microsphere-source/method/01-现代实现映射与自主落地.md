# 01-现代实现映射与自主落地（source/ 提取 SOP）

> 角色：AI 自约束操作规范。microsphere-source 源码提取专用——**在 02 SOP 穷尽提取之上叠加三层处理**。
> 先修：microsphere-extraction methodology 02（穷尽逐文件提取）/ 08（需求→自主实现→参考实现）/ 04（过时三级）/ 09（前置与掌握度）
> 输入：单个 microsphere 仓库源码
> 试点实证：confucius-commons（2026-08-12，36 文件 35 KP，7 轮 review 修正 8 处断言错误）

## 核心原则

**"别人的东西，只有自己重写一遍 + 上真线才算自己的。"**

microsphere 源码提取的目标不是"分析代码"，而是四步落地：
```
microsphere 源码 → 知识点
  → ① 现代主流实现是什么？（具体类/库，本地源码验证 code/spring/）
  → ② 官方已实现？→ 标注 [已实现→链接源码分析文档]
  → ③ 官方没有？→ 写"如果我来实现"自主方案（可重写，进 my-xhs）
  → ④ my-xhs 结合：已用 / 该用没用（差距）/ 不该用（理由）
```

**穷尽提取不能丢**（02 SOP 完整保留）：宁可多提取标低置信度，也不遗漏——"触发点提取"会退回"按主题找文件"的老坑（02 反模式 2）。漏知识点的风险只在提取层，映射层只是附加值。

---

## 1. 提取流程（每仓库）

### 1.1 准备

1. 建 MCP 索引（02 §1.1，index_repository mode=full）
2. 读仓库上下文：README（定位）+ pom.xml（依赖链/版本）+ 模块结构 + 测试目录
3. 文件清单：`find src/main/java -name "*.java" | sort`——记录总数，逐批标注进度

### 1.2 分批提取（≤10 文件/批）

每批：**带行号读取源码（grep -n）** → 即时提取 → 测试同步扫描 → 产出映射 → 停批

**行号纪律（试点最重要教训）**：行号必须在**写入时**从 `grep -n` 输出抄录，禁止凭文件总行数估算或凭记忆——批 2 曾整批行号张冠李戴（AND :6-17 实际 :21-31）。

### 1.3 每批完成

- 写入文档（追加）
- **立即执行批判性 review**（§3），不等用户催
- 更新七项报告

### 1.4 仓库完成（单元确认门）

- 36 文件级穷尽自检：清单总数 = 已提取数
- 全文件残留扫描（grep 类名/行号在文档中出现的完整度）
- 停下交用户 review → 确认后下一仓库

## 2. 逐知识点原子记录（07 §1.3 + 三层叠加）

每个 KP 六元元数据 + 三层 + my-xhs：

```markdown
#### KP-NN {知识点}（{文件}:{行号}）

- **维度**：[规范/分布式问题/分布式理论/工程问题/性能优化] | **权重**：[核心/支撑/边缘] | **深度**：🔴/🟡/🟢 | **优先级**：P1/P2/P3 | **过时**：[有效/过时→替代/时间无关] | **置信度**：High/Medium/Low
- **前置**：{理解前需掌握的概念}
- **需求**：{解决什么生产问题}
- **自主实现**：{如果我来做，怎么设计}（核心产出）
- **参考实现**：{小马哥怎么做，file:line 实证}
- **对比取舍**：{我的方案 vs 参考差异 + 为什么}（缺陷/好实践都写）
- **机制/说明**：{🔴/🟡 才写——原理/关键组件}
- **测试佐证**：{测试断言验证了什么/暴露了什么}
- **my-xhs**：**已用**（链接）/ **该用没用**（差距项，进 my-xhs/ 清单）/ **不该用**（理由）
```

### 2.1 my-xhs 判定三分法

| 判定 | 含义 | 处理 |
|------|------|------|
| **已用** | my-xhs 已有同机制实现 | 标注 + 链接（如 zone 包） |
| **该用没用** | 官方/生态有缺口且 my-xhs 需要 | 进 my-xhs 差距清单（接 my-xhs-优化规划 P1/P2） |
| **不该用** | JDK/框架原生覆盖 / 无场景 / 过时 | 给理由（一句话） |

> **"不该用"也是有效判定**——工具库整包"不该用"（JDK 强替代）不构成"现状吞没知识"：每个 KP 的知识本体（JDK 机制）必须独立完整落位（08 §5-4 判据：知识本体 KP 无"现状"字样）。

### 2.2 过时判定要点（04 增强）

- 每个 KP 必须三级之一（有效/过时→替代/时间无关）
- **替代物必须给全**：具体类/机制 + 本地源码位置（04 §3.5）——如 `ProcessHandle.current().pid()`（JDK17 ProcessHandle.java:135）
- **"已弃用"断言必须实证**：如 ResourceBundle.Control——JDK17 实测未标 @Deprecated（ResourceBundle.java:2518），修正为"扩展路径迁移"（教训：凭印象标弃用 = 断言错误）
- **来源标注必须实证**：如 Base64 作者 Josh Bloch（:6）+ @see Preferences（:8）——实为 Preferences 复制非 sun.misc（教训：来源断言凭猜测 = 错误）

## 3. 批判性 review（每批必做，不等用户）

**自查（存在性）≠ 批判性 review（正确性）**。每批写入后立即执行：

1. **行号抽查**：本批所有 file:line 用 grep 实证（§1.2 纪律的复核）
2. **逻辑证伪**：对每个"缺陷/行为/语义"断言，回到源码读完整上下文——**重点看初始值/边界分支/运算符语义**（教训：XOR 初始值 true 实为 XNOR、"contains 子串匹配"非路径边界、空数组返回值）
3. **替代物实证**：JDK/Spring 替代物必须本地源码实测存在（code/spring/jdk17 + spring-framework）
4. **测试同步**：本批涉及文件对应的测试必须逐个扫描（02 §2.1 铁律）——测试暴露的行为/缺陷写入测试佐证
5. **来源归属**：移植/借鉴代码必须实证原作者标注（header 注释）
6. **过时断言**："弃用/移除"必须源码实证（@Deprecated 注解 / 类是否存在）

### 3.1 试点实证的坑清单（写入时对照）

| # | 坑 | 教训 | 来源 |
|---|----|------|------|
| 1 | XOR 用 `^=` 初始 true | 组合运算符语义必须算完整真值表——初始值决定语义（实为 XNOR） | KP-14 |
| 2 | `&=`/`|=` 非短路 | "看起来在做 AND"≠短路 AND——JDK `&&` 才是 | KP-14 |
| 3 | 行号凭估算 | 写入时必须 grep -n 抄录 | 批 2 整批 |
| 4 | contains 当路径前缀 | 子串匹配≠路径边界——兄弟目录误匹配 | KP-19 |
| 5 | "已弃用"凭印象 | @Deprecated 必须实证 | KP-30 |
| 6 | 来源凭猜测 | 移植代码查 header 作者 | KP-35 |
| 7 | 测试标记"存在"不扫描 | 测试必须逐个读断言 | 批 5 |
| 8 | 死代码未标注 | sun.reflect.Reflection JDK17 已移除——查类存在性 | KP-28 |

## 4. 产出文档结构

```
microsphere-source/
├── discussion/          ← 临时讨论
├── method/              ← 本文（方法论）
├── mapping/             ← 逐仓库：01-{仓库名}.md（穷尽映射表 + 三层叠加）
├── design/              ← 自主实现方案（官方缺口，进 my-xhs 的实现设计）
└── my-xhs/              ← my-xhs 落地规划（差距清单）
```

mapping 文档模板（07 §1.2 + 增强）：
1. 头部：源码位置/版本/批次进度/状态
2. 仓库定位（需求 + 维度）
3. 前置条件清单 + 掌握度
4. 逐文件映射 + 原子记录（按包分节）
5. 每包总结
6. my-xhs 落地判定汇总表
7. 测试扫描记录表（§四.5）
8. 深度 review 七项报告（逐轮累积）

## 6. 反模式

### 1. 跳过穷尽只做"三层叠加"

```
错误：只挑"有含金量"的文件做映射，工具类跳过
正确：36 文件全过——工具类可能是 JDK 机制的触发点（KP-01 findLoadedClass 来自工具类）
```

### 2. 批 2 式行号估算

```
错误：按文件总行数估算行号区间
正确：grep -n 写入时抄录，review 时再抽查
```

### 3. 测试只标注不扫描

```
错误："XXTest 存在（后续批扫描）"
正确：立即读断言——测试暴露的行为/缺陷是最佳佐证（XOR bug 未被测试捕获、SimpleClassScanner 缺陷被测试实证）
```

### 4. 过时/来源断言凭印象

```
错误："Control 已弃用" / "是 sun.misc 移植"
正确：@Deprecated 实证（未标）/ header 作者实证（Josh Bloch）
```
