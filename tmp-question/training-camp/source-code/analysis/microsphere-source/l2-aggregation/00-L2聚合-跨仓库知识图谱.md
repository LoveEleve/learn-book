## 一、跨仓库模式家族（本聚合最大价值——10 大复现模式）

> **核心发现**：microsphere 生态 14 个仓库不是 14 套独立知识——是 **10 大复现模式在不同领域的实例化**。学一个模式 = 懂多个仓库。

### 1.1 SPI 注册中心模式（10/14 仓库——生态核心 DNA）
- **来源**（深度 review 核对——05/08/12 无 SPI 修正）：01（SPI 类加载器）、02（SPI+Prioritized 选优——三处实证）、03（SpringFactoriesLoader 选择）、04（条件）、06（ZoneLocator 双通道装配）、07（4 SPI 管道——loadFactories 四族）、09（条件 SPI）、10（Serializers）、13（BeanSource 三源）、14（SentinelPlugin 仓库）
- **机制**：接口 + SpringFactories/ServiceLoader 加载 + Prioritized 排序 + 懒加载缓存（07 Processor :218-246 最完整）
- **变体**：双通道装配（06 ZoneAutoConfiguration loadFactories + Bean 收集）、多态分派（BeanSource 枚举——13 正确 vs 手写 switch 缺陷）
- **知识本体**：SPI 扩展点的完整设计（加载/排序/缓存/兜底）

### 1.2 事件化模式（11/14 仓库）
- **来源**：02（EventDispatcher 族）、03（事件拦截链/Environment 双钩）、05（注册四态事件）、06（ZoneContextChangedEvent 双事件桥接）、07（DynamicJdbcConfigChangedEvent 传播链）、08（PropertySourcesChangedEvent）、10（RedisCommandEvent）、11（P1 时序陷阱）、14（RedisCommandEvent 对应）
- **机制**：事件载体 + 发布者 + 监听器 + **时序纪律**（11 P1：自动配置 @EventListener 早期事件永不触发——时序铁律）
- **变体**：双事件桥接（06 JavaBeans→Spring）、事件传播链（03→06→07 三仓库接力）、事件 AOP（05 注册切面）

### 1.3 条件注解模式（10/14 仓库——深度 review 核对修正）
- **来源**：04（前缀条件/可选依赖）、06（可用⊃启用组合）、09（Gateway 条件族）、10（Redis 条件族）、11（P2 @ConditionalOnBean name/value 陷阱）、12（MyBatis 条件）、13（Druid 条件）、14（四重条件——跨仓库条件消费）
- **机制**：@ConditionalOnXxx 组合 + matchIfMissing 默认 + 类名探测（无编译依赖）
- **陷阱**：P2 name=bean 名/value=类（11——官方 micrometerClock 实证）

### 1.4 模板方法模式（9/14 仓库）
- **来源**：01（AbstractSerializer——01 也是）、02（Abstract 基座）、05（AbstractServiceRegistration）、07（AbstractConfigurationConfig* 四族）、10（AbstractSerializer 定长）、12（Abstract*Test）、13（AbstractStatementFilter 491→13→2 收敛）、14（AbstractSentinelPlugin + SentinelTemplate）
- **机制**：final 路由 + 抽象回调 + 子类最小实现
- **极致案例**：13 三层收敛（491 方法 → 13 final → 2 回调）

### 1.5 缓存与热更新模式（8/14 仓库——深度 review 核对修正）
- **来源**：05（Feign 组件注册表+装饰器）、06（Composite 缓存+系统属性回写）、07（DynamicDataSource delegate 交换+延迟关闭）、08（Apollo 克隆替换——属性级 vs Bean 级）、09（Filter 链缓存）、10（ConfigClient 缓存——D1 HashMap）、11（SkipList 去重副作用）、12（MethodMetadata 索引——V0/V1）
- **机制**：volatile/mutex 交换 + 事件驱动失效 + 延迟关闭
- **粒度对照**：属性级克隆替换（08）vs Bean 级子上下文重建（07）vs 池级预建切换（my-xhs）

### 1.6 线程池与并发模式（7/14 仓库）
- **来源**：02（ExecutorUtils shutdownOnExit）、03（并行 Bean 初始化——ParallelEventDispatcher）、05（监控线程池）、06（Composite 并行定位）、07（并行子上下文+InitializeErrors ConcurrentHashMap）、10（closeScheduler 延迟）、11（P1 时序）
- **机制**：newFixedThreadPool 并行 + 错误聚合（putIfAbsent 首错保留）+ 生命周期（shutdownOnExit）
- **缺陷**：忙等轮询无超时（07 R1）

### 1.7 框架无关抽象 + 适配器桥接模式（6/14 仓库）
- **来源**：03（跨生态转换桥）、05（ReactiveDiscoveryClientAdapter）、10（双层代理——观察者非守卫）、11（Filter 抽象+Log4j2 桥接）、12（Interceptor↔ExecutorFilter）、14（插件+扩展点双实现）
- **机制**：自研抽象 + 框架适配器 + 定位决策（可干预 vs 纯观察）

### 1.8 元数据/编译期生成模式（4/14 仓库）
- **来源**：02（配置元数据三阶段闭环 + APT）、09（metadata 协议——G12 无版本号）、10（Doclet 生成命令元数据）、05（Features）
- **机制**：编译期生成（APT/Doclet）→ 运行时加载
- **对照**：02 APT vs 10 Doclet——两种编译期生成路径；09 无版本号缺陷 vs 10 V0/V1 版本字节

### 1.9 反射读私有字段模式（5/14 仓库——脆弱性家族）
- **来源**：01（findLoadedClass/Unsafe）、02（MethodHandle 版本探测）、09（G8 globalFilters）、12（P1 CachingExecutor.delegate）、10（MethodHandle resetContextMap）
- **风险**：框架升级静默失败（G8/P1）

### 1.10 错误聚合/失败处理模式（5/14 仓库）
- **来源**：07（InitializeErrors/ValidationErrors——ConcurrentHashMap 首错）、06（fast-fail 两种语义）、09（G15 静默 200）、11（静默失效家族）、14（高基数）
- **机制**：收集 + 聚合 + 首错保留 vs 静默（可观测性缺口）
