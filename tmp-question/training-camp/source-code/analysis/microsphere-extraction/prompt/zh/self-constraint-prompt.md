# AI 自约束启动契约

> **每次提取前必读。** 此文是绑定契约。违反本文任何规则意味着提取无效。
> 权威来源：核心约束（§1）提取自 methodology/00-07。
> 阅读顺序：00 → 01 → 02 → 03 → 04 → 05 → 06 → 07 → 本文（最后读，作为执行摘要）。

---

## 1. 核心约束

开始任何提取前，全部验证通过。任何一条不满足，不得继续。

### 防编造

1. **每个类名、接口名、方法签名必须 grep/源码验证**后才能写入产出。不确定的写 `[待验证]`——不得猜测。
2. **每个知识点必须可追溯到源码 `file:line` 或 docs 章节。** 不从名称推断。
3. **不得在未 grep 确认的情况下写技术名称**（如某注解、某配置项、某 Key 前缀）。
4. **每个代码块要么逐字来自源码（标注 `file:line`），要么标 `[伪代码]`。**

### 流程完整

5. **必须先完成提取（01 课程 / 02 源码），才能进入聚合分类（03）。** 穷尽性是保证。
6. **禁止"后面讲"——所有依赖必须先提取。** 参考依赖图（00 + 05）。
7. **每个结论必须标注来源位置：** 源码 `file:line` 或 docs 章节。
8. **穷尽性优先**：宁可多提取、标注低置信度，也不遗漏任何单元。这是本框架存在的意义——之前的梳理"不齐全"就是因为遗漏了文件。
9. **课程与源码的关联必须源码验证**（06）——不能凭课程标题和仓库名"看起来像"就下结论。

### 深度与维度标准

10. **问"这个文件/章节承载什么知识点？"——而非"这个文件重要吗？"**（01/02）。所有单元都过。
11. **连续多个文件是纯 getter/setter → 归为 🟢 表层，不深挖。**（03）
12. **每个知识点必须打维度标签**（规范/分布式问题/分布式理论/工程问题/性能优化）——这是更高层次抽象的关键（03 §1）。
13. **规范/理论维度的知识点通常加权到 🔴**，因为承载标准/理论（03 §3.3）。
14. **过时内容必须处理**：三级过时状态（有效/过时→替代/时间无关模式）——过时工具提取底层模式（04）。
15. **总大纲按 5 大维度组织，而非按仓库**——同一主题跨课程/跨仓库聚合（05 §1.1）。

### 禁止批量操作（质量铁律）

16. **禁止一次性批量生成全部单元。** AI 极容易"一篇/一仓库一次性全生成"，结果必然是编造、重复、深度不足、质量崩塌。必须**逐单元、小步、可审查**地推进。
17. **每个单元（一篇 docs / 一个仓库）独立完成后，必须停下来交给用户 review，用户确认后才进入下一个单元。** 未经确认不得连续推进多个单元。
18. **单次会话推进上限**：默认一次只做 **1 个单元**（一篇 docs 或一个仓库）的完整提取 + 分类。用户明确要求扩大时才可一次 2-3 个，但每个仍独立 review。
19. **逐文件扫描时也禁止"一次扫完所有文件再一起写"** ——应分批读（每批 ≤10 个文件）→ 即时提取 → 再下一批，避免上下文超载导致质量稀释。
20. **聚合/聚类/关联同样禁止一次性全做**——按维度或 Cluster 分批，每批确认。

### 规划期盘问（grill-me）

21. **任何提取动手前，先运行 `skills/zh/grill-me.md` 盘问**：把「提取对象/范围/深度/顺序」一问一答盘问清楚，**达成共识后才能开工**。
22. **事实自查、决策等用户**：能用 bash/MCP 查到的事实绝不问用户；范围/深度/优先级等**决策必须等用户**，绝不 AI 自答。
23. **方向性分歧时立即回到盘问**：当用户说"不对 / 你不理解"时，暂停执行，回到 grill-me 重新对齐。

### 需求转换与自主实现视角

24. **小马哥课程/源码只是参考，不是知识本体。** 每个知识点都要带"需求 + 自主实现 + 参考实现"三层次（08）——先想"解决什么生产问题 + 如果我来实现会怎么做"，再对照小马哥/源码。禁止只翻译源码。
25. **技术基准 JDK11/JDK17**：过时判断与 JDK 机制验证以 JDK11/JDK17 为准。涉及 JDK 机制（ClassLoader/Unsafe/反射/GC/并发）的断言，用 JDK11（`openjdk11u`）/JDK17（`code/spring`）源码验证，验证不了标 `[待验证]`。

### 前置知识与掌握度

26. **每个知识点必须标注前置知识** `[前置:...]`——读者理解它之前需掌握的概念；每篇/每仓库篇首列"前置条件清单" + 补基础路径（09）。
27. **知识掌握度是决策，必须盘问用户，AI 不得自猜**——目标读者（初级/中级/高级）决定讲解深度和补前置程度。不确定时默认中级并标 `[待确认：读者掌握度]`（09 + grill-me）。

## 2. 提取前问题

**任何单元提取前必问。** AI 先提出推荐答案，用户确认或纠正。如果 AI 能从源码自己找到答案（README、pom.xml、类名），**不要问用户**——自己找。

| # | 问题 | AI 能自己答吗？ | 怎么找 |
|---|------|---------------|--------|
| Q1 | 提取哪个单元？（哪期课程/哪个仓库） | **能** — 从目录名 | `ls` 根目录 |
| Q2 | 单元定位是什么？ | **能** — 从 README/docs | `Read README.md` |
| Q3 | 深度期望？ | **不能** — 用户判断 | AI 推荐："🔴 全量深提取，🟡 标准" |
| Q4 | 本次提取范围？ | **不能** — 用户判断 | AI 推荐："训练营 4 期 + microsphere 全部仓库" |

### 规则

- **Q1-Q2**：AI 必须从源码自己找答案。找不到才问用户。
- **Q3-Q4**：用户必须回答（或确认 AI 的推荐）。这些决定深度和范围。
- **绝不问用户 AI 自己能查到的东西。** 从源码找事实，不从用户找事实。

## 3. 单元提取检查单

### 单元级（每个单元一次，第一个文件/章节之前完成）

- [ ] **MCP 索引已建**（源码单元）：`index_repository` 已建当前仓库索引（02 §1.1）
- [ ] **上下文已读**：README、包结构、pom.xml、测试目录（01/02）
- [ ] **单元清单已确定**：docs 清单 或 `find src/main/java -name "*.java"`（01/02）
- [ ] **依赖已映射**：当前单元的机制层依赖已确认（00）

### 逐项级（每篇 docs / 每个文件）

- [ ] **知识点已提取**：该单元承载的知识点已记录（01 §2 / 02 §2）
- [ ] **维度已标注**：每个知识点有维度标签（03 §1）
- [ ] **置信度已标注**：High/Medium/Low（01/02）
- [ ] **来源位置已记录**：docs 章节 或 `file:line`

### 单元完成（最后一项之后）

- [ ] **所有单元已覆盖**：docs 全部章节 / `find` 每个文件都有映射
- [ ] **聚合完成**：跨单元去重，P1/P2/P3 已分配（03 §1）
- [ ] **维度已分配**：每个知识点有维度标签（03 §1）
- [ ] **过时已处理**：每个知识点有三级过时状态（04，按 JDK11/JDK17 基准）
- [ ] **需求/自主实现已记录**：每个知识点有"需求 + 自主实现 + 参考实现"（08）
- [ ] **前置知识已标注**：每个知识点有 `[前置:...]`，篇首有前置清单（09）
- [ ] **掌握度已对齐**：目标读者已盘问/确认（或标 `[待确认]`）（09）
- [ ] **深度已分配**：🔴/🟡/🟢 已标注，含理由 + 规范/理论加权（03 §3）
- [ ] **聚类完成**：知识点按维度归入 Cluster，教学顺序拓扑化（05）
- [ ] **逐单元文档已产出**：按 07 §1 模板（07）

### 单元确认门（每个单元完成后强制执行）

- [ ] **已停下来交给用户 review**：当前单元（一篇 docs / 一个仓库）已完成完整提取 + 分类
- [ ] **用户已确认**：用户确认后才进入下一个单元
- [ ] **未批量推进**：没有在用户未确认的情况下连续做多个单元

### 规划盘问门（G0，每个项目/新单元开始前）

- [ ] **已 grill-me 盘问**：动手前已一问一答盘问「范围/深度/对象/顺序」
- [ ] **已达成共识**：用户确认了盘问结果后才开始执行
- [ ] **事实已自查**：能用 bash/MCP 查到的事实已自查，未问用户

## 4. 踩坑清单

写完之后、展示之前检查。

- [ ] **无编造类名**——每个类/接口名 grep 验证过源码（§1 #1）
- [ ] **无遗漏单元**——每个文件/章节都有映射，无静默跳过（§1 #8）
- [ ] **无"已记录"逃避**——每个发现要么已提取，要么已证明不是知识点
- [ ] **无代码块当伪代码**——所有代码块要么逐字来自源码（标注），要么标 `[伪代码]`（§1 #4）
- [ ] **无过期索引**——提取前验证 MCP 索引新鲜（02 §1.1）
- [ ] **无未验证关联**——课程 ↔ 源码关联都 grep/源码验证过（§1 #9）
- [ ] **无缺失维度**——每个知识点都有维度标签（§1 #12）
- [ ] **无未处理过时**——过时工具都提取了底层模式并映射现代替代（§1 #14）
- [ ] **无批量操作**——没有一次性生成多个单元；每个单元都已交用户 review 并确认（§1 #16-20）
- [ ] **无未盘问开工**——动手前已 grill-me 盘问并达成共识，未自答决策（§1 #21-23）
- [ ] **无源码翻译**——每个知识点都带"需求 + 自主实现 + 参考实现"三层次，非只翻译源码（§1 #24）
- [ ] **无未验证 JDK 断言**——JDK 机制断言已用 JDK11/JDK17 源码验证或标 `[待验证]`（§1 #25）
- [ ] **无缺失前置**——每个知识点有 `[前置:...]`，未假设读者全都会（§1 #26）
- [ ] **无自猜掌握度**——读者画像已盘问/确认或标 `[待确认]`，未 AI 自猜（§1 #27）

## 5. 等等——用户中断信号

**用户可以在任何时候中断 AI**，通过说：
- "wait" / "stop" / "不对" / "等等"
- "我听不懂" / "重新讲"

当用户说任何一句：

1. **立即停止当前提取** —— 不继续到下一阶段
2. **重新说明当前状态** —— 你在哪里、已经做了什么、接下来要做什么
3. **请求澄清** —— "哪里没跟上？需要重新讲哪里？"
4. **不继续** —— 直到用户确认理解正确

---

## 违例处理

提取过程中违反 §1 任何规则：

1. **立即暂停当前阶段。**
2. **修复违例**——重读受影响源码、重新 grep 缺失声明、回溯到违例阶段。
3. **违例未解决前不得进入下一阶段。**
4. **违例不可修复时**（如依赖仓库未提取），标记为 [BLOCKED]，转向下一个可提取仓库。
