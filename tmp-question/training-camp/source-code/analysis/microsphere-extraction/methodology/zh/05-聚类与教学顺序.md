# 聚类与教学顺序

> 角色：AI 自约束操作规范。知识点聚合分类完成后，做聚类和教学排序前必读。
> 先修：`03-聚合与深度分类.md`
> 输入：单主体（课程或源码）的聚合 + 分类结果
> 阅读顺序：00 → 01/02 → 03 → 04 → 05（本文）→ 07。

## 核心原则

知识点是"点"，聚类是"线"——把散落的知识点按概念依赖关系组织成教学序列。教学顺序 = 拓扑序：依赖先讲，被依赖后讲。

**维度是聚类的主纲**：每个知识点已带维度标签（03），聚类**先按维度分组**（规范/分布式问题/分布式理论/工程问题/性能优化），再在维度内按概念依赖排序。这样同一主题的知识点（无论来自课程还是源码）聚合在一起。

**禁止前向引用**："后面会讲"是错误的教学组织方式。任何复杂知识点 = 基础知识点组合。A 依赖 B → 先讲 B，再讲 A。

---

## 1. 聚类

### 1.1 先按维度分组

每个知识点已带维度标签（03 §1）。聚类第一层按维度：

```
维度一：规范
  Cluster 1.1 Servlet 规范实现
  Cluster 1.2 JDBC 规范实现
维度二：分布式问题
  Cluster 2.1 服务发现
  Cluster 2.2 分布式事务
...
```

### 1.2 维度内按概念依赖聚类

在维度内，把功能相关、依赖相关的知识点归为 Cluster。每个 Cluster 有一个主题名。

```
Cluster A: {主题}（N KP）
  KP1, KP2, KP3 — 依赖关系：KP1 是基础，KP2/KP3 构建其上
```

### 1.3 依赖判断

"KP A 依赖 KP B" = 不理解 B 的机制，就无法理解 A 的行为或设计原因。这是机制层面依赖，不是"相关"。

---

## 2. 教学顺序 = 拓扑排序

### 2.1 维度级顺序

先讲**基础理论/基础规范**，再讲**应用性问题**，最后讲**性能优化**：

```
分布式理论 → 规范 → 分布式问题 → 工程问题 → 性能优化
（理论是基础，规范定义契约，问题是应用，工程是组织，性能是调优）
```

### 2.2 维度内 Cluster 顺序

```
Cluster A（无前置依赖）
  → Cluster B（依赖 A）
  → Cluster C（依赖 A+B）
  → ...
```

### 2.3 跨维度依赖

若 Cluster 依赖其他维度的知识点，先讲被依赖维度。例如"分布式事务实现（分布式问题）"依赖"Jakarta Transactions / XA 规范（规范）"→ 先讲规范维度。

### 2.4 环形依赖处理

若 Cluster 间有环，用三轮化解：
1. 找出环中的公共基础点，提到环外先讲
2. 打破一个最小依赖边
3. 若无法打破，合并环内 Cluster

## 5. 反模式

### 1. 重要性决定顺序

```
错误：CFS 是 🔴 → 先讲 CFS
正确：依赖决定顺序。重要性决定深度，不决定顺序。
```

### 2. 前向引用

```
错误："SPI 优先级（将在事件系统讲解）"——前向引用未学概念
正确：SPI 优先级依赖理解 SPI 加载器 → 先讲 SPI 加载器
```
