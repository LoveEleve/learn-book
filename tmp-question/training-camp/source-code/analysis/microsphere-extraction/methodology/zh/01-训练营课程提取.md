# 训练营课程提取

> 角色：AI 自约束操作规范。对训练营课程（stage-1~4 的 docs 文档 + 示例代码）做知识点提取前必读。
> 先修：`00-项目清单与依赖.md`
> 输入：训练营课程文档与示例代码
> 阅读顺序：00 → 01（本文）→ 03 → 04 → 05 → 06 → 07。

## 核心原则

训练营课程是**教学主线**，microsphere 是底层生态。课程提取的目标是：**逐篇 docs 提取知识点，并标注它与 microsphere 生态的关联**。

课程提取与源码提取不同：docs 是**文本**，源码是**代码**。课程提取单位是"一篇 docs"，不是"一个文件"。

---

## 1. 提取单位

| 主体 | 提取单位 | 产出 |
|------|---------|------|
| docs 文档 | 一篇 docs | 章节 → 知识点列表 |
| 示例代码 | 一个示例类/方法 | 佐证 docs 知识点（不独立成知识点） |
| 论文/电子书 | 一篇论文 | 经典理论知识点（🟢/🟡） |

### 1.1 docs 提取

每篇 docs 是一个提取单元。对每篇 docs：

```
读全文 → 识别知识点（章/节标题 + 正文） → 产出知识点列表
```

**知识点来源**：
- 章节标题明确命名的概念（如"CAP 定理"）
- 正文中承载设计决策的机制（如"Maven 依赖仲裁规则"）
- 示例代码佐证的实现

### 1.2 示例代码

示例代码（stage-1 biz-project、stage-2 middleware-projects）作为 docs 的佐证：
- 不作为独立提取对象
- 当示例代码有独立于 docs 的知识点时才单独提取（标注来源）

### 1.3 论文/电子书

stage-2 的 10 篇经典论文（paxos/raft/zab/拜占庭/BASE 等）可提取经典理论知识点，但标记为 🟢（背景理论）或 🟡（有设计决策）。

---

## 2. 逐篇提取产出格式

```markdown
## 01 课程提取 — 逐篇映射：{stage-N}

### docs: {第 X 节：标题}

| 章节/知识点 | 维度 | 过时状态 | 置信度 | 关联 microsphere |
|------------|------|---------|--------|-----------------|
| {知识点} | {规范/分布式问题/分布式理论/工程问题/性能优化} | {有效/过时→替代/时间无关} | High/Medium/Low | {关联仓库} |
| {知识点2} | ... | ... | ... | ... |
```

---

## 3. 与源码提取的关系

课程提取在源码提取之前或之后均可，但**合并阶段**（05）需要两者的知识点才能做关联分析。

**维度标签**：每篇 docs 的知识点打维度标签（03 §1），供聚类和总大纲按维度组织。

**关联标注**：每篇 docs 的知识点标注它可能关联的 microsphere 仓库（如"服务容错 → microsphere-resilience4j / microsphere-sentinel"）。关联是**推断**，标注 `[待验证]` 直到在源码中验证。

**过时处理**：课程文档中过时的工具/版本按 04 处理（如 stage-1 的 Eureka → 标 `[过时→Nacos]`）。

**分批纪律（质量铁律）**：
- **禁止一次性读完全部 docs 再一起写**。
- 每篇 docs 独立提取 → 完成后**停下来交给用户 review** → 用户确认后进入下一篇。
- 每期（stage-N）可作一个批次单位，但期内仍逐篇独立确认。

---

## 4. 完成检查单

- [ ] **所有 docs 已提取**：stage-1~4 的每篇 docs 都有映射
- [ ] **知识点已识别**：每篇 docs 的章节标题和设计决策已提取
- [ ] **维度已标注**：每个知识点有维度标签
- [ ] **过时已处理**：过时工具/版本按 04 标注现代替代
- [ ] **置信度已标注**：High/Medium/Low
- [ ] **关联已标注**：每个知识点标注关联的 microsphere 仓库（推断标 `[待验证]`）
- [ ] **示例代码已佐证**：docs 知识点已与示例代码核对
- [ ] **论文已提取**：stage-2 论文的经典理论已提取（🟢/🟡）
- [ ] **已交用户 review**：每篇 docs 已停下确认，无批量连续提取多篇

---

## 5. 反模式

### 1. 批量一次性扫描全部 docs

```
错误：一次性把 24 篇 docs 全读完全部提取
     （上下文超载 → 编造、浅尝辄止 → 质量崩塌）
正确：逐篇提取 → 每篇完成后停下交用户 review → 确认后下一篇。
```

### 2. 每期只做一个汇总不逐篇

```
错误：按 stage-N 只写一个笼统的"本期主题"汇总
正确：逐篇 docs 独立提取知识点，粒度到章/节。汇总只是最后的聚合。
```
