# 产出格式

> 角色：AI 自约束操作规范。所有提取产出必须符合本节模板。
> 先修：`01-训练营课程提取.md` / `02-源码逐文件提取.md` → `03-聚合与深度分类.md` → `04-过时内容处理.md` → `05-聚类与教学顺序.md` → `06-关联分析.md`
> 输入：两主体的提取/聚合/分类/聚类/过时/关联分析结果
> 阅读顺序：00 → 01/02 → 03 → 04 → 05 → 06 → 07（本文）。

## 核心原则

产出分两级：
1. **逐单元提取文档**：
   - 训练营课程：**每期一份**（stage-1~4 各一份，内含该期全部 docs 的逐篇映射）
   - microsphere 源码：**每个仓库一份**
2. **总教学大纲**：两主体都提取完成后，合并成**按维度组织**的跨主体总教学大纲，附关联分析

**关键**：总教学大纲**按 5 大维度组织**（规范/分布式问题/分布式理论/工程问题/性能优化），而非按仓库。这样同一主题的知识点（无论来自课程还是源码）聚合在一起。

> **粒度约定**：课程提取文档按"期"（stage-N）聚合，文档内部按"篇"（docs）分节；源码提取文档按"仓库"聚合，文档内部按"文件"分节。

## 1.3 单个知识点的记录格式（原子单元）

每个知识点在映射表/聚合表/大纲中，统一用如下**原子记录**呈现。这是知识点的最小可交换单元：

```markdown
- **{知识点名称}**
  - 维度：{规范/分布式问题/分布式理论/工程问题/性能优化}
  - 深度：🔴/🟡/🟢 | 优先级：P1/P2/P3 | 过时状态：{有效/过时→替代/时间无关}
  - 前置：{理解本知识点前需掌握的概念}（09）
  - 需求：{解决什么生产问题}（08 需求层）
  - 自主实现：{如果我来做，怎么设计}（08 自主实现层——核心产出）
  - 参考实现：{小马哥/源码怎么做，file:line}（08 参考实现层）
  - 对比取舍：{自主方案 vs 参考的差异 + 为什么}
  - 来源：{源码 `file:line` 或 docs 章节}
  - 机制/说明：{工作层/深层才写——原理、为什么、关键组件}
  - 关联 microsphere：{课程知识点才写}
  - 测试佐证：{可选——测试暴露的行为/边界}
```

**深度对应的填写要求**：
- 🟢 表层：只写"定义"（一句话）+ "需求"
- 🟡 工作层：写"定义 + 需求 + 自主实现 + 参考实现"
- 🔴 深层：写"定义 + 需求 + 自主实现 + 参考实现 + 对比取舍 + 机制/说明 + 关键组件"（可含源码佐证）

> **三层次视角**（08）：所有深度都要带"需求 + 自主实现"视角。🟢 至少写"需求"；🟡/🔴 必须写"自主实现 + 参考实现对比"。这是本框架的核心价值——小马哥源码只是参考。

## 3. 统一标记

| 标记 | 含义 |
|------|------|
| `[待验证]` | 不确定性，需源码确认 |
| `[缺口：{概念}]` | 知识缺口 |
| `[BLOCKED]` | 阻塞（依赖单元未提取） |
| `[N=1]` | 单单元信号，无法交叉验证 |
| `[空壳]` | 0 Java 文件仓库 |
| `[有效]` / `[过时→{现代替代}]` / `[时间无关模式]` | 过时状态（04） |
