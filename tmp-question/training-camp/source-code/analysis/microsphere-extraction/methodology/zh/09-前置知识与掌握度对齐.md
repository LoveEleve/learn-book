# 前置知识与掌握度对齐

> 角色：AI 自约束操作规范。**贯穿所有提取**。提取的知识点是给"学习者"看的，必须考虑读者需要的前置知识，以及读者的起点水平。
> 先修：`00-项目清单与依赖.md` → `08-需求转换与自主实现视角.md`
> 输入：提取到的知识点
> 阅读顺序：00 → 08 → 09（本文）→ 01/02 → 03 → 04 → 05 → 06 → 07。

## 核心原则

**"读者需要前置知识才能理解某个知识点；读者的起点水平决定讲多细、补多少。"**

- 前置知识：理解某个知识点/某篇 docs **之前**必须掌握的基础概念
- 知识掌握度：读者的起点水平（初级/中级/高级），决定讲解深度和是否需要补基础
- **知识掌握度是"决策"，必须由用户/读者定，AI 不得自猜**（纳入 grill-me 盘问）

---

## 1. 前置知识标注

### 1.1 每个知识点标注前置条件

```markdown
**{知识点名称}**
- 前置：{理解本知识点前需掌握的概念，如 Maven、JVM 类加载、依赖仲裁}
- ...
```

### 1.2 每篇 docs / 每仓库标注"前置条件清单"

在篇首列出读者要理解本文需先掌握的基础：

```markdown
## 前置条件清单
读者需先掌握：
1. {基础1}（如 Maven 基础用法）
2. {基础2}（如 JVM 类加载机制）
3. ...
未达前置者，先补：{建议的补基础路径}
```

### 1.3 前置知识的来源

- 本篇/本仓库**依赖**的其它知识点（依赖图，见 05）
- 读者**默认应该会**的基础（如 Java 语法）——但这也要**明确列出**，不默认

---

## 2. 知识掌握度对齐

### 2.1 掌握度分级

| 级别 | 画像 | 讲解策略 |
|------|------|---------|
| **初级** | 基础概念不熟 | 每篇先补前置基础，放慢节奏，多解释"为什么" |
| **中级** | 会用但不懂原理 | 讲机制 + 设计决策 |
| **高级** | 懂原理 | 直接讲权衡/取舍/源码对照 |

### 2.2 掌握度必须盘问（grill-me）

**知识掌握度是"决策"，不能 AI 猜。** 在 G0 或每单元开始前盘问：

```
❓ 读者画像：本教学大纲的读者是初级/中级/高级？
➡️ 我建议：{根据任务判断，如"中级偏上——训练营学员"}
```

- 读者级别不同，同一篇的讲解深度、是否需要补前置、是否给源码对照都不同
- **不确定时，AI 默认按"中级"处理，并标注 `[待确认：读者掌握度]`**

### 2.3 掌握度与深度的关系

- 🔴 深层：高级读者直接讲；中级需先补前置；初级需先讲基础
- 🟢 表层：各级都一样，一句话定义
- **深度的"补前置"程度由掌握度决定**

---

## 3. 产出格式

每篇 docs / 每仓库提取文档增加"前置知识"和"掌握度"两部分：

```markdown
## 前置条件清单
读者需先掌握：{列表}
未达前置者，先补：{路径}

## 掌握度
目标读者：{初级/中级/高级}
讲解策略：{根据掌握度调整}
```

---

## 4. 完成检查单

- [ ] **前置知识已标注**：每个知识点有 `[前置:...]`
- [ ] **前置清单已列**：每篇/每仓库篇首有前置条件清单
- [ ] **掌握度已对齐**：读者画像已盘问/确认（或标注 `[待确认]`）
- [ ] **补前置路径已给**：未达前置者知道怎么补
- [ ] **讲解策略已调整**：根据掌握度调整了深度和补基础

---

## 5. 反模式

### 1. 假设读者全都会

```
错误：直接讲依赖仲裁，假设读者懂 Maven
正确：标注"前置：需理解 Maven 依赖机制"，并给补基础路径
```

### 2. AI 自猜读者水平

```
错误：AI 默认读者是高级工程师
正确：知识掌握度是决策，盘问用户确认，不确定标 [待确认]
```

### 3. 前置知识不列清单

```
错误：只在正文提"前置"字样，不系统列出
正确：篇首有完整前置条件清单 + 补基础路径
```
