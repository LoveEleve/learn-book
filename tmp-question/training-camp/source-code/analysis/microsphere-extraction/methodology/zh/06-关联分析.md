# 关联分析

> 角色：AI 自约束操作规范。训练营课程和 microsphere 生态都提取完成后，做两者关联分析前必读。
> 先修：`01-训练营课程提取.md` → `02-源码逐文件提取.md` → `03-聚合与深度分类.md` → `04-过时内容处理.md` → `05-聚类与教学顺序.md`
> 输入：两主体的提取结果
> 阅读顺序：00 → 01/02 → 03 → 04 → 05 → 06（本文）→ 07。

## 核心原则

训练营课程（stage-1~4）是**教学主线**，microsphere 生态是**底层生态代码**。关联分析要回答："每篇课程/每个主题用到了哪些 microsphere 仓库？"以及"每个 microsphere 仓库支撑了课程的哪个主题？"

**关联必须源码验证**——不能凭课程标题和仓库名"看起来像"就下结论。课程提到某个技术栈，要 grep 确认对应 microsphere 仓库确实实现了它。

---

## 1. 关联方向

### 1.1 课程 → 源码（正向）

每篇 docs 的知识点，标注它使用的 microsphere 仓库：

```
课程知识点 "服务容错" → 使用的 microsphere 仓库
```

**验证方式**：读 docs 确认提到技术栈 → 在对应 microsphere 仓库 grep 确认实现了它。

### 1.2 源码 → 课程（反向）

每个 microsphere 仓库，标注它支撑的课程主题：

```
microsphere-resilience4j → 支撑 stage-1 的"服务容错"主题
```

**验证方式**：从源码定位到对应课程章节。

---

## 2. 关联验证规则

1. **每个关联必须源码验证**——不能凭直觉。
2. **未验证的关联标注 `[待验证]`**。
3. **区分"课程提到"和"仓库实现"**——课程可能提到某技术但训练营用的不是 microsphere 版本（如用 Spring 原生而非 microsphere 封装）。
4. **标注关联强度**：强（课程直接使用该仓库）/ 弱（课程主题相关但非直接依赖）/ 无（无关联）。

---

## 3. 产出格式

```markdown
## 06 关联分析

### 课程 → 源码
| 课程主题/章节 | 知识点 | 关联 microsphere 仓库 | 验证 | 强度 |
|--------------|--------|---------------------|------|------|
| stage-1 服务容错 | Resilience4j 容错 | microsphere-resilience4j | grep 验证 | 强 |

### 源码 → 课程
| microsphere 仓库 | 支撑课程主题 | 验证 |
|-----------------|------------|------|
| microsphere-resilience4j | stage-1 服务容错 | 源码定位 |
```

## 4. 完成检查单

- [ ] **正向关联已建立**：每篇课程知识点标注关联仓库
- [ ] **反向关联已建立**：每个仓库标注支撑的课程主题
- [ ] **关联已源码验证**：每个关联 grep/源码验证，无直觉判断
- [ ] **未验证已标注**：所有 `[待验证]` 已标注
- [ ] **强度已标注**：强/弱/无已区分
