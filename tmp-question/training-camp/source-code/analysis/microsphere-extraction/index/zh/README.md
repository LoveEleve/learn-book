# Microsphere 源码知识点提取 — 方法论框架

> **先读这个。** 这是所有 AI 代理使用本框架的入口。不要随意读单个文档——按下面规定的顺序读。

---

## 这是什么

一套**从 microsphere 源码仓库中提取知识点并组织成教学大纲**的 AI 方法论框架。

与 talk-method 的关系：talk-method 的 `source-code-analysis` 教你"如何分析单个框架源码"，`knowledge-planning` 教你"如何从书籍 TOC 规划知识"。本框架是**两者的结合体**——针对 microsphere 生态这个**多仓库源码工程**，做**逐仓库、逐文件**的知识点提取，最终产出**教学大纲**。

关键差异：

| 维度 | talk-method/source-code-analysis | 本框架（microsphere-extraction） |
|------|----------------------------------|----------------------------------|
| 分析单元 | 单个框架，域驱动（入口点展开） | 两主体（课程+源码），文件/docs驱动 |
| 深度 | 深挖设计决策（Pass 0-3） | 提取知识点 + 分类（维度/深度/优先级/过时） |
| 组织 | 按域组织 | **按 5 大维度组织**（规范/问题/理论/工程/性能） |
| 过时 | 不处理 | **三级过时状态**（有效/过时→替代/时间无关） |
| 产出 | 深度分析文章 | 逐单元提取文档 + 维度化总教学大纲 |
| 目标 | 理解框架设计意图 | 覆盖全部知识点的系统梳理 + 更高层次抽象 |

## 执行流程

```
G0 盘问闸（grill-me）→ 动手前用一问一答把「提取对象/范围/深度/顺序」盘问清楚
   └─ 达成共识后才能进入 00
00 项目清单 → 确认本次要提取的范围（训练营 4 期 + microsphere 36 仓库）
  ↓
08 需求转换 + 自主实现视角 → ★贯穿所有提取：小马哥是参考，先自主设计再看源码对照
09 前置知识 + 掌握度 → ★贯穿：标注前置知识，盘问读者掌握度（决策，不 AI 猜）
  ↓
01 训练营课程提取 → 逐篇 docs 提取知识点（含维度/过时标签 + 关联标注）
   └─ 每篇完成后停下交用户 review → 确认后下一篇
02 源码逐文件提取 → 对每个 microsphere 仓库逐文件扫描（分批 ≤10 文件）
   └─ 每仓库完成后停下交用户 review → 确认后下一仓库
  ↓
03 聚合 + 分类 → 跨单元去重，维度标签 + 深度（🔴/🟡/🟢）+ 优先级（P1/P2/P3）
04 过时处理 → 三级过时状态（有效/过时→替代/时间无关）【按 JDK11/JDK17 基准】
05 聚类 + 排序 → 按 5 大维度聚类，拓扑排序教学顺序
06 关联分析 → 课程 ↔ 源码关联（源码验证）
07 产出格式 → 逐单元提取文档 + 维度化总教学大纲
```

> **G0 盘问闸**：每个提取任务开始前（以及每个新单元、每个方向性分歧时），先运行 `skills/zh/grill-me.md`——一问一答，把"范围/深度/对象/顺序"盘问清楚，**达成共识后才能开工**。这防止在错误方向上盲目执行（本轮多次"不对，你不理解"的教训）。

> **禁止批量操作（质量铁律）**：本流程每一步都要求**逐单元、小步、可审查**推进。AI 极容易一次性生成多个单元导致质量崩塌——每篇 docs / 每仓库 / 每维度聚类完成后都必须停下来交用户 review，**用户确认后才继续**。默认一次只做 1 个单元。

## 关键约定

### 语言

- **zh/** = 仅供人类审查 + AI 执行
- 本框架只维护中文版（用户要求），不维护 en/ 版

### 统一标记

| 标记 | 含义 |
|------|------|
| `[待验证]` | 不确定性，需源码确认 |
| `[缺口：{概念}]` | 知识缺口，需外部来源 |
| `[BLOCKED]` | 阻塞（依赖单元未提取） |
| `[N=1]` | 单单元信号，无法交叉验证 |
| `[空壳]` | 0 Java 文件仓库 |

### 过时状态标记（04，按 JDK11/JDK17 基准）

| 标记 | 含义 |
|------|------|
| `[有效]` | JDK11/JDK17 基准下仍适用 |
| `[过时→{现代替代}]` | 工具/版本过时，标现代对应 |
| `[时间无关模式]` | 模式/规范/理论，不绑定工具 |

> **JDK 机制验证源码**：JDK11 = `openjdk11u`；JDK17 = `code/spring/jdk17`；参考 `openjdk-book`。

### 深度、优先级与维度标记

| 标记 | 含义 |
|------|------|
| 🔴 / 🟡 / 🟢 | 深度：深层 / 工作层 / 表层 |
| P1 / P2 / P3 | 优先级：共识 / 强信号 / 孤立 |
| `[规范]` | 规范维度（Servlet/JDBC/JMS/CDI/Bean Validation/SPI/ClassLoader/MicroProfile/Spring，只列活跃规范；JTA 等过时规范交 04 处理） |
| `[分布式问题]` | 分布式问题维度（发现/配置/均衡/容错/事务/锁/网关/多活/可观测） |
| `[分布式理论]` | 分布式理论维度（CAP/Raft/Paxos/ZAB/2PC/TCC/SAGA） |
| `[工程问题]` | 工程问题维度（多模块/自动装配/扩展点/SPI/三层架构） |
| `[性能优化]` | 性能优化维度（容器/JVM/网络IO/数据库/缓存） |

### MCP 工具

microsphere 源码提取时每个仓库先建 codebase-memory 索引（`index_repository`），再配合 `search_graph`/`get_code_snippet`/`trace_path` 辅助。详见 `methodology/zh/02`。

## 快速开始

```
1. 读 index/zh/README.md（本文）
2. 读 prompt/zh/self-constraint-prompt.md
3. 读 skills/zh/01-快速参考.md
4. G0 盘问闸 → 读 skills/zh/grill-me.md，一问一答盘问清楚「范围/深度/对象/顺序」，达成共识
```

> **默认一次只做 1 个单元**。禁止批量生成多个单元。
> **每个新单元前**：如方向有分歧，回到 grill-me 盘问。
