# Grill-Me — 提取前盘问纪律

> 角色：AI 自约束运行纪律。任何提取（训练营课程 / microsphere 源码）**动手前**、以及**每个新单元开始前**，先用本纪律盘问清楚，避免在错误方向上开始执行。
> 定位：规划期的对齐闸（G0）。与"禁止批量操作"（执行期闸）互补——本纪律防"方向错"，批量闸防"执行快"。
> 来源：改编自 Matt Pocock 的 `grilling`/`grill-me` skill，按本场景做一问一答适配。

---

## 核心原则

**把要提取的计划/范围映射成一棵"决策树"**——每个决策分支出挂在它下面的决策。**逐枝盘问，不留任何静默假设**。共识未达成前，不得开始执行。

---

## 一、盘问格式（一问一答）

本框架采用 **一问一答**（非原版整轮一次问完）——因为中文 + 复杂多仓库盘问场景下，一问一答更稳，避免"一次抛一堆"造成的信息过载（呼应 grilling.md 对"第二语言/慢读用户"的适配建议）。

### 每个问题的固定格式

```
❓ **Q{N}** - **<问题标题>**: <问题正文，可含多个选项>

➡️ <你的推荐答案>
```

- `❓` 后：编号 + 标题 + 问题正文
- `➡️` 后：**单独一行你的推荐答案**
- 用户可用"1 是 / 2 选第二个 / 3 否"按编号回答，无需逐字引用

### 节奏规则

- **一次只问一个决策**，等用户回答后才问下一个
- 上一个答案会 reshape 决策树 → 根据答案决定下一个问题
- 不一次性抛所有问题，不连续追问多个

---

## 二、事实 vs 决策的分野（关键铁律）

**找事实是 AI 的活，决策是用户的活。**

### AI 必须自己查的事实（绝不问用户）
- 源码位置、版本、包结构 → 用 `bash` / `find` / `grep`
- 类/方法/接口 → 用 MCP `search_graph` / `get_code_snippet` / `trace_path`
- 仓库清单、依赖、git remote → 用 `ls` / `cat pom.xml` / `git remote -v`

### 必须等用户决策的（绝不 AI 自答）
- 提取范围（做哪些单元）
- 深度期望（🔴 全量 / 🟡 标准）
- 优先级（先做哪个）
- **目标读者掌握度**（初级/中级/高级）——决定讲解深度和补前置程度
- 任何"要不要 / 选哪个"的方向性问题

> **自答决策 = 破坏盘问纪律。** 一个跑了 grill-me 却自己替用户定了范围/深度/掌握度的 AI，等于没跑。
> **知识掌握度尤其不能自猜**（09）：读者水平不同，同一篇的讲解深度和是否需要补前置完全不同。

---

## 三、什么时候触发盘问

### 触发时机
1. **项目开头**（G0 闸）：提取前，把"提取对象 / 范围 / 深度 / 顺序"盘问清楚
2. **每个新单元前**：每篇 docs / 每仓库开始前，盘问"这个单元的范围 / 深度 / 是否值得做"
3. **出现方向性分歧时**：当用户说"不对 / 你不理解"时，**立即回到盘问**，而不是继续

### 触发信号（grilling.md 的 trigger phrases）
用户说 "grill" / "盘问" / "拷问" / "先对齐" / "你确定吗" / "理解对吗" → 进入盘问模式

---

## 四、结束条件 = 共识确认门

**前沿空 = 决策树每枝都访问过、无遗留静默假设。**

但**AI 不得自行判定"结束了就开工"**——必须：
1. 向用户总结已盘问清楚的所有决策
2. **等用户明确说"达成共识 / 确认 / 可以了"**
3. 用户确认后才开始提取

> **未达成共识就动手 = 破坏纪律。** 弱模型最常见的失败是"盘问两三句 → 直接给个大纲 → 开工"。本纪律强制：共识确认门是硬性的。

---

## 五、反模式

### 1. 自问自答决策
```
错误：范围我替你定成"全部 36 仓库"就开工
正确：范围是决策 → 摆给用户 → 等回答
```

### 2. 问用户 AI 能自己查到的事实
```
错误：问"源码在哪个路径？"
正确：bash/find 自己查，只把"决策"摆给用户
```

### 3. 一次性抛所有问题
```
错误：一次性问 13 个问题
正确：一问一答，答案 reshape 树后再问下一个
```

### 4. 没确认就开工
```
错误：盘问完直接开始提取
正确：先总结共识 → 等用户确认 → 才开工
```
