## 5 大维度标签

```
[规范]            Servlet/JDBC/JMS/CDI/Bean Validation/SPI/ClassLoader/MicroProfile/Spring（只列活跃规范）
[分布式问题]      服务发现/配置管理/负载均衡/容错/事务/锁/网关/多活/可观测/消息
[分布式理论]      CAP/BASE/PACELC/Paxos/Raft/ZAB/2PC/TCC/SAGA
[工程问题]        多模块/BOM/自动装配/条件注解/扩展点/SPI/三层架构
[性能优化]        容器/Tomcat/Netty/JVM/网络IO/数据库/缓存/线程模型
```

> deprecated 规范（如 JTA）不入规范维度 → 交 04 处理：底层模式进理论/问题维度，映射现代替代（Jakarta Transactions / Seata）

规范/理论维度 → 通常加权到 🔴 深层

## 过时状态（三级）【按 JDK11/JDK17 基准】

```
[有效]                     JDK11/JDK17 基准下仍适用
[过时→{现代替代}]          工具/版本过时，标现代对应
[时间无关模式]             模式/规范/理论，不绑定工具
```

过时工具 → 提取底层"时间无关的模式"，映射现代替代。规范/理论 → 保留。

**JDK 机制验证源码**：
- JDK11：`/data/workspace/source-code/openjdk11u/`
- JDK17：`/data/workspace/source-code/code/spring/jdk17/`
- 参考：`/data/workspace/source-code/openjdk-book/`（格物致知 OpenJDK 分析）

## 需求转换 + 自主实现视角（贯穿）

```
每个知识点三层次：
  需求：解决什么生产问题
  自主实现：如果我来做，怎么设计（先于看源码）
  参考实现：小马哥/源码怎么做（file:line）
  对比取舍：自主方案 vs 参考的差异
```

> 小马哥课程/源码只是参考，不是知识本体。先自主设计再看源码对照。

---

## 前置知识 + 掌握度（贯穿）

```
每个知识点：前置：{读者需先掌握的概念}
每篇/每仓库：前置条件清单 + 补基础路径
掌握度：初级/中级/高级（决策，盘问用户，不 AI 猜）
```

> 读者水平决定讲解深度和补前置程度。未达前置者给补基础路径。

## 深度判定三问（含维度加权）

```
1. 面试频繁 或 生产常见？→ 🔴 深层
2. ≥3 依赖 且 偶尔遇到？→ 🟡 工作层
3. 属于规范/理论维度且规范权威？→ 🔴（维度加权）
4. 提取到了？→ 🟢 表层（1-2 句）
```
