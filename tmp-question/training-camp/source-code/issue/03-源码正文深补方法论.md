## 一、正文结构规范

每篇正文必须是 **3 层结构**（一级标题 → 二级节 → 三级节），缺一不可：

### 0. 标题（1 行）
格式：`# 01. 一个核心问题，为什么不能简单解决`

### 1. Header 段（3-5 行）
```
> **前置依赖**: [01-xxx](link)：具体背景
> → **后续**: [02-xxx](link)
> 关联域：xx、yy
```

### 2. 插入层：困惑开场 + 直觉方案（约 120 行）

#### 2.1 困惑开场（3-5 段）
用具体代码/场景/问题切入，让读者产生"为什么？"疑问。这段之后必须有至少 6 个"为什么"问题列表。

#### 2.2 三个直觉方案推演（每方案 20-30 行，共 60-90 行）
这是 vol-02 最关键的差异化步骤。每个方案必须拆成三级节：
```
### 方案一：[简单方案 1]（代码/布局）
#### 为什么不行：缺陷 1（具体到运行时场景）
#### 为什么不行：缺陷 2
### 方案二：[简单方案 2]
#### 为什么不行：缺陷
### 方案三：[简单方案 3]
#### 为什么不行：缺陷
```
每个方案的缺陷必须具体到"真实运行时场景"，不是抽象描述。

#### 2.3 一句话顿悟（1 段）
**加粗**，用一句话说清核心设计。必须来自对三个方案的归纳，不能是重复标题。

### 3. 总图（约 20 行）
用 ASCII 图展示完整架构，必须包含所有关键组件和它们的关系。图后用文字解释"这张图最重要的价值"。

### 4. 分层拆解（主体，约 400 行，5-8 个二级节）
这是 vol-02 的核心差异。**不能平铺 5-8 个二级节**，每个二级节必须再拆 3-5 个三级节。

#### 4.1 每个二级节的结构：
```
## 一、[机制名]：核心问题
### 1.1 [子机制/子问题]
`filename.java:line`：
```java
[代码块]
```
[解释：这个子机制解决了什么，为什么是这样]

### 1.2 [子机制/子问题]
[代码块 + 解释]

### 1.3 [设计约束/为什么不是另一种方案]
[解释]

### 1.4 路标：到这里真正确定了什么
[总结本节的收获，为下一节铺垫]
```

#### 4.2 二级节数量标准：
- 分层拆解必须有 **5-8 个二级节**
- 每个二级节必须有 **3-5 个三级节**
- 每篇总计 **20-30 个三级节**

#### 4.3 每二级节的"路标"子节
每个二级节末尾必须有"路标"子节，总结本节收获，为下一节铺垫。

### 5. 失败路径（6-10 条，约 60 行）
每条失败路径必须：具体场景 + 源码锚点 + 后果 + 如何避免。

### 6. 收网 + 下篇桥接（约 30 行）
用一张"全文章节对照表"概括，再指向下一篇。
