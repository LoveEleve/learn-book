## 二、因果审

### 跨域因果链

```
R-1 redisObject 奠定类型-编码地基
  -> R-4 SDS 提供 String 编码的存储载体
    -> R-3 Dict 提供 HT 编码的哈希表结构
      -> R-5 List 提供 quicklist(listpack+ziplist) 列表结构
        -> R-6 ZSet 提供 skiplist+dict 双结构
          -> R-7 Set 提供 intset 整数集合编码
            -> R-10 Stream 提供 rax 基数树
              -> R-2 事件驱动提供"何时执行"的时钟
                -> R-25 缓冲区提供"数据如何进出"的管道
                  -> R-26 命令执行提供"命令如何穿过"的骨架
                    -> R-27 Lua 脚本提供"执行逻辑如何扩展"
                      -> R-29 键空间提供"key 存在哪里"的容器
                        -> R-28 内存淘汰提供"内存满了怎么办"的决策
                          -> R-30 阻塞命令提供"拿不到数据怎么办"的等待
                            -> R-31 发布订阅提供"消息怎么广播"的通信
                              -> R-32 ACL 提供"谁可以做什么"的边界
                                -> R-8 持久化提供"数据怎么不丢"的保证
                                  -> R-9 复制提供"数据怎么同步"的链
                                    -> R-14 Sentinel 提供"怎么自动切换"的保障
                                      -> R-15 Cluster 提供"怎么水平扩展"的分布
                                        -> R-19~R-24 排障层提供"线上故障怎么排查"的视角
                                          -> R-16~R-18 高级特性
```

### 因果链完整性

- 所有因果链都是单向的，无回环
- 每个域的前置域在阅读顺序中已安排在其之前
- R-28 与 R-23 的"混淆"关系已明确标注：过期删除 vs 内存淘汰是概念上的混淆对，不是因果上的依赖对

## 三、结构审

### 8 层结构

| 层 | 包含域 | 层内逻辑 |
|----|--------|---------|
| A. 数据结构编码 | R-1~R-7、R-10 | 先类型系统，再 SDS 载体，再 Dict/List/ZSet/Set/Stream 各结构 |
| B. 事件驱动 | R-2 | 单层，但作为"时钟"地位独立 |
| C. 命令执行基础设施 | R-25~R-27 | 缓冲区 → 命令流程 → 脚本扩展，层层递进 |
| D. 经典混淆补深 | R-28~R-32 | 淘汰/键空间/阻塞/PubSub/ACL，五个独立但都容易混淆的主题 |
| E. 持久化/复制 | R-8~R-9 | 数据持久 + 主从同步，天然一对 |
| F. 高可用 | R-14~R-15 | Sentinel + Cluster，高可用两支柱 |
| G. 生产排障 | R-19~R-24 | 6 个排障域，独立成组 |
| H. 高级特性 | R-11~R-13、R-16~R-18 | Bitmap/HLL/GEO/事务/Tracking/Defrag |

### 结构合理性判断

- 每个域只属于一个层，无跨层归属
- 层与层之间按"数据 → 驱动 → 执行 → 深入 → 持久 → 高可用 → 排障 → 高级"递进
- 8 层结构比原规划的 5 层更精细，但每个层内域数控制在 2~7，适中
