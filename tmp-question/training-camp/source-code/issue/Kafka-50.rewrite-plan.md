# Kafka-50 重写规划

> 题目：Kafka 源码 50 篇总索引——从 Producer 到 KRaft、再到桥接篇的阅读导航
> 状态：全系列收束导航篇。不是新增源码专题，而是把 1~50 篇按问题域、阅读顺序、排查/估算/桥接用途重新组织，方便读者按目标而不是按编号阅读。

## 1. 读者困惑
- 50 篇已经很多了，应该从哪开始读？
- 如果我只关心 Producer / Consumer / 事务 / KRaft，应该看哪几篇？
- 如果我在排查“像丢消息”、做容量评估、看启动恢复，应该跳到哪几篇？

## 2. 一句话顿悟
**Kafka 这 50 篇不该按编号硬读，而应按“主链（Producer/Log/Consumer/Group/ISR/KRaft/事务）→ 细化篇 → 桥接篇（排查/容量/启动/可靠性）”来导航；总索引的目标不是重复内容，而是让读者按问题快速定位到最短阅读路径。**

## 3. 失败方案推演
- 按 1→50 顺序硬啃，丢失主题聚类感
- 碰到故障排查问题还去从基础篇重看，成本太高
- 看完很多篇，却不知道各篇之间依赖关系

## 4. 章节问题
- 哪些是骨架主链篇？
- 哪些是“某一域的拆深篇”？
- 哪些是桥接篇/总结篇？
- 不同读者目标（入门、排查、事务、KRaft）怎么走最短路径？

## 5. 至少要排除的误解
- 总索引只是目录复制
- 编号顺序就是最佳阅读顺序
- 桥接篇可以脱离主链直接看
- 收束篇不需要证据与边界

## 6. 关键证据清单
- 以已完成的 `Kafka-1` ~ `Kafka-49` 作为导航对象
- 交叉引用 `Kafka源码学习范围规划.md` 与 `源码分析执行计划.md`

## 7. 版本与实现边界
- Kafka v4.x KRaft
- 这是导航/收束篇，不新增实现细节
