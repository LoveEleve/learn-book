## 二、知识域规划（修订版）

### 🔴 核心域（7 个）

#### E-1a Engine 写入主路径

**入口**：`InternalEngine.java:1314` `planIndexingAsPrimary()`、`InternalEngine.java:1384` `indexIntoLucene()`
**核心类**：InternalEngine(3378行), Engine(2161行), EngineConfig, IndexingStrategy
**状态核心**：`planIndexingAsPrimary()` 决定 `indexIntoLucene`/`addStaleOpToLucene`/`useLuceneUpdateDocument`→`indexIntoLucene()` 执行 Lucene 写入。`canOptimizeAddDocument()` 利用 autoGeneratedIdTimestamp 检测重试→直接用 `addDocument` 而非 `updateDocument`。`LiveVersionMap` 内存版本映射。
**并发**：`readLock.acquire()` 允许多 index 并发，refresh/flush 序列化。
**写入路径**：`IndexRequest` → `TransportShardBulkAction` → `IndexShard.applyIndexOperationOnPrimary()` → `Engine.index(index)`: ① `indexIntoLucene`(Lucene `IndexWriter`) ② `translog.add()`(WAL) ③ 返回 `IndexResult(version, seqNo, translogLocation)`
**跨域桥**：E-1b(flush)、E-3 Translog、E-7 Mapping、E-12 Lucene
**面试价值**：写入一个文档经过哪些节点和步骤

#### E-1b refresh/flush 与可见性

**入口**：`InternalEngine.refresh()`、`InternalEngine.flush()`
**核心类**：InternalEngine, ReferenceManager, Translog
**状态核心**：**refresh(默认1s)**：`Engine.refresh()` → `ReferenceManager.maybeRefresh()` → 打开新 `IndexReader`。**flush(默认30min或 translog 512MB)**：`InternalEngine.flush()` → ①refresh → ②Lucene `IndexWriter.commit()`(fsync) → ③`Translog.createNewTranslog()` 新 generation。**NRT 可见性**：refresh 使新 segment 可见，但未 fsync（crash-safe 由 translog 保证）。
**失败路径**：refresh 间隔内数据只在内存 buffer，宕机后由 translog 恢复
**跨域桥**：E-1a(写入)、E-3 Translog(generation 轮转)
**面试价值**：为什么 ES 是近实时搜索（NRT）

#### E-2a Search 查询阶段

**入口**：`SearchService.java:522` `executeQueryPhase()`、`SearchService.java:485` `executeDfsPhase()`
**核心类**：SearchService(1825行), DfsPhase(232行), QueryPhase(270行), FetchPhase(378行)
**状态核心**：两阶段查询：① **QueryPhase**：协调节点 broadcast 到所有相关分片 → 各分片 Lucene `IndexSearcher.search()`→返回 doc_id+score(不返回 `_source`) ② **FetchPhase**：协调节点根据 doc_id 从分片拉取 `_source`/`stored_fields`/`highlight`。**DFS(分布式词频)**：三阶段（先收集词频，再 Query，再 Fetch）。
**深度分页**：`search/searchafter/`、`search/scroll/`——`SearchAfter` 和 `Scroll` 两种避免深度分页性能问题的方案。
**面试价值**：查询完整路径、深度分页问题

#### E-2b 打分与 Query 重写

**入口**：`lucene/similarity/`（BM25 定制）、`lucene/queries/`（自定义 Query）
**核心类**：BM25Similarity, BooleanQuery, TermQuery, MatchQuery, RangeQuery, PrefixQuery
**状态核心**：Lucene `IndexSearcher.search(Query, Collector)` → `BooleanQuery`(MUST/SHOULD/FILTER/MUST_NOT) → `TermQuery`/`MatchQuery`/`RangeQuery`/`PrefixQuery` 各类 Query **重写**为 `Weight.scorer()` → 迭代 doc_id 打分。**BM25**(TF-IDF 改进，`k1=1.2, b=0.75`)——词频饱和 + 文档长度归一化。
**跨域桥**：E-2a(QueryPhase)、E-12 Lucene(相似度/查询扩展)
**面试价值**：BM25 公式、Query 重写过程

#### E-3 Translog—WAL 写入日志

**核心类**：Translog(1941行), TranslogWriter, TranslogDeletionPolicy, Checkpoint
**状态核心**：双缓冲写入。`TranslogWriter` 通过 `FileChannel.force(false)` 确保元数据写入。`translog.ckp` 文件记录 globalCheckpoint 和 minTranslogGeneration。flush 时 `createNewTranslog()` 使当前 generation 封闭、只读，创建新 generation。`Translog.newSnapshot()`(L657) 创建 TranslogSnapshot 用于 peer recovery。
**跨域桥**：E-1a(Engine 写入)、E-1b(flush)
**面试价值**：translog 的作用和 flush 机制

#### E-4 Cluster Routing—分片路由

**核心类**：RoutingTable(654行), IndexRoutingTable, ShardRouting, OperationRouting
**状态核心**：`version` 字段每次路由变更递增。`ImmutableOpenMap<String, IndexRoutingTable>` 索引级路由。`ShardRouting` 含 `shardId/primary/replica/currentNodeId/state(INITIALIZING/STARTED/RELOCATING/UNASSIGNED)`。分片分配算法：`AllocationDeciders`(10+ 决策器) + `BalancedShardsAllocator`。读路由：`OperationRouting` 根据 `preference` 和 `routing` 选目标分片——默认 round-robin。写路由：`routing=_id` hash → target shard → 只发 Primary → Primary 复制到 Replicas。
**跨域桥**：E-10(ClusterState 是路由表的基础)
**面试价值**：routing 机制、分片分配

#### E-5 分片生命周期与复制（E-5 + E-6 合并）

**核心类**：IndexShard(4242行), ReplicationGroup, IndexShardOperationPermits, SequenceNumbers(120行), ReplicationOperation(698行), GlobalCheckpointSyncer(25行)
**状态核心**：5 种状态：`CREATED→RECOVERING→POST_RECOVERY→STARTED→CLOSED`。IndexShard 核心组件：Engine + Translog + Store + ShardPath。**ReplicationGroup**：维护 primary + replicas + inSyncAllocationIds + trackedAllocationIds。**SeqNo 递增**：每次写入分配递增的 seqNo，主副分片共享同一序列。**PrimaryTerms**：每次当选获得新 primaryTerm。**GlobalCheckpoint**：所有活跃副本中已确认完成的最小 seqNo。**ReplicationOperation**：Primary 将操作发送给 replicas，按 seqNo 顺序逐个 apply，收集 ack。
**Peer Recovery**：`StoreRecovery` 处理分片启动时的数据恢复，从主分片或本地恢复。
**面试价值**：分片生命周期、数据一致性、复制协议

#### E-10 ClusterState 与协调层（扩展）

**核心类**：ClusterState(1195行), Metadata(2857行), CoordinationState(656行), ClusterStatePublisher(68行), ClusterBootstrapService, ElectionStrategy, FollowerChecker, LeaderChecker, PreVoteCollector
**状态核心**：ClusterState 三层：`Metadata`(2857行) + `RoutingTable` + `ClusterBlocks`。**CoordinationState**：Raft 风格 term-based 共识——`PersistedState`(持久化 currentTerm + lastAcceptedState) + `ElectionStrategy` + `VoteCollection`。两阶段发布：Master 收到变更 → `CoordinationState` → `ClusterStatePublisher` publish 到所有节点。**FollowerChecker/LeaderChecker**：心跳检测。**ClusterBootstrapService**：集群引导。
**注意**：E-10 是基础设施域，在阅读顺序中应**前置**（所有域依赖 ClusterState）。
**面试价值**：集群选举、脑裂、集群状态发布

### 🟡 扩展域（5 个）

#### E-7 Mapping—文档映射

**核心类**：Mapping(190行), DocumentMapper(141行), MapperService(725行)
**状态核心**：JSON Schema 定义字段类型(text/keyword/long/date/geo_point/nested/object)。`DocumentParser` 解析 JSON → 按 Mapping 提取字段值 → 构建 `ParsedDocument`。`FieldMapper` 体系：`TextFieldMapper`/`KeywordFieldMapper`/`NumericFieldMapper`/`DateFieldMapper`。
**跨域桥**：E-1a(Engine 写入时使用)、E-2a(Search 查询时使用)

#### E-8 Merge Policy—段合并

**核心类**：`ElasticsearchConcurrentMergeScheduler`(约100行, Lucene `TieredMergePolicy` 使用), `MergePolicyConfig`, `MergeSchedulerConfig`
**状态核心**：`TieredMergePolicy`(Lucene 类)按大小分层合并。`ElasticsearchConcurrentMergeScheduler` 限制合并线程数+maxMergeCount，防止合并占用过多 IO。`forceMerge`(API) 强制合并到指定 segment 数。
**跨域桥**：E-1a(Engine 后台任务)

#### E-9 Bulk Processor—批量写入

**核心类**：BulkProcessor(540行), BulkRequest, BulkShardRequest
**状态核心**：Bulk API 的 NDJSON 格式 → `TransportBulkAction` 预检 → 按 shard 分组(`BulkShardRequest`) → 每个 shard 内部 apply 多条操作。**批量优化**：按 shard 聚合 + 顺序执行 + pipeline 预处理。

#### E-11 FieldData Cache

**核心类**：IndexFieldData(255行), GlobalOrdinalsBuilder, CircuitBreaker
**状态核心**：**DocValues**(列式存储) → `IndexFieldData.load()` 按 Segment 加载。**GlobalOrdinals**：跨 Segment 去重编号。**CircuitBreaker**：`fielddata.breaker.limit` 限制单节点 fielddata 总内存(默认 JVM heap 40%)，超限抛 `CircuitBreakingException`。

#### E-12 Lucene 集成层（新增）

**入口**：`server/src/main/java/org/elasticsearch/lucene/` 顶级包
**核心类**：`lucene/similarity/`(BM25 定制)、`lucene/queries/`(自定义查询)、`lucene/search/`(TopDocs 扩展)、`lucene/analysis/`(分析器集成)
**状态核心**：**Lucene 相似度扩展**：ES 如何定制 `BM25Similarity`（`k1=1.2, b=0.75`）。**Lucene 查询扩展**：自定义 `Query` 实现，覆盖 `Weight.scorer()` 迭代器。**Lucene 分析器集成**：`analysis/` 包处理文本分析（分词、过滤、归一化）。**Lucene 搜索扩展**：`TopDocs` 扩展、`Collector` 体系、`FieldDoc` 排序。
**面试价值**：ES 怎么在 Lucene 之上构建搜索引擎

## 三、阅读顺序（修正版）

```
E-10 ClusterState(基础设施，前置)
  → E-4 Routing(基于 ClusterState 的路由)
    → E-3 Translog(WAL，最底层组件)
      → E-1a Engine 写入主路径
        → E-1b refresh/flush(可见性，基于 Engine)
          → E-5 分片生命周期与复制(基于 Engine + SeqNo)
            → E-7 Mapping(被 Engine 和 Search 共享)
              → E-2a Search 查询阶段
                → E-2b 打分与 Query 重写
                  → E-12 Lucene 集成层(贯穿查询与写入)
                    → E-8 MergePolicy(Engine 后台合并)
                      → E-9 BulkProcessor(批量写入)
                        → E-11 FieldData(聚合/排序性能)
```
