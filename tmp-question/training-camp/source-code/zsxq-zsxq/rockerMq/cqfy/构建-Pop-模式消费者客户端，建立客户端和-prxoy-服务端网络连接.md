在回顾了之前的知识之后，我相信在大家的脑海里应该也形成了一个共识，那就是 ProducerImpl 生产者客户端只是一个最外层的、暴露给用户使用的对象，这个 ProducerImpl 生产者客户端似乎只是为某些操作提供了入口方法，除此之外，它并不负责更多核心工作。就比如说，用户虽然可以使用 ProducerImpl 向指定服务器发送生产消息，但是消息最终的发送还需要 ClientManagerImpl 客户端管理器以及真正发送消息的 RpcClientImpl 对象来完成；而在生产者客户端启动的过程中，我们也可以发现，客户端和服务端建立连接、从 Proxy 获得指定主题路由信息、以及执行心跳检测的操作也并不真的是由 ProducerImpl 对象来完成的，而是由 ClientImpl、ClientManagerImpl 以及 RpcClientImpl 这几个对象协作完成的。种种情况似乎都在告诉我们，虽然我们之前构建的是一个生产者客户端，但是整个客户端的核心功能和生产者并没有非常紧密的联系。  
  
生产者客户端要做的肯定是把生产出来的消息发送给指定服务端，但说到底这无非就是客户端向服务端发送消息的操作，确切地说，无非就是客户端向服务端发送一个请求，服务端再回复给客户端一个响应而已，生产者客户端从服务端得到指定主题的路由信息、和指定服务端进行心跳检测等等活动都是在重复请求响应操作而已。如果是这样的话，那接下来就很简单了， 因为根据我们已经定义的 ClientImpl、ClientManagerImpl、RpcClientImpl 这三个类，基本上就把所谓的请求响应模式实现了，那如果我们要在此基础上实现一个消费者客户端，先不考虑消费者客户端的具体功能，只考虑客户端本身的话，那我们其实只要再为 ClientImpl 定义一个 ConsumerImpl 子类，这个子类对象不就是消费者客户端了吗 ？  
  
从功能上来说， 消费者客户端和生产者客户端有很多交集，比如说，消费者客户端和生产者客户端都需要和服务端建立网络连接，都需要在启动的过程中从 Proxy 服务端得到订阅主题的路由信息、都需要和服务端进行心跳检测活动、也都需要把自己的客户端信息注册到服务端，交给服务端来管理等等 。这些常规操作大家都可以理解吧？ 而这些操作只需要使用 ClientImpl、ClientManagerImpl、RpcClientImpl 这三个类就能完成， 也就是说，我们已经把消费者客户端和生产者客户端的公共功能都提炼出来了，并且也都实现了，而在这些公共功能的基础上构建一个消费者客户端，确实是易如反掌，这一点大家应该也都认同吧？如果大家理解了以上内容，那接下来我们就可以真正构建一个消费者客户端了。

好了，现在消费者客户端重构完毕了，可以看到，内容比之前又丰富了很多，虽然我们还不知道怎么使用这些内容，但很快就会知道。当然，实现到这种程度并不意味着简单模式的消费者客户端就重构结束了，我相信就算我不提示大家也能意识到，目前的消费者客户端还需要从四个方面去完善： 第一个方面就是消费者客户端并没有从 Proxy 服务端获取要消费的消息的方法 ，这个大家可以理解吧？就像生产者客户端要把生产的消息发送给 Proxy 服务端，消费者客户端要想消费消息，肯定要从 Proxy 获取能够被消费的消息； 第二个方面就是我们并没有给消费者客户端定义缓存主题路由信息的容器，确切地说是能够负载均衡路由信息的组件，因为从 Proxy 节点获取的路由信息都会缓存在 ClientImpl 对象的 topicRouteCache 成员变量中，但在生产者发送消息时具体怎么对这些路由信息执行负载均衡以便选择目标节点，这个操作还是会交给 ClientImpl 的子类，也就是生产者客户端自己执行 ，这一点大家肯定也能想到，我们实现生产者客户端的时候，在生产者客户端启动的过程中，就会从 Proxy 节点获取自己订阅的主题的路由信息，然后缓存在本地，当发送消息的时候，就可以从缓存的路由信息中选在目标节点，把消息发送过去。现在要逐步完善消费者客户端，那消费者客户端消费消息的时候，也要知道自己订阅主题的所有路由信息，然后使用负载均衡，从路由信息中不断选择节点消费消息，这个逻辑大家应该也能理解吧？而消费者客户端在启动的过程中也会从 Proxy 节点获取订阅主题的路由信息，并且执行的操作和生产者客户端一致，那么消费者客户端从 Proxy 节点获取到了主题路由信息之后肯定也应该缓存到本地，在必要的时刻对这些信息执行负载均衡操作， 所以我们还应该为消费者客户端定义一个能够对缓存的路由信息执行负载均衡操作的对象 。  
  
要完善的第三个方法其实也很简单，那就是消费者客户端也要像生产者客户端那样，在和 Proxy 构建了网络连接之后，要把自己的信息都注册到 Proxy 节点，当然，这些信息最终并不一定是 Proxy 节点管理，而是 Broker 节点管理，并且还要定期和 Proxy 执行心跳检测活动，而在执行这些操作的过程中，消费者客户端还会定期从 Proxy 节点同步设置信息到本地 。对于消费者客户端来说，这些操作肯定也是要执行的吧？当然，这些操作其实已经被我们实现了，毕竟这些操作都会在 ClientImpl、ClientManagerImpl、RpcClientImpl、ClientSessionImpl 这四个对象中执行，但有一点需要我们继续完善，那就是从 Proxy 节点同步设置信息到本地后，那些设置信息应该被保存在哪里？在生产者客户端中，设置信息都被封装在了 ProducerSettings 中(这一点我就不展开了，大家自己回顾之前的内容即可)，那来到消费者客户端中， 我们不妨就给消费者客户端定义一个 SimpleConsumerSettings 类，消费者客户端的设置信息都封装在这个类的对象中即可 。至于设置信息是什么就很简单了，无非就是消费者客户端所属消费组的名称，主题过滤信息，请求超时时间等等信息，大家可以直接去我提供的第十八版本代码中查看，我就不在文章中展示了。
