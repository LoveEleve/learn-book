## **02 ES 索引模板深度实战**

## **2.1 ES 索引模板入门**

在 ES 中，当需要创建大量结构相似的索引（如「**日志索引按天分割**」、「**日用户行为数据按租户隔离**」）时，手动配置每个索引的映射（Mapping）和设置（Settings）会导致效率低下且容易出错。

索引模板（Index Template）正是为解决这一问题而生，它允许通过预定义的规则自动生成索引配置，确保同类索引遵循统一的结构规范。

接下来将全面介绍索引模板的「**核心概念**」、「**配置语法**」、「**匹配机制**」、「**动态字段处理**」、「**生命周期管理 ILM 集成**」。

### **2.1.1 ES 索引模板核心概念**

1.  索引模板（Index Template）：包含索引映射、设置、别名等配置的预定义模板，通过索引模式匹配自动应用于新创建的索引。
2.  索引模式（Index Pattern）：用于匹配索引名称的通配符或正则表达式（如logs-\*、user-\\d+）。
3.  映射（Mapping）：定义索引字段的数据类型、分词器、搜索属性等元数据。
4.  设置（Settings）：包含分片数量、副本数、刷新间隔、生命周期策略等索引级配置。
5.  动态模板（Dynamic Template）：在映射中定义的动态字段匹配规则，用于自动处理未知字段的映射配置。
6.  模板优先级（Priority）：当多个模板匹配同一索引时，优先级高的模板配置会覆盖低优先级的冲突部分。
7.  索引别名（Index Alias）：可附加到模板中的逻辑名称，支持读写请求路由，方便索引切换（如日志索引的滚动切换）。
8.  日期数学模式（Date Math Pattern）：用于动态生成索引名称的时间表达式（如logs-%{now/d}表示当天日志索引）。
9.  字段数据类型（Field Data Type）：ES支持的核心类型（如text、keyword、date、nested）及其子属性（如分词器、格式规范）。

  
![](images/FkwmiLqa-LLpr34t7zM7Wf12BFHE.png)

Elasticsearch 索引模板是定义索引配置（设置、映射、别名）的蓝图，当新索引名称匹配模板模式时自动应用。主要有两种类型：

1.  历史模板 (Templates) - 已废弃
2.  组合模板 (Ccomponent Templates) - 推荐使用，实战部分重点讲解这个。

### **2.1.2 ES 索引模板核心组成和架构设计**

索引模板由以下四部分构成，通过 REST API 以 JSON 格式定义：

1.  基础元数据：模板名称、索引模式、优先级。
2.  映射配置：字段类型、动态模板、属性设置。
3.  索引设置：分片策略、refresh 间隔、ILM 策略。
4.  别名定义：可选的逻辑索引名称。

索引模板结构示意图：

│ └─ index.lifecycle.name: "log\_lifecycle" \# ILM策略

└─ 别名 (aliases)

└─ my\_logs: { ... } \# 可选别名配置

### **2.1.2 ES 索引模板核心配置**

通过 dynamic\_templates 定义字段名匹配规则，支持通配符（\*）、正则（regex）及数据类型推断：

{

"mappings": {

"dynamic\_templates": \[

{

"string\_fields": {

"match": "\*\_str", \# 匹配字段名以\_str结尾

"match\_mapping\_type": "string",

"mapping": {

"type": "text",

"fields": {

"keyword": { "type": "keyword" }

}

}

}

},

{

"numeric\_fields": {

"match\_mapping\_type": "number",

"mapping": {

"type": "double",

"doc\_values": true \# 启用文档值用于排序聚合

}

}

}

\]

}

}

通过 dynamic 参数控制未知字段的处理方式：

1.  true（默认）：自动添加动态字段（可能导致映射膨胀）
2.  false：忽略未知字段（数据仍存储，但无法搜索）
3.  strict：拒绝包含未知字段的文档（抛出异常）

分片与副本配置：

{

"settings": {

"number\_of\_shards": 5, \# 主分片数（创建后不可修改）

"number\_of\_replicas": 1, \# 副本数（可动态调整）

"index.routing.allocation.disk.threshold\_enabled": false \# 禁用磁盘阈值分片分配

}

}

性能优化设置：

{

"settings": {

"refresh\_interval": "30s", \# 降低刷新频率提升写入性能

"translog": {

"durability": "async", \# 异步提交translog（牺牲部分一致性）

"sync\_interval": "5s"

},

"index.store.compress.stored\_fields": true \# 压缩存储字段

}

}

生命周期策略集成：

{

"settings": {

"index.lifecycle.name": "log\_policy", // 关联ILM策略

"index.lifecycle.rollover\_alias": "logs\_write" // 用于滚动的别名

}

}

### **2.1.3 ES 索引模板动态配置匹配与冲突处理**

索引模板优先级顺序：固定字段定义 > 动态模板（按模板优先级降序）> 默认动态映射

当多个模板匹配同一索引时，优先级（数值越大优先级越高）决定配置合并顺序：

1.  设置合并：高优先级模板的设置覆盖低优先级（冲突项以高优先级为准）。
2.  映射合并：字段定义冲突时，以最先出现的高优先级模板为准（需注意动态模板与固定字段的优先级）。

假设存在两个模板T1（priority=100）和T2（priority=50），字段 status 在 T1 中定义为 integer，在 T2 中定义为keyword，合并规则为：

1.  按优先级降序排列模板：T1 → T2。
2.  遍历每个模板的字段定义，后出现的高优先级定义覆盖低优先级，最终 status 类型为 integer（T1 的定义保留）。

  
索引模板匹配流程图：

![](images/FuAW30wus75PbrRM0wrW_9V0H4zW.png)

冲突解决策略​：

1.  字段映射冲突：后应用模板覆盖先应用模板。
2.  设置冲突：最高优先级模板生效。
3.  别名冲突：多个别名共存。

### **2.2.1 ES 索引模板之生产级日志系统**

以生产环境的日志系统管理为场景，设计一个完整的索引模板案例。

假设有如下需求：

1.  日志索引按天滚动，索引命名格式：logs-{service\_name}-{yyyy.MM.dd}。
2.  需要支持全文搜索和关键字搜索。
3.  设置合适的分片数和副本数（生产环境一般分片数根据数据量调整，假设每个索引1个主分片，2个副本）。
4.  使用ILM进行生命周期管理（热阶段 3 天，然后删除）。
5.  严格模式，避免动态映射造成映射爆炸。
6.  添加一些元数据字段，如 @timestamp, service\_name, log\_level 等。
7.  为不同环境（dev, prod）设置不同的副本数（开发环境 0 副本，生产环境 2 副本）。

  
我们将采用「**组件模板**」和「**索引模板**」的分层架构：

1.  全局基础组件（global\_base）：包含通用设置，如压缩方式、默认字段等。
2.  日志基础组件（logs\_base）：包含日志相关的通用映射，如 @timestamp, message 等。
3.  服务特定组件（service\_specific）：包含特定服务的映射（按需）。
4.  环境特定组件（env\_specific）：根据环境设置不同的副本数。

### **2.2.1.4 创建 ILM 策略**

\# 4.1 日志数据ILM策略（30天热阶段，然后删除）

PUT \_ilm/policy/logs\_ilm\_policy

{

"policy": {

"phases": {

"hot": {

"min\_age": "0ms",

"actions": {

"rollover": {

"max\_size": "50gb", // 达到50GB时滚动

"max\_age": "30d" // 或者索引创建超过30天时滚动

},

"set\_priority": {

"priority": 100

}

}

},

"delete": {

"min\_age": "30d", // 滚动后30天（即数据产生后约31天）删除

"actions": {

"delete": {}

}

}

}

}

}

当后续 xxx-2025.08.21-000001 索引满足 max\_age: 1d 或 max\_size: 50gb 条件时，ILM 自动执行滚动：

1.  创建一个新索引 xxx-2025.08.21-000002。
2.  将 logs-write 别名的写索引指向 xxx-2025.08.21-000002。
3.  xxx-2025.08.21-000001 变为只读，并开始进入生命周期后续阶段。

4.  第二级：插件相关索引（APM、Fleet）
5.  第三级：后台作业索引（任务、Watcher）
6.  ​动态排除​：定期检查新系统索引模式

### **2.2.1.8 脚本验证模板**

这里创建一个综合验证脚本，检查所有模板是否正确应用：

#!/bin/bash

\# ES 模板验证脚本（支持认证）

\# 配置信息

ES\_HOST="localhost:9200"

ES\_USER="elastic" \# 替换为实际用户名

ES\_PASS="elastic" \# 替换为实际密码

INDICES=(

"audit-security-prod-2025.08.21-000001"

"logs-app-prod-2025.08.21-000001"

"biz-orders-prod-2025.08.21-000001"

"logs-app-dev-2025.08.21-000001"

)

\# 认证参数

AUTH\_PARAM="-u $ES\_USER:$ES\_PASS"

\# 验证函数

function validate\_index() {

local index=$1

echo "--- 验证索引: $index ---"

\# 检查索引是否存在

status=$(curl -s -o /dev/null -w "%{http\_code}" $AUTH\_PARAM "http://$ES\_HOST/$index")

if \[ "$status" -eq 401 \]; then

echo " ❌ 认证失败：无效的用户名或密码"

return

fi

if \[ "$status" -eq 403 \]; then

echo " ❌ 权限不足：无法访问索引"

return

fi

if \[ "$status" -ne 200 \]; then

echo " ❌ 索引不存在 (HTTP $status)"

return

fi

\# 获取索引信息

settings=$(curl -s $AUTH\_PARAM "http://$ES\_HOST/$index/\_settings")

mapping=$(curl -s $AUTH\_PARAM "http://$ES\_HOST/$index/\_mapping")

aliases=$(curl -s $AUTH\_PARAM "http://$ES\_HOST/$index/\_alias")

count=$(curl -s $AUTH\_PARAM "http://$ES\_HOST/$index/\_count" | jq '.count')

\# 检查是否获取到有效数据

if \[ -z "$settings" \] || \[ "$settings" == "{}" \]; then

echo " ❌ 无法获取索引设置"

return

fi

echo " ✅ 索引存在"

echo " 文档数量: $count"

\# 根据索引类型验证特定设置

if \[\[ $index == \*"prod"\* \]\]; then

replicas=$(echo "$settings" | jq '.\[\].settings.index.number\_of\_replicas')

if \[ "$replicas" == "\\"2\\"" \]; then

echo " ✅ 生产环境副本数: $replicas"

else

echo " ❌ 生产环境副本数异常: $replicas (应为 2)"

fi

fi

if \[\[ $index == \*"dev"\* \]\]; then

replicas=$(echo "$settings" | jq '.\[\].settings.index.number\_of\_replicas')

if \[ "$replicas" == "\\"0\\"" \]; then

echo " ✅ 开发环境副本数: $replicas"

else

echo " ❌ 开发环境副本数异常: $replicas (应为 0)"

fi

fi

if \[\[ $index == \*"audit"\* \]\]; then

shards=$(echo "$settings" | jq '.\[\].settings.index.number\_of\_shards')

if \[ "$shards" == "\\"2\\"" \]; then

echo " ✅ 安全审计分片数: $shards"

else

echo " ❌ 安全审计分片数异常: $shards (应为 2)"

fi

fi

if \[\[ $index == \*"logs"\* \]\]; then

shards=$(echo "$settings" | jq '.\[\].settings.index.number\_of\_shards')

if \[ "$shards" == "\\"3\\"" \]; then

echo " ✅ 应用日志分片数: $shards"

else

echo " ❌ 应用日志分片数异常: $shards (应为 3)"

fi

\# 检查 ILM 策略

ilm\_policy=$(echo "$settings" | jq '.\[\].settings.index.lifecycle.name')

if \[ "$ilm\_policy" != "null" \] && \[ "$ilm\_policy" != "\\"\\"" \]; then

echo " ✅ ILM 策略: $ilm\_policy"

else

echo " ❌ ILM 策略未设置"

fi

fi

if \[\[ $index == \*"biz"\* \]\]; then

shards=$(echo "$settings" | jq '.\[\].settings.index.number\_of\_shards')

if \[ "$shards" == "\\"5\\"" \]; then

echo " ✅ 业务数据分片数: $shards"

else

echo " ❌ 业务数据分片数异常: $shards (应为 5)"

fi

fi

\# 检查别名

alias\_count=$(echo "$aliases" | jq 'length')

if \[ "$alias\_count" -gt 0 \]; then

echo " ✅ 别名数量: $alias\_count"

echo " 别名列表:"

echo "$aliases" | jq -r '.\[\].aliases | keys\[\]' | sed 's/^/ - /'

else

echo " ⚠️ 无别名设置"

fi

}

\# 主程序

echo "=== 开始 Elasticsearch 模板验证 ==="

echo "验证时间: $(date)"

echo "ES 主机: $ES\_HOST"

echo "ES 用户: $ES\_USER"

echo ""

\# 检查 jq 依赖

if ! command -v jq &> /dev/null; then

echo "❌ 错误：需要安装 jq 工具"

echo "Ubuntu/Debian: sudo apt install jq"

echo "CentOS/RHEL: sudo yum install jq"

exit 1

fi

\# 验证所有索引

for index in "${INDICES\[@\]}"; do

validate\_index "$index"

echo ""

done

echo "=== 验证完成 ==="

### **2.2.2 ES 索引模板之生产级时间序数据系统**

以生产环境的监控平台管理为场景，设计一个完整的索引模板案例。

假设有如下需求：

某公司需要构建一个集中的监控平台，用于收集、存储和查询来自数千台服务器和应用的各种性能指标（如：CPU使用率 cpu\_usage、内存占用 memory\_used、磁盘I/O disk\_io\_write、应用QPS api\_qps 等）。

这些数据以时间序列的形式持续高频写入，数据量巨大，需要对数据进行高效的管理，以平衡查询性能和经济高效的长期存储。

核心目标：

1.  高效写入与查询：保证每秒数十万数据点的写入性能，并支持对近期数据的快速聚合查询。
2.  自动化生命周期管理：自动处理索引的滚动更新（Rollover）、从热节点迁移至冷节点、以及最终的删除。
3.  存储成本优化：将不再频繁查询的历史数据转移到成本更低的硬件上，并冻结索引以进一步节省内存。
4.  schema 灵活性：能够灵活地添加新的监控指标，而无需频繁修改索引映射。
