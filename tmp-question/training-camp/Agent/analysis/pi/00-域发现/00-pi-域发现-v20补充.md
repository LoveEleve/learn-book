### 关键行为契约(writer-leases 测试)

| 契约 | 要点 |
|------|------|
| **栅栏 stale owner** | "fences a stale owner after an expired lease is acquired by another writer"——过期租约被他人接管后,旧 owner 被栅栏隔离(**Fencing Token 的行为测试**) |
| 单写者 | "rejects a second writer until the first session releases its claim" |
| 心跳续租 | "renews an idle writer lease with a heartbeat" |
| 元数据读不取租约 | "lists complete metadata without acquiring active sessions' writer leases"(读不阻塞写) |
| 共享连接串行 | "serializes lease-checked writes for sessions sharing one database connection" |

### repository 契约(其他)

- 失败回滚:fork 复制条目失败 → 整个 fork 回滚
- 失败保持:失败操作后数据库保留到 dispose(不提前关)
- 解码失败 → 大声失败("fails loudly when a stored entry is read and cannot be decoded"——与 reducer 拒绝损坏同哲学)
- 连接状态:追加事务失败时不发布连接状态

## 二、关键设计(通用价值)

1. **"conformance 工厂"是测试即契约的终极形态**:一个工厂生成 N 个后端的同一套契约测试——**多后端产品的行为一致性靠共享测试工厂锁定**(Hermes conformance 向量、Reasonix 一致性测试同思想,Pi 的工厂形态最通用)
2. **栅栏的行为测试**:Fencing Token 的正确性由行为测试证明(接管后旧 owner 被拒)——**理论机制的测试化**
3. **"读不取租约"**:元数据读不获取写租约——读写分离的正确性
