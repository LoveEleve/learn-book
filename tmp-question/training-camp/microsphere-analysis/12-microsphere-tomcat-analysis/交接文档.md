## 3. 已犯错误清单（接手方避免重复）

这是 10 篇文章 4 轮 review 中踩过的坑，写新文章时**先对照此清单自查**：

### 3.1 行号类（最容易被抓的错误）

- 行号必须**重新核对**，不要凭记忆写——源码版本固定，但方法实际行号与直觉常不符
- 类声明行号 ≠ 方法行号；`@Override` 注解行 ≠ 方法签名行
- 多态方法注意区分"接口/父类声明"与"子类实现"的位置
- 例：`Tomcat.getEngine()` 实际在 572-583（不是 554）；`loadClass` 实际 1207 行（不是 1182）

### 3.2 概念类（更严重的错误）

| 错误 | 正确 |
|---|---|
| Tomcat ThreadPoolExecutor 继承 JDK 的 | 继承 `AbstractExecutorService`，**自研实现**（`ThreadPoolExecutor.java:330`）——因为需要 `getPoolSizeNoLock`/`getSubmittedCount` 内部钩子 |
| Webapp 类加载器的父是 CatalinaLoader | 是 **SharedLoader**（`Bootstrap.java:272` → Catalina.setParentClassLoader(sharedLoader) → SetParentClassLoaderRule → Engine） |
| filter() 的 javax 分支保护 annotation/el/servlet | **只有 websocket**（其余已迁移 jakarta） |
| `connectionTimeout` 默认 60000 | **20000**（`SocketProperties.soTimeout = 20000`） |
| `server.shutdown` 默认 immediate | **GRACEFUL**（`ServerProperties.java:116`） |
| `setState` 调 `setStateInternal` 还是反过来 | `setState`（protected）委托 `setStateInternal(state, null, true)`；骨架方法内部直接调 `setStateInternal(..., false)` |
| Engine "根据域名选择 Host" | 域名→Host 由 **Mapper** 完成，Engine 只持有集合 |
| `ServletContext.getServerInfo()` 可用 server-header 定制 | 两者独立：getServerInfo 读 `ServerInfo.properties`；server-header 定制 HTTP 响应头 |
| `max-queue-capacity=0` 可快速失败 | Spring Boot Customizer `.when(isPositive)` 过滤 0，**不生效**；且快速失败是连接关闭不是 503 |
| maxPostSize 超限返回 413 | 返回 **400**（`FailReason.POST_TOO_LARGE`） |
| `StandardWrapper.startInternal` 加载 Servlet | **不加载**——只发通知+setAvailable；加载在 `StandardContext.loadOnStartup()`（4165-4199） |
| "已加载未初始化"状态存在 | `instance = loadServlet()` 原子赋值，失败则 instance 保持 null，该状态不会出现 |
| `Registry.disableRegistry()` 是设标志 | 是**替换单例为 NoDescriptorRegistry** |
| `ApplicationContext.getFacade()` 懒创建 | facade 字段**构造时创建**（140 行），getFacade 只返回 |
| `processorCache` 默认 0 禁用 | Tomcat 裸机默认 0，但 **Spring Boot 默认 200**（`ServerProperties.java:470`） |
| SocketState 只有 4 态 | 9 态（OPEN/CLOSED/LONG/ASYNC_END/SENDFILE/UPGRADING/UPGRADED/ASYNC_IO/SUSPENDED） |
| `bindState` 三态 | 四态（多 SOCKET_CLOSED_ON_STOP） |
| `CoyoteAdapter` 是"唯一粘合点" | "最主要的粘合点"（Connector 也跨两层） |

### 3.3 遗漏类

- `getRequestURI()` 来自 coyote 层（`coyoteRequest.requestURI()`），不是 `mappingData.requestPath`
- `@PreDestroy` 在 `destroy()` 之后且 **finally 中执行**（destroy 抛异常也会执行）
- `load()`（loadOnStartup 路径）**不递增 countAllocated**
- 嵌入式 `getProperty("bindOnInit")` 返回 null 的原因：AbstractProtocol 无该属性，fallback 查 attributes Map
- `mergeInitializers` 有 4 个组成部分（context-param + SessionConfiguringInitializer + selfInitialize + 用户自定义）
- `LazySessionIdGenerator` 覆写 startInternal 为空（延迟 SecureRandom 初始化）
