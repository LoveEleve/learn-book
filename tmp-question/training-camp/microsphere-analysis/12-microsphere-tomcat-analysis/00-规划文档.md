## 分析原则

只分析 Spring Boot 嵌入式中**实际执行的代码路径**，过时/不走的功能一律跳过。

### 跳过清单

| 跳过内容 | 原因 |
|---|---|
| JSP/Jasper (`shouldRegisterJspServlet()` 默认 false) | `spring-boot-starter-web` 不包含 Jasper |
| DefaultServlet (`registerDefaultServlet` 默认 false) | Spring Boot 3.x 默认不注册 |
| WebSocket 运行时处理 | `WsSci.onStartup()` 仅在 classpath 有 WebSocket 时才触发，现代应用基本走 Reactor Netty |
| Session 持久化到文件 | 仅 `getSession().isPersistent()` 为 true 才走，分布式不用 |
| server.xml / web.xml 解析 | 嵌入式不走 Catalina 模式 |
| Host 自动部署 | Spring Boot 显式 `setAutoDeploy(false)` |
| Cluster / 集群会话复制 | 嵌入式中无意义 |
| Manager App / Host Manager | 独立 Tomcat 管理功能 |
| LegacyCookieProcessor | 嵌入式默认 `Rfc6265CookieProcessor` |
| JMX MBean 注册 | `Registry.disableRegistry()` 关掉了（但第 11 篇 4.4 节会讨论 Actuator + Micrometer 指标对这个开关的实际依赖关系） |

## 源码探索成果摘要

> 以下是规划阶段积累的核心机制要点，作为快速回顾。详细内容见各篇正文。

### 1. LifecycleBase 状态机

```
NEW → INITIALIZING → INITIALIZED → STARTING_PREP → STARTING → STARTED
  ↑                                                      ↓
  └────────────────── STOPPED ← STOPPING ← STOPPING_PREP ┘
                          ↓
                     DESTROYING → DESTROYED
```

关键设计：`init()` / `start()` 是 `final` 模板方法，子类实现 `initInternal()` / `startInternal()`。`start()` 内部如果状态是 `NEW`，会先调用 `init()` 自动补链。

### 2. 容器层次

```
StandardServer
  └── StandardService
        ├── Connector (Http11NioProtocol → NioEndpoint)
        └── StandardEngine
              └── StandardHost (autoDeploy=false)
                    └── StandardContext / TomcatEmbeddedContext
                          └── StandardWrapper
```

`ContainerBase.startInternal()` 默认通过 `InlineExecutorService` **串行**启动子容器（配置 `startStopThreads > 1` 才真正并行）。

`StandardService.startInternal()` 的顺序是：**Engine → Executors → MapperListener → Connectors**。Spring Boot 正是利用这个顺序，用 `removeServiceConnectors()` 在 `tomcat.start()` 前把 Connector 从 Service 中剥离——这样 Engine/Context/Wrapper 都正常启动，但 Connector 不 bind 端口。

### 3. Spring Boot → Tomcat 完整链路

```
SpringApplication.run()
  → AbstractApplicationContext.refresh()
    → ServletWebServerApplicationContext.onRefresh()       ← 创建 WebServer（不 bind 端口）
      → createWebServer()
        → TomcatServletWebServerFactory.getWebServer(initializers)
          → new Tomcat() + new Connector() + prepareContext()
          → return new TomcatWebServer(tomcat)
            → tomcat.start()  ← 启动容器但不 bind
    → finishRefresh()                                       ← 启动 WebServer（bind 端口）
      → TomcatWebServer.start()
        → addPreviouslyRemovedConnectors() → connector.start()  ← 真正 bind
```

### 4. 三个定制器层级

Spring Boot 3.5 为 Tomcat 提供了四层定制接口 + 四个内置 Customizer：

**定制接口**（开放给用户）：
- `WebServerFactoryCustomizer<TomcatServletWebServerFactory>` — 最顶层，对 Factory 整体配置
- `TomcatConnectorCustomizer` — 对 Connector 做细粒度定制
- `TomcatContextCustomizer` — 对 Context 做细粒度定制
- `TomcatProtocolHandlerCustomizer` — 对 ProtocolHandler 做细粒度定制

**内置 Customizer**（Spring Boot 自动注册，对应 `server.*` / `server.tomcat.*` 配置）：
- `ServletWebServerFactoryCustomizer` — 通用 `server.*` 属性（port, address, contextPath, SSL, compression, session, HTTP2, shutdown 等）
- `TomcatServletWebServerFactoryCustomizer` — `server.tomcat.*` 属性中与生命周期相关的（redirectContextRoot, useRelativeRedirects, disableMBeanRegistry, useApr, TLD skip）
- `TomcatWebServerFactoryCustomizer` — `server.tomcat.*` 属性中与协议/性能相关的（threads, connections, timeouts, accesslog, remoteip, static resources, error report）
- `TomcatVirtualThreadsWebServerFactoryCustomizer` — 虚拟线程（Spring Boot 3.2+，`@ConditionalOnThreading(Threading.VIRTUAL)`）
