## Buddy 分配器

| 考点 | 频次 | 答案要点 | 正文位置 |
|------|:--:|----------|---------|
| Buddy 如何解决外部碎片 | ★★★ | 2^n 页块粒度；分裂满足小请求、合并恢复大块；buddy 对唯一性 → 合并 O(1) | §1.1 |
| 分裂/合并流程 | ★★★ | `__rmqueue_smallest` 递归分裂；`__free_one_page` 检查 buddy 空闲后向上合并 | §1.3-1.4 |
| buddy 对如何判定 | ★★★ | 同 order 且物理页号相差 2^order：`pfn ^ (1 << order)` 位运算 | §1.4 |
| 11 个 order 的含义 | ★★ | order n = 2^n 页；0→4KB，10→4MB；页分配请求按 2^n 上取整 | §1.2 |
| MIGRATE_TYPES 作用 | ★★ | 按可移动性分 3 链表，防不可移动页造成永久碎片；`__rmqueue_fallback` 兜底借用 | §1.5 |
| per-CPU page list 为什么快 | ★★ | order 0 单页分配走本地缓存，批量取页分摊 zone->lock | §1.6 |
| 内存规整(compaction)与迁移类型的关系 | ★★ | 只迁移 MOVABLE 页拼大块 → 支撑 THP | §1.5 |
| GFP 标志与迁移类型/zone 的映射 | ★ | 分配请求的标志决定从哪个链表、哪个 zone 取 | §1.5/§3.2 |

## SLAB/SLUB

| 考点 | 频次 | 答案要点 | 正文位置 |
|------|:--:|----------|---------|
| SLAB 为什么快 | ★★★ | 固定槽缓存：分配=取槽、释放=还槽，零分配开销 | §2.1 |
| SLAB 三链表状态机 | ★★ | full/partial/free；分配优先 partial | §2.2 |

| kmem_cache 构造/析构回调 | ★ | ctor 首次构造对象，复用不重建 | §2.4 |

## 典型追问链

1. "Buddy 怎么分配 1 页？" → order 0 → PCP 热路径 → 无货则批量取 → 无则全局 → 慢路径回收/OOM (§1.3, §1.6)
2. "kmalloc 和 alloc_pages 什么关系？" → kmalloc 走 SLUB 缓存，缓存无货时向 Buddy 要页 (§2.3)
3. "32 核机器内存怎么分？" → NUMA node 划分 → zone → page；`numactl --hardware` 看拓扑 (§3.1, §3.3)
4. "系统启动初期内存是谁分配的？" → memblock → 移交 Buddy (§4.2)
5. "为什么说 O(1) 找到合并伙伴？" → `pfn ^ (1 << order)` 唯一候选，只需检查空闲位 (§1.4)
