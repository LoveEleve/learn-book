## 阶段1: 本地文件系统内核实现 (A集群, 10项)

### 1.1 Ext2 磁盘布局 — SuperBlock/GDT/Bitmap/Inode (🔴)
- **整体布局(宏)**: 磁盘→Boot Sector(逻辑扇区0, 512B, 含MBR分区表)→每个Block Group按序排列: BG0→BG1→...→BGN。每个Block Group内5段: (1)SuperBlock(1 block, 存全局元数据)→(2)GDT(Group Descriptor Table, 每个BG一个entry, blocks_per_group/8个block)→(3)Block Bitmap(1 block, 每bit代表一个block, 0=空闲/1=已用)→(4)Inode Bitmap(1 block, 每bit代表一个inode)→(5)Inode Table(N blocks, blocks_per_group×inode_size)→(6)Data Blocks(剩余blocks)。Block Size=1KB(log=0)/2KB(log=1)/4KB(log=2), 创建时指定(`mkfs.ext2 -b 4096`)。bg#=inode/`s_inodes_per_group`, inode#在bg内偏移=`inode%s_inodes_per_group`——SuperBlock备份在BG0/BG1和3^n号BG(3,5,7,9,25...) (B1/Ch4)
- **SuperBlock 完整字段**(fs/ext2/ext2.h: `struct ext2_super_block`): `__le32 s_inodes_count;`(inode总数)→`__le32 s_blocks_count;`(block总数)→`__le32 s_r_blocks_count;`(root保留块, 5%)→`__le32 s_free_blocks_count;`(空闲块)→`__le32 s_free_inodes_count;`(空闲inode)→`__le32 s_first_data_block;`(0=4KB block, 1=1KB block)→`__le32 s_log_block_size;`(块大小=1024<<log)→`__le32 s_log_frag_size;`(片大小)→`__le32 s_blocks_per_group;`(每BG块数, 通常=8*s_log_block_size MB, 如4KB→32768=128MB)→`__le32 s_frags_per_group;`→`__le32 s_inodes_per_group;`(每BG inode数, 约block/4)→`__le32 s_mtime;`(最后挂载)→`__le32 s_wtime;`(最后写入)→`__le16 s_mnt_count;`(挂载次数)→`__le16 s_max_mnt_count;`(最大挂载, 达此强制fsck)→`__le16 s_magic;`(0xEF53)→`__le16 s_state;`(0=干净, 1=错误, 2=孤儿文件)→`__le16 s_errors;`(错误处理)→`__le16 s_minor_rev_level;`→`__le32 s_lastcheck;`(最后fsck时间)→`__le32 s_checkinterval;`→`char s_volume_name[16];`→`char s_last_mounted[64];`→SB读取时: `ext2_fill_super→sb_set_blocksize(sb, block_size)→parse_options→ext2_check_descriptors→ext2_setup_super` (B1/Ch4)
- **GDT(Group Descriptor Table)**: `struct ext2_group_desc { __le32 bg_block_bitmap; // block bitmap所在块号(绝对块号, 非BG内偏移)`→`__le32 bg_inode_bitmap; // inode bitmap所在块号`→`__le32 bg_inode_table; // inode table起始块号`→`__le16 bg_free_blocks_count; // BG内空闲块数`→`__le16 bg_free_inodes_count; // BG内空闲inode数`→`__le16 bg_used_dirs_count; // BG内目录数`→`__le16 bg_pad;`→`__le32 bg_reserved[3]; }`——BG#从0开始→bg#=0=第一个BG→每个bg占用`group_desc_size=32`字节(ext2)/64字节(ext4)→GDT总大小=`s_groups_count*group_desc_size`字节→GDT跨越多block→备份GDT在SuperBlock之后的block→读取: `ext2_get_group_desc(sb, bg, &bh)→bh->b_data+offset→gdp`—Block Bitmap: 每个bit对应一个block。例: block size=4KB, `s_blocks_per_group`=32768, bitmap=4096块→bitmap=4KB block→32768/8=4096字节→`find_first_zero_bit(bitmap, end)→get bit`→`ext2_set_bit(i, bitmap)`已用→`ext2_clear_bit(i, bitmap)`空闲 (B1/Ch4)
- **Inode 结构与间接块链**(fs/ext2/ext2.h): `struct ext2_inode { __le16 i_mode; // low 9bit(rwx×ugo), high 3bit(type: IFREG=0x8000, IFDIR=0x4000, IFLNK=0xA000, IFCHR=0x2000, IFBLK=0x6000, IFIFO=0x1000, IFSOCK=0xC000)→ __le16 i_uid; // uid→ __le32 i_size; // 文件实际大小(字节)→ __le32 i_atime; // 访问时间→ __le32 i_ctime; // inode变更时间→ __le32 i_mtime; // 修改时间→ __le32 i_dtime; // 删除时间→ __le16 i_gid; // gid→ __le16 i_links_count; // 硬链接数→ __le32 i_blocks; // 占用512B扇区数(含间接块)→ __le32 i_flags; // EXT2_SECRM_FL(1)/EXT2_UNRM_FL(2)/EXT2_COMPR_FL(4)/EXT2_SYNC_FL(8)/EXT2_IMMUTABLE_FL(16)/EXT2_APPEND_FL(32)/EXT2_NODUMP_FL(64)/EXT2_NOATIME_FL(128)→ __le32 i_block[EXT2_N_BLOCKS=15]; // 15个指针: [0-11]直接块←[12]单重间接(→1 block store 更多块号)→[13]双重间接(→1 indirect block→N个indirect→...)→[14]三重间接 }`—i_block[12]间接→一个block可存`block_size/4`个块号(4KB=1024个)→i_block[13]二重→`(block_size/4)^2`=1M→i_block[14]三重→`(block_size/4)^3`=1G—解析间接块: `ext2_block_to_path(inode, iblock, offsets, &boundary)`→path[i]=offset在第i级→`ext2_get_branch(inode, depth, offsets, chain, &err)→chain[0].bh=sb_bread(block=inode→i_block[0])`→`chain[1].bh=sb_bread(block=chain[0].p+offsets[1])`→遍历到最终block→`bh→b_blocknr`=物理块号 (B1/Ch4)
- **目录项 ext2_dir_entry**(fs/ext2/ext2.h): `struct ext2_dir_entry_2 { __le32 inode; // inode号, 0=空洞(已删除)`→`__le16 rec_len; // 本entry总长度(字节, 必须为4的倍数, 对齐到4字节边界)`→`__u8 name_len; // 文件名长度`→`__u8 file_type; // EXT2_FT_REG_FILE=1, FT_DIR=2, FT_SYMLINK=7`→`char name[EXT2_NAME_LEN=255]; // 文件名(仅前name_len字节有效, 不是null-terminated) }`—目录的底层是文件→data blocks存`ext2_dir_entry`数组→`struct file *dir_file = filp_open(dirpath, O_RDONLY, 0)`→`vfs_readdir→ext2_readdir→ext2_get_page→ext2_find_entry→逐entry→de->name_len==namelen && !memcmp(name, de->name, namelen)`→找到→`inode=de->inode`→新建entry: `ext2_add_link(dir, dentry)→ext2_find_entry`找空洞→`de->rec_len>=needed`→`ext2_set_de_type(de, inode)` (B1/Ch4)

### 1.2 文件创建全链路 — "touch a.txt" 到底经历了什么 (🔴)
- **路径解析 link_path_walk**(fs/namei.c): `sys_open("test/a.txt", O_CREAT|O_WRONLY, 0644)→...→do_filp_open→path_openat→link_path_walk(&nd, name="test/a.txt")`→(1) 第一个分量`test`→`walk_component→lookup_fast→__d_lookup(nd->path.dentry, name="test")`→dentry缓存(dcache)命中→`follow_managed→__follow_mount→path_to_nameidata`→`nd->path=new_dentry`→(2) 第二个分量`a.txt`→`lookup_fast`→dcache未命中→`lookup_slow→d_alloc_parallel`→分配新dentry→`dir->i_op->lookup(dir, dentry, flags)←ext2_lookup`→`ext2_find_entry→ext2_get_page(or reading dir)→逐entry比对name_len+name`→不存在→`err=-ENOENT`→返回→(3) flags有O_CREAT→进入`do_last→lookup_open→atomic_open→vfs_create(dir, dentry, mode, true)→ext2_create` (B1/Ch5, Ch2)
- **ext2_create 详细实现**(fs/ext2/namei.c): `ext2_create(dir, dentry, mode, bool)→ext2_new_inode(dir, mode, &dentry)`:(A) 选择块组: `find_group_dir`(对于目录→均匀分布)或`find_group_orlov`(普通文件→父目录组优先)→(B) `read_inode_bitmap(sb, block_group)→bh`读inode bitmap→`ext2_find_next_zero_bit((unsigned long*)bh->b_data, EXT2_INODES_PER_GROUP(sb), 0)`→找空闲inode→`ext2_set_bit(ino, bh->b_data)`标记→`mark_buffer_dirty_inode(bh, inode)`→(C) 分配inode block: `ext2_new_inode→new_inode(sb, block_group, ino)→ext2_read_inode(inode)`→`inode->i_block[0..14]=0`清零→`i_uid=current_fsuid(), i_gid=current_fsgid(), i_mode=mode, i_atime=i_ctime=i_mtime=inode_set_ctime_current(inode)`→`ext2_write_inode(inode)`(标记脏写回)→(D) 分配数据块(如果需要): `ext2_alloc_blocks`→位图扫描→(E) 加入目录: `ext2_add_link(dir, dentry, inode)`→定位父目录的数据块→找到有足够空间的空洞→写入`ext2_dir_entry`→merge空洞调整rec_len→`mark_buffer_dirty(bh)` (B1/Ch4, Ch5)
- **孤儿文件与末次关闭**: 文件创建→inode刚分配→`i_links_count=0`(还没有目录项)→加入`orphan list`(孤儿inode链表, `EXT2_SB(sb)→s_orphan`→`inode->i_next_orphan=sbi→s_orphan; sbi→s_orphan=inode`)→创建完后→`inode_inc_link_count(inode); i_links_count=1`→从orphan list移除——若创建中途崩溃→重启后`ext2_orphan_cleanup(sb)`→fsck→遍历orphan list→删除或修复——这是ext3/ext4 `has_journal`后不需要orphan list而改用日志回滚的原因 (B1/Ch4, Ch5)

### 1.3 写数据流程 — write() 不立即落盘的完整链路 (🔴)
- **sys_write→ext2 全链路**(fs/read_write.c, mm/filemap.c, fs/ext2/file.c): `sys_write(fd, buf, count)→ksys_write(fd, &pos)→vfs_write(file, buf, count, &pos)→file->f_op->write(file, buf, count, pos)←ext2_file_write_iter`→`generic_file_write_iter(iocb, from)→__generic_file_write_iter(file, &iocb, &iter, &ret)`→`generic_perform_write(file, &iocb, &iter)`→for each folio: `a_ops->write_begin(file, mapping, pos, len, flags, foliop, fsdata)→ext2_write_begin`——**ext2_write_begin**: `block_write_begin(mapping, pos, len, flags, &folio, ext2_get_block)`→计算块号: `ext2_get_block(inode, iblock, bh_result, create=1)`→通过inode→i_block解析间接块→`bh_result→b_blocknr=blocknr`(物理块号)→若需要新块: `ext2_new_blocks(inode, goal, &count, err)`→**copy**: `iov_iter_copy_from_user_atomic(folio, iter, offset, bytes)`→内核→用户拷贝→`folio_mark_accessed(folio)`→`folio_mark_dirty(folio)→__folio_mark_dirty→a_ops->dirty_folio→__xa_set_mark(PG_dirty)→__mark_inode_dirty(inode, I_DIRTY_PAGES)`——**write_end**: `block_write_end(file, mapping, pos, len, copied, folio, fsdata)→__block_commit_write(inode, folio, from, to)`→`SetPageUptodate(folio)`→`mark_buffer_dirty(bh)→test_set_buffer_dirty`→`folio_unlock`→**writeback触发**: `balance_dirty_pages_ratelimited(mapping)`→检查脏页量→超`dirty_ratio`→`balance_dirty_pages(bdi)→io_schedule_timeout(pause)`睡眠→写被阻塞→直到脏页回写到磁盘 (B1/Ch4, Ch7)
- **延迟分配问题**(ext4, 🟡 AI-supplement): ext4→`ext4_da_write_begin→ext4_da_get_block_prep`→写时只reserve块(不调用`ext4_new_blocks`)→`ext4_da_write_pages(回写)→mpage_da_map_and_submit→ext4_map_blocks→ext4_mb_new_blocks`——此时才真正分配块——好处: 多个写合并→大extent(连续块段)→减少碎片→坏处: `write+rename+crash`场景: 应用→write("0")→close→rename(oldfile, newfile)→crash→分配未完成→rename销毁了旧文件→write未提交→新文件为空(数据丢失)→解决方案: `ext4_alloc_da_blocks(inode)`在close时强制分配→`ext4_truncate_failed_write`失败时的回滚—`fallocate(fd, 0, 0, size)`预分配(绕过delay alloc) (🟡 AI-supplement)

### 1.4 读数据流程 — 缓存命中/未命中/预读 (🔴)
- **sys_read→页缓存完整链路**(fs/read_write.c, mm/filemap.c): `sys_read(fd, buf, count)→ksys_read→vfs_read(file, buf, count, &pos)→file->f_op->read(file, buf, count, pos)←ext2_file_read_iter`→`generic_file_read_iter(iocb, to)→filemap_read(iocb, to, &iocb->ki_pos, 0)`→循环: `error = filemap_get_pages(iocb, to, &pvec)`——`filemap_get_pages→page_cache_sync_readahead(mapping, ra, filp, index, last_index - index)`→同步预读→`filemap_get_entry(mapping, index)→folio`查找——页面存在(folio): `folio_lock_folio(folio)`→`folio_put(folio)→copy_folio_to_iter(folio, offset, bytes, iter)`→用户buf——**页面不存在**: `filemap_create_folio(gfp, mapping, index)`→`filemap_read_folio(file, mapping, folio)→a_ops->read_folio(file, folio)←ext2_read_folio`→`block_read_full_folio(folio, ext2_get_block)→create_empty_buffers(folio, blocksize, 0)`→for each buffer_head: `bh->b_blocknr=ext2_get_block`→`get_block`解析间接块→`submit_bh(REQ_OP_READ, bh)`→IO→`wait_on_buffer(bh)`→folio标记`uptodate`→解锁→`copy_folio_to_iter`→返回——**下一个folio预读**: `page_cache_async_readahead(mapping, ra, filp, folio, index, last_index - index)`→异步→`ondemand_readahead→ra_submit→read_pages`→后台IO——顺序读→检测→扩大预读窗口→下次缺页已缓存 (B1/Ch4, Ch8)

### 1.5 文件删除、扩展属性与锁 (🟡)
- **文件删除 unlink 全链路**(fs/namei.c, fs/ext2/namei.c, fs/ext2/inode.c): `sys_unlink(pathname)→do_unlinkat(dfd, &name)→vfs_unlink(mnt_userns, dir, dentry, &delegated_inode)→dir->i_op->unlink(dir, dentry)←ext2_unlink`——(1) 删除目录项: `ext2_delete_entry(dir, de, bh)`→`de->inode=0`(空洞) + merge空洞→`ext2_delete_entry```→`pde->rec_len += de->rec_len`→`mark_buffer_dirty_inode(bh, dir)`→(2) 更新inode引用计数: `inode_dec_link_count(inode)→drop_nlink(inode)`→`i_links_count`减1——`i_links_count=0`→触发删除——(3) 将inode加入orphan list: `ext2_orphan_add(inode)`→(4) 释放inode: `ext2_free_inode(inode)→clear_inode(inode)→ext2_clear_inode(inode)`→`inode->i_size=0`→`ext2_truncate(inode)`→通过i_block[0..14]递归释放所有indirect blocks——(5) 释放数据块: 遍历i_block→`ext2_free_data(inode, i_data, i_data+EXT2_N_BLOCKS-1)`→每个直接块→`ext2_clear_bit(block, bitmap_bh→b_data)`→间接块递归→`ext2_free_branches`→三重间接→双重→单重→直接→每个块: `ext2_free_blocks(sb, block, count)`→clear block bitmap→更新`sbi→s_free_blocks_count`和gdp→bg_free_blocks_count——(6) 释放inode bitmap: `ext2_clear_bit(ino, bitmap_bh→b_data)`→inode空闲——(7) 从orphan list移除——(8) `ext2_write_inode(inode)`写入i_dtime标记 (B1/Ch4, Ch6)
- **扩展属性 xattr + ACL**(fs/ext2/xattr.c, fs/ext2/acl.c): `setxattr(path, name, value, size, flags)→ext2_xattr_set→ext2_xattr_get`→xattr存在额外的磁盘块(位于inode→i_file_acl)→`ext2_xattr_find_entry→ext2_xattr_list`→**属性布局**: `ext2_xattr_header`(magic=0xEA020000)→`ext2_xattr_entry`数组(e_name_index, hash, name, value_start, value_len)→末尾→value存储区——ACL==xattr的子集: `system.posix_acl_access→posix_acl_from_xattr`→`ext2_set_acl→posix_acl_create→ext2_init_acl`→新文件默认继承父目录ACL→`getfacl/setfacl`→`ext2_permission→generic_permission→ext2_acl_permission_check`→遍历ACL entries (B1/Ch4)
- **文件锁 flock + fcntl**(fs/locks.c): `flock(fd, LOCK_SH|LOCK_EX|LOCK_UN)→sys_flock→ext2_flock→locks_lock_file_wait→flock_lock_inode`→`struct file_lock`新建→加入`inode→i_flock`链表→冲突→sleep→等待持有者释放——`**fcntl POSIX锁**: `fcntl(fd, F_SETLK, &flock)→f_setlk→do_fcntl_setlk→vfs_lock_file→posix_lock_file`→`struct file_lock fl`→fl_start+fl_len→可为文件任意范围加锁→`locks_insert_lock_ctx`→`/proc/locks`→`lslocks`→`lockf`库函数(简化的fcntl)——区别: flock(文件级+劝告)/fcntl(范围+强制位+记录+进程)/lockf(范围+POSIX) (B1/Ch4)
- **文件系统对比**(fs/ext4, fs/xfs, fs/btrfs): ext4→ext2+extent+journal+extent tree→max 1EB/16TB→RHEL/SUSE/Linux默认→稳定→ext4_mb_regular_allocator→XFS→SGI→64位→extent-based B+tree→元数据journal→在线扩展(不可缩)→RHEL7/8默认→max 8EB→**ext4 vs XFS**: ext4更广泛应用+recovery; XFS更大扩展+并发——**Btrfs**: COW→快照→subvolume→压缩(zlib/lzo/zstd)→去重→RAID→校验和→Fedora默认——**ZFS**: 128位→pool→dataset→dnode→checksum→快照→L2ARC/slog→`zpool/zfs`→FreeBSD/Linux (`openzfs`) (🟡)

## 阶段2: 扩展特性与跨域文件系统 (B集群, 6项)

### 2.1 日志技术 — JBD2 (🟡 AI-supplement)
- **为什么ext4需要日志**: ext2→无日志→崩溃→fsck→scan all inodes+bitmaps→大FS数小时→ext4→journal→保证元数据一致性→**JBD2架构**(fs/jbd2/): `struct journal_s { unsigned long j_flags; int j_errno; struct block_device *j_dev; struct inode *j_inode; unsigned long j_head, j_tail, j_free; unsigned int j_max_transaction_buffers; struct task_struct *j_task; // jbd2 journal thread`→`jbd2_journal_commit_transaction(journal)`—**事务生命周期**: `jbd2_journal_start(handle, nblocks)→handle_t`→`jbd2_journal_get_write_access(handle, bh)`获得修改权限→modify the buffer→`jbd2_journal_dirty_metadata(handle, bh)`标记脏元数据→`jbd2_journal_stop(handle)`结束事务→后台: `jbd2_journal_commit_transaction→jbd2_journal_write_metadata_buffer→jbd2_journal_submit_bh`——Journal 提交块结构: descriptor block(前导, 列出所有元数据块)→metadata blocks→tag blocks——replay: `jbd2_journal_recover(journal)→jbd2_journal_skip_recovery→do_one_pass`扫描日志→找到descriptor block→根据bock映射读data blocks→`jbd2_journal_do_checkpoint`→checkpoint→日志空间回收 (🟡 AI-supplement)
- **ext4 三种日志模式**: `data=writeback`: 元数据journal+数据异步→最快→崩溃后文件内容有垃圾(上次写入未完成)→`data=ordered`(默认): 元数据journal+数据先flush到磁盘再commit journal→`data=journal`: 元数据+数据两者都写journal→最安全最慢→`/proc/fs/ext4/<dev>/options`→`tune2fs -o journal_data /dev/sdX`→`tune2fs -O ^has_journal /dev/sdX`可关日志 (🟡 AI-supplement)

### 2.2 快照与COW文件系统 (🟡 AI-supplement)
- **Btrfs COW原理**: subvolume(子卷, `btrfs subvolume create`)—所有写→COW: tree block→修改→新位置写→指针更新→旧数据保留→快照(`btrfs subvolume snapshot /mnt/@ /mnt/@snap`)=冻结根指针→写操作→仅被写的block→新位置+copy→共享不变block——`btrfs receive/send`→增量快照→`btrfs-find-root`恢复——**数据完整性**: checksum: `csum_tree_block`→读→`csum_verify`→失败→`btrfs_readpage_end_io`→mirror重试/data corruption报错——**去重**: `duperemove /mnt`→`btrfs-extent-same`→byte-by-byte compare→share extent——**ZFS快照**: `zfs snapshot pool/fs@snap`→COW+dnode→`zfs rollback`→`zfs clone`→**ZFS send**: full(`zfs send pool/fs@snap`)→incremental(`-i @old @new`)→pipe→`zfs receive`异地容灾 (🟡 AI-supplement)
- **LVM快照**(🟡 AI-supplement): `lvcreate -L 2G -s -n snap /dev/vg/lv`→快照卷→COW: 原卷被写→先copy原内容到快照卷→然后允许写→快照卷存"修改前的数据"→`lvs /dev/vg/snap`→`mount -o ro /dev/vg/snap /mnt/snap`→`lvremove /dev/vg/snap`删除快照→扩展: `lvextend -L +1G /dev/vg/snap`

### 2.3 挂载与权限管理 (🟡)
- **挂载全流程**(fs/namespace.c, fs/ext2/super.c): `mount -t ext2 /dev/sda1 /mnt→sys_mount→do_mount→path_mount→do_new_mount→vfs_kern_mount(type=ext2_fs_type, flags, dev_name="/dev/sda1", data=NULL)→ext2_mount→mount_bdev(fs_type, flags, dev_name, data, ext2_fill_super)`→`blkdev_get_by_path(dev_name)`→bd_claim→`sget(fs_type, ext2_test_super, ext2_set_super, flags, sb)`→未找到→`sb=alloc_super(type, flags)`→`sb->s_op=&ext2_sops`→`ext2_fill_super(sb, data, silent)`——读取SuperBlock: `sb_bread(sb, 1)`→`es=(struct ext2_super_block*)bh->b_data`→验证magic=0xEF53→`sb_set_blocksize→parse_options→ext2_setup_super→ext2_check_descriptors`→`ext2_fill_super`创建sbi→`iget_locked(sb, EXT2_ROOT_INO=2)→ext2_read_inode(inode)→inode_init_owner`→`d_make_root(inode)→sb->s_root`→`mount`完成 (B1/Ch4)
- **权限管理(RWX/ACL)**(fs/namei.c): `may_open→inode_permission(mnt_userns, inode, MAY_OPEN|acc_mode)→do_inode_permission→generic_permission(inode, mask)`→检查: `mode & 0007`→`uid_eq(inode->i_uid, fsuid)`→检查owner(高3bit)→不匹配→检查是否是`in_group_p(inode->i_gid)`→检查group(中3bit)→不匹配→检查other(低3bit)→`capable_wrt_inode_uidgid(CAP_DAC_OVERRIDE)`→capability bypass→**POSIX ACL扩展**: `posix_acl_permission(inode, mask)→acl->a_entries`→遍历: `ACL_USER_OBJ(owner)/ACL_USER(name)/ACL_GROUP_OBJ(group)/ACL_GROUP(name)/ACL_MASK/ACL_OTHER`→按照最小匹配→**ACL配置**: `setfacl -m u:alice:rw file`→`setfacl -m g:staff:r file`→`getfacl file`→default ACL(新文件继承) (B1/Ch2, Ch4)

### 2.4 网络文件系统 — NFS 协议 (🟡)
- **NFS v3/v4 协议栈**: XDR(External Data Representation)→portmap/rpcbind→`NFS_PROGRAM=100003`→**NFS v3**(无状态): `NFSPROC3_NULL→NFSPROC3_GETATTR(fh)→NFSPROC3_SETATTR(fh, attr)→NFSPROC3_LOOKUP(dirfh, name)→NFSPROC3_READ(fh, offset, count)→NFSPROC3_WRITE(fh, offset, count, stable)→NFSPROC3_CREATE(dirfh, name, mode)→NFSPROC3_MKDIR(dirfh, name, mode)→NFSPROC3_REMOVE(dirfh, name)→NFSPROC3_RMDIR(dirfh, name)→NFSPROC3_RENAME(fromdirfh, fromname, todirfh, toname)→NFSPROC3_LINK(dirfh, name)→NFSPROC3_READDIR(dirfh, cookie)→NFSPROC3_FSSTAT(fh)→NFSPROC3_COMMIT(fh)`——**NFS v4**(有状态, 复合操作=多个ops合并一次RPC): `SEQUENCE→PUTFH→OPEN→READ→CLOSE`→delegation(客户端独占→无锁→无RPC)→`stateid`→`layout`→pNFS灵活布局——**file handle(fh)**: 服务端返回→客户端opaque→标识文件——客户端挂载: `mount -t nfs server:/export /mnt→nfs_get_root→nfs4_proc_get_root(fh)→nfs_fhget(sb, fh, fattr)→inode`——属性缓存: `nfs_inode→cache_validity=NFS_INO_INVALID_ATTR|NFS_INO_INVALID_DATA`→`acregmin=3s`(文件属性缓存)→`acregmax=60s`→`acdirmin/acdirmax`(目录属性缓存)——write delegation→客户端独占写→服务端grant→客户端本地写→结果提交(delegation return)→`async`模式: 客户端write不等待服务端提交→数据可能丢失→`sync`模式: 每个write等commit→安全慢化 (B1/Ch5)

### 2.5 FUSE 用户态文件系统 (🟡)
- **FUSE内核模块**(fs/fuse/): VFS→`/dev/fuse`→字符设备→ioctl→`fuse_ioctl`→用户态daemon——内核发送request: `fuse_request_end(fc, req)→req->in.h.opcode→req->out.args`→`fuse_dev_read(fc, file, buf, count, ppos)`→copy_to_user→用户态daemon→`/dev/fuse`→`fuse_session_loop→fuse_session_receive_buf→process→fuse_session_send_reply`→`write(fc→pipe, iov, 2)`→内核: `fuse_dev_write(fc, file, write_buf, count, ppos)→fuse_request_end`→唤醒等待——**libfuse ops**: `struct fuse_operations { .init, .destroy, .getattr, .readlink, .mknod, .mkdir, .unlink, .rmdir, .symlink, .rename, .link, .chmod, .chown, .truncate, .open, .read, .write, .statfs, .flush, .release, .fsync, .setxattr, .getxattr, .listxattr, .removexattr, .opendir, .readdir, .releasedir, .fsyncdir, .access, .create, .lock, .utimens, .bmap, .ioctl, .poll, .write_buf, .read_buf, .flock, .fallocate, .copy_file_range, .lseek }`→**示例: 简单内存FS**: `struct memfs { char name[256]; char data[4096]; }`→`create=malloc→read=memcpy→write=memcpy_to_fuse→unlink=free`→`fuse_main(argc, argv, &memfs_oper, NULL)`——**sshfs**: `sshfs user@host:/remote /mnt→ssh→sftp subsystem`→远程文件做成本地挂载——性能: 每个IO→内核→用户态→sftp→网络→返回→2×上下文切换+网络RTT→吞吐量低但极致灵活 (B1/Ch7)

### 2.6 对象存储与分布式FS概览 (🟡🟢)
- **对象存储 S3/Haystack**(🟡): S3 API: `bucket→object_key→{metadata: {Content-Type, ETag(md5), Last-Modified, x-amz-*}, data}`→HTTP REST: GET/PUT/DELETE/HEAD→versioned: `?versionId`→无需文件系统→**Haystack(元数据+FUSE挂载)**: Facebook亿级照片→`write(needle_id)→append-only log→needle_index`(hash→log offset)→`read(needle_id)→read_index→seek_log(lookup_offset)→read data→stitch_photo`→compact: 垃圾回收→标记dead needles→新log→迁移live needles→回收旧log→**优点**: 无目录树→无任意修改(只写一次多读)→无碎片→水平扩展简单→分区(hash) (B1/Ch7)
- **分布式FS**(🟢→分布式专题): CephFS(CRUSH→无中心MDS→`ceph mds stat`→元数据集群可多活)→RADOS→pool→PG→OSD→`ceph df`→**GlusterFS**(对等→DHT hash dir+elastic hash algorithm→无MDS→`gluster volume create test-volume replica 2 server{1,2}:/brick`→`mount -t glusterfs server1:/test-volume /mnt`)——详细归分布式专题 (🟢)
