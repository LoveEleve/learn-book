## 阶段1: 物理内存分配 — 从struct page到Buddy (A集群, 零依赖)

### 1.1 struct page & struct folio — 物理页描述符 (🔴)
- **struct page 核心字段**(include/linux/mm_types.h): `unsigned long flags`(page→flags, 按位编码: PG_locked/PG_dirty/PG_writeback/PG_reclaim/PG_swapbacked/PG_uptodate/PG_referenced/PG_unevictable/PG_mlocked/PG_error/PG_slab)——`atomic_t _refcount`(引用计数, page_ref_inc/page_ref_dec, 0→可回收)——`atomic_t _mapcount`(页表映射数, page_mapcount, -1=无映射, 0=单映射)——`struct address_space *mapping`(所属address_space for file-backed / 所属anon_vma→root for anonymous)——`pgoff_t index`(在mapping中的偏移, 文件偏移>>PAGE_SHIFT)——`void *private`(私有数据, buffer_head for buffers / swp_entry_t for swap)——`struct list_head lru`(LRU链表节点, ke ep pagevec)——每个struct page 64字节→1GB物理内存需16MB struct page→vmemmap数组存放 (B1/Ch2)
- **PG_* 标志位全集与测试宏**: PG_locked(PG_locked=0, folio_trylock/folio_lock/folio_unlock→bit_spin_lock)→PG_dirty(PG_dirty=4, folio_mark_dirty/folio_clear_dirty_for_io)→PG_writeback(PG_writeback=6, folio_start_writeback/folio_end_writeback)→PG_reclaim(PG_reclaim=17)→PG_swapbacked(PG_swapbacked=18, 有swap后备的匿名页)→PG_uptodate(PG_uptodate=2, folio_mark_uptodate)→PG_referenced(PG_referenced=3, folio_mark_accessed→LRU升权)→PG_unevictable(PG_unevictable=19, mlock锁住的页, 不可回收)→PG_mlocked(PG_mlocked=20)→PG_error(PG_error=1)——`folio_test_*`/`folio_set_*`/`folio_clear_*`系列宏访问——`page_flags` 不是原子读(竞态存在)但有`Page*`内联函数+`SetPage*`原子版本 (B1/Ch2)
- **struct folio 设计演进**(include/linux/page-flags.h, mm/types.h): Linux 5.16+ 引入→多页抽象→解决compound page碎片化→`struct folio { struct page page; }`(超集, 嵌入首个page)——`unsigned long flags`(folio级标志, 比page级更粗)——`unsigned int _folio_order`(阶数, 0=单页, 1=2页, 2=4页...)——`atomic_t _refcount`(folio整体引用计数)——`folio_order(folio)`/`folio_nr_pages(folio)`(1<<order页)——`folio_page(folio, n)`取第n页——`folio_lock(folio)`替代`lock_page(page)`——`folio_end_read(folio)`/`folio_end_writeback(folio)`——转换: `page_folio(page)→compound_head(page)→folio`——s multi-page folio减少每个subpage的独立锁+状态追踪 (B1/Ch2, 🟡设计意图)
- **物理内存模型三组件**(mm/mmzone.c, include/linux/mmzone.h): **Sections**(SPARSEMEM: 内存分section, `SECTION_SIZE_BITS`=30→1section=1GB, `mem_section[NR_SECTION_ROOTS][SECTIONS_PER_ROOT]`稀疏存储`struct mem_section`)——**PFN**(Page Frame Number: 物理地址>>PAGE_SHIFT, `pfn_to_page(pfn)`/`page_to_pfn(page)`, 全局唯一, PFN_ALIGN对齐)——**Node**(NUMA节点: `pg_data_t *node_data[MAX_NUMNODES]`, `pgdat→node_zones[ZONELIST_FALLBACK]`, `pgdat→node_mem_map`/`pgdat→node_start_pfn`/`pgdat→node_spanned_pages`/`pgdat→node_present_pages`——`NODE_DATA(nid)`宏)——**Zone**(区域: `struct zone { unsigned long watermark[NR_WMARK]; long lowmem_reserve[MAX_NR_ZONES]; struct per_cpu_pageset __percpu *pageset; struct free_area free_area[MAX_ORDER]; spinlock_t lock; }`——zone类型: ZONE_DMA(0-16MB)/ZONE_DMA32(0-4GB)/ZONE_NORMAL(16MB-896MB,直接映射)/ZONE_HIGHMEM(>896MB,32位,64位无)/ZONE_MOVABLE(可移动))——`zone→present_pages`实在内存/`zone→spanned_pages`含空洞 (B1/Ch2, 🟡)
- **Direct Mapping 直接映射**(arch/x86/mm/init.c): 物理地址→线性偏移→内核虚拟地址——`__va(phys)=phys+PAGE_OFFSET`(PAGE_OFFSET=0xffff880000000000)——`__pa(virt)=virt-PAGE_OFFSET`——`phys_to_virt()/virt_to_phys()`——kmalloc从直接映射区分配→无需额外页表→高效——vmalloc从vmalloc区分配→需逐页建立页表→慢——direct mapping大小为`MAXMEM`(64TB, 5级页表) / 64TB(4级)——内核态可直接访问所有物理内存(通过direct mapping) (B1/Ch3, 🟡)

### 1.2 Buddy Allocator + PCP — 伙伴系统核心路径 (🔴)
- **核心数据结构**(include/linux/mmzone.h): `struct zone { struct free_area free_area[MAX_ORDER]; }`——`struct free_area { struct list_head free_list[MIGRATE_TYPES]; unsigned long nr_free; }`——MAX_ORDER=11(PAGE_ALLOC_COSTLY_ORDER=3)——order 0=4KB, order 1=8KB, ..., order 10=4MB——每个order+迁移类型一个`free_list`——空闲伙伴通过`page→buddy_list`链接——`PageBuddy(page)`标记——`page→private`存储order——伙伴条件: 两个page的PFN连续+order相同+都在free_area中 (B1/Ch2, B2/Ch5)
- **分配全路径**(mm/page_alloc.c): `alloc_pages(gfp_mask, order)→alloc_pages_node→__alloc_pages→__alloc_pages_nodemask`→prepare alloc_context(从gfp_mask提取zone+watermark要求)→first pass(get_page_from_freelist: 尝试当前zone→备用zone, `node_zonelist`定义优先级)→fail→second pass(`__alloc_pages_slowpath`: 唤醒kswapd回收→允许直接回收→compact→重试)→still fail→`__alloc_pages_may_oom`→OOM Killer→`__alloc_pages_cpuset_fallback`最后回退——`get_page_from_freelist→rmqueue→__rmqueue→__rmqueue_smallest(当前order有空闲)=fast path / __rmqueue_fallback(当前order无, 从大order分裂)→rmqueue_pcplist(per-CPU热页列表优先, 减少zone→lock竞争)` (B1/Ch2)
- **PCP(Per-CPU Pageset)**(include/linux/mmzone.h): `struct per_cpu_pages { spinlock_t lock; int count; int high; int batch; struct list_head lists[MIGRATE_PCPTYPES]; }`——`pageset→pcp[ migratetype ]`——分配优先`rmqueue_pcplist`从PCP取(无需zone lock)→PCP空→`rmqueue_bulk`从zone bulk refill(batch个页)→释放优先回灌PCP→PCP count达high→`free_pcppages_bulk`回灌zone——`high=max(batch*6, batch*4)`→cold pages(刚从alloc返回的)和hot pages(最近free的)有不同PCP列表→减少false sharing (B1/Ch2)
- **单页释放路径**(mm/page_alloc.c): `__free_pages(page, order)→__free_pages_ok→free_one_page→__free_one_page`——检查伙伴是否空闲(`page_is_buddy`: 同zone+同order+PG_buddy标志+PFN连续)→空闲→`__del_page_from_free_list`从链表删除→`page_idx & (1<<order)`确定伙伴PFN→page(order+1)合并→重复直到最大order或伙伴忙——`add_to_free_list`加入对应order+迁移类型链表——`SetPageBuddy(page)`/`ClearPageBuddy(page)`——`__ClearPageBuddy`标记非伙伴 (B1/Ch2)
- **迁移类型与Fallback**(include/linux/mmzone.h): MIGRATE_UNMOVABLE(0): `GFP_KERNEL`分配, 内核核心(slab/内核栈/页表)——MIGRATE_MOVABLE(2): `GFP_HIGHUSER_MOVABLE`, 用户页——MIGRATE_RECLAIMABLE(1): `GFP_KERNEL`+可回收(SLAB_RECLAIM_ACCOUNT)——MIGRATE_PCPTYPES(3)前3个有PCP——MIGRATE_CMA(3)/MIGRATE_ISOLATE(4)——`fallbacks[MIGRATE_TYPES][4]`矩阵: MOVABLE→UNMOVABLE→RECLAIMABLE→CMA→...→`__rmqueue_fallback`当当前迁移类型order链表为空时→按矩阵从其他类型偷页→`steal_suitable_fallback`最多偷1/2——`movablecore=nn[KMG]`内核参数预留MOVABLE区——减少UNMOVABLE页导致的碎片化 (B1/Ch2, 🟡碎片策略)

### 1.3 GFP Flags — 分配控制字 (🔴)
- **GFP掩码四类位域**(include/linux/gfp.h): **Zone Modifiers**: `__GFP_DMA`(bit0, 限制ZONE_DMA)/`__GFP_DMA32`(bit1)/`__GFP_HIGHMEM`(bit2, 32位ZONE_HIGHMEM)——**Reclaim Modifiers**: `__GFP_RECLAIM`(允许回收, must have for sleepable)/`__GFP_DIRECT_RECLAIM`(bit18, 允许直接回收, blocking, 可睡眠) / `__GFP_KSWAPD_RECLAIM`(bit20, 唤醒kswapd, 不阻塞)——**Watermark Modifiers**: `__GFP_HIGH`(bit3, 允许使用MIN水位紧急预留)<`__GFP_ATOMIC`(bit4, 不能睡眠, 隐含__GFP_HIGH) | `__GFP_MEMALLOC`(bit12, 允许使用全部内存, 回收上下文专用) | `__GFP_NOMEMALLOC`(bit14, 不允许使用紧急预留)——**Action Modifiers**: `__GFP_NOWARN`(bit6, 抑制分配失败警告)/`__GFP_NORETRY`(bit5, 不重试)/`__GFP_NOFAIL`(bit9, 永不失败, 无限重试, 危险)/`__GFP_ZERO`(bit7, 返回零页)/`__GFP_NO_KSWAPD`(bit17, 不唤醒kswapd) (B1/Ch2)
- **常用组合宏**: `GFP_KERNEL`=`__GFP_RECLAIM|__GFP_IO|__GFP_FS`—内核标准分配, 可睡眠可回收——`GFP_ATOMIC`=`__GFP_HIGH|__GFP_ATOMIC|__GFP_NOWARN`—中断上下文, 不睡眠, 允许用到MIN水位——`GFP_USER`=`__GFP_RECLAIM|__GFP_IO|__GFP_FS|__GFP_HARDWALL`—用户空间分配——`GFP_HIGHUSER_MOVABLE`=`GFP_USER|__GFP_HIGHMEM|__GFP_MOVABLE`—高地址用户空间+可移动——`GFP_DMA`=`__GFP_DMA`—ISA DMA区域, 历史遗留——`GFP_NOWAIT`=`GFP_ATOMIC & ~__GFP_HIGH`—不睡眠+不用紧急预留——选错GFP: 中断上下文用GFP_KERNEL→睡眠→kernel panic (B1/Ch2)
- **Watermark 三级水位**: `zone→watermark[WMARK_MIN]`(min_free_kbytes, 默认~4MB, 紧急预留)—`zone→watermark[WMARK_LOW]`(low, ~5MB, kswapd唤醒)—`zone→watermark[WMARK_HIGH]`(high, ~6MB, kswapd停止)—`__GFP_HIGH`允许访问MIN—分配时检查: `zone_watermark_fast(zone, order, mark)→__zone_watermark_ok`→free_pages≥mark→`zone→lowmem_reserve[classzone_idx]`保护低zone不被高zone耗尽—`/proc/sys/vm/min_free_kbytes`改变MIN—水线计算: `min=sqrt(zone_managed_pages*16)` (B1/Ch2)

### 1.4 vmalloc 与扩展分配器 (🟡)
- **vmalloc**: 虚拟连续+物理不连续—`vmalloc(size)→__vmalloc_node_range→__get_vm_area_node`(找空闲虚拟地址区间: `alloc_vmap_area`→红黑树`vmap_area_root`→first-fit找空闲)—`__vmalloc_area_node→vmalloc_pages→__vmalloc_pages_node(alloc_page单页)`每页单独alloc_page→`map_vm_area→vmap_pages_range_noflush→__vmap_pages_range`建立页表映射(逐级pgd_populate/pud_populate/pmd_populate/`set_pte`)→内核虚拟地址→比kmalloc慢(需逐页分配+建页表+TLB miss)—适合大块(>PAGE_SIZE)临时buffer—`/proc/vmallocinfo`查看所有vmalloc区域—`vfree→__vunmap→remove_vm_area→unmap_kernel_range_noflush→free_vm_area→free_unref_page` (B1/Ch3)
- **memblock**(🟢→OS内核交叉引用): `memblock_add(base, size)`注册—`memblock_reserve(base, size)`保留—`memblock_alloc(size, align)`分配—`memblock=debug`内核参数—`/sys/kernel/debug/memblock/` (B2)

## 阶段2: 虚拟内存与缺页 — 从地址空间到COW (B集群, 依赖A)

### 2.1 页表 — 四级遍历、PTE标志与页表锁 (🔴)
- **四级页表完整结构**(arch/x86/include/asm/pgtable_64_types.h): PGD(Page Global Directory)→P4D(5级页表用, non-5LEVEL时通过p4d_offset透明折叠→P4D→PUD旁路)→PUD(Page Upper Directory)→PMD(Page Middle Directory)→PTE(Page Table Entry)——每级9位偏移→虚拟地址48位(4级) / 57位(5级, La57)——`pgd_t`(8字节)/`p4d_t`/`pud_t`/`pmd_t`/`pte_t`——遍历宏: `pgd_offset(mm, addr)`/`p4d_offset(pgd, addr)`/`pud_offset(p4d, addr)`/`pmd_offset(pud, addr)`/`pte_offset_map(pmd, addr)`→返回`pte_t *`——`pgd_none(*pgd)`检查是否空(全0)→`p4d_alloc/pud_alloc/pmd_alloc`分配中间页表 (B1/Ch3, B2/Ch6)
- **PTE 64位的完整标志位定义**(arch/x86/include/asm/pgtable_types.h): bit0 `_PAGE_PRESENT`(0x001, 页在内存, 缺页时=0导致#PF)——bit1 `_PAGE_RW`(0x002, 可写, 只读时=0→写触发COW或SIGSEGV)——bit2 `_PAGE_USER`(0x004, 用户态可访问, 内核页=0)——bit3 `_PAGE_PWT`(0x008, Page Write-Through)——bit4 `_PAGE_PCD`(0x010, Page Cache Disable)——bit5 `_PAGE_ACCESSED`(0x020, 被访问过→LRU→`ptep_test_and_clear_young`清除)——bit6 `_PAGE_DIRTY`(0x040, 脏→`ptep_test_and_clear_dirty`清除→软脏页跟踪)——bit7 `_PAGE_PSE`(0x080, 2MB大页)——bit8 `_PAGE_GLOBAL`(0x100, 全局页→TLB不刷新)——bit9-11 可用(软件定义)——bit12-51 物理页帧号(PFN)→bit63 `_PAGE_NX`(0x8000000000000000, No-eXecute)——**软件定义标志**: `_PAGE_SPECIAL`(bit9, 非struct page)/`_PAGE_PROTNONE`(bit8, NUMA迁移标记)/`_PAGE_SOFT_DIRTY`(bit11, 软脏页, CRIU迁移)——操作函数: `set_pte(ptep, pte)`/`ptep_set_wrprotect(mm, addr, ptep)`同时TLB flush/`ptep_set_access_flags`设置Accessed+Dirty+可写/`pte_mkclean`清Dirty/`pte_mkdirty`设Dirty/`pte_mkold`清Accessed/`pte_young`测Accessed (B1/Ch3)
- **页表锁分级**(mm/memory.c): 老式(2.6.23前): `mm→page_table_lock`全局自旋锁→分配新页表→修改现有PTE→所有操作争用同一锁——新式: split PTL——**PMD lock**: THP(大页=PMD级映射)用`pmd_lock(mm, pmd)`→pmd_lockptr→spin_lock——**PTE lock**: 普通页用`pte_lockptr(mm, pmd)`→`spin_lock(ptl)`→`pte_offset_map_lock(mm, pmd, addr, &ptl)`组合获取→`pte_unmap_unlock(ptep, ptl)`组合释放——锁范围最小化: 每个pmd/PTE表对应一个spinlock→锁的粒度=页表页粒度→页表分配时`__pte_alloc`→`pmd_populate`→关联锁 (B1/Ch3)
- **页表遍历完整开销**: 无TLB命中→硬件Page Table Walk: MMU→CR3取PGD→4次内存访问→找到PTE→计算物理地址→访问最终页→4+1=5次内存访问≈几百ns。TLB命中→0次内存访问→1cycle→差距百倍。TLB miss+软件walk(硬件不支持时)→`do_page_fault→handle_mm_fault→pgd_none/pud_none/pmd_none→p4d_alloc/pud_alloc/pmd_alloc`→建中间页表→`handle_pte_fault`→建最终映射→更多开销 (B1/Ch3)

### 2.2 TLB — 页表缓存与跨核刷新 (🔴)
- **TLB硬件组织**: 全相联或组相联→通常ITLB(指令)+DTLB(数据)分离→L1 TLB(小,fast: ~64项)+L2 TLB(大: ~1024-2048项)→MMU硬件自动查询→命中latency~1cycle→缺失→PMH(Page Miss Handler)硬件walk→查页表→填充TLB→**x86 TLB flush指令**: `invlpg addr`(单条, 无效指定地址的TLB条目)→`mov %cr3, %rax; mov %rax, %cr3`(全刷新, 成本极高~1000+ cycles)→**ASID**(ARM)/**PCID**(x86): Process-Context Identifier→12位→4096个不同PCID→每个进程分配一个→TLB条目打PCID标签→上下文切换不刷新TLB→只切换CR3(CR3低12位存PCID)→`X86_FEATURE_PCID` (B1/Ch3, B2/Ch1)
- **TLB shootdown流程**(arch/x86/mm/tlb.c): 修改页表(如mprotect/munmap/ksm合并/THP拆分)→必须无效其他CPU的stale TLB→`flush_tlb_mm_range(mm, start, end, stride, freed_tables)`→检查`mm->cpumask`(哪些核使用本mm)→`smp_call_function_many(&mask, native_flush_tlb_others, &info, 1)`→IPI(处理器间中断, vector=0xfd CALL_FUNCTION_VECTOR)发送到目标核→目标核在中断上下文执行`flush_tlb_func`→`__flush_tlb_one_user(addr)`: `invlpg addr`(若PCID→`invlpg`按PCID无效)→优化: `tlb_is_not_lazy`检测→lazy TLB模式下延迟刷新→`mm_cpumask(mm)`→`cpumask_test_cpu(cpu, mm_cpumask(mm))`确定目标——开销: IPI latency几十微秒+INVLPG~几十cycle→频繁munmap/mprotect导致大量IPI→性能杀手 (B1/Ch3)
- **大页与TLB效率**: 2MB page→虚拟地址bit21-47直接映射→PMD级→TLB单个2MB条目=512个4KB条目→1GB page→bit30-47→PUD级→Gigantic Huge Page——hugetlbfs: `hugetlb_fault→hugetlb_no_page→alloc_huge_page→gather_surplus_pages(超过预分配时动态分配)——配置: `hugepagesz=2M hugepages=1024`引导参数→`/proc/sys/vm/nr_hugepages`→`mmap MAP_HUGETLB`→`HugePages_Total`/`HugePages_Free`→缺点: 分配延迟(compaction)+内存碎片 (B2/Ch1)

### 2.3 mm_struct 与 VMA (🔴)
- **mm_struct 完整定义**(include/linux/mm_types.h): `struct mm_struct { struct vm_area_struct *mmap; struct rb_root mm_rb; unsigned long mmap_base; unsigned long mmap_legacy_base; unsigned long task_size; pgd_t *pgd; atomic_t mm_users; atomic_t mm_count; int map_count; spinlock_t page_table_lock; struct rw_semaphore mmap_lock; struct list_head mmlist; unsigned long hiwater_rss; unsigned long hiwater_vm; unsigned long total_vm, locked_vm, pinned_vm, data_vm, exec_vm, stack_vm; unsigned long start_code, end_code, start_data, end_data; unsigned long start_brk, brk, start_stack; unsigned long arg_start, arg_end, env_start, env_end; }`——每个进程一个(mm指向)→内核线程mm=NULL→mm_users(用户态引用计数:进程+所有线程共享此mm)→mm_count(内核引用: page fault handler, oom reaper等hold→mmgrab/mdrop)→mmap_lock(rwsem→保护mmap/munmap/mprotect等操作的VMA修改, `mmap_read_lock/mmap_write_lock`)→`task_size`(用户空间上限: TASK_SIZE_MAX=47位=128TB 虚拟空间) (B1/Ch4)
- **VMA 完整定义**(include/linux/mm_types.h): `struct vm_area_struct { unsigned long vm_start, vm_end; // 虚拟地址区间, [start, end)`→`struct vm_area_struct *vm_next, *vm_prev; // 排序链表`→`struct mm_struct *vm_mm; // 所属mm`→`pgprot_t vm_page_prot; // PTE保护位`→`unsigned long vm_flags; // VM_READ|VM_WRITE|VM_EXEC|VM_SHARED|VM_MAYSHARE|VM_GROWSDOWN|VM_GROWSUP|VM_DONTEXPAND|VM_DENYWRITE|VM_LOCKED|VM_IO|VM_SEQ_READ|VM_RAND_READ|VM_ACCOUNT|VM_NORESERVE|VM_HUGETLB|VM_MERGEABLE`→`struct file *vm_file; // 映射文件(匿名时NULL)`→`unsigned long vm_pgoff; // 文件偏移(页单位PAGE_SHIFT)`→`const struct vm_operations_struct *vm_ops; // open/close/fault/page_mkwrite/pfn_mkwrite`→`void *vm_private_data;`→进程地址空间组织: VMA按地址排序的链表(`mmap`)+红黑树(`mm_rb`)双索引→`find_vma(mm, addr)`: 红黑树O(log n)→`find_vma_intersection(mm, start, end)`: 查找VMA→`/proc/PID/maps`遍历`mmap`链表→`/proc/PID/smaps`遍历所有VMA (B1/Ch4)

### 2.4 缺页异常四场景 — 匿名/COW/文件/栈 (🔴)
- **匿名缺页完整流程**(mm/memory.c): 访问mmap MAP_ANONYMOUS|MAP_PRIVATE分配的地址→MMU→页表Present=0→#PF(page fault error code)→`do_user_addr_fault→handle_mm_fault→__handle_mm_fault→handle_pte_fault`(PTE不存在)→`do_anonymous_page`→检查VMA→vm_flags&VM_WRITE→1. 只读访问→`do_anonymous_page→pte_alloc`分配PTE→映射zero page(`my_zero_pfn`全零共享页→设置PTE为_PAGE_SPECIAL|_PAGE_PFN=zero_pfn→只读)——2. 写访问→`alloc_zeroed_user_highpage_movable(gfp)`通过Buddy分配零页→`pte_mkwrite`设置可写+`__SetPageUptodate`+`page_add_new_anon_rmap`建立匿名反向映射→`lru_cache_add`加入LRU→`set_pte_at`设置PTE→首次缺页≈1-2微秒(Buddy分配+zeroing+PTE设置) (B1/Ch6)
- **COW缺页完整路径**(mm/memory.c): fork→子进程拷贝父进程页表→所有可写页标记为`_PAGE_RW=0`(只读)→子进程写→#PF(write=1, present=1)——`handle_pte_fault→do_wp_page`→检查`page_count(page)>1`(多次共享)→需要COW: `wp_page_copy`→`alloc_page_vma(GFP_HIGHUSER_MOVABLE, vma, addr)`通过Buddy分配新物理页→`cow_user_page(new_page, old_page, addr, vma)`→copy_user_highpage(kmap_atomic拷贝)→`page_remove_rmap(old_page)`减少旧页映射计数→`page_add_new_anon_rmap(new_page)`新页建立匿名反向映射→`lru_cache_add(new_page)`加LRU→`ptep_clear_flush`清除旧PTE+TLB flush→`set_pte_at_notify`设置新PTE为可写+映射新页→`new_folio`→COW后父/子各自独立物理页——父进程写同样的触发自己的COW——`reuse_old_page`: page_count=1(仅当前进程映射)→直接`pte_mkwrite`→跳过拷贝 (B1/Ch6)
- **文件缺页 File-Backed Fault**(mm/memory.c): 访问mmap文件地址→#PF→`handle_pte_fault→do_fault→do_shared_fault(MAP_SHARED)/do_read_fault(MAP_PRIVATE读)/do_cow_fault(MAP_PRIVATE写)`——MAP_SHARED写: `do_shared_fault→__do_fault→vma→vm_ops→fault(vmf)`→`filemap_fault→do_sync_mmap_readahead→page_cache_sync_readahead`→`__filemap_get_folio→filemap_get_entry→folio`页缓存未命中→`readpage→submit_bio→IO`→之后: `finish_fault→alloc_page`→`page_add_file_rmap→set_pte_at`→MAP_PRIVATE写: `do_cow_fault→__do_fault`读原页→然后`do_wp_page`COW分支→copy page+修改→写不传播到文件→MAP_PRIVATE读: `do_read_fault→__do_fault`→`finish_fault`→映射页缓存页(只读) (B1/Ch6)
- **栈扩展与GUP**(mm/memory.c, mm/gup.c): 栈→访问栈下方未映射区域→#PF→`handle_mm_fault→do_anonymous_page`→`expand_stack(vma, addr)`: 检查addr是否在栈可扩展范围(`vma→vm_start - stack_guard_gap - PAGE_SIZE`)→`acct_stack_growth(mm, vma, grow)`检查RLIMIT_STACK是否超→`vma→vm_start -= PAGE_SIZE×grow`→分配新页→匿名缺页→`/proc/PID/limits Limit=8192KB`——**GUP(Get User Pages)**(mm/gup.c): 内核访问用户地址(`O_DIRECT/O_ pipe/splice`): `get_user_pages(start, nr_pages, gup_flags, pages, vmas)→__get_user_pages→find_extend_vma`找VMA→`follow_page_mask`→判断PTE→Present=1→`try_grab_folio`增加引用计数→`pin_user_pages`pin→`FOLL_WRITE/FOLL_FORCE/FOLL_PIN/FOLL_LONGTERM`→注意事项: pin过多引发内存压力→`FOLL_LONGTERM`与MOVABLE冲突→cma区域preferred (B1/Ch6/Ch8, 🟡)

## 阶段3: 页缓存与写回 — I/O 性能基石 (D集群, 依赖A+B)

### 3.1 页缓存 — xarray/Readahead/Fault-Around (🔴)
- **address_space 与 xarray**(include/linux/fs.h, lib/xarray.c): `struct address_space { struct inode *host; struct xarray i_pages; gfp_t gfp_mask; unsigned long nrpages; unsigned long nrexceptional; unsigned long writeback_index; const struct address_space_operations *a_ops; }`——`i_pages`: 基数树存储→键=文件偏移/PAGE_SHIFT(页索引)→值=folio指针——xarray API: `XA_STATE(xas, &mapping→i_pages, idx)`定义遍历状态→`xas_load(&xas)→folio`查找——`xas_store(&xas, folio)→void* old`存储→`xas_find(&xas, max)`范围查找——`xas_for_each(&xas, folio, max)`遍历——`xas_set_order(&xas, idx, order)`多阶索引——`xa_lock_irq(&mapping→i_pages)`锁——RCU保护读路径: `rcu_read_lock→xas_load→rcu_read_unlock`无锁查找——`find_get_page→pagecache_get_page→find_get_entry→xa_load`→`folio_lock`独占页——4.20+替代radix tree→解释: xarray更简洁API+自动resize+RCU集成更好 (B1/Ch9)
- **Readahead 预读完整算法**(mm/readahead.c): 触发时机: (1)缺页→`filemap_fault→do_sync_mmap_readahead→page_cache_sync_ra`同步预读——(2)顺序访问→`filemap_fault→do_async_mmap_readahead→page_cache_async_ra`异步预读——预读状态: `struct file_ra_state { pgoff_t start; // 当前窗口开始`→`unsigned int size; // 当前窗口大小(页数)→async_size; // 异步部分; // 前一个窗口开始}`——`ondemand_readahead(ractl, folio, offset, req_size)`: 初始窗口→4页→顺序访问→检测`offset==ra→start+ra→size`连续→`ra→size *= 2`倍增→最大`ra→size=VM_READAHEAD_PAGES(默认512KB=128页)`→随机访问→`ra→size/= 2`缩小到→1页——`ra_submit(ractl)→read_pages→a_ops→readahead→mpage_readahead→mpage_alloc+add page→bio_alloc→bio_add_folio→submit_bio`→启动IO→`blk_finish_plug`——`fadvise(POSIX_FADV_SEQUENTIAL, 0, 0)`设置FMODE_RANDOM(关闭预读)/FMODE_RANDOM(随机, 减半) (B1/Ch9)
- **Fault-Around 缺页预填**(mm/memory.c): 缺页时not only填充当前页→同时填充相邻页→`do_fault_around(vmf, start_pgoff)`: 计算前后范围→`vmf→pgoff=start_pgoff—nr_pages`→`filemap_map_pages(vmf, start_pgoff, end_pgoff)`→`next=find_get_page(mapping, pgoff)`在页缓存中→存在→`alloc_set_pte`建立映射→PTE→前后各`fault_around_bytes/PAGE_SIZE`页(默认=65536/4096=16页,前后共32页)——仅文件缺页触发(`vma->vm_ops->map_pages`)——匿名缺页不适用——对顺序读有效, 随机读浪费 (B1/Ch9)
- **Direct I/O**(🟡相关): `O_DIRECT→__generic_file_write_iter→generic_file_direct_write→invalidate_inode_pages2_range`→bypass页缓存→`iomap_dio_rw→__iomap_dio_rw→bio_alloc→submit_bio`→应用管理缓存→必须block对齐——`o_sync`→`O_DIRECT|O_DSYNC`→每次IO后fdatasync——数据库首选(管理自己的buffer pool)
- **mlock/mprotect/madvise 系列**(mm/mlock.c, mm/mprotect.c, mm/madvise.c): **mlock**`(addr, len)→__mm_populate→populate_vma_page_range→get_user_pages`→锁物理页在内存→`vma→vm_flags|=VM_LOCKED`→`munlock`解锁→`/proc/PID/status VmLck`——**mprotect**`(addr, len, prot)→mprotect_fixup→change_protection→change_protection_range→walk_page_range→change_pte_range`→修改每个PTE的保护位→`set_pte_at`+TLB flush——**madvise**`(addr, len, advice)→madvise_walk_vmas→madvise_vma_behavior→`MADV_NORMAL/MADV_RANDOM(减少预读)/MADV_SEQUENTIAL(增加预读)/MADV_WILLNEED(预读预分配, `force_page_cache_readahead`)/MADV_DONTNEED(丢弃页缓存, `lru_add_drain→zap_page_range→free_pages`)/MADV_FREE(标记可立即回收)/MADV_COLD(移出活跃LRU→inactive)/MADV_PAGEOUT(立即回收)/MADV_HUGEPAGE/MADV_NOHUGEPAGE→`khugepaged_enter`扫描merge——`process_madvise`(5.10+)跨进程madvise (B1/Ch8, 🟡)

### 3.2 Writeback — 脏页回写 (🔴)
- **脏页标记与限流触发链**(mm/page-writeback.c): `folio_mark_dirty→folio_account_dirtied→__folio_mark_dirty→a_ops→dirty_folio→__xa_set_mark(&mapping→i_pages, folio_index(folio), PAGECACHE_TAG_DIRTY)`→xarray标记DIRTY→`inc_node_page_state(folio, NR_FILE_DIRTY)`→全局脏页计数+1→`wb_dirty_exceeded(wb, bg_thresh)`检查是否超后台阈值→超→`wb_start_background_writeback(wb)`唤醒flusher——第二层: `balance_dirty_pages_ratelimited(current→dirty_paused_when)`→`balance_dirty_pages(bdi, pages_dirtied)`→`global_dirty_limits(&background_thresh, &dirty_thresh)`计算两个阈值——`background_thresh=total_available_memory * dirty_background_ratio/100`(默认10%)——`dirty_thresh=total_available_memory * dirty_ratio/100`(默认20%)——脏页超dirty_thresh→`current→nr_dirtied`和`dirty_pause`→`io_schedule_timeout(pause)`进度睡眠→直到脏页低于dirty_thresh——`dirty_expire_interval`(30s)→超时无写回→`wb_check_background_flush→wb_queue_work(wb, &wb→dwork)`→唤醒flusher (B1/Ch10)
- **Flusher线程工作机制**(fs/fs-writeback.c): per-backing-device→`struct bdi_writeback`→`wb_workfn→wb_do_writeback→wb_check_background_flush→wb_check_old_data_flush`→`wb_writeback(wb, work)`: `writeback_sb_inodes(wb, sb)`→遍历sb的脏inode→`__writeback_single_inode(inode, wbc)→do_writepages(mapping, wbc)→a_ops→writepages→mapping→a_ops→writepages→ext4_writepages`→`mpage_map_and_submit_extent`→`mpage_submit_bio→bio_alloc→bio_add_folio→submit_bio`→创建bio→块层→磁盘——写完→`folio_end_writeback(folio)→folio_clear_dirty`→`__xa_clear_mark(&mapping→i_pages, index, PAGECACHE_TAG_DIRTY)`——`writeback_inodes_wb(wb, nr_pages)`限制单次回写量→`wbc→nr_to_write=LONG_MAX`(默认全回写)→单位`4KB`=1页——`writeback_sb_inodes`→判断`wbc→sync_mode==WB_SYNC_NONE`(后台)/`WB_SYNC_ALL`(sync系统调用)→WB_SYNC_ALL等待每个inode回写完成 (B1/Ch10)
- **Dirty Throttling 限流数学**(mm/page-writeback.c): 核心目标: 脏页量稳定在`setpoint=(background_thresh+dirty_thresh)/2`→pid控制器思想——`dirty_ratelimit=bdi_dirty_ratelimit`: 平滑的长期写速率(页/秒)——`pos_ratio`: 当前脏页量偏离setpoint的比例→`pos_ratio < 1`(脏页多于goal→slow down)→`pos_ratio > 1`(少于goal→speed up)→计算: `bdi_position_ratio(bdi, thresh, bg_thresh, dirty, bdi_dirty)`→返回0-2倍间值——`task_ratelimit=dirty_ratelimit * pos_ratio >> RATELIMIT_CALC_SHIFT`→每个任务的实际写速率——`bdi_dirty_limit(bdi, dirty)`→此设备的脏页上限——`global_dirty_limits`已过时(5.9+统一domain→`domain_dirty_limits`)——`wb->balanced_dirty_ratelimit`→每200ms更新一次——`/proc/sys/vm/dirty_ratio`(全局, %)/`dirty_background_ratio`(全局, %)——`dirty_bytes`/`dirty_background_bytes`(绝对值, 覆盖ratio) (B1/Ch10, 🟡限流数学)
- **memfd**(mm/memfd.c): `memfd_create(name, MFD_CLOEXEC|MFD_ALLOW_SEALING)→get_unused_fd_flags→anon_inode_getfile("[memfd]", &memfd_fops)→shmem_file_setup(name, size, VM_NORESERVE)`→匿名文件→无磁盘后备→完全在页缓存中→`ftruncate(fd, size)`→写(fd,"data")→shmem`writepage→shmem_writepage→swap_writepage`(可swap)→`mmap`共享→`F_ADD_SEALS(F_SEAL_SHRINK|F_SEAL_GROW|F_SEAL_WRITE)`不可修改——Android/Graphics/Flatpak→高效率IPC共享内存 (B1/Ch10, 🟡)

### 4.1 Reverse Mapping — 反向映射 (🔴)

- **Freeing Userland Memory**(mm/memory.c): munmap→`unmap_region→unmap_single_vma→unmap_page_range→zap_pte_range`→遍历pte→`ptep_get_and_clear→tlb_remove_page_sync_one`→MMU gather: `tlb_gather_mmu(&tlb, mm)`→tlb_finish_mmu释放(TLB flush+page释放)→`free_pages_and_swap_cache(pages)`→`free_swap_cache`/`put_page`→`lru_add_drain`→TLB延迟刷新: 批量flush减少IPI→`range_end=range_start+HPAGE_SIZE*(n)`每次batch边界→`tlb_flush_mmu_tlbonly→flush_tlb_mm_range` (B1/Ch7, 🟡)

### 4.2 LRU 与回收 — kswapd + Direct Reclaim (🔴)
- **LRU 四链表传统模型**(include/linux/mmzone.h, mm/vmscan.c): `struct lruvec { struct list_head lists[NR_LRU_LISTS]; // LRU_INACTIVE_ANON=0, LRU_ACTIVE_ANON=1, LRU_INACTIVE_FILE=2, LRU_ACTIVE_FILE=3→ LRU_UNEVICTABLE=4`→`struct pglist_data *pgdat; }`→**状态转移**: inactive到active→`folio_activate→folio_inc_gen(lruvec, folio, LRU_ACTIVE_ANON/file)`→访问时(`folio_mark_accessed→folio_referenced`二次访问→`folio_activate`)——active到inactive→`folio_deactivate→lru_move_tail_fn`长时间未访问——回收inactive开始: `shrink_inactive_list→isolate_lru_folios`从inactive tail隔离→`shrink_folio_list`回收→未回收成功的folio→`lru_add_fn`移到active(二次机会)——**MGLRU(Multi-Gen LRU, Linux 6.1+)**: 替代四链表→`lru_gen_folio`→多代(generation)→`lru_gen_del_folio/lru_gen_add_folio`→每代有时间戳→回收最老代→更精确侦测冷热——`/sys/kernel/mm/lru_gen/enabled`开关 (B1/Ch11)
- **kswapd 后台回收**(mm/vmscan.c): per-NUMA-node→`kswapd_run(nid)→kthread_run(kswapd, pgdat, "kswapd%d", nid)`→`kswapd→balance_pgdat(pgdat, order, highest_zoneidx)`→检查每个zone的水位→低于low→`kswapd_shrink_node(pgdat, &sc)`→`shrink_node(pgdat, sc)→shrink_node_memcgs`→每个memory cgroup→`shrink_lruvec(lruvec, sc)→get_scan_count(lruvec, sc, nr)`确定anon/file扫描比例→`shrink_inactive_list(lruvec, sc, LRU_INACTIVE_ANON/file, &stat)`→`isolate_lru_folios`→`shrink_folio_list`回收→回收量达标水位high→kswapd睡眠——`pgdat_balanced(pgdat, order, classzone_idx)→zone_watermark_ok`检查——`kswapd_try_to_sleep→schedule_timeout`——kswapd_order控制回收order→order=0(普通)→唤醒时`pgdat→kswapd_order=max(order, pgdat→kswapd_order)`→`kswapd_highest_zoneidx`记录需要回收的最高zone (B1/Ch11)
- **直接回收 Direct Reclaim**(mm/page_alloc.c, mm/vmscan.c): Buddy分配失败→`__alloc_pages_direct_reclaim(gfp_mask, order, alloc_flags, ac, &did_some_progress)`→检查当前上下文是否允许回收(`gfpflags_allow_blocking(gfp_mask)`)→是→`__perform_reclaim(gfp_mask, order, ac)→try_to_free_pages(zonelist, order, gfp_mask, nodemask)`→`do_try_to_free_pages(zonelist, &sc)→shrink_zones(zonelist, sc)→shrink_node→shrink_node_memcgs→shrink_lruvec`——直接回收在分配路径上执行→阻塞当前任务→优先级:`sc.priority=DEF_PRIORITY(12)`→下降到0→回收越来越激进→`sc.may_writepage`(允许脏页写回)→`sc.may_unmap`(允许unmap)→`sc.may_swap`(允许swap)——分配成功→`did_some_progress=1`→page可用——分配仍失败→`__alloc_pages_may_oom→out_of_memory→oom_kill_process`————无`__GFP_DIRECT_RECLAIM`→直接返回NULL→上层处理 (B1/Ch11)

### 4.3 Swap — 匿名页换出换入 (🔴)
- **Swap换出路径**(mm/page_io.c, mm/swap_state.c): 匿名页回收→`shrink_folio_list→add_to_swap(folio)→get_swap_page`→分配swap slot→`swp_entry(val)`构造swap entry→`slot=swp_offset(entry)`→`nr_pages=1<<order`多页连续slot——`__swap_writepage(page, wbc, &plug)→swap_writepage(page, wbc)→bdev_write_page(bdev, sector, page, wbc)`直接写→`swap_slot_free_notify`→**换出后PTE**: `set_pte_at(mm, addr, pte, swp_entry_to_pte(entry))`→PTE低12位=0(Present=0)→高48位=`(type<<SWP_TYPE_SHIFT)|(offset<<SWP_OFFSET_SHIFT)`→type索引swap_info_struct(最多MAX_SWAPFILES)→offset指swap分区中的slot——`swap_info_struct→swap_map[offset]`记录slot使用计数: 0=free, SWAP_HAS_CACHE(1)=有swap cache无映射, SWAP_MAP_MAX=最大引用——`__swap_count(entry)`读计数——`find_next_to_swap`找可换出folio (B1/Ch12)
- **Swap换入路径**(mm/memory.c, mm/swap_state.c): 访问swap出的页→PTE Present=0但非零→`is_swap_pte(pte)`检测→`do_swap_page(vmf)→lookup_swap_cache(entry)`→**hit**: `swapcache=swap_address_space(entry)→i_pages→lookup`→folio已在swap cache(还没释放物理页)→直接`pte_unmap_unlock+set_pte`映射→**miss**: `swapin_readahead(entry, gfp_mask, vmf)`→`swap_cluster_readahead`→预读周围swap slots→`read_swap_cache_async(entry, gfp_mask, vma, addr, &page_allocated)`→`swap_readpage(page, synchronous, &psi)`→`swap_readpage_fs→bdev_read_page`从swap分区读→中断→bio→end_io→`end_swap_bio_read→folio_end_read`设置uptodate→唤醒do_swap_page→`swap_free(entry)`减少slot ref→`set_pte_at`建立用户页表映射→**Swap Cache 生命周期**: `__read_swap_cache_async→alloc_page_vma+add_to_swap_cache(page, entry)`→folio加入swap address_space→`SetPageSwapCache(page)`→换入完成→`delete_from_swap_cache(page)`→移除cache→`swapcache_free(entry)`→folio重新为user page (B1/Ch12)
- **Swap 碎片化处理**(mm/swapfile.c): swap_info_struct→`cluster_info→cluster_next`→next分配指针→`scan_swap_map_slots`→设备级扫描→`cluster_is_free`找空闲cluster→每个cluster=SWAPFILE_CLUSTER(256)个slots→cluster分配减少碎片→`swap_entry_free`释放slot→device full→`nr_swap_pages`追踪→`get_swap_pages`→`scan_swap_map_try_ssd_cluster`SSD快速路径——Swap priority: `swapon -p PRIORITY`→`highest_priority`优先分配→`swap_list→next`轮询——swapoff→`try_to_unuse→unuse_pte→unuse_pte_range`（遍历所有进程页表，重新映射回物理页）→迁移完所有swap entries→关闭swap文件/分区 (B1/Ch12)
- **Folio Batches 批量回收**(mm/vmscan.c): `shrink_folio_list→folio_list`→需要batch处理避免过多pagevec操作→`free_unref_page_list→free_unref_page_commit`→PCP回灌→`rotate_reclaimable_folios→folio_rotate_reclaimable`→`lru_add_drain→lru_add_fn`→批量：减少zone→lru_lock获取次数→减少TLB shootdown累积→每次batch_size=`SWAP_CLUSTER_MAX`(32)个folio→shrink_inactive_list→`sc->nr_scanned+=nr_taken`扫描计数——`shrink_folio_list`→`pageout()`/`pageout_writeback`→`VM_BUG_ON_PAGE(PageWriteback(page))`→`submit_bio`后folio writeback→`PG_writeback` (B1/Ch11, 🟡)

### 4.4 Overcommit 与 OOM Killer — 最后的防线 (🔴)
- **Overcommit 三策略**(mm/util.c): `sysctl_overcommit_memory`→`/proc/sys/vm/overcommit_memory`——**0(启发式)**: `__vm_enough_memory(pages, 0)→vm_acct_memory(pages)`→检查:`allowed=(totalram_pages-hugetlb_total_pages+total_swap_pages)*overcommit_ratio/100+total_swap_pages`→if `allowed < pages+vm_committed_as`→return -ENOMEM→失败。**1(总是)**: 乐观→从不拒绝→OOM处理——**2(严格)**: `allowed=(totalram_pages-hugetlb_total_pages)*overcommit_ratio/100+total_swap_pages`→if `committed+pages > allowed`→-ENOMEM→`/proc/sys/vm/overcommit_ratio`(默认50%, 表示可用RAM的50%为额外可分配)——overcommit=0时OOM是不可避免的——`vm_commit_limit`记录当前commit上限 (B1/Ch4)
- **OOM Killer 选择流程**(mm/oom_kill.c): Buddy分配→所有回收尝试失败→`__alloc_pages_may_oom→out_of_memory(oc)→oom_kill_process(oc, task, points, totalpages, NULL, "Out of memory")`→ (1) `select_bad_process(oc)→for_each_process(p)`→`oom_evaluate_task(p, oc)`→跳过: `is_global_init(p)`(PID 1)/`same_thread_group(p, current)`/`test_tsk_thread_flag(p, TIF_MEMDIE)`(已被kill的进程)/`oom_unkillable_task(p)`→(2) 计算`oom_badness(p, oc, totalpages)`: `points=get_mm_rss(p->mm)+get_mm_counter(p->mm, MM_SWAPENTS)+mm->nr_ptes/2+oom_adj_val`→`points*1000/totalpages`归一化→`points+=oom_score_adj→`(3) 在`oc→chosen_points<points`时更新选择→`oc→chosen=task`→(4) `oom_kill_process(oc, chosen, points)`→`pr_err("Out of memory: Killed process %d (%s)...")`→dmesg——若选择的任务有子进程→`for_each_child`→若子进程有不同mm→尝试杀子进程(减少伤害)→若杀主进程→`send_sig(SIGKILL, victim, 0)`→`TIF_MEMDIE`设置→`wake_oom_reaper(victim)`→收割 (B1/Ch12)
- **OOM Reaper 收割**(mm/oom_kill.c): `wake_oom_reaper(victim)→queue_delayed_work(system_wq, &oom_reaper_wait, 0)`→`oom_reaper(victim)→mutex_lock(&oom_lock)->mmap_read_lock(mm)`——`__oom_reap_task_mm(victim, mm)`: 遍历所有VMA→`for_each_vma(vmi, vma)→MADV_DONTNEED`类型的unmap→`unmap_page_range`→释放所有物理页→`tlb_finish_mmu`→解锁`mmap_read_unlock`——若进程阻塞(D状态,不可打断睡眠)→无法获取mmap_lock→等待最多`MAX_OOM_REAP_RETRIES=10`次(1秒)→失败→`oom_reap_task_mm`返回false→`force_sig(SIGKILL)`强制KILL(不等reaper)——已经设置TIF_MEMDIE的进程在alloc时走快速路径→直接返回失败不重试 (B1/Ch12)
- **OOM Score 调整接口**: `/proc/PID/oom_score`(动态,随内存使用变化,范围0-1000)→`/proc/PID/oom_score_adj`(手动,范围-1000~1000, -1000永不杀, 1000必杀)→`choom -n <score_adj> -p <PID>`修改——保护关键进程: `echo -1000 > /proc/$(pidof sshd)/oom_score_adj`→`echo -1000 > /proc/$(pidof mysqld)/oom_score_adj`——`oom_score_adj`会加到`points`后影响OOM Killer选择——`/proc/vmstat oom_kill`记录总共来OOM次数 (B1/Ch12, 🟡解读)

### 4.5 内存监控与统计接口 (🟡)
- **MemAvailable 计算**(mm/page_alloc.c): `si_mem_available()`→`MemAvailable=MemFree+pagecache+slab_reclaimable-(watermark_low+reserved)`→`MemFree`(`/proc/meminfo MemFree`—完全空闲)→`pagecache`=`NR_ACTIVE_FILE+NR_INACTIVE_FILE`(可回收的文件页)→`slab_reclaimable`=`NR_SLAB_RECLAIMABLE_B`(可回收SLAB)——`reserved`=每个zone的水位预留——`watermark_low`=每个zone的WMARK_LOW——`/proc/meminfo`: MemTotal/MemFree/MemAvailable/Buffers/Cached/SwapCached/Active/Inactive/Active(anon)/Inactive(anon)/Active(file)/Inactive(file)/Unevictable/Mlock/SwapTotal/SwapFree/Dirty/Writeback/AnonPages/Mapped/Shmem/KReclaimable/Slab/SReclaimable/SUnreclaim/KernelStack/PageTables/NFS_Unstable/Bounce/WritebackTmp/CommitLimit/Committed_AS/VmallocTotal/VmallocUsed/VmallocChunk/Percpu/HardwareCorrupted/AnonHugePages/ShmemHugePages/ShmemPmdMapped/FileHugePages/FilePmdMapped/HugePages_Total/HugePages_Free/HugePages_Rsvd/HugePages_Surp/Hugepagesize/Hugetlb/CmaTotal/CmaFree (B1/Ch13)
- **PSS 与 smaps**(fs/proc/task_mmu.c): `/proc/PID/smaps`→每个VMA→Rss/Size/Pss/Shared_Clean/Shared_Dirty/Private_Clean/Private_Dirty/Referenced/Anonymous/LazyFree/AnonHugePages/ShmemPmdMapped/FilePmdMapped/Shared_Hugetlb/Private_Hugetlb/Swap/SwapPss/Locked/THPeligible/VmFlags——**PSS**(Proportional Set Size): `Private+Shared/n_shared`→两进程共享10MB库→每进程PSS=Private+5MB→`smaps_rollup`(4.14+)汇总所有VMA→Pss_Anon/Pss_File/Pss_Shmem→比RSS精确——`/proc/PID/status`: VmPeak/VmSize/VmLck/VmPin/VmHWM/VmRSS/RssAnon/RssFile/RssShmem/VmData/VmStk/VmExe/VmLib/VmPTE/VmSwap——`cat /proc/meminfo`→`htop`内存颜色→蓝色=buffer/绿色=cache/黄色=swap/红色=used (B1/Ch13)
- **procfs vm 参数汇总**(/proc/sys/vm/): `min_free_kbytes`(MIN水位,默认~4MB,大内存建议增)→`dirty_ratio`(20%, 脏页阻塞阈值)→`dirty_background_ratio`(10%, 后台回写阈值)→`dirty_expire_centisecs`(3000=30s,脏页过期时间)→`dirty_writeback_centisecs`(500=5s,flusher唤醒周期)→`swappiness`(0-200,默认60: 0=尽量不用swap, 100=积极swap, 200=内存+cgroup)——`overcommit_memory`(0/1/2)——`overcommit_ratio`(50%, strict策略用)——`oom_kill_allocating_task`(0=杀最坏/1=杀当前分配者)——`panic_on_oom`(0=仅OOM/1=OOM+cgroup/2=panic)——`watermark_scale_factor`(10/1000=0.1%,水位缩放)——`vfs_cache_pressure`(100, 越低保留更多dentry/inode缓存) (B1/Ch13)
- **内存cgroup v2**(🟢→OS内核交叉引用): `memory.max`/`memory.high`/`memory.low`/`memory.min`→`memory.stat`(anon/file/swap/pgfault/kmem/slab)——`memory.events`(low/high/max/oom/oom_kill)——`memory.oom_control`→cgroup OOM: 比全局OOM先触发→`mem_cgroup_oom→mem_cgroup_out_of_memory→oom_kill_process`→Docker `--memory`→K8s `resources.limits.memory` (B2)

### 4.6 用户态内存 — ptmalloc 与栈 (🟡)
- **ptmalloc(glibc 内存分配器)**: `malloc(size)→__libc_malloc(bytes)→arena_get(ar_ptr, bytes)`→获取或创建arena→**fastbins**(≤64B,单链表,LIFO,不合并相邻chunk)→**smallbins**(≤512B,双链表,与相邻free chunk合并)→**largebins**(>512B,排序双链表)→**unsorted bin**(缓存, 任何刚释放的chunk先放这里,下次malloc时优先)→大块(>MMAP_THRESHOLD=128KB)→`sys_mmap`分配→释放通过`munmap`——**brk**(≤128KB→扩展堆)→`sys_brk→brk`→arena→top chunk→top不够→`sbrk→sys_brk`(扩展program break)→线性——`malloc_trim(pad)→sbrk(-pad)`缩回OS→`MALLOC_ARENA_MAX`限制arena数(默认8*core)——ptmalloc与Buddy不同层: ptmalloc在用户态,Buddy在内核→malloc/free不一定会触发系统调用(fastbin+tcache缓存)→碎片化: ptmalloc的连续alloc→free→产生hole→外部碎片→Buddy`_alloc_pages`返回连续物理页→内核层无此碎片 (B2, 🟡)
- **进程栈与线程栈**: 主线程→`mm→start_stack→VM_GROWSDOWN`→自动扩展→`RLIMIT_STACK`(默认8MB)→`expand_stack→acct_stack_growth→vma→vm_start-=PAGE_SIZE`→匿名缺页分配→线程→`mmap MAP_ANONYMOUS|MAP_STACK|MAP_GROWSDOWN, size=N*1024*1024`→`pthread_attr_setstacksize`→默认2-8MB(glibc)→`/proc/PID/maps [stack]`/`[stack:THREAD_ID]`→`pthread_getattr_np`获取栈属性→栈溢出→分配guard page(保护页)→#PF→SIGSEGV→`pthread_attr_setguardsize`——栈大小不足→无限递归→栈扩展→耗尽地址空间→SIGSEGV (B2, 🟡)
