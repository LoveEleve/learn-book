## 视角1: 开发者视角 (Developer) — "我会不会写?"

1. 客户端POST一个JSON到微服务, 数据经过TCP→TLS→epoll→Reactor→ByteBuffer→序列化→JWT验证→业务处理的全路径, 每个环节的关键类/函数是什么?
2. RPC框架(Dubbo/gRPC)中服务注册、发现、负载均衡的完整调用链(Provider→Registry→Consumer→Monitor), 每一步的失败模式是什么?
3. 为什么Cache Aside模式下"先删缓存再写DB"比"先写DB再删缓存"更容易产生脏数据? 延时双删的延迟时间怎么确定?
4. Kafka中消费者offset提交机制和分区有序保证: 为什么partition key选择影响消息顺序? 消费者重平衡(Rebalance)时的坑?
5. K8s Deployment RollingUpdate中maxSurge和maxUnavailable两个参数如何影响滚动更新的速度和安全?

## 视角2: 性能工程师视角 (Performance) — "哪里最慢?"

1. ByteBuffer的HeapByteBuffer vs DirectByteBuffer: 为什么Direct更快(省一次拷贝)? 什么场景必须用Heap(中间数据频繁读写)?
2. 一致性Hash vs 轮询 vs 加权最少连接在缓存命中率和节点增减时的性能差异量化对比 — 什么场景选哪个?
3. 本地缓存(Guava/Caffeine) vs Redis vs CDN的延迟差(微秒/毫秒/秒级), 多级缓存中每级命中率和内存开销的权衡公式
4. select(O(n))/poll(O(n))/epoll(O(1))在1万连接和10万连接下的CPU占用差异和内存开销量化分析
5. HTTP/1.1(队头阻塞) → HTTP/2(多路复用但TCP队头阻塞) → QUIC/HTTP3(彻底消除, UDP+多独立流)的延迟堆叠: 为什么HTTP/2在高丢包网络可能比HTTP/1.1更慢?

## 视角3: SRE/运维视角 (Operations) — "挂了怎么办?"

1. 分布式Session的三方案(粘滞/复制/集中存储): 在RPC集群扩容缩容时可操作性和数据一致性对比, 线上出问题回滚操作指南
2. 熔断器三状态(CLOSED→OPEN→HALF_OPEN)转换时, 监控指标和告警规则应该怎么设置? 误熔断(下游正常但统计错误)和漏熔断(下游异常但没检测到)哪种更致命?
3. 分库分表后的数据迁移(re-sharding)的完整SOP: 双写期(多久)→数据校验(checksum)→灰度切读(如何保证一致)→清理老库(何时)? 哪步最容易出错?
4. 灰度发布(金丝雀)操作手册: 5%流量到v2→检查哪些Metrics→如果异常→回滚时间线和通知模板(消息给谁? 什么消息?)
5. CI/CD流水线的安全检查清单: 代码扫描(Sonar/Snyk)→镜像扫描(Trivy)→部署前准入(签名→批准)→健康检查(Readiness/Liveness)→回滚SOP

## 视角4: 架构师视角 (Architect) — "为什么这么选?"

1. 你整个系统ACP选择: 配置(ZK=CP)+缓存(Redis=AP)+订单(MySQL=CP+主从=AP读/CP写) → 为什么不是全局一致选择? 各子系统ACP冲突的工程解法
2. 从单体→微服务→Service Mesh的演进: 每一步要满足什么前提条件(团队规模/部署能力/监控体系/多语言需求)才能走下一步? 什么情况下应该停在当前阶段?
3. DDD限界上下文和微服务边界的对齐: 聚合根怎么映射到服务粒度? 多个聚合在同一服务是否违反DDD? 服务=聚合的陷阱是什么?
4. 单元化(Shard→Unit) vs 分库分表(Shard→DB): 什么时候需要升级到单元化? 单元化的成本(应用改造/数据同步/运维)和收益(故障隔离/跨机房延迟)的量化分析
5. Serverless(FaaS) vs K8s容器 → 什么场景Serverless有优势(冷启动可接受/事件驱动/短任务)? 什么场景必须用K8s(长连接/低延迟/复杂编排)? 混合架构的最佳实践?

## 视角5: 学生/初学者视角 (Student) — "我理解对了吗?"

1. "Reactor模式就是单线程处理所有网络事件"这个说法对吗? Redis 6.0引入了多线程——那Redis还是Reactor吗? 多线程和Reactor的关系是什么?
2. 分布式锁"Redis SET NX 30秒 + A线程业务执行40秒→锁自动过期→B线程拿到锁→A释放了B的锁"这个场景是Redlock能解决的吗? Martin Kleppmann的批评和antirez的回应各是什么?
3. 熔断器OPEN状态下请求全部被拒绝——但如果服务已恢复正常呢? HALF_OPEN状态如何探测"服务恢复"? 探测成功率多少才算通过?
4. 分库分表后"查询不带分片键就要全表扫描"的终极解法: 为什么不能自动在所有分片上查询再合并? ES索引和TiDB(Hash分片后自动聚合)是怎么解决这个问题的?
5. Service Mesh的Envoy Sidecar为每个Pod注入一个代理——额外增加CPU/内存/延迟开销。小规模部署(5个服务,20个Pod)值得吗? Istio建议的最小规模是多少? 什么场景下Service Mesh的收益超过成本?
