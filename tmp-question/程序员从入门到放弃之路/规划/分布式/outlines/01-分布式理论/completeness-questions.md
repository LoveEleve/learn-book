# 01-分布式理论 — 多视角完备性提问

> 5 视角 × 5 题 = 25 题 | 2026-08-09

---

## 视角1: 开发者 (写分布式系统代码的人)

1. 一个跨Redis和MySQL的事务, @Transactional只对MySQL有效 — Redis操作失败后MySQL能自动回滚吗? Seata AT模式的自动回滚原理是什么?
2. Raft日志中一个entry的index=5,term=3被提交了 — 如果后续Leader的term=4又重新写了index=5 — Raft怎么保证旧index=5不会被覆盖?
3. ZooKeeper的临时节点, 如果客户端心跳断了30秒会话过期, ZK删除了临时节点 — 但客户端还在运行(只是网络抖动) — 会发生什么? 怎么设计防御?
4. TCC的Cancel操作因为网络原因执行失败 — Hmily/Seata会怎么处理? 为什么Cancel需要幂等?
5. 使用RocketMQ事务消息发送Half Message后, 本地事务执行成功但Producer宕机 — RocketMQ的回查机制多久触发一次? 消费者什么时候能看到这条消息?

## 视角2: 架构师 (系统设计与选型)

1. 一个全球部署的金融系统, 需要跨纽约/伦敦/新加坡三地的分布式事务 — 选Seata AT还是基于TrueTime的Spanner-like方案? 延迟/一致性/成本的三角怎么权衡?
2. 微服务拆了50个服务, 需要分布式事务但不想所有服务都加TCC的三套代码 — 哪些场景用可靠消息(异步解耦)足以替代TCC? 评估标准是什么?
3. 5节点的Paxos vs 5节点的Raft — 如果业务有频繁的Leader切换(运维/升级), 哪个更合适? Multi-Paxos的日志空洞在Leader切换时有什么额外的恢复成本?
4. 需要设计一个配置中心(类似ZooKeeper) — 从零实现ZAB/Raft vs 直接用现有ZK/etcd/Nacos — 最小化开发成本时, 哪个是正确选择?
5. Redis Cluster用Gossip做成员检测, etcd用Raft做Leader选举 — 一个系统可以同时用两种共识/广播协议吗? 什么场景需要?

## 视角3: SRE/排错 (生产故障处理)

1. 线上ZooKeeper集群3节点, 突然2个节点宕机(Java OOM) — 最后一个节点能继续服务吗? ZAB协议在"多数派丢失"后的行为是什么?
2. 一个2PC事务卡在PREPARED状态, 锁一直没有释放 — 你怎么判断是协调者宕机还是参与者hang住了? MySQL `XA RECOVER`能帮你看到什么?
3. Raft集群频繁选举(每秒Leader切换一次) — 可能的根因有哪三类? election timeout调大能解决吗? 需要检查哪些指标?
4. 可靠消息消费端有大量重复消息(msg_id相同, 内容相同) — 是生产者重发还是消费者重复消费? 怎么排查?
5. 一个Cassandra集群的客户端偶尔读到旧数据(10秒前的版本) — Quorum设置是W=1/R=1 — 怎么调成强一致? 改W/R=QUORUM后还能保证写入永远不会失败吗?

## 视角4: 研究者/深层追问 (为什么这样设计)

1. Lamport的Paxos论文(The Part-Time Parliament, 1998)用古希腊议会的故事写算法 — 这篇论文为什么被拒了8年才发表? "Paxos"的名字从何而来?
2. FLP(1985)证明异步系统+1故障→无确定性共识 — 但Paxos(1989)在异步系统中"尽可能"工作 — 这两个结论矛盾吗? Paxos引入的"非确定性"到底是什么(Random/Timeout)?
3. Lamport逻辑时钟(1978) vs Mattern向量时钟(1989) — 它们分别能检测什么不能检测什么? 为什么向量时钟大小随节点数线性增长是根本性的(证明: N个节点的最少状态)?
4. Google Spanner的TrueTime基于GPS+原子钟 — 如果GPS被欺骗(spoofing), Spanner的外部一致会被破坏吗? 什么攻击可以打破TT.now()的不确定性窗口?
5. PBFT(BFT共识)在区块链(Cosmos/Tendermint)领域复兴 — 为什么传统分布式系统(数据库/协调服务)不用PBFT而用崩溃故障模型? 是性能问题还是信任模型问题?

## 视角5: 学生/新手 (刚接触分布式理论)

1. CAP说"P发生时C和A只能二选一" — 但网上有人说"CAP三者可以同时满足" — 这两种说法矛盾在哪里? "P不发生时三者都能满足"是对的吗?
2. Paxos有Proposer/Acceptor/Learner三个角色 — 一个节点可以同时当多个角色吗? 如果可以, 为什么论文要分开定义三个角色?
3. 2PC和3PC的"阻塞"到底是什么意思? 为什么3PC的"预提交"能打破阻塞, 但又因为网络分区不安全?
4. 最终一致和强一致的区别: 一个用户付款后马上关闭了页面 — 他的余额会立刻显示扣款吗? 如果不显示, 系统算bug还是正常?
5. Raft的"日志复制"和MySQL的主从复制(Binlog)是一回事吗? 它们有什么相同和不同?
